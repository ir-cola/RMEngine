## 2. Prefab の上書きを「部品の変わらない番号」で覚える

2026-11-21 13:29 に見つけた穴。**同じ型の部品を 2 つ付けた物**で、Prefab の側の 1 つ目を消す / 並べ替えると、
置いた物の上書き (`Prefab.cpp` の `"index"` = 型の中の何番目) が**別の部品に掛かるか、黙って消える**。
別の型どうしでは起きない。Undo は大丈夫 (戻す順に探し直す)。

### 2-a. 形

- 部品に **`key`** (`uint32_t`。エンティティの中で重ならない番号。付けた順に 1, 2, 3 …) を持たせ、保存する:
  `{"type": "...", "key": 2, "data": {...}}`
- 付けるとき: そのエンティティの今の一番大きい `key` + 1。消しても番号は詰めない
- コピー・貼り付け・Prefab から作る: **`key` をそのまま写す** (Prefab の部品と置いた物の部品が同じ番号で対になる)
- 上書き (`fields` / `removedComponents`) は `"key"` で覚える。`"index"` は書かない
- **前のファイル**: `key` の無い部品は、読むときに並び順で 1, 2, 3 … を振る。上書きの `"index"` は、
  そのときの Prefab の並びで `key` に置き換える (今と同じ意味になる)。知らないキーは書き戻すので、前の版の
  エンジンで開いても `key` は消えない (憲法 6)
- スクリプトの `Get<T>(n)` の n は今のまま「何番目」(コードの中の数なので)。ヘルプに「並べ替えると変わる」と書く

### 2-b. 段取り

1. **先にテスト**: 「Prefab に回り続けるを 2 つ → 置いた物で 2 つ目を上書き → Prefab で 1 つ目を消す →
   伝える → 上書きが 2 つ目に残る」。今のコードで**落ちることを確かめてから**直す
2. 前の形のファイルが同じ意味で読めるテスト
3. Undo の命令 (今は「型 + 何番目」で探す) も `key` で探すように変える (同じことを 2 通りで探さない)

## 3. 形を増やす

**決めたこと (ユーザー 2026-11-21)**: 3D は円柱・円錐・四角錐・アーチ、2D は直角三角形・半円・台形など。
**描く形とコライダーの両方**に。自分で作る形はモデリングのソフトの後。

### 3-a. 今の形 (2026-11-23 にコードで確かめた)

- 描く形: `space3d::Shape` = 箱・球・円柱・カプセル・平面 (`Primitives.h`。どれも大きさ 1 で、大きさは Transform)
- コライダー (3D): 箱・球・カプセル・メッシュ。2D: 箱・円・カプセル
- 「追加 ▸ 3D オブジェクト ▸ 円柱」は、**円柱を囲む箱のコライダー**が付く (`physics/editor/Connector.cpp` の
  `AddCollider`。円柱のコライダーが無いため)。→ 3-b で円柱のコライダーに直る
- 2D の描画 (`space2d/Renderer2D`) は、画像か 1 色の四角だけ。図形を塗る道は無い

### 3-b. 3D

**形の計算は 1 か所** (憲法 2): `space3d` に純粋な関数を置き、描く形 (`ShapeMesh`) も物理のコライダーも、
そこから作る。物理は `space3d` を前提にしているので読める。

| 形 | 大きさ 1 のとき | 描く形 | Jolt の形 |
|---|---|---|---|
| 円柱 | 直径 1・高さ 1 (今のまま) | 今のまま | `CylinderShape`。★ 横の大きさが X と Z で違う (楕円) ときは `ConvexHullShape` (24 角の筒) |
| 円錐 | 底の直径 1・高さ 1・先が上 | 新しく | `TaperedCylinderShape` (上の半径 0。同梱の Jolt で 0 を許すことを確かめた)。楕円なら凸包 |
| 四角錐 | 底 1 × 1・高さ 1・先が上 | 新しく | `ConvexHullShape` (5 点) |
| アーチ | 外の幅 1・高さ 1・奥行き 1 | 新しく | **`StaticCompoundShape`** (へこんだ形なので、弧を N 個の凸のかけら (四角の柱) に分けて並べる) |

- **アーチの欄**: 「太さ」(0.05〜0.5。外の幅に対する割合。最初 0.2)・「分ける数」(4〜32。最初 12)。
  形が「アーチ」のときだけ出す (`ShowIf`)。**描く形とコライダーで同じ欄を持つと 2 か所になる**ので:
  - 描く形 (メッシュの部品) に欄を持つ
  - コライダーの形「アーチ」は、自分の欄 (太さ・分ける数) を持つ。「追加 ▸ 3D オブジェクト ▸ アーチ」で作ると
    両方に同じ値が入る。★ 後から片方だけ変えるとずれる → コライダーに「**メッシュの形に合わせる**」を作るか
    (物理がメッシュの部品 = ゲーム制作 × 3D を読む必要があり、前に「ゲーム制作 × 3D × 物理」をやめた経緯と
    ぶつかる)、ずれを受け入れるか。★ 確認待ち。推しは「受け入れる + シーンビューの緑の線でずれが見える」
- コライダーの大きさ: 新しい 4 つは今の「箱の大きさ」(`size`) を「**大きさ**」として使う (幅・高さ・奥行き)。
  `size = (1, 1, 1)` で描く形とぴったり重なる。Transform の大きさを掛けるのは今と同じ (`DimsOf`)
- **負の大きさ** (鏡に映す): 今の `DimsOf` は大きさの絶対値を取る。円柱・円錐・四角錐・アーチは左右対称なので
  困らない (2D の直角三角形は困る: 3-c)
- 重さ: 凸の形・組み合わせの形は、Jolt が体積から出す (今の剛体の「質量」で上書きするのも今と同じ)
- 「追加 ▸ 3D オブジェクト」に 円錐・四角錐・アーチ を足し、作るとそれぞれの形のコライダーが付く
- シーンビューの緑の線 (`Outline`) にも 4 つを足す
- 保存: 列挙は名前で保存するので、項目を足しても前のファイルはそのまま読める
- テスト: 形の頂点の数・体積 (メッシュと Jolt の形でほぼ同じ)・表の向き (`FaceOut`)・アーチのかけらがすき間なく
  つながる・作った物に同じ形のコライダー

### 3-c. 2D

- 形の計算は `space2d` に 1 か所: `Outline2D(形, 欄) → 点の並び` (反時計回り・凸)。2D のコライダー (物理) と
  新しい描く部品の両方がこれを使う

| 形 | 大きさ 1 のとき | 欄 |
|---|---|---|
| 直角三角形 | 幅 1・高さ 1。直角は左下 | — (向きは Transform の回転と負の大きさで) |
| 半円 | 直径 1 (平らな辺が下) | 分ける数 (8〜64。最初 24) |
| 台形 | 下の辺 1・高さ 1 | 上の辺の割合 (0〜1。最初 0.5)・上の辺のずれ (-0.5〜0.5。0 = 左右対称) |
| 凸の多角形 | 点の並び | 点 (`std::vector<Vec2>`)。へこんだ点は凸包で除いて、インスペクターに「へこんだ点は使いません」 |

- **コライダー (2D)**: 4 つとも、点の並びを厚さ 1 の凸包 (`ConvexHullShape`) にする (今の 2D の物と同じ厚さ)
- ★ **負の大きさを残す**: 直角三角形は「直角が左下 / 右下」を負の大きさで作るのが自然。今の `DimsOf` は絶対値を
  取るので、**点に符号付きの大きさを掛けてから凸包を作る** (並びが裏返ったら逆にする)。描く側も同じ関数
- **描く部品「図形 (2D)」** (ゲーム制作 × 2D): 形・欄・塗りの色・縁の色と太さ。スプライトと同じ並び順
  (奥から手前) で描くので、`Renderer2D` の `SpriteDraw` の並びに「図形」の種類を足す (別の並びにすると、
  スプライトとの前後が決められない)。Direct2D の `ID2D1PathGeometry` で塗る
- 「追加 ▸ 2D オブジェクト」に 4 つを足し、作るとコライダー (2D) も付く (3D と同じ)
- 凸の多角形の点をシーンビュー (2D) でドラッグして動かすのは後 (最初はインスペクターの一覧)
- テスト: 点の数・面積・向き (反時計回り)・負の大きさで直角の位置が変わる・凸包

### 3-d. 段取り

1. 円柱のコライダー (+ 作った円柱に付くコライダーを直す) → 2. 円錐・四角錐 (描く + コライダー) →
3. アーチ → 4. 2D の 3 つ + 図形 (2D) → 5. 凸の多角形

## 4. 数の欄のドラッグ

インスペクターの数の欄 (`w::NumberField`) を、マウスで左右にドラッグして変える。

- **ドラッグするのは欄の名前 (左の文字)** (Unity と同じ)。数の上でのドラッグは今のまま文字の選択
  (同じ所に 2 つの意味を持たせない)。名前の上ではカーソルを ↔ に
- 動かした量: 1 DIP で `Step` (`RM_PROPERTY` の Step。無ければ数の大きさから決める: 値の 1% くらい、最小 0.01)。
  Shift で 10 分の 1 (細かく)、Ctrl で 10 倍。整数の欄は丸める。`Min` / `Max` で止める
- **Undo は離したときに 1 回** (憲法 7)。ドラッグ中は値を見せるだけ (毎フレーム積まない)。Esc で元に戻す
- ドラッグ中の Ctrl+Z はドラッグをやめる (UI タブのドラッグと同じ決まり。TestEngine の不具合 #15 の反省:
  掴んでいる間に Undo しない)
- 複数選んでいるときは、全部に同じ量を足す (1 回の Undo)
- 画面の端で止まらず回り込む (カーソルを反対の端へ) のは後

## 5. カーソルを隠す・固定する (スクリプト)

6 の FPS / TPS のカメラに要る。今の `rm::Mouse` には無い。

- `rm::Mouse::SetVisible(bool)`・`SetLocked(bool)` (固定: カーソルを止め、`Delta()` だけが動く)・`Locked()`
- **エディターの Play では、いつでもマウスを取り戻せること**: Esc で固定を外す (ゲームがまた固定するまで)・
  ゲームビューからフォーカスが外れたら外す・■ / シーンの切り替えで元に戻す
  - ★ Esc はゲームも使う (ゲーム UI の「戻るで押すボタン」・ポーズのメニュー)。**Esc はゲームにもそのまま届け**、
    エディターだけが固定を外す (書き出したゲームでは Esc で外さない。外すかはゲームが決める)。
    Esc を取り上げると、エディターと書き出したゲームで動きが変わってしまうため
- 書き出したゲーム: 固定はウィンドウの中に `ClipCursor` + 隠す。ウィンドウが裏に回ったら外す
- エディターでは、ゲームビューの上にあるときだけ隠す (TestEngine の `cursor-visible` と同じ考え)

| 距離・高さのずれ (TPS) | 最初 4 m・1.6 m |
| 感度・上下の角度の範囲・上下の反転 | マウスとパッドの右スティック (アクション LookX / LookY) |
| 壁に埋まらない (TPS) | 物理があるとき、追う物からカメラへ球を投げて、当たったら手前へ |
| なめらかさ | 追う遅れ (0 = ぴったり) |
| カーソルを固定する | オン (FPS / TPS)。5 の API で |

- 簡易移動の「カメラの向きに合わせる」は、ゲームが今見ているカメラ (`rm::Game::Camera()`) を見る
  (簡易カメラを使っていなくても動く)

### 6-c. 置き場所

「簡易操作 × 2D」のつなぎ。

## 7. 物の性質 → 燃やす・電気

**決めたこと (ユーザー 2026-11-21)**: 燃やす・電気を流すは、材質によって、それぞれ別のプラグイン。

- 案 (2026-11-21 13:28): **「物の性質」を持つ小さなプラグインを先に作り**、燃焼・電気・流体はそれを前提にする
  (燃えやすさ・電気の通しやすさを 3 つのプラグインが別々に持つと、同じ物に 3 つの設定ができる = 憲法 1)
- 形の案: アセット `.rmprops` (性質の組: 木・鉄・水 …) + 部品「物の性質」(どの組か)。中身:
  燃えやすさ・燃え始める温度・燃え続ける時間・電気の通しやすさ・熱の伝わりやすさ
- ★ **確認待ち 1: 名前** (「材質」は見た目の材質 (色・金属・法線マップ) で使っているので別の名前に。案「物の性質」)
- ★ **確認待ち 2: 物理の摩擦・跳ね返りとの関係**。今は剛体の欄。物の性質にも入れると 2 か所になる。
  案: 摩擦・跳ね返りは**剛体のまま** (物理だけが使う)。物の性質には、2 つ以上のプラグインが使うものだけ入れる
- 気温: プラグイン「気候」(版 0.0.7) が**場所ごとの気温**を持つ。燃焼・溶岩・凍るは、まわりの気温を気候から読む
  (つなぎ「燃焼 × 気候」など)。気温を別に持たない

## 9. オープンワールドの土台

BotW くらいの海 (8 の F5) の前に要る。どれもオープンワールドでなくても役に立つ順に並べた。
