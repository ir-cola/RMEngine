## 2. Prefab の上書きを「部品の変わらない番号」で覚える

**保留** (ユーザー 2026-11-23)。直し方の案だけ残す。

2026-11-21 13:29 に見つけた穴。**同じ型の部品を 2 つ付けた物**で、Prefab の側の 1 つ目を消す / 並べ替えると、
置いた物の上書き (`Prefab.cpp` の `"index"` = 型の中の何番目) が**別の部品に掛かるか、黙って消える**。
別の型どうしでは起きない。Undo は大丈夫 (戻す順に探し直す)。

### 2-a. 形

- 部品に **`key`** (`uint32_t`。エンティティの中で重ならない番号。付けた順に 1, 2, 3 …) を持たせ、保存する:
  `{"type": "...", "key": 2, "data": {...}}`
- 付けるとき: そのエンティティの今の一番大きい `key` + 1。消しても番号は詰めない
- コピー・貼り付け・Prefab から作る: **`key` をそのまま写す** (Prefab の部品と置いた物の部品が同じ番号で対になる)
- 上書き (`fields` / `removedComponents`) は `"key"` で覚える。`"index"` は書かない
- **前のファイル**: `key` の無い部品は、読むときに並び順で 1, 2, 3 … を振る。上書きの `"index"` は、
  そのときの Prefab の並びで `key` に置き換える (今と同じ意味になる)。知らないキーは書き戻すので、前の版の
  エンジンで開いても `key` は消えない (憲法 6)
- スクリプトの `Get<T>(n)` の n は今のまま「何番目」(コードの中の数なので)。ヘルプに「並べ替えると変わる」と書く

### 2-b. 段取り

1. **先にテスト**: 「Prefab に回り続けるを 2 つ → 置いた物で 2 つ目を上書き → Prefab で 1 つ目を消す →
   伝える → 上書きが 2 つ目に残る」。今のコードで**落ちることを確かめてから**直す
2. 前の形のファイルが同じ意味で読めるテスト
3. Undo の命令 (今は「型 + 何番目」で探す) も `key` で探すように変える (同じことを 2 通りで探さない)

## 3. 形を増やす

**決めたこと (ユーザー 2026-11-21)**: 3D は円柱・円錐・四角錐・アーチ、2D は直角三角形・半円・台形など。
**描く形とコライダーの両方**に。自分で作る形はモデリングのソフトの後。

### 3-a. 今の形 (2026-11-23 にコードで確かめた)

- 描く形: `space3d::Shape` = 箱・球・円柱・カプセル・平面 (`Primitives.h`。どれも大きさ 1 で、大きさは Transform)
- コライダー (3D): 箱・球・カプセル・メッシュ。2D: 箱・円・カプセル
- 「追加 ▸ 3D オブジェクト ▸ 円柱」は、**円柱を囲む箱のコライダー**が付く (`physics/editor/Connector.cpp` の
  `AddCollider`。円柱のコライダーが無いため)。→ 3-b で円柱のコライダーに直る
- 2D の描画 (`space2d/Renderer2D`) は、画像か 1 色の四角だけ。図形を塗る道は無い

### 3-b. 3D

**形の計算は 1 か所** (憲法 2): `space3d` に純粋な関数を置き、描く形 (`ShapeMesh`) も物理のコライダーも、
そこから作る。物理は `space3d` を前提にしているので読める。

| 形 | 大きさ 1 のとき | 描く形 | Jolt の形 |
|---|---|---|---|
| 円柱 | 直径 1・高さ 1 (今のまま) | 今のまま | `CylinderShape`。★ 横の大きさが X と Z で違う (楕円) ときは `ConvexHullShape` (24 角の筒) |
| 円錐 | 底の直径 1・高さ 1・先が上 | 新しく | `TaperedCylinderShape` (上の半径 0。同梱の Jolt で 0 を許すことを確かめた)。楕円なら凸包 |
| 四角錐 | 底 1 × 1・高さ 1・先が上 | 新しく | `ConvexHullShape` (5 点) |
| アーチ | 外の幅 1・高さ 1・奥行き 1 | 新しく | **`StaticCompoundShape`** (へこんだ形なので、弧を N 個の凸のかけら (四角の柱) に分けて並べる) |

- **アーチの欄**: 「太さ」(0.05〜0.5。外の幅に対する割合。最初 0.2)・「分ける数」(4〜32。最初 12)。
  形が「アーチ」のときだけ出す (`ShowIf`)。欄は**描く形 (メッシュの部品) にだけ**持つ (下の「メッシュに合わせる」)

#### コライダーを「メッシュに合わせる」(ユーザーの決定 2026-11-23)

ユーザーの答え: メッシュとコライダーがずれる問題は、「メッシュコライダーを付けて解く」か「描く形と同じように
コライダーも変わる (追従する)」のどちらか。→ **両方を 1 つの形「メッシュに合わせる」にまとめる案**:

- コライダーの形に「**メッシュに合わせる**」を足す。同じエンティティのメッシュの部品の形と欄を読み、
  **描く形と同じ形のコライダー**を作る。メッシュの形や欄を変えると、コライダーも付いてくる (エディターでも Play 中でも)
- 「追加 ▸ 3D オブジェクト」で作った物は、最初からこれ (今の「箱には箱のコライダー」の代わり)。
  自分で箱・球などを選べば、今までどおり自分の大きさの形 (メッシュより小さい当たりにしたいときなど)
- 読んだメッシュの形から作る Jolt の形:

| メッシュの形 | コライダー |
|---|---|
| 箱・球・円柱・円錐・四角錐 | 同じ形の凸の形 (上の表)。**動く物にも使える** |
| カプセル | カプセル |
| アーチ | かけらの組み合わせ。動く物にも使える |
| 平面 | 下に薄い箱 (今と同じ) |
| モデル (ファイル) | 動かない物: 三角形のメッシュ (今の「メッシュ」と同じ)。**動く物: モデルの頂点の凸包** (へこみは埋まる。今は「動かない物として扱います」になっている) |

- = ユーザーの 2 つの案の**両方**: モデルのときは「メッシュコライダー」、単純な形のときは「描く形に追従する」
- 今の形「**メッシュ**」は**そのまま残す** (三角形のメッシュ・動かない物だけ)。「メッシュに合わせる」と 1 つに
  まとめると、前のシーンで「動く物 + メッシュ」(今は「動かない物として扱います」) が凸包で**落ち始めて**しまい、
  開き直しただけで動きが変わる (自分で見直して気づいた。まとめない)
- **形の情報は 1 か所**: 形と欄 (`space3d::ShapeSpec` = 形 + アーチの欄) を `space3d` に置き、メッシュの部品は
  その型の欄を 1 つ持つ。物理は `space3d` を前提にしているので、型をそのまま読める (今も物理は、メッシュの
  コライダーのモデルを、メッシュの部品の型の名前と欄の名前で読んでいる: `PhysicsWorld.cpp` の `ModelOf`。
  前提に「ゲーム制作 × 3D」を足さずに済む)
- 作り直す条件 (`shapeFp`) に `ShapeSpec` を足す (形を変えたら物体を作り直す)。シーンビューの緑の線も同じ形
- コライダーの「大きさ」「半径」「高さ」「ずらし」は、「メッシュに合わせる」のときは出さない (`ShowIf`)
- 同じエンティティにメッシュの部品が無いときは、コライダーは作らず、インスペクターに「メッシュがありません」
- コライダーの大きさ: 新しい 4 つは今の「箱の大きさ」(`size`) を「**大きさ**」として使う (幅・高さ・奥行き)。
  `size = (1, 1, 1)` で描く形とぴったり重なる。Transform の大きさを掛けるのは今と同じ (`DimsOf`)
- **負の大きさ** (鏡に映す): 今の `DimsOf` は大きさの絶対値を取る。円柱・円錐・四角錐・アーチは左右対称なので
  困らない (2D の直角三角形は困る: 3-c)
- 重さ: 凸の形・組み合わせの形は、Jolt が体積から出す (今の剛体の「質量」で上書きするのも今と同じ)
- 「追加 ▸ 3D オブジェクト」に 円錐・四角錐・アーチ を足し、作るとそれぞれの形のコライダーが付く
- シーンビューの緑の線 (`Outline`) にも 4 つを足す
- 保存: 列挙は名前で保存するので、項目を足しても前のファイルはそのまま読める
- テスト: 形の頂点の数・体積 (メッシュと Jolt の形でほぼ同じ)・表の向き (`FaceOut`)・アーチのかけらがすき間なく
  つながる・作った物に同じ形のコライダー

### 3-c. 2D

- 形の計算は `space2d` に 1 か所: `Outline2D(形, 欄) → 点の並び` (反時計回り・凸)。2D のコライダー (物理) と
  新しい描く部品の両方がこれを使う

| 形 | 大きさ 1 のとき | 欄 |
|---|---|---|
| 直角三角形 | 幅 1・高さ 1。直角は左下 | — (向きは Transform の回転と負の大きさで) |
| 半円 | 直径 1 (平らな辺が下) | 分ける数 (8〜64。最初 24) |
| 台形 | 下の辺 1・高さ 1 | 上の辺の割合 (0〜1。最初 0.5)・上の辺のずれ (-0.5〜0.5。0 = 左右対称) |
| 凸の多角形 | 点の並び | 点 (`std::vector<Vec2>`)。へこんだ点は凸包で除いて、インスペクターに「へこんだ点は使いません」 |

- **コライダー (2D)**: 4 つとも、点の並びを厚さ 1 の凸包 (`ConvexHullShape`) にする (今の 2D の物と同じ厚さ)。
  3D と同じく「**図形に合わせる**」(同じエンティティの「図形 (2D)」の形と欄を読む。形の情報は `space2d` に 1 か所)
- ★ **負の大きさを残す**: 直角三角形は「直角が左下 / 右下」を負の大きさで作るのが自然。今の `DimsOf` は絶対値を
  取るので、**点に符号付きの大きさを掛けてから凸包を作る** (並びが裏返ったら逆にする)。描く側も同じ関数
- **描く部品「図形 (2D)」** (ゲーム制作 × 2D): 形・欄・塗りの色・縁の色と太さ。スプライトと同じ並び順
  (奥から手前) で描くので、`Renderer2D` の `SpriteDraw` の並びに「図形」の種類を足す (別の並びにすると、
  スプライトとの前後が決められない)。Direct2D の `ID2D1PathGeometry` で塗る
- 「追加 ▸ 2D オブジェクト」に 4 つを足し、作るとコライダー (2D) も付く (3D と同じ)
- 凸の多角形の点をシーンビュー (2D) でドラッグして動かすのは後 (最初はインスペクターの一覧)
- テスト: 点の数・面積・向き (反時計回り)・負の大きさで直角の位置が変わる・凸包

### 3-d. 段取り

3. アーチ → 4. 2D の 3 つ + 図形 (2D) → 5. 凸の多角形

## 4. 数の欄のドラッグ

インスペクターの数の欄 (`w::NumberField`) を、マウスで左右にドラッグして変える。

- **ドラッグするのは欄の名前 (左の文字)** (Unity と同じ)。数の上でのドラッグは今のまま文字の選択
  (同じ所に 2 つの意味を持たせない)。名前の上ではカーソルを ↔ に
- 動かした量: 1 DIP で `Step` (`RM_PROPERTY` の Step。無ければ数の大きさから決める: 値の 1% くらい、最小 0.01)。
  Shift で 10 分の 1 (細かく)、Ctrl で 10 倍。整数の欄は丸める。`Min` / `Max` で止める
- **Undo は離したときに 1 回** (憲法 7)。ドラッグ中は値を見せるだけ (毎フレーム積まない)。Esc で元に戻す
- ドラッグ中の Ctrl+Z はドラッグをやめる (UI タブのドラッグと同じ決まり。TestEngine の不具合 #15 の反省:
  掴んでいる間に Undo しない)
- 複数選んでいるときは、全部に同じ量を足す (1 回の Undo)
- 画面の端で止まらず回り込む (カーソルを反対の端へ) のは後

## 5. カーソルを隠す・固定する (スクリプト)

6 の FPS / TPS のカメラに要る。今の `rm::Mouse` には無い。

- `rm::Mouse::SetVisible(bool)`・`SetLocked(bool)` (固定: カーソルを止め、`Delta()` だけが動く)・`Locked()`
- **エディターの Play では、いつでもマウスを取り戻せること**: Esc で固定を外す (ゲームがまた固定するまで)・
  ゲームビューからフォーカスが外れたら外す・■ / シーンの切り替えで元に戻す
  - ★ Esc はゲームも使う (ゲーム UI の「戻るで押すボタン」・ポーズのメニュー)。**Esc はゲームにもそのまま届け**、
    エディターだけが固定を外す (書き出したゲームでは Esc で外さない。外すかはゲームが決める)。
    Esc を取り上げると、エディターと書き出したゲームで動きが変わってしまうため
- 書き出したゲーム: 固定はウィンドウの中に `ClipCursor` + 隠す。ウィンドウが裏に回ったら外す
- エディターでは、ゲームビューの上にあるときだけ隠す (TestEngine の `cursor-visible` と同じ考え)

### 6-0. テンプレートスクリプトの形 (案)

- **置き場所**: プラグイン「簡易操作」の `scripts/` (`EasyMove.h/.cpp`・`EasyCamera.h/.cpp`)。中身は**ふつうの
  スクリプトと同じ書き方** (`RM.h` などの SDK だけを使う)。`check_layers.ps1` が「`scripts/` は SDK のヘッダーしか
  読まない」を見る (写したときにそのままプロジェクトでビルドできるように)
- **いつでも付けられる**: 「＋ 部品を足す」の一覧に、プラグインが入っていればいつも出る。**Visual Studio も、
  プロジェクトのスクリプトのビルドも要らない** (テンプレートは**エンジンの側で先にビルドしておく**)
  - ★ 作り方の確認待ち (実装するチャットで確かめる): (a) プラグインに一緒にコンパイルする (SDK の関数表を
    エンジンの中でも渡す) / (b) テンプレートだけの DLL をエンジンのビルドで作り、プロジェクトの DLL と一緒に読む。
    推しは (a) (書き出したゲームに DLL が 1 つ増えない)。どちらでも、ユーザーから見た動きは同じ
- **書き換えられない**: インスペクターの「スクリプトを開く」は、テンプレートなら**読むだけで開く** (ファイルに
  読み取り専用の印・先頭のコメントに「書き換えず『自分のスクリプトにする』を使ってください」)。
  入れたプラグインのフォルダーは入れ直すと上書きされるので、書き換えても残らない
- **改造する = 「自分のスクリプトにする」**: 部品の ⋮ のメニュー → 名前を聞く (最初 `MyEasyMove`) →
  `Assets/Scripts/` に写す (型の名前と見出しを付け替える。同じ名前の型が 2 つあると登録がぶつかるため) →
  スクリプトをビルド → その部品を写した方に**置き換える** (欄の値は名前で引き継ぐ: 今のホットリロードと同じ) →
  Undo 1 回分
  - 置き換えるのは「この物だけ / このシーンの同じテンプレートの物を全部」を選ぶ
  - 写した後は自分のもの: エンジンを新しくしても、テンプレートの直りは入らない (写した方の先頭のコメントに、
    どの版のテンプレートから写したかを書く)
- 保存: 部品の型の名前は `rm::easy_controls::EasyMove` (プラグインの中の名前で変わらない)。写した方はふつうの
  スクリプトの型の名前
- テンプレートが少しずつ増えても同じ仕組み (簡易移動・簡易カメラのあと、追う敵・回るアイテム … は後で)

### 6-d. 2D 版と、2D / 3D を分けるか (案)

**推し: 別のテンプレートにする** (「簡易移動 (3D)」「簡易移動 (2D)」…)。1 つにまとめて切り替えない。理由:

1. **使う部品が違う**: 3D は Transform・キャラクター (Jolt の CharacterVirtual)・3D のカメラ、2D は Transform 2D・
   コライダー (2D)・カメラ (2D)。1 つにすると、**2D のゲームにも 3D のプラグインが要る**
   (2026-09-29 の決まり「2D を選べば 3D の下は入らない」と、エンジンを重くしない決まりに反する)
2. **欄が違う**: 3D は「カメラの向きに合わせる」、2D の横スクロールは「壁ジャンプ」「押す長さでジャンプの高さ」など。
   1 つにすると半分の欄がいつも隠れ、インスペクターも中身も読みにくい
3. **テンプレートは読んで改造するもの**: 「自分のスクリプトにする」で写したとき、使わない側のコードまで付いてくる
4. 同じところ (速くなる・止まる・コヨーテタイム・先行入力・ジャンプの高さから速さ) は、**純粋な計算を 1 か所に
   置いて両方が使う** (憲法 2・テストを書く)。分けても式は 2 つにならない

切り替えにするのは「**同じ部品を使って、欄だけ少し違う**」もの (2D の中の 2 つの動き方など) にする。

2D のテンプレート (案):

| テンプレート | 動き方 | 例 |
|---|---|---|
| 簡易移動 (2D 横から) | 重力・ジャンプ・押す長さでジャンプの高さ・壁ジャンプ (オフ)・動く床 | マリオ |
| 簡易移動 (2D 上から) | 重力なし・4 / 8 方向・**低速** (押している間ゆっくり・当たりの印を出す)・**画面の中に留める** | ゼルダの見下ろし / 東方 (低速と画面の中をオン) |
| 簡易カメラ (2D) | 追う (遊び (デッドゾーン)・先読み・動ける範囲) / 固定 (東方のように画面が動かない) | |

★ **2D の前に要るもの**: 物理の「キャラクター」は 3D (立ったカプセル) しか無い。2D の横から動く物には
**「キャラクター (2D)」**(坂・段差・接地を 2D で) を物理に足す。上から (重力なし) は剛体 (2D) か Transform 2D を
直接動かしてもよいが、壁で止まるにはコライダーが要る → これもキャラクター (2D) で

### 6-c. 置き場所

簡易移動は物理 (キャラクター) を、簡易カメラは 3D のカメラを使う。前提が両方になるので、
**「簡易操作」(前提: ゲーム制作。2D / 3D で同じ純粋な計算だけ)** + つなぎ **「簡易操作 × 3D」**(前提: ゲーム制作 × 3D・物理)
と **「簡易操作 × 2D」**(前提: ゲーム制作 × 2D・物理) の案 (今の「ゲーム制作 × 3D / × 2D」と同じ形)。
2D のゲームを作る人に 3D のテンプレートは入らない

## 7. 物の性質 → 燃やす・電気

**決めたこと (ユーザー 2026-11-21)**: 燃やす・電気を流すは、材質によって、それぞれ別のプラグイン。

- 案 (2026-11-21 13:28): **「物の性質」を持つ小さなプラグインを先に作り**、燃焼・電気・流体はそれを前提にする
  (燃えやすさ・電気の通しやすさを 3 つのプラグインが別々に持つと、同じ物に 3 つの設定ができる = 憲法 1)
- 形の案: アセット `.rmprops` (性質の組: 木・鉄・水 …) + 部品「物の性質」(どの組か)。中身:
  燃えやすさ・燃え始める温度・燃え続ける時間・電気の通しやすさ・熱の伝わりやすさ
- **【決定】名前は「物の性質」** (ユーザー 2026-11-23。「材質」は見た目の材質 (色・金属・法線マップ) で使っているため)
- **【決定】摩擦・跳ね返りは剛体のまま** (ユーザー 2026-11-23。物理だけが使う)。物の性質には、2 つ以上のプラグインが使うものだけ入れる
- 気温: プラグイン「気候」(版 0.0.7) が**場所ごとの気温**を持つ。燃焼・溶岩・凍るは、まわりの気温を気候から読む
  (つなぎ「燃焼 × 気候」など)。気温を別に持たない

### 8-b. 「ドット絵」のプラグイン (ユーザーの案 2026-11-23)

ユーザー: 2D は「マリオや東方のようなゲーム」全般で、ドット絵だけではない。ただしドット絵の表現はあってよい。
**ドット絵のゲーム向けにいろいろな機能を変えるプラグインを作れば、全部解決するかも。**

**良い点**: ドット絵でないゲームを作る人には何も入らない (重くならない)。ドット絵に要るものが 1 つにまとまり、
入れるだけでドット絵のゲームの形になる。RME の「機能はプラグインで足す」に合う。

**気をつけること**: 「ほかの機能を変える」は、**変えられる側が口 (差し出しの場所) を用意しているときだけ**できる
(憲法 10: プラグインは `requires` に書いたものしか読めない。核も 2D 空間も、ドット絵のプラグインを知らない)。
変えたい所ごとに、2D 空間・ゲーム制作 × 2D に口を足すことになる。→ 決まり:
- **どのゲームでも使う簡単な選び肢は、元の機能に置く** (例: スプライトの「くっきり (ドット絵)」はもう `Sprite` にある)
- **ドット絵でしか使わないものだけ**をドット絵のプラグインに置き、元の機能の口を使って変える

ドット絵のプラグインに入れるもの (案):

| もの | 中身 |
|---|---|
| 小さな画面で描いて整数倍で広げる | 例 320 × 180 で描いて 4 倍 (にじまない・ピクセルの大きさがそろう)。ゲームの設定に「ドットの画面の大きさ」 |
| ピクセルに合わせる | 物とカメラの位置を描くときだけピクセルの格子にそろえる (ちらつき・ゆがみを無くす。動きの計算は滑らかなまま) |
| 新しいスプライトの既定 | 「くっきり」をオン・1 単位のピクセル数をそろえる |
| 色の数を減らす (後で) | パレットに寄せる |
| ドットのフォント・UI の整数倍 (後で) | |
| マス目の流体 (8 の C0〜) | つなぎ「**ドット絵 × 流体**」(流体のプラグインと両方あるときだけ)。落ちる砂の方法で、ピクセル 1 つが水・砂・溶岩 |

★ 「全部解決」ではない所: 滑らかな流体 (8 の F0〜F3 の 2D) はドット絵とは別に要る (マリオや東方の水は滑らかでよい)。
