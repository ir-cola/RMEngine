# 骨のアニメーション (3D)

3D のキャラクターを骨で動かす。FBX / glTF から骨・ウェイト・クリップを読み、GPU で頂点を動かし、
「いつどのクリップを流すか」を専用のタブで決める。**線をつなぐ図 (ノード・矢印) は使わない。**

作り始める前の設計で、まだコードは無い。[ANIMATION_PARTICLES.md](ANIMATION_PARTICLES.md) の 2 章
(3D のボーンアニメーション) は、この文書で置き換える。前のエンジンの反省はそちらの末尾にある。

## 2. プラグインの分け方

前の案 (ANIMATION_PARTICLES.md 1 章) と同じ 3 つ。読む・描くは 3D 空間に足す (読む場所と描く場所を 2 つにしない: 憲法 3)。

| プラグイン | 中身 | 前提 |
|---|---|---|
| **3D 空間** `space3d` (今のもの) | 骨・スキン・クリップの**データの型**と、glTF / FBX からそれを読むこと・`.rmmesh` の骨のチャンク・**GPU スキニング** (`Renderer3D`) | 変わらない |
| **アニメーション** `animation` (新しい) | アニメーターのアセット `.rmanim` (パラメーター・レイヤー・状態・ルール)・条件の式・ルールを進める計算・ブレンドの重み (1D / 2D)・イベントの通過。**3D も 2D も知らない** (純粋) | なし |
| **3D アニメーション** `animation3d` (新しい) | 四元数・姿勢 (ポーズ) の計算: クリップを読む → 混ぜる → マスク → 骨の行列。ルートモーション・(後で) IK・揺れ | アニメーション・3D 空間 |
| **ゲーム制作 × アニメーション** `game_x_animation` (つなぎ) | 部品「アニメーター」「骨に付ける」・Play の間のシステム・スクリプトの `RMAnim.h`・「アニメーション」タブ・シーンビューの再生・書き出しで焼く | ゲーム制作・ゲーム制作 × 3D・3D 空間・アニメーション・3D アニメーション |

- ゲーム制作 × 3D の `GameDraw3D` はアニメーションを知らない。新しい口 `rm_engine.game_x_3d.mesh_pose` (「このエンティティの骨の行列」を答える関数) を作り、つなぎが差し出す。シーンビューも同じ口を使う
- (作った。2026-11-25) 段階 1 の **ゲーム制作 × アニメーション** の `requires` は ゲーム制作・ゲーム制作 × 3D・3D 空間・3D アニメーション の 4 つ。**アニメーション** `animation` はまだ無い (段階 3 で `.rmanim` と一緒に作る) ので、そのとき `requires` に足す。口 `mesh_pose` の形 (`game_x_3d/runtime/MeshPose.h`): 画面ごとに `MeshPoser` を 1 つ作り、1 フレームに 1 回 `Begin(場面・dt・Play 中か・選択・時間・どの絵か)`、骨のあるモデルの物ごとに `Pose(エンティティ, モデルの骨とクリップ)` → スキンの行列・姿勢の版・動いているか。描く道は `ApplyPoses` の 1 本 (シーンビュー・カメラのプレビュー・ゲームビュー・書き出したゲーム)。モデルの CPU の骨とクリップ (`SkinnedModel`: `shared_ptr`) はゲーム制作 × 3D が GPU の形の隣に持つ。止まっているシーンビューの上の操作は、もう 1 つの口 `rm_engine.game_x_3d.scene_overlay` (エディターだけ。`game_x_3d/editor/SceneOverlay.h`)
- アニメーションは 3D を知らないので、後で 2D のコマ送りの状態の切り替えにも同じタブとルールを使える (6 章の 6)

## 3. ランタイムの設計

### 3-1. データ

| 型 | 中身 | どこ |
|---|---|---|
| `Skeleton` (骨の木) | 骨の名前・親の番号 (**親が先に並ぶ**)・休みの姿勢 (位置・回転・大きさ)。骨は**エンティティにしない** (100 本で階層が埋まらない・速い) | space3d |
| `SkinData` (スキン) | 頂点ごとに骨 4 本の番号 (u16) とウェイト (unorm16)・骨ごとの逆バインド行列・骨ごとの範囲 (その骨が動かす頂点を囲む箱。見えるかの判定用) | space3d (`MeshData` に `std::optional<SkinData>` を足す) |
| `ClipData` (クリップ) | 名前・長さ (秒)・刻み (1 秒のサンプル数)・骨ごとの位置 / 回転 / 大きさのサンプルの列 (変わらない値はサンプル 1 つ) | space3d (読む)。サンプルの読み方は animation3d |
| `Pose` (姿勢) | 骨ごとの位置・回転 (四元数)・大きさ (親の空間で)。計算の途中だけにある | animation3d |
| `.rmanim` (アニメーター) | パラメーター・レイヤー・状態・ルール (4 章)。`RM_STRUCT` で書く (憲法 9) | animation |
| クリップの設定 | モデルの `.meta` の取り込みの設定に、クリップの一覧 (名前・元のテイク・始め / 終わり・ループ・ルートモーション・イベント) | 3D アニメーション (下の注) |

- クリップは**モデルのサブアセット**。アセットのパネルでモデルを開くと中にクリップが並ぶ。参照は「モデルの ID + クリップの名前」
- 注: 今の `ModelImport` は核 (`src/core/asset`) にある。クリップの設定はアニメーションのものなので、核に足さず、**プラグインが `.meta` の `"import"` に自分のキー (`"clips"`) を足せる口**を核に作る (知らないキーは今も書き戻すので、データは壊れない)。段階 1 で作る

### 3-2. 読み込み

**glTF**
- `skins[]` (`joints`・`inverseBindMatrices`)・`JOINTS_0` (u8 / u16)・`WEIGHTS_0` (float / unorm8 / unorm16)
- スキンのあるメッシュは**ノードの行列で焼かない** (glTF の決まり: 頂点は骨の行列だけで動く)。今の `AppendPlaced` の道を、スキンのあるものだけ分ける
- `animations[]`: チャンネル (ノード・`translation` / `rotation` / `scale`)・サンプラー (`LINEAR` / `STEP` / `CUBICSPLINE`)。`weights` (モーフ) は段階 6
- 骨の下にある普通のメッシュ (手に持った剣・頭の帽子) は、**その骨にウェイト 1 で付いたスキン**にする。骨に付いて動く
- (作った。2026-11-25) 決めたこと: どの骨の下にも無い普通のメッシュは、動かない骨 `(骨の外)` (休みの姿勢も逆バインドも単位行列。要るときだけ最後に足す) に付ける。骨の上や骨の間にある骨でないノード (アーマチュア) の行列は、子の骨の休みの姿勢とクリップに掛けておく。クリップは時刻 0 から最後のキーまで。骨でないノードのアニメーションは読まない

**FBX**
- `Deformer` (Skin) → `SubDeformer` (Cluster): `Indexes` / `Weights` (コントロール点ごと)・`Transform` / `TransformLink` (バインドの行列)。骨は `LimbNode` のモデル
- `AnimationStack` (テイク) → `AnimationLayer` → `AnimationCurveNode` (T / R / S。モデルのプロパティ `Lcl Translation` などにつながる) → `AnimationCurve` (`KeyTime` は 1 秒 = 46186158000、`KeyValueFloat`)
- FBX の回転はオイラー角の曲線で、ピボットや前の回転も掛かる。だから**読むときにサンプルに焼く**: 刻みごとに曲線の値を入れて、今の `World` の式で骨の行列を作り、位置・回転・大きさに分ける。今の式を「値を渡すと行列を返す」関数に分けて、メッシュと骨で 1 本にする (憲法 2)

**両方**
- 刻み: ファイルの 1 秒のコマ数 (無ければ 30)。上限 60
- 取り込みの設定 (座標系・単位・前後の反転・大きさ) を**骨とクリップにも同じに掛ける**。左手系への反転は四元数では間違えやすいので、行列にしてから掛けて分け直す。鏡の向きのファイルでテストする
- 1 つの頂点に骨が 5 本以上あるときは、重い 4 本を残して合計 1 にし直し、**警告** (`MeshData::warnings`) に数を出す
- 骨は 1 つのスキンで 1024 本まで。超えたら**読めないとして理由を出す** (前のエンジンは 512 を超えた骨が黙って 1 本に潰れた)
- 前のエンジンで踏んだ罠 (ANIMATION_PARTICLES.md の末尾) をテストにする: バインドポーズとファイルの姿勢は別物・アニメーションが無くてもスキニングを通す・メッシュのノードの行列を二重に掛けない・骨の親は「骨として登録された一番近い祖先」・同じ名前の骨 (名前 + 何番目で引く)・日本語の骨の名前
- **実物のモデルで試す**: Blender の書き出し・Mixamo・VRoid の書き出し・Khronos の glTF の見本 (ライセンスを確かめて `docs/samples/models/` に)

### 3-3. 姿勢の計算 (純粋。テストを書く: 憲法 5)

1 体ごと、1 フレームに 1 回、CPU で:

1. **サンプル**: クリップの時刻 t → `t × 刻み` の前後 2 つを混ぜる (位置・大きさは直線、回転は向きをそろえてから nlerp)
2. **混ぜる**: 重みの付いた姿勢を足し合わせる (ブレンドとクロスフェード)。足すレイヤーは「クリップの姿勢 − その最初のコマ」を足す
3. **マスク**: レイヤーごとに骨ごとの重み (0 / 1。後で中間も)
4. **ルートモーション**を抜く (3-5)
5. **親から順に掛ける** → モデルの空間の骨の行列 (親が先に並んでいるので 1 回のループ)
6. **スキンの行列** = 骨の行列 × 逆バインド行列 → GPU へ (3x4 の行列。float4 が 3 つ)

- テスト: サンプルの補間・ループの継ぎ目・四元数の反対側・重みの合計が 0 のとき・マスク・親の順・スキンの行列が休みの姿勢で単位行列になること
- メモリ: 60 本 × 60 コマ × 10 秒 で約 1.4 MB。まずは圧縮しない (後で: 変わらない列を消す・回転を 48 ビットに)
- 数百体で重くなったら: 姿勢の計算を作業スレッドに並べる・Compute Shader のスキニング (段階 7)

### 3-4. GPU スキニング (`Renderer3D` の変わり方)

| 変えるところ | どう変えるか |
|---|---|
| `MeshDraw` | `std::span<const BoneMatrix> bones` を足す (空: 今のまま動かない)。`BoneMatrix` = 3x4 (float 12 個) |
| 骨の行列の置き場所 | フレームの全部の骨の行列を 1 つの `Buffer<float4> bones` (t10。t9 は天候の雪のシェーダーが使う) に 1 回書く。今の `things` と同じ作り。**定数バッファの上限 (4096 個の float4) に縛られない** |
| 描画ごとのデータ | `DRAW` (スロット 1) を `uint2` から `uint4` に。z = その描画の骨の行列の先頭 |
| 頂点 | スキンのあるメッシュだけ、**2 本目の頂点バッファ** (スロット 2: 骨の番号 `R16G16B16A16_UINT` + ウェイト `R16G16B16A16_UNORM`、16 バイト / 頂点)。動かないメッシュは今のまま (重くならない) |
| シェーダー | `SkinnedMeshVS` / `SkinnedShadowVS` を足す (入力レイアウトも 1 つ足す)。ピクセルシェーダーは今のもの。接線はピクセルシェーダーが画面の上の変化から作っているので、**接線のスキニングは要らない** |
| インスタンス描画 | 同じメッシュを違う姿勢で描いても、骨の先頭は描画ごとのデータにあるので、今のまま 1 回にまとまる |
| 見えるかの判定 | 骨ごとの範囲 (読み込みで作る) を今の骨の行列で動かし、その和で判定する。`MeshDraw` に「この範囲を使う」を足す |
| 影の地図 | 姿勢が変わっている間は `moving` を立てる。止まっているときは姿勢の版番号を `hash` に入れて、描き直さない |
| 上限 | 1 回の描画の骨は 1024 本 (読み込みと同じ)。1 フレームの合計は数を数えて、超えたら警告 (黙って潰さない) |

- 法線は同じ行列の 3x3 で動かす (骨の大きさが軸ごとに違うと少しずれる。普通のモデルでは目に見えない)
- テスト: `RendererShaders` のテスト (fxc でコンパイルできる) に新しいシェーダーを足す。頂点の計算は CPU の同じ式 (テスト用) と比べる

### 3-5. ルートモーション

- クリップの設定に「根の骨」(自動: 一番上の骨) と、抜くもの「横の移動 (XZ)」「縦の移動 (Y)」「Y のまわりの回転」
- 毎フレーム、根の骨の動いた分 (前の時刻 → 今の時刻。ループをまたいだら 1 周分を足す) を取り出して、姿勢からは消す
- 動いた分はエンティティの向きで回して、Transform に足す。物理のキャラクターがあるときは、その速さとして渡す (つなぎ「アニメーション × 物理」。段階 5)
- 混ぜているときは、動いた分も同じ重みで混ぜる

### 3-6. イベント

- クリップの設定に「時刻・名前・数・文字」の一覧。タブのクリップの帯で置く (4-6)
- 再生の位置が前のフレームから今のフレームの間でその時刻を**通ったら**出す。ループをまたぐ・1 フレームで何周もする・逆再生も数える (純粋。テストを書く)
- 混ぜているときは、**レイヤーごとに一番重いクリップのイベントだけ**出す (歩きと走りを混ぜても足音は 1 回)
- 届け方は**今の `rm::Events` を使う** (新しいフックを作らない: 憲法 3)。そのエンティティのスクリプトの `OnEvent` に、名前・数・文字が届く (送り手はエンジン)

### 3-7. 骨に付ける

- 部品「骨に付ける」: 骨の名前 (一覧から選ぶ)・位置と回転のずれ。アニメーターを持つ祖先の骨に、毎フレーム Transform を合わせる
- 剣・帽子・エフェクト・カメラを骨に付けられる。付けた物も普通のエンティティ (階層に出る)

### 3-8. 書き出し (.rmpak)

- `.rmmesh` にチャンクを足す: `SKEL` (骨の名前・親・休みの姿勢)・`SKIN` (頂点ごとの骨とウェイト)・`IBND` (逆バインド)・`BBOX` (骨ごとの範囲)。知らないチャンクは飛ばすので、形式の番号は上げても上げなくても読める (上げる: 古いゲームが黙って休みの姿勢で描かないように)
- クリップは `.rmclip` (チャンクのバイナリ: 刻み・長さ・骨の名前ごとのサンプル・イベント) に焼く。**使っているクリップだけ** (書き出すシーンのアニメーターが指すもの + クリップの設定の「いつも入れる」: スクリプトが名前で流すもの)
- `.rmanim` は JSON のまま入れる (ゲームも JSON を読める)。条件の式はゲームが読むときに解く (小さいので速い)
- ゲームは FBX / glTF を読まない (今のメッシュと同じ)

### 3-9. スクリプト (`#include "RMAnim.h"`)

```cpp
rm::Animator anim(self);
anim.SetFloat("speed", v);          // パラメーター
anim.SetBool("grounded", true);
anim.SetTrigger("jump");            // ルールが使うと消える
anim.Play("Attack1", 0.1f);         // ルールを飛ばしてその状態へ (0.1 秒で混ぜる)。次のフレームからルールがまた働く
anim.PlayClip("hero.fbx#Wave", 0.2f);  // .rmanim なしで、クリップを直に (アニメーターにクリップだけ指したとき)
anim.SetSpeed(1.5f);  anim.Pause();
anim.SetLayerWeight("上半身", 0.5f);
std::string_view s = anim.State();  float t = anim.StateTime();   // 今の状態と、その中の時刻 (0..1)
rm::Vec3 hand = anim.BonePosition("RightHand");                   // ワールドの位置
rm::Quat head = anim.BoneRotation("Head");

void Player::OnEvent(rm::Entity self, const rm::Event& e) {      // クリップのイベント
    if (e.Is("Footstep")) rm::AudioSource(self).Play();
}
```

- 形はパーティクルと同じ: `RMAnimAbi.h` (C の関数の表)・口 `rm_engine.game_production.script_api`・部品は `RM_TRANSIENT` でスクリプトが頼んだことを持つ
- **ルールを使わずスクリプトだけで動かす**こともできる (`.rmanim` を空にして `PlayClip`)。4 章の案 C の「スクリプトが主」はこれで足りる

### 3-10. 1 フレームの順番

1. Fixed (物理)
2. スクリプトの `Tick` (パラメーターを入れる)
3. システム「アニメーション」(Frame): ルール → 時刻を進める → 姿勢 → ルートモーションを Transform に → イベントをためる
4. システム「骨に付ける」(Frame。アニメーションの後)
5. `rm::Events` が `OnEvent` に届ける・描く (`mesh_pose` の口から骨の行列)

止まっているエディターのシーンビューでは、選んだ物だけ 3 と 4 を動かす (再生・一時停止・時間のつまみ。パーティクルと同じ)。

## 4. 線をつながない作り方の案

決めたいのは「**いつ・どのクリップへ・何秒で移るか**」の書き方。4 つ出す。どれもランタイムは同じ
「状態の機械」(状態・パラメーター・移る条件) に写せる。違うのは**人が書いて読む形**だけ。

### 案 A: 状態の一覧 + 遷移の表

左に状態の一覧、右に**選んだ状態から出る遷移の表**。Unity の Animator の矢印を、表の行にしたもの。

```
┌ 状態 ──────────┐┌ 「Idle」から出る ───────────────────────────────────────────────┐
│ ● Idle   ←選択 ││ 先        条件                    時間    終わりを待つ  割り込み   │
│   Move         ││ Move      speed > 0.1             0.20    □            □         │
│   Jump         ││ Jump      jump                    0.10    □            □         │
│   Attack1      ││ Attack1   attack                  0.10    □            □         │
│   Die          ││ ＋ 遷移                                                         │
│ ◇ どこでも      │└─────────────────────────────────────────────────────────────────┘
└────────────────┘
```

- 遷移 = 1 行。条件は文字で書く (4-8)。上の行が先に調べられる
- 「どこでも」(Any State) は一覧の特別な行
- **良い**: Unity と考え方が 1 対 1 (調べた知識がそのまま使える)。1 つの状態の出口が全部見える
- **困る**: 同じ遷移を何度も書く (Idle からも Move からも「→ Jump」)。全体が見えない (表を 1 つずつ開く)。状態が 20 を超えると行が増えすぎる (矢印のスパゲッティが、表のスパゲッティになる)
- ランタイム: そのまま (状態ごとの遷移の並び)

### 案 B: ルールの並び (上から調べて、最初に当てはまったもの)

1 本の縦の並び。各行は「**今がこの状態のとき、この条件なら → この状態へ (何秒で)**」。毎フレーム
上から調べて、**最初に当てはまった行**で決まる。CSS や優先度の付いたルールと同じ考え。

```
┌ ルール (上から調べる) ──────────────────────────────────────────────────────────┐
│ ⠿ 1 ⚡ どこでも   hp <= 0                   → Die      0.10 s                 │
│ ⠿ 2    どこでも   jump                      → Jump     0.10 s                 │
│ ⠿ 3    Jump      grounded                  → Land     0.05 s                 │
│ ⠿ 4    どこでも   attack                    → Attack1  0.10 s                 │
│ ⠿ 5    Attack1   attack && t > 0.5         → Attack2  0.10 s                 │
│ ▶ 6    どこでも   speed > 0.1               → Move     0.20 s     ← 今これ    │
│ ⠿ 7    どこでも   (いつも)                   → Idle     0.20 s                 │
│   ＋ ルール                                                                    │
└────────────────────────────────────────────────────────────────────────────────┘
```

- 「どこでも」の行 1 つで、全部の状態からの遷移になる。**遷移の数が状態の数の 2 乗にならない**
- 優先度は**上下の位置そのもの** (ドラッグで並べ替え)。Unity の「遷移の順番が隠れている」問題が無い
- 一番下に「(いつも) → Idle」を置けば「どれでもないときは待機」になる
- 状態ごとの「出口」で、割り込まれたくない状態を守る (4-7。ジャンプの途中に歩きへ戻らない)
- **良い**: 全部が 1 画面に文字で見える。動かしながら「今どの行が効いているか」を光らせ、当たらない行には理由 (`speed (0.0) > 0.1 ✗`) を出せる。データは普通の `RM_STRUCT` (保存・インスペクター・Undo が付いてくる)
- **困る**: 順番を間違えると下の行が効かない (→ 「この行は 3 行目に隠れて当たりません」と警告)。コンボのような順番の決まった流れは「元」の欄で書く (5 行目)。行が多くなったら状態で絞る (「Jump に関わる行だけ」)
- ランタイム: 状態ごとに「使える行の並び」に開いて持つ (読み込むときに 1 回)。中身は普通の状態の機械

### 案 C: 文字で書く (テキストの `.rmanim` か、スクリプトだけ)

**C-1 テキスト**: `.rmanim` を小さな言葉で書く。タブは文字の編集とプレビュー。`.rmfx` と同じ体験。

```
param   speed: float
param   grounded: bool = true
trigger jump, attack

state Idle    = clip "hero.fbx#Idle" loop
state Move    = blend1d speed { Walk: 1.5, Run: 4, Sprint: 7 }
state Jump    = clip "hero.fbx#Jump_Air" loop, exit own

rule any  : hp <= 0     -> Die  0.1 interrupt
rule any  : jump        -> Jump 0.1
rule Jump : grounded    -> Land 0.05
rule any  : speed > 0.1 -> Move 0.2
rule any  :             -> Idle 0.2
```

**C-2 スクリプトだけ**: アセットを作らず、C++ の `Tick` で `anim.Play("Run", 0.2f)` を呼ぶ。

- **良い**: 一番速く書ける。GitHub で差分が読める・コピーできる。AI にも書かせやすい
- **困る**: C-1 は保存の形が JSON でなくなり、インスペクター・Undo・知らないキーの書き戻しを手で作ることになる (憲法 1・6・9 に反する)。クリップの名前を文字で書くので、名前を変えると切れる。イラストや 3D の人には入りにくい。C-2 は見た目で確かめられず、ブレンドの重みの調整に向かない
- ランタイム: C-1 は解いて案 B と同じ構造に。C-2 は 3-9 の API そのもの (**どの案でも必ず作る**)

### 案 D: タイムライン (シーケンサー)

横が時間、縦がレイヤーの帯。クリップを帯の上に並べ、重なりがクロスフェード。

```
┌ シーケンス: boss_intro ──────────────────────────────────────────────────┐
│ 時間     0s       1s       2s       3s       4s                         │
│ 体       [Idle──────][Roar──────────][Walk──────────────→ ループ]       │
│ 上半身                 [Point────]                                      │
│ イベント        ▲足音        ▲咆哮の音     ▲カメラを揺らす                 │
└──────────────────────────────────────────────────────────────────────────┘
```

- **良い**: 決まった流れ (登場の演出・会話・カットシーン) に一番わかりやすい。イベントを置く画面としても良い
- **困る**: 入力で変わるゲームの動き (走る・跳ぶ・攻撃) は書けない。条件で分かれない
- ランタイム: 「この時刻にこのクリップをこの秒数で」の並び。状態の機械ではない
- 使いどころ: 状態の切り替えには使わず、**クリップのイベントの帯** (4-6) と、後で作る「演出」のタブに使う

### 4-5. どの案とも組み合わせる部品

**混ぜる (ブレンド) は「図」で置く** (線ではなく、数直線と平面の上の点):

```
1D  speed   0 ──●Idle──────●Walk 1.5────────●Run 4──────────●Sprint 7── 8
                              ▲ プレビューの点 (ドラッグして試す) = 2.4

2D  x: moveX  y: moveY            ●Fwd
                         ●Left    ●Idle    ●Right      点をドラッグして置く
                                   ●Back               ＋ を動かすと重みが出る
```

- 1D: 両隣の 2 つを直線で混ぜる。2D: 点を三角形に分け (ドロネー)、入った三角形の 3 点で混ぜる。外は一番近い辺へ寄せる
- 足をそろえる: 混ぜるクリップの時刻を割合 (0..1) でそろえ、長さも重みで混ぜる

**レイヤーは「重ねた一覧」**:

```
レイヤー   重み            重ね方    マスク
 体        1               上書き    全部
 上半身    aim (パラメーター) 上書き    Spine から下 ▾     ← 骨の木にチェック
 呼吸      1               足す      胸・首
```

- レイヤーごとに自分の状態とルールを持つ。マスクは骨の木 (今の木の部品) にチェック。「この骨から下を全部」

### 4-6. おすすめ: **案 B (ルールの並び) を主に、部品を組み合わせる**

```
┌ アニメーション: player.rmanim ─────────────────────────────────── [▶] [‖] ──┐
│ ┌ プレビュー ──────────────────────┐ ┌ パラメーター (動かして試す) ─────────┐ │
│ │                                  │ │ speed     数        [====|-----] 2.4│ │
│ │    (モデルが床の上で動く。         │ │ grounded  真偽       [✓]             │ │
│ │     ドラッグで回す)                │ │ jump      トリガー   [ 引く ]         │ │
│ │  体: Move (ルール 6)  t = 0.42    │ │ attack    トリガー   [ 引く ]         │ │
│ └──────────────────────────────────┘ │ ＋ パラメーター                      │ │
│ [体] [上半身] ＋ レイヤー               └──────────────────────────────────────┘ │
│ ┌ ルール ────────────────────────────────────────────────────────────────────┐ │
│ │ ⠿ 1 ⚡ どこでも   hp <= 0               → Die      0.10 s                  │ │
│ │ ⠿ 2    どこでも   jump                  → Jump     0.10 s                  │ │
│ │ ⠿ 3    Jump      grounded              → Land     0.05 s                  │ │
│ │ ▶ 6    どこでも   speed > 0.1           → Move     0.20 s      ← 今これ    │ │
│ ├ 状態 ──────────────────────────────────────────────────────────────────────┤ │
│ │ Idle     クリップ      hero.fbx ▸ Idle         ループ                       │ │
│ │ Move     1D で混ぜる   speed: Walk 1.5 ─ Run 4 ─ Sprint 7   [図を開く]      │ │
│ │ Jump     クリップ      Jump_Air  ループ   出口: 自分のルールだけ             │ │
│ │ Attack1  クリップ      Slash1    1 回     出口: 終わるまで自分のルールだけ   │ │
│ ├ クリップ「Slash1」の帯 ─────────────────────────────────────────────────────┤ │
│ │ 0s ──────────▲Hit──────────────▲Swoosh────────────── 0.8s   ＋ イベント    │ │
└──────────────────────────────────────────────────────────────────────────────────┘
```

理由:

1. **線が無い**。1 本の縦の並びで、全部が文字で 1 画面に見える (ユーザーの希望)
2. **遷移が増えない**。「どこでも」の行で、状態が増えても行はあまり増えない (Unity の矢印のスパゲッティが起きない)
3. **優先度が見える**。上の行が強い。順番が隠れない
4. **確かめやすい**。プレビューでパラメーターを動かすと、効いている行が光り、当たらない行に理由が出る。図より速く原因が分かる
5. **憲法に合う**。データは `RM_STRUCT` の JSON (保存・インスペクター・Undo が付いてくる)。条件だけが文字 (`.rmfx` の `param` と同じく、欄の中の文字)
6. **パーティクルとそろう**。「並び + 文字で書く」はパーティクルのタブと同じ見た目と操作
7. **逃げ道がある**。スクリプトから `Play` / `PlayClip` で直に動かせる (案 C-2)。決まった流れはクリップの帯と、後で「演出」のタブ (案 D)

選ばなかった理由: 案 A は状態が増えると表が増えすぎる (案 B は A の行を「どこでも」でまとめたもの)。案 C-1 は保存の形が 2 つになる。案 D は入力で分かれない。

### 4-7. ルールの決まり (案 B。純粋な計算でテストする)

毎フレーム、レイヤーごとに:

1. 今の状態の**出口**で、調べる行を決める
   - **自由** (既定): 全部の行
   - **自分のルールだけ**: 「元」にこの状態を書いた行と ⚡ の行 (空中の Jump: 着地まで歩きに戻らない)
   - **終わるまで自分のルールだけ**: クリップが終わるまでは上と同じ、終わったら全部 (攻撃・着地)
2. 上から調べ、「元」が合って条件が真の**最初の 1 行**で決まる。どれも当たらなければそのまま
3. 先が今の状態と同じなら何もしない (行に「やり直す」があれば始めから)
4. 違えば移る。その時の混ざった姿勢を**止め絵**にして、そこから先へフェードする (移る途中にまた移っても、止め絵を差し替えるだけ。前のエンジンと同じ)
5. 移る途中も、先の状態にいるものとして 1 から調べる (反応が遅れない)
6. 当たった行が使ったトリガーを消す。使われなかったトリガーは**保持時間** (既定 0.2 秒) で消える (押しっぱなしの先行入力が残り続けない)
7. 1 フレームに移るのは 1 回まで (行が輪になっても止まらない事故を防ぐ)

### 4-8. 条件の書き方 (小さな式)

| 書けるもの | 例 |
|---|---|
| パラメーター (数・整数・真偽・トリガー) | `speed`・`grounded`・`jump` (トリガーは立っていれば真) |
| 数・真偽 | `0.1`・`true` |
| 比べる | `<` `<=` `>` `>=` `==` `!=` |
| つなぐ | `&&` `\|\|` `!` `( )` (前のエンジンは AND だけだった。OR は行を 2 つにしなくてよい) |
| 計算 | `+ - * /`・`abs(x)`・`min(a, b)`・`max(a, b)` |
| 今の状態のこと | `t` (今の状態の中の割合 0..1)・`ended` (1 回のクリップが終わった / ループが 1 周した) |
| 空 | 「(いつも)」= いつでも真 |

- C++ と同じ書き方 (ユーザーはスクリプトと HLSL を書く)。名前は日本語でもよい
- 打っている間にパラメーター名の候補を出す。間違いはその行の下に赤で「何文字目」まで出し、**その行は当たらないものとして**動き続ける (ゲームは止まらない)
- パラメーターの名前を変えると、全部の行の式も書き換える (文字で書く弱点を埋める)
- 式を解く・調べる計算は純粋 (`animation/runtime/Condition.*`)。テスト: 優先順位・型の違い・知らない名前・割る 0・トリガーの消え方
