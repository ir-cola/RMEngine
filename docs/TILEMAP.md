# 2D のタイルマップ

2D のゲームの地面・壁・背景を、小さな四角い絵 (タイル) を**マス目に並べて**作る。
1 枚の画像を同じ大きさに切ったもの (タイルセット) を用意し、シーンビューで筆のように塗る。
塗ったタイルは区画ごとにまとめて速く描き、壁のタイルはつながった形にまとめて当たり判定にする。

段階 1 (描いて見る) を作った (2026-11-27、版 0.0.42。15 章)。段階 2 から先は設計だけ。姉妹の設計図は [NAVIGATION.md](NAVIGATION.md)
(マス目の上の経路探し)。

## 2. プラグインの分け方

核 (`src/`) はタイルを知らない。ゲーム制作も知らない。今の「天候 × 気候」「パーティクル × 物理」と同じ形で、
両方を知る部分だけを**つなぎ**に入れる。

```
              2D 空間 (space2d)  ◀── 描く装置にまとめ描きを足す・画像の切り方 (余白と間)
                  ▲
タイルマップ (tilemap) ── 純粋: タイルセットの型・マス目の計算・区画・オートタイル・当たりをまとめる
                  ▲
ゲーム制作 × タイルマップ (game_x_tilemap、つなぎ) ── 部品・描く・道具・パレット・スクリプト・セーブ
        │   requires: ゲーム制作・ゲーム制作 × 2D・2D 空間・タイルマップ
        ├── タイルマップ × 物理 (tilemap_x_physics、つなぎ) ── 物理の口に形を渡す
        └── タイルマップ × ナビ (tilemap_x_navigation、つなぎ) ── 通れるマスを渡す
```

| プラグイン | 中身 | 前提 |
|---|---|---|
| **2D 空間** `space2d` (今のもの) | 描く装置に「区画の束」を足す (5-1)。`Atlas` に余白と間のある切り方 (`GridCellOf`) を足す | 変わらない |
| **タイルマップ** `tilemap` (新しい) | タイルセットの型 (`RM_STRUCT`)・マスの値・区画の置き場・マス目 ↔ 平面の計算・オートタイルの規則・筆 / 四角 / 塗りつぶしの計算・当たりをまとめる計算 (Jolt を知らない)。エディターの部分は `.rmtileset` のファイルの種類 (核の口) とサムネイル。**ゲーム制作も物理も知らない** | 2D 空間 |
| **ゲーム制作 × タイルマップ** `game_x_tilemap` (つなぎ) | 部品「タイルのグリッド」「タイルの層」・2D の絵に区画を足す・シーンビューの塗る道具・パネル「タイル」(パレットとタイルセットの編集)・追加 ▸ 2D オブジェクト ▸ タイルマップ・スクリプトの `RMTilemap.h`・世界のセーブの差 | ゲーム制作・ゲーム制作 × 2D・2D 空間・タイルマップ |
| **タイルマップ × 物理** `tilemap_x_physics` (つなぎ) | タイルの当たりをまとめた形を、物理の口に渡す。シーンビューに当たりの線 (口 `kSceneLinesPoint`) | ゲーム制作 × タイルマップ・物理 |
| **タイルマップ × ナビ** `tilemap_x_navigation` (つなぎ) | マス目のゲームには口 `rm_engine.game_x_navigation.grid` に通れるマスと費用を、自由に動く 2D のゲームには口 `rm_engine.game_x_navigation.source` に通れないタイルを壁として答える (11-1・NAVIGATION.md 4-3) | ゲーム制作 × タイルマップ・ゲーム制作 × ナビゲーション |

- 描く装置 (まとめ描き) は 2D 空間に足す。描く場所を 2 つにしない (憲法 3。3D の骨のスキニングを 3D 空間に足したのと同じ: ANIMATION.md 2 章)
- タイルマップは純粋なので、後でイラストのソフト (タイルの絵を描く) や、ほかの 2D のソフトからも使える
- 新しいフォルダは `plugins/` の下なので `layers.txt` は要らない (柵は `check_layers.ps1` がプラグインの決まりで見る)。純粋な塗る計算を核へ移すとき (11-3) は `src/core` の中なので、上の層を受け継ぐ

## 3. データ

### 3-1. タイルセット (`.rmtileset`。アセット)

タイルの組。**画像そのものではなく、画像を指して「どう切るか・各タイルが何か」を書いたファイル**。
核の `AssetFileType` で作る (アセットのパネルの「作成 ▸ タイルセット」)。中身は `RM_STRUCT` 1 つ (憲法 9)。

| 型 | 中身 |
|---|---|
| `Tileset` | 絵の元の並び (`sources`)・独自データの欄の定義 (`fields`)・オートタイルの組 (`autoSets`)・タイルごとの情報 (`tiles`)・1 単位のピクセル数 (既定 0 = タイルの幅: **1 マス = 1 単位 = 物理の 1 m**) |
| `TileSource` (絵の元) | 番号 `id` (1〜255。並べ替えても消しても変わらない)・画像 (`AssetRef`、`AssetKind="image"`)・タイルの幅 / 高さ (px)・余白・間 (px)・くっきり |
| `TileInfo` (1 つのタイル) | どのタイルか (絵の元・列・行)・名前 (スクリプトが引く。空でよい)・当たりの形 (3-1-1)・タグ (`std::vector<std::string>`)・独自データの値・コマ送り (4-4)・ランダムの重み (既定 1)・オートタイルの印 (4-3) |
| `TileField` (独自データの欄) | 名前・種類 (真偽 / 整数 / 数 / 文字)・既定値。値は `TileInfo` の `data` に名前で持つ (欄を消しても値は知らないキーとして残す) |

- **タイルごとの情報は、既定と違うタイルだけを書く** (まばら)。1000 枚のタイルセットでも、何も決めていないタイルはファイルに出ない
- タイルの見分けは「絵の元の番号・列・行」。画像を右や下に広げても番号がずれない (左上から数えた通し番号にしない)
- 知らないキーは書き戻す (憲法 6。リフレクションの `Unknowns` がそのまま効く)
- サムネイルは 1 つ目の絵の元の画像 (核の `ThumbnailMaker` の `extension` と、別のアセットを引く `prepareWith`)

#### 3-1-1. 当たりの形 (タイルごと)

| 形 | 中身 |
|---|---|
| なし | 既定 |
| 全部 | マスいっぱいの四角 |
| 上半分 / 下半分 / 左半分 / 右半分 | 半分の四角 |
| 斜め (4 向き) | 直角三角形。坂 |
| 自分で描く | マスの中の点 (0〜1) の並び = 凸の多角形 1 つか 2 つ (7-5 の画面で点を置く) |

### 3-2. マップ: 部品か、アセットか

**案 A: 層ごとのエンティティ + 部品 (おすすめ)**

```
タイルマップ          部品「タイルのグリッド」 (マスの大きさ・形)        ← Transform 2D で動かせる・回せる
 ├ 背景              部品「タイルの層」 (タイルセット・並び順 -10)
 ├ 地面              部品「タイルの層」 (並び順 0・当たり あり)
 └ 前景 (葉っぱ)      部品「タイルの層」 (並び順 10)
```

- 層 = エンティティ。階層で並べ替え・名前・有効 / 無効・Prefab が**今の道のまま**使える
- 前後は Transform 2D の並び順。キャラクター (スプライト) を層の間に挟める (5-2)
- データはシーンのファイル (`.rmscene`) の中。保存・読み込み・知らないキーの書き戻しはリフレクションのまま
- Godot 4.3 も、1 つのノードに層を持たせる形 (TileMap) から、層ごとのノード (TileMapLayer) に変えた。理由は同じ (層ごとに並べ替え・当たり・有効を分けたい)

**案 B: 1 つの部品に層の並び**

- エンティティは 1 つ。層の並べ替えは部品の中の配列
- 困る: 層の間にスプライトを挟めない (前後は 1 つの描く物)。層ごとの有効 / 無効・当たりを部品の中で作り直すことになる

**案 C: マップを別のアセット (`.rmtilemap`) にして、部品が指す**

- 良い: 同じマップを別のシーンで使い回せる。シーンのファイルが小さい
- 困る: 編集の Undo を、アセットの中身の Undo (`ContentCommand`: 前と後の中身を丸ごと持つ) で作り直すことになる。Prefab・コピー・世界のセーブが別の道になる

おすすめは **案 A**。とても大きなマップ (3-5) だけ、後で区画を外のファイルに出せるようにする。

### 3-3. 部品の中身

| 部品 | 欄 |
|---|---|
| `TileGrid` (タイルのグリッド) | マスの大きさ (`Vec2`、既定 1 × 1)・**形** (列挙: 四角。後で アイソメ・ずらしたアイソメ・六角を足す: 3-6) |
| `TileLayer` (タイルの層) | タイルセット (`AssetRef`、`AssetKind=".rmtileset"`)・並び順・色 (掛ける。透明度も)・当たりを作る (真偽)・区画の並び (`chunks`。インスペクターには出さない) |

- 層は親を順にたどって一番近い `TileGrid` のマス目に乗る。グリッドが無ければ 1 × 1 の四角 (ずれた層を作らない)
- マスの大きさを 1 か所 (グリッド) に置くので、層ごとにずれない (憲法 2)

### 3-4. マスの値と区画

**マスの値** (32 ビットの数 1 つ):

| ビット | 中身 |
|---|---|
| 0〜7 | 列 (絵の元の中) |
| 8〜15 | 行 |
| 16〜23 | 絵の元の番号 (1〜255)。**0 = 空のマス** |
| 24〜26 | 左右反転・上下反転・斜めの反転 (斜め + 反転で 90 度回す。Tiled と同じ考え) |
| 27〜31 | 使わない (0) |

**区画** (チャンク): マス目を 32 × 32 マスごとに分けたもの。

- 区画の番号 = floor(マス ÷ 32)。負の場所も同じ式 (マップはどの向きにも広がる)
- **空の区画は持たない** (まばら)。描いたところだけがファイルに出る
- 区画は描く・当たり・Undo・ゲーム中の変更の**単位**。1 マス変えたら、その区画だけ作り直す

**保存の形** (シーンのファイルの部品の中。自己記述の JSON):

```json
{ "type": "rm::game_x_tilemap::TileLayer",
  "data": {
    "tileset": "<.rmtileset の ID>", "order": 0, "color": [1, 1, 1, 1], "collision": true,
    "chunk": 32,
    "chunks": [
      { "x": 0,  "y": 0, "cells": "0*96,65537*12,65538,0*915" },
      { "x": -1, "y": 0, "cells": "0*1000,65792*24" }
    ] } }
```

- `cells` は区画の 1024 マスを、下の行から左から右へ読んだ値の**ランレングス** (`値` か `値*数` をカンマで区切る)。気候の地図と同じ書き方 (`EncodeRuns`)。地面のように同じタイルが続くと短くなり、GitHub で差分が読める
- `chunk` (区画の一辺) は書くが、読む側は今の大きさ (32) に詰め直す (将来変えても古いファイルが読める)
- ランレングスの関数は今、気候のプラグインの中にある。タイルマップが気候を前提にしないよう、**実装するときに核 (`base/` か `core/`) へ移して両方が使う** (憲法 2)

**ランタイムの置き場** (`tilemap/runtime/TileStore`。純粋):

- 保存の形 (`chunks` の文字) が**正**。広げた形 (区画ごとの `uint32_t[1024]` と版の番号) は、そこから作る写し
- 写しは層ごとに 1 回作って覚え、マスを変えるときは写しを変えてから、その区画の文字だけを書き直す (1 区画 = 1024 マスなので軽い)
- 区画ごとの**版の番号**: 変えるたびに 1 上がる。描く束・当たりの形・ナビゲーションは版を見て、変わった区画だけ作り直す

### 3-5. とても大きなマップ

| 大きさ | どうするか |
|---|---|
| 〜 1000 × 1000 マス | 全部シーンのファイルに。広げると 1 層 4 MB (1000 × 1000 × 4 バイト)。ランレングスでふつうは何分の 1 にもなる |
| それより大きい | 段階 6: 区画を外のファイル (`Assets/…/<シーン>.tiles/<層>/<x>_<y>.json`) に出し、カメラのまわりだけ読む (流し読み)。シーンのファイルの上限 (256 MB) から離れる |

- 描くのは見えている区画だけ (5-1)。当たりも全部の区画を作るが、作り直すのは変わった区画だけ
- 遠くから見たとき (1 マスが 2 DIP より小さい) は、区画を 1 枚の小さな絵にして描く (5-4)

### 3-6. 形の種類 (アイソメ・六角)

- データ (マスの (x, y) と区画) は形によらない。違うのは「マス ↔ 平面」の計算・まわりのマス (六角は 6 つ)・描く順 (アイソメは奥から)
- だから**形の欄は最初から持つ** (列挙は名前で保存するので、後で項目を足しても古いファイルの意味は変わらない)。最初に作るのは四角だけ。アイソメと六角は段階 7

## 4. ランタイム (純粋な計算。テストを書く: 憲法 5)

全部 `plugins/rm_engine/tilemap/runtime/` (Jolt も Direct2D もゲーム制作も知らない)。

### 4-1. マス目の計算 (`TileGrid`)

- `CellAt(平面の点) → マス`・`CellRect(マス) → 平面の四角`・`CellsIn(平面の四角) → マスの範囲`。層のワールド行列 (親の Transform 2D) は呼ぶ側が掛ける
- 区画の番号とその中の場所 (負の数の割り算は floor)

### 4-2. 塗る計算 (`TilePaint`)

| 計算 | 中身 |
|---|---|
| 線 | 前のマスから今のマスまで、すき間なく通るマス (速く動かしても飛ばない) |
| 四角 | 2 つの角の間の全部のマス |
| 塗りつぶし | 押したマスと**同じ値**でつながったマス (上下左右)。上限 100 万マス (超えたら塗らずに理由を出す)。空のマスを塗りつぶすときは「今ある区画の範囲 + 1 区画」を外の壁にする (果てしない空を塗らない) |
| スタンプ | パレットで選んだ何マスかの四角を、そのまま置く (反転・回転も) |
| ランダム | 選んだタイルから重みで 1 つ。**マスの場所と種から決まる乱数** (同じ所は同じ結果: やり直しても変わらない) |

### 4-3. オートタイル (まわりを見て絵を選ぶ)

「種類」(草・水・道) で塗ると、まわりのマスの種類を見て、つながる絵を自動で選ぶ。

| 見方 | まわりのどこを見るか | タイルの数 | 向いているもの |
|---|---|---|---|
| **3x3 (ブロブ)** | 8 マス (上下左右と斜め)。斜めは、隣り合う 2 辺が同じ種類のときだけ数える (256 通りが 47 通りになる) | 47 | 壁・崖・道。角の内側と外側が両方きれい |
| **2x2 (角)** | マスの 4 つの角に種類を持たせる (角を共有するマスどうしが合う) | 16 | 草と土の境目・水辺。少ない絵で済む |
| 辺だけ | 4 マス (上下左右) | 16 | 線路・パイプ・柵 |

- タイルセットの `autoSets` に組 (名前・見方・種類の並び)。各タイルの「オートタイルの印」に、どの組のどの種類か・角 / 辺ごとの種類 (Godot の terrain の peering bits と同じ考え)
- 決め方 (純粋): まわりの種類から印の数 (ビットの並び) を作り、それと合うタイルを引く (表は組ごとに 1 回作る)。**ぴったりが無ければ一番多く合うもの** (足りない絵があっても穴にならない)。同じ印が何枚もあればランダムの重みで (4-2 と同じ乱数)
- 1 マス塗ると、そのマスと**まわり 8 マス**を決め直す (2x2 は角を共有する 4 マス)
- 保存するのは**決まったタイル** (14 章の 6)。だからゲームは規則を解かずに描ける
- 言葉: Godot の「Terrain」を「地形」と訳すと 3D の地形と紛れるので、この文書では **オートタイルの組 / 種類** と呼ぶ

### 4-4. 動くタイル (水・溶岩・旗)

- `TileInfo` のコマ送り: コマの並び (同じ絵の元の中のタイル)・1 秒のコマ数・繰り返す。スプライトのアニメーション (`SpriteAnimation`) と同じ 3 つの欄・同じ名前
- 今のコマは**今の `space2d::AnimationCell`** で、ゲームの時間から決める (同じ式を 2 つ書かない: 憲法 2)。コマの並びの型は ANIMATION.md 7-4 の `space2d::FrameClip` (コマの並び・速さ・ループ) を使う (型は 1 か所: 憲法 1。2D のコマ送りと一緒に作る)。同じタイルは全部同じコマ (水面がそろって揺れる)
- 保存するのは元のタイル。描くときにコマのタイルへ差し替えるだけ (マスの値は変わらない = 当たり・ナビゲーション・セーブに効かない)
- エディターで止まっているときは動かさない (毎フレーム描き直さない)。シーンビューの帯の「動かして見る」で動く (14 章の 16)

### 4-5. 当たりをまとめる (`TileCollision`)

タイルを 1 つずつ四角にすると、数千の形になり、つなぎ目で転がる物やキャラクターが引っかかる。
区画ごとに、つながった形にまとめる。

1. 区画のマスを見て、当たりの形のあるタイルを集める
2. **「全部」の形**: 横に続くマスを 1 本の帯にし、すぐ下の帯と同じ幅なら縦にもつなぐ (貪欲な長方形の詰め方。greedy meshing)。広い床が 1 つの長方形になる
3. **半分の形**: 同じ向きの半分どうしを同じやり方でつなぐ
4. **斜めと自分で描いた形**: 1 マスずつの凸の多角形。同じ傾きで続く斜めは 1 つの多角形にまとめる
5. 出力 = 区画ごとの「凸の多角形の並び」(平面の点。層の中の単位)。版の番号つき

- 区画をまたいではまとめない (変えた区画だけ作り直せるように)。区画の境目の引っかかりは Jolt の `mEnhancedInternalEdgeRemoval` で減らす (6 章)
- テスト: 四角が 1 つの長方形になる・L 字が 2 つになる・穴のある形・斜めが続く・区画の端・マスの数より形の数が少ないこと

### 4-6. テスト (`tests/TestTilemap.cpp`)

マス ↔ 平面 (負の場所・回した層)・区画の番号・ランレングスの往復・知らないキーの書き戻し・線 / 四角 / 塗りつぶし (上限)・ランダムが場所で決まる・オートタイル 3 通りの見方の表と「一番多く合う」・コマ送りのコマ・当たりのまとめ方・1000 × 1000 の層の読み込みと 1 マスの変更がゆるい時間 (数百 ms) で終わること。

## 5. 描画

### 5-1. 区画ごとにまとめて描く

```
層 1 つ × 見えている区画 1 つ × 絵の元 1 つ = 束 (スプライトの束) 1 つ = 描く命令 1 回
```

- **Direct2D のスプライトの束** (`ID2D1SpriteBatch`): 1 枚の画像から切った多くの四角を、1 回の命令で描く Direct2D の仕組み (Windows 10 から。`ID2D1DeviceContext3::CreateSpriteBatch` → `AddSprites` → `DrawSpriteBatch`)。今の 2D は Direct2D で描いているので、Direct3D に移らずに済む
  - 束は区画ごとに作って覚え、**区画の版が変わったときだけ**作り直す。動くタイルはそのマスだけ `SetSprites` で差し替える
  - 色を掛ける・反転 (マスごとの行列) も束の中でできる。補間は最近傍か線形だけ (ドット絵は最近傍)
  - `DrawSpriteBatch` は角のぼかしを切った状態 (`D2D1_ANTIALIAS_MODE_ALIASED`) で呼ぶ決まりがある。描く間だけ切り替えて戻す
  - デバイスの作り直し (`gfx.Generation()`) で束を捨てる (今のビットマップと同じ)
- 見えている区画だけ: カメラの見える四角 → 層の中へ戻す (逆行列) → 区画の範囲。回した層でも外接の四角で判定する
- 描く装置 (`Renderer2D`) に足すもの: 「並べた描く物」の 1 本の列 (スプライト 1 つか、区画の束 1 つ)。スプライトの描き方は今のまま

### 5-2. 前後の順 (ほかのスプライトとの)

- 1 つの層 = 今の `DrawKey` の 1 つの描く物: (ワールドの並び順, 層の並び順, 階層の順)。スプライトと**同じ列で並べる**
- 例: 背景 (-10) → 地面 (0) → キャラクター (0、スプライトの並び順 1) → 前景の葉 (10)
- そのために、2D の描く物を集める所を**1 本にする**: 今はシーンビュー (`SceneView2D`) と書き出したゲーム (`GameDraw2D`) が別々にスプライトを集めている。段階 1 で、集める関数を `game_x_2d/runtime` に 1 本にし (憲法 3)、新しい口 `rm_engine.game_x_2d.world_draw` に差し出された物 (タイルの層) もそこで足す
- 見下ろしの RPG の「キャラクターが木の後ろに回る」(Y で並べる) は後で (14 章の 11)

### 5-3. タイルの間の継ぎ目

拡大縮小の途中の大きさでは、隣のタイルの絵がにじんだり、1 ピクセルのすき間が出たりする。

- 絵の元を読むとき、**各タイルの縁を 1 ピクセル外へ伸ばした絵**をメモリーの中で作る (エディターもゲームも同じ関数。ファイルは変えない)
- 束の四角はマスの大きさちょうど。ドット絵は「くっきり」(最近傍) を既定に

### 5-4. 遠くから見るとき

- 1 マスが 2 DIP より小さいとき (縮めて全体を見る) は、区画を 32 × 32 ピクセルの小さな絵 (マスごとの代表の色) にして 1 枚で描く。区画の版が変わったら作り直す
- 気候のタブの「縮めて 1 マスが 2 DIP より小さいときは何マスかおきに見る」と同じ考え

## 6. 当たり判定 (物理とのつなぎ)

```
タイルマップ (純粋)     TileCollision: 区画 → 凸の多角形の並び + 版
        ▼
タイルマップ × 物理     物理の口 rm_engine.physics.static_shapes に答える
        ▼
物理                    持ち主 (層のエンティティ)・鍵 (区画)・版 が変わった物だけ作り直す
                        区画 1 つ = 動かない物体 1 つ (StaticCompoundShape: 多角形を厚さ 0.5 の凸の形に)
```

- **物理に新しい口**: 「ほかのプラグインが作る動かない形」。物理はタイルを知らない (形と持ち主と版だけを受け取る)。2D の形は今の 2D の物体と同じ厚さ (`kPlaneHalfDepth`) の凸の形 (`ConvexHullShape`) にし、区画ごとに `StaticCompoundShape` に寄せる
- 区画の物体は `mEnhancedInternalEdgeRemoval` を立てる (区画の境目・長方形の境目で引っかかりにくい)
- フック: 当たった相手 (`other`) は層のエンティティ。どのマスかは、スクリプトが場所から引く (9 章の `CellAt`)。今のフック (`HookCall`) は当たった場所を持たないので、光線 (`Raycast` の point と normal) か足元で調べる
- 層の「当たりを作る」を切ると作らない。層が無効なら消す (今の部品と同じ)
- エディター: シーンビューの「形: 選択 / 全部」で、まとめた形の線を出す (口 `kSceneLinesPoint`。今のコライダーと同じ色)
- **2D のキャラクター**: 物理のキャラクターは 3D だけ (1 章)。横スクロールのアクションには 2D のキャラクターが要るが、それは物理の設計 (14 章の 9)。それまでは「剛体 + コライダー (2D) のカプセル + 回転の固定 Z」で歩ける
- テスト: 箱が床のタイルの上で止まる・斜めを転がる・区画の境目で止まらずに滑る・ゲーム中に壁のタイルを消すと次の刻みで通れる

## 7. エディターの画面

### 7-1. 置き方

- 階層の「追加 ▸ 2D オブジェクト ▸ タイルマップ」: グリッドのエンティティと、層 1 つ (「地面」) を作る (口 `kCreateItemPoint`。Undo の 1 件)
- インスペクター: グリッドと層の欄はリフレクションのまま (`Tr` の言葉は `Label`)。層には「N 区画・M マス」と、タイルセットが無いときの注意
- 層をシーンビューでクリックすると選べる (絵のあるマスの上)

### 7-2. パレット (パネル「タイル」)

ゲーム制作の口 `rm_engine.game_production.view_panel` で出すパネル。シーンビューの隣にドッキングして使う。

```
┌ タイル ─────────────────────────────────────────────┐
│ [パレット | タイルセット]        tiles.rmtileset ▾   │
│ 絵の元: [草原 ▾]   ＋ 拡大 −                          │
│ ┌─────────────────────────────────┐                  │
│ │ ■ ■ ■ ■ ■ ■ ■ ■                 │  ← クリックで 1 つ │
│ │ ■ ▣ ▣ ■ ■ ■ ■ ■                 │    ドラッグで四角  │
│ │ ■ ▣ ▣ ■ ■ ■ ■ ■                 │    Ctrl で足す     │
│ └─────────────────────────────────┘                  │
│ オートタイル: [なし] [草] [水] [道]                    │
│ ランダム: ■ 3  ■ 1  ■ 1      (重み)                   │

- 選んだ層のタイルセットを出す。層を選んでいないときは「タイルの層を選んでください」
- 選んだもの (タイル・スタンプ・オートタイルの種類) と拡大はパネルの見え方 (`UserSettings`。プロジェクトに入れない)
- 描く部品は `w::` に足す (タイルの格子・選んだ枠)。画面のコードで四角を塗らない

### 7-3. 塗る道具 (シーンビュー)

ゲーム制作 × 2D に新しい口 `rm_engine.game_x_2d.scene_tool` を作り、2D のシーンビューの左上の道具の列に足す。
タイルの層を選んでいるときだけ出る。

| 道具 | キー | 動き |
|---|---|---|
| 筆 | B | クリック・ドラッグで塗る (選んだタイル / スタンプ / オートタイルの種類) |
| 四角 | U | ドラッグした四角を塗る。Shift で中を空けて枠だけ |
| 塗りつぶし | G | 同じ値でつながったマスを塗る (4-2) |
| 消しゴム | Shift + 筆 / 道具の列 | 空にする (オートタイルならまわりを決め直す) |
| スポイト | I / Alt + クリック | マスのタイルをパレットに取る (ドラッグで四角に取るとスタンプ) |
| ランダム | 筆の帯のさいころ | パレットで選んだタイルから重みで選ぶ |
| 反転・回す | X / Y / Z | 置く前のタイルを左右・上下・90 度 |

- マウスの下に**置く前の絵** (半透明) とマスの枠。右 / 中ドラッグとホイールは今のまま (動かす・近づく)。Esc で移動の道具に戻る
- 道具の印 (四角・塗りつぶし・スポイト・さいころ) は `w::Icon` に足す (線で描く印)
- Play 中は塗れない (道具を薄く。止めると消えるため。今の決まりと同じ)

### 7-4. Undo (憲法 7)

- **1 回のドラッグ (1 回のクリック・1 回の塗りつぶし) = Undo の 1 件**。ドラッグの間は層の写しと区画の文字を直に書き換え (Transform 2D のドラッグと同じ)、離したときに積む。Esc で戻す
- 命令 `TileEditCommand`: 層のエンティティの ID・触った区画ごとの (区画の番号, 前の文字, 後の文字)。戻すときは ID と型で部品を探し直す (`SetFieldCommand` と同じ考え)。**触った区画だけ**を持つので、大きなマップでも軽い (`SceneRecord` のようにエンティティ全体の JSON を取らない)
- 積む = 未保存の印 (今の配線のまま)。何も変わらなかった操作は積まない
- 層を作る・消す・並べ替える・グリッドの欄は今の道 (`editScene` / `SetFieldCommand`)

### 7-5. タイルセットの編集 (パネル「タイル」の「タイルセット」)

```
┌ タイル ─ [パレット | タイルセット] ────────────────────────────────────────┐

│ │ ■ ■ ■ ■ ■ ■                   │ │ 名前       [宝箱・開いた       ]      │ │
│ │ ■ ▣ ■ ■ ■ ■   ← 選ぶ           │ │ 当たり     [全部 ▾]   (絵の上に形)    │ │
│ │ ■ ■ ■ ■ ■ ■                   │ │ タグ       [壊せる] [×]  ＋           │ │
│ └───────────────────────────────┘ │ かたさ     [ 3 ]   (独自データ)       │ │
│ 見る: [当たり] [オートタイル] [コマ]  │ コマ送り   4, 5, 6, 7   8 / 秒  繰り返す │ │

- 絵の上に、選んだ「見る」を重ねる: 当たりの形 / オートタイルの角と辺の種類 (クリックで塗る) / コマ送りの印
- 右の欄はインスペクターと同じ描き方 (`editor::inspector::Draw`。気候のタブと同じ)。複数選ぶと同じでない値は「—」
- 編集は `.rmtileset` の中身の Undo (核の `ContentCommand`: アセットのパネルからインスペクターで編集したときと同じ道)。ファイルへは編集が終わってから
- 絵の元の追加・切り方 (タイルの大きさ・余白・間) もここ。切り方を変えたら、マスの値は同じ列と行を指したまま

### 7-6. 文字

画面の文字は日本語で書いて `Tr` / `TrF` / `TrU8` を通し、英語を `plugins/rm_engine/<名前>/lang/en.json` に。ヘルプは各プラグインの `help/*.md` と `help/en/`。

## 8. 書き出し (`.rmpak`)

- タイルの層はシーンのファイルの中 (JSON のまま `.rmpak` に入る。今のシーンと同じ)
- `.rmtileset` はシーンが名指すアセットなので入る。その中の画像も入る (`CollectAssets` はアセットの中の ID をたどる)。画像は今の 2D の焼き手で `.rmimage` に
- ゲームが使うプラグイン: 層の部品の持ち主 (ゲーム制作 × タイルマップ) → 前提 (タイルマップ・2D 空間) とつなぎ (タイルマップ × 物理: 物理も入っているとき) が足される (今の数え方のまま)
- 焼かないもの: オートタイルの規則・パレットの見え方 (ゲームは決まったタイルを描くだけ)
- 後で: 層の区画をバイナリに焼く (シーンをバイナリにするとき一緒に: ARCHITECTURE 7-9 の「★ まだ」)

## 9. スクリプト API (`#include "RMTilemap.h"`)

```cpp
rm::Tilemap ground(rm::Find("地面"));             // タイルの層のエンティティ
rm::Cell c = ground.CellAt(rm::Transform2D(self).WorldPosition());   // 平面 → マス
rm::Tile t = ground.Get(c);                        // t.Empty() で空
if (ground.HasTag(c, "壊せる")) ground.Erase(c);   // 壊せる壁
ground.Set(c, ground.TileNamed("宝箱・開いた"));    // 名前を付けたタイルに替える
ground.Set(c, rm::Tile{1, 3, 2});                  // 絵の元 1 の 3 列 2 行
ground.Paint(c, "草");                             // オートタイルの種類で (まわりも決め直す)
ground.Fill(rm::CellRect{x0, y0, x1, y1}, t);
int hard = ground.Int(c, "かたさ");                 // 独自データ (Bool / Int / Number / Text)
rm::Vec2 p = ground.CellCenter(c);                 // マス → 平面 (ワールド)
```

- 形は今と同じ: `RMTilemapAbi.h` (C の関数の表)・口 `rm_engine.game_production.script_api` に部分 `rm_engine.game_x_tilemap.tilemap` 版 1
- 書き換えは Play のコピーの中だけ (■ で消える)。書くとその区画の版が上がり、描く束・当たり (次の固定の刻み)・ナビゲーションが付いてくる
- 1 フレームにたくさん書いても、作り直すのは区画ごとに 1 回 (版を見るのは使う側の都合のとき)

## 10. ゲーム中に変える・セーブ ([SAVE.md](SAVE.md))

- 世界のセーブは「部品「セーブする」の付いた物だけ」(SAVE.md の決定)。**タイルの層にも「セーブする」を付けたときだけ**、ゲーム中に変えたタイルが残る
- ただし「全部の部品の値」で層を丸ごと書くと、変えていない区画まで毎回書く。そこで:
  - ゲーム制作に新しい口 `rm_engine.game_production.world_save_part` (プラグインが世界のセーブに自分のキーを足す: 取る・当てる)
  - ゲーム制作 × タイルマップが答える: シーンを読んだときの区画ごとの印 (中身の FNV-1a) と比べて、**違う区画だけ**を書く
  - 「全部の部品の値」のときも、タイルの層の部品はこの差の道だけで書く (同じものを 2 回書かない)

```json
"world": { "format": 1, "scene": {…}, "base": 57, "entities": […],
  "parts": { "rm_engine.game_x_tilemap": { "format": 1,
    "layers": [ { "id": 12, "chunks": [ { "x": 0, "y": 0, "cells": "…" } ] } ] } } }
```

- 当てるのはシーンを読み直した後 (SAVE.md の「フレームの切れ目」と同じ)。無い層・壊れた区画は飛ばしてコンソールに 1 行
- 知らない `parts` のキー (プラグインが無い) は書き直しても残す (憲法 6)

## 11. ほかの設計図とのつなぎ

### 11-1. ナビゲーション ([NAVIGATION.md](NAVIGATION.md))

タイルマップはナビゲーションを知らない。ナビゲーションもタイルマップを知らない。つなぎが渡す:

| 渡すもの | 中身 |
|---|---|
| マス目の形 | 原点 (層のワールド行列)・マスの大きさ・形 (四角。後でアイソメ・六角: まわりのマスの数が変わる) |
| マスごと | 通れるか (当たりの形が「なし」か、タグ「通れない」が無い)・移動のコスト (独自データ「移動コスト」。無ければ 1) |
| 変わった所 | 区画の番号と版 (ゲーム中に壁を壊したら、その区画だけ経路を作り直せる) |

- どの層を読むか (当たりを作る層全部 / 選んだ層) と、斜めに進めるか (角を切るか) は、NAVIGATION.md と合わせて決める
- 口の名前と形はナビゲーションの側が決める (読む側が口を決める: ARCHITECTURE 6 章の「差し出し」)。NAVIGATION.md 4-3 では、マス目のゲームは口 `rm_engine.game_x_navigation.grid` (「このマスは通れるか・費用は」の関数と、マスの大きさ・原点)、自由に動く 2D のゲームは口 `rm_engine.game_x_navigation.source` (通れないタイルを壁の形に)。つなぎ `tilemap_x_navigation` が両方に答える

### 11-2. アニメーション ([ANIMATION.md](ANIMATION.md))

- 6 章の 6「2D のコマ送りにも同じタブとルール」は、**動くエンティティ** (キャラクターのスプライト) のためのもの。タイルの動き (4-4) は状態もルールも持たず、ゲームの時間で回り続けるだけなので、`.rmanim` は使わない
- ただしコマの並びの形はそろえる: スプライトのアニメーションと同じ 3 つの欄 (コマの並び・1 秒のコマ数・繰り返す) と同じ関数 `AnimationCell`。その型は ANIMATION.md 7-4 の `space2d::FrameClip` に決めた (2D のコマ送りと一緒に作る。タイルマップの段階がそれより先なら、そのとき `FrameClip` を先に作る)

### 11-3. 地形 (3D) と気候

- 3D の地形 (まだ設計図は無い。気候の設計図に「地形ができてから」とある) も、筆・消しゴム・四角・塗りつぶし・スポイトで塗るはず。気候のタブもすでに筆を持つ
- そこで、**マス目に塗る純粋な計算** (線を半径の 3 割ごとに補う・塗りつぶし・四角・ランレングス) を核 (`src/core` の中) に 1 か所置き、気候・タイルマップ・地形が使う (憲法 2)。タイルマップの段階 1 で移す
- 気候の設計図の「決めていないこと」に「2D のシーンの気候の地図」がある。後で、タイルのタグ (雪・砂) から気候を答えるつなぎも作れる (今はしない)

### 11-4. イラスト (これから)

- タイルセットは画像を `AssetRef` で指すだけなので、イラストのソフトで描いた画像をそのまま使える
- 後で: パネル「タイル」から「この絵をイラストで開く」・マップの上で直接タイルの絵を直す (イラストのソフトができてから)

## 12. 1 フレームの順番

1. 入力 → スクリプトの `Tick` (タイルを読む・書く: 書いた区画の版が上がる)
2. Fixed (固定の刻み): システム「物理」の Step の始めに、口 `static_shapes` に聞き、版の変わった区画の物体だけ作り直す → Jolt の 1 刻み
3. Frame (毎フレーム): ほかのシステム (スプライトのアニメーション …)。タイルのためのシステムは無い (動くタイルは描くときに時間から決める)
4. ナビゲーション: 版の変わった区画を見て経路の網を直す (NAVIGATION.md の順に合わせる)
5. フックを届ける (`ScriptRunner::Deliver`。OnHit の相手は層)
6. 描く: 見える区画だけ。版の変わった区画の束を作り直し、動くタイルのコマを差し替え、スプライトと同じ列で前後に並べて描く

止まっているエディターでは 2 と 4 は動かない。塗るたびに描く束 (6) とシーンビューの当たりの線だけが付いてくる。

### 設計から変えたこと (実装で決めた)

- **継ぎ目の対策 (5-3)**: タイルの縁を 1 ピクセル伸ばした絵は作らない。スプライトの束の `D2D1_SPRITE_OPTIONS_CLAMP_TO_SOURCE_RECTANGLE` が、混ぜるときに自分の四角の外を読まないので、それで足りる (画面では未確認。にじむようなら伸ばした絵を足す)
- **タイルセットの「1 単位のピクセル数」**: 置かない。タイルはいつもマスいっぱいに描くので要らない (1 マス = 1 単位の決定)。書いてあるファイルは知らないキーとして残る
- **層の「当たりを作る」**: 段階 2 で足す (今は効かない欄を出さない)
- **スタンプの向き**: パレットと同じ向き (上の行から)。置くときはスタンプの左上をマウスの下のマスに合わせる
- **消しゴムの大きさ**: 1 マス (スタンプの大きさでは消さない)
- **区画の大きさが 32 でない層**: 読んで描けるが、塗ろうとするとコンソールに 1 行出して塗らない (将来の形)
