# RM Engine の形 (2026-11-04 時点)

この文書は「いま何がどう動いているか」と「なぜそうしたか」。
前のエンジン (TestEngine) の反省は `TestEngine/新エンジンへの引き継ぎメモ.txt` と、その `docs/` の設計書 (DESIGN_SUMMARY / RME_PLATFORM) にある。
ここでは、それを受けて**このリポジトリで実際に採った形**だけを書く。

---

## 1. 決まっていること

| 項目 | 決定 | 出どころ |
|---|---|---|
| 対象環境 | **Windows + Visual Studio が使える PC**。Windows の機能・VS が必須なのは問題にしない | ユーザー 11-04 |
| VS が無いとき | 「Visual Studio をインストールしてください」と案内する。**後で作る** | ユーザー 11-04 |
| UI | **ImGui は一切使わない**。軽くて使いやすい独自 UI | ユーザー 11-04 / RME_PLATFORM 7-1 |
| 形 | 核 → プラグイン。ソフト (ゲーム / イラスト / 作曲 …) はプラグインが出す | RME_PLATFORM |
| Hub とエディター | **同じ exe・別ウィンドウ**。書き出したゲームは別 exe (エディターを含まない) | BluePrint 4-k |
| 保存形式 | 自己記述型 JSON。**知らないキーは捨てずに書き戻す** | 憲法 10 / 引き継ぎ 3-5 |
| 未保存の印 | **Undo 履歴に積んだ編集 = 未保存**。配線 1 本 (`SetOnModified`) | 引き継ぎ 2-1 |
| パス | プロジェクトのデータに絶対パスを入れない (別の PC で開けるように) | 引き継ぎ 4-7 |
| パネルの配置 | **ユーザーの見た目であって、プロジェクトのデータではない**。Undo に積まない・未保存にしない。`<プロジェクト>/UserSettings/Layout.json` に**ソフトごと**に保存 | RME_PLATFORM 4 |
| プラグイン | `plugins/<作者>/<名前>/` (`plugin.json` + `runtime/` + `editor/`)。**全部 exe に静的リンク** (DLL は後で)。ID は作者名とプラグイン名の 2 つの値 | RME_PLATFORM 3-a / 3-b / 10 |
| ソフト | **前提プラグインが出す** (ゲーム = ゲーム制作プラグイン)。ソフトごとにパネル・配置・**Undo の履歴**を持つ。**未保存の印はプロジェクトで 1 つ** | RME_PLATFORM 4 |
| 入れたプラグイン | **全部のプロジェクトで使える** (プロジェクトごとの ON / OFF は無し)。`.rmpf` の `plugins` に記録されたプラグインがそろっていなければ**開かない** | RME_PLATFORM 5-a |
| データの型 | **1 か所に書く** (`RM_STRUCT` + `RM_PROPERTY`)。保存・読み込み・インスペクター・比較・Undo・範囲のクランプはそこから。`tools/rmgen` がビルドのたびに表を作る | 憲法 1 / 設計 R1 |
| 入れる・消す | **Hub**: インストール / 再インストール / 削除。**エディター**: インストールだけ (保存して同じプロジェクトを開き直す)。削除は Hub だけ | RME_PLATFORM 5-a / 1-b-2 |
| 外へ出したパネル | エディターのウィンドウが持ち主の別ウィンドウ (上に乗り続ける・タスクバーに出ない) | RME_PLATFORM 4 |

## 2. 層

`layers.txt` が唯一の出所。`tools/check_layers.ps1` が include の向きを検査する (ビルドスクリプトと CI で毎回)。

| フォルダ | 層 | ゲームに入るか | 中身 |
|---|---|---|---|
| `base` | L0 | 入る | UTF 変換・JSON・ファイル名の検査・ログ。**標準ライブラリだけ** |
| `core` | L2 | 入る | Undo 履歴・プラグインの ID・**リフレクション** (`core/reflect`)・**アセットの ID** (`core/asset`) |
| `platform` | L3 | 入る | Win32 ウィンドウ・D3D11/D2D・ファイルダイアログ・原子的なファイル書き込み |
| `ui` | L4 | 入る | 核の UI の**土台** (ID・ホバー・フォーカス・文字入力・描画)。**色を持たない** |
| `game` | L5 | 入る | 書き出したゲームの枠 (ウィンドウ・`.rmpak`・プラグインの登録・フレーム)。ソフトもプラグインも知らない (7-9 章) |
| `editor` | L6 | 入らない | Hub・エディターの枠・エディターの見た目 (テーマ・ボタン・入力欄・メニュー・ダイアログ) |

「土台は見た目を持たない」は RME_PLATFORM 7-1 の条件 2。ゲーム UI プラグインが同じ土台の上に別の見た目を付けても、エディターのテーマを変えてもゲームは変わらない。

プラグイン (`plugins/`) の柵も同じスクリプトが見る: **核 (`src/`) はプラグインを読まない** / プラグインのコードは `runtime/` か `editor/` / `runtime/` はゲームに入る層と前提の `runtime/` だけ / 読めるのは自分と `requires` のプラグインだけ / `requires` が輪にならない / `plugin.json` の ID = フォルダ名 / `editor/` を持つプラグインは `BuiltinPlugins.cpp` に載っている。

## 3. Hub とエディターの切り替え

```
起動 ─┬─(引数なし)──────────▶ Hub ──(作成 / 開く)──▶ エディター
      └─(--project x.rmpf)──────────────────────────▶ エディター
                                Hub ◀──(✕ / Hub に戻る)── エディター
                                 └──(✕)──▶ 終了       └──(ファイル > 終了)──▶ 終了
```

- `App` が GPU デバイスと「今の画面」を 1 つ持つ。画面の切り替えは**予約だけ**して、メッセージループに戻ってから行う (`App::ApplyPending`)。自分のウィンドウプロシージャの中で自分を壊さないため
- 新しいウィンドウを出してから古いウィンドウを閉じる (ウィンドウが 0 個になる瞬間を作らない)
- 開けなかったとき (壊れた `.rmpf` / 新しい版で作られた `.rmpf` / ファイルが無い) は Hub にエラーを出す。**新しい版の `.rmpf` は開かない** (データを壊さないため)
- エディターを閉じる道は 3 つ (✕ / Hub に戻る / 終了) あるが、**未保存の確認は 1 本の道** (`RequestClose`) を通る。**Windows の終了** (`WM_QUERYENDSESSION` → `ScreenWindow::OnQueryEndSession`): 未保存ならエディターが同じ確認を出し、`ShutdownBlockReasonCreate` で理由を Windows に見せて FALSE を返す (待ってもらう)。キャンセルか閉じたら理由を消す。それでも終わるとき (`WM_ENDSESSION`) は配置だけ保存する
- **ログはどのスレッドからでも書ける** (`base/Log`。2026-11-12): 受け手 (sink) は 2 種類。`Delivery::AnyThread` (デバッガーの出力・`editor.log`: 書いた人のスレッドですぐ呼ぶ。受け手が自分で鍵を持つ) と `Delivery::Queued` (エディターの再描画: 待ち行列に入れ、UI のスレッドが `log::DeliverQueued()` を呼んだときに渡す。`App::Run` のメッセージループが 1 つずつのメッセージの後に呼び、別のスレッドが書いたら `log::SetWake` の `PostThreadMessage(WM_NULL)` でループを起こす。待ち行列が空から 1 つになったときだけ起こす)。`RemoveSink` は、ほかのスレッドで呼ばれている最中の受け手が戻るまで待ってから返り、その後は二度と呼ばない (`~EditorScreen` が消えた `this` を呼ばれない)。自分の中から自分を外すときは待たない。テストは `tests/TestLog.cpp` (8 本のスレッドで 1 万 6 千行・書いている最中の RemoveSink・待ち行列のスレッドと順番・自分を外す)
- Hub の「プラグイン」のインストール・削除・入れ直しは `Defer` で描画の後に行う (入れると `Plugins::Entries()` を作り直すので、その一覧を描いている途中に行わない)
- **同じプロジェクトを 2 つで開かない**: エディターは開いている間 `<名前>.rmpf.lock` (`ProjectLockFile`) を `platform::FileLock` で持つ (共有なしで開いた隠しファイル、`FILE_FLAG_DELETE_ON_CLOSE` なので閉じても落ちても消える。テストは本物のファイルで `tests/TestFileLock.cpp`)。`App::OpenProjectNow` が取れなければ (別の RM Engine が持っている) 開かずに Hub にエラー。取れない理由がそれ以外 (書けないフォルダ) なら警告して開く。Hub の名前の変更も先に試しに取ってみて、持たれていれば止める (取れたらすぐ放す: 中のファイルが開いているとフォルダの名前を変えられないため)
- プロジェクトの名前の変更は Hub だけ (Hub が出ている間はこの RM Engine ではどのプロジェクトも開いていない)。`.rmpf` のファイル名・中の `name`、それに**フォルダの名前がプロジェクトの名前と同じとき (このエンジンが作った形) だけ**フォルダを一緒に変える (`RenameProject`。何を変えるかは純粋な `PlanProjectRename`、テストは `tests/TestProject.cpp`。ユーザーのフォルダ `D:\Work\game.rmpf` の `D:\Work` は変えない)。順番はフォルダ → ファイル → 中身で、失敗した段より前を元に戻す (半分だけ変わった状態を残さない)。最近の一覧は同じ位置のまま新しいパスに置き換える

## 4. 独自 UI の仕組み

**即時モード + 変わったときだけ描く。**

```
入力メッセージ ─▶ Invalidate ─▶ WM_PAINT ─▶ RunFrame
                                              ├ 画面のコード (OnFrame) を 1 回走らせる
                                              ├ Direct2D で描く ─▶ Present
                                              └ クリック・キーがあったフレームの後は、もう 1 回だけ描く
サイズ変更 ──────────────────────────────▶ WM_SIZE の中で RunFrame (枠を掴んでいる間も絵が止まらない)
```

- 何もしていないときは描かない (入力欄にフォーカスがあるときだけ、キャレットの点滅で 0.5 秒ごと)
- スワップチェーンは `FLIP_DISCARD` + `DXGI_SCALING_NONE` (古い画を引き伸ばさない)。DPI は Per-Monitor v2。座標は全部 DIP
- 部品の ID は**文字列のハッシュ + ID スタック**。グローバルな番号では持たない (前のエンジンのスライダー番号の衝突 #17 の再発防止)
- 重ねる UI (メニュー・ダイアログ) は「下の画面を入力なしで描く → 上を入力ありで描く」で作る
- 文字入力 (`ui/TextEdit` + `editor/widgets` の `TextField`): キャレット・選択・Ctrl+A/C/X/V・単語移動・サロゲートペア。**日本語 IME は変換中の文字を入力欄の中に自前で描き**、候補ウィンドウをキャレットに合わせる。変換中に別の場所をクリックすると、先に確定してから移る
- 文字は DirectWrite (`Yu Gothic UI`)。日本語の組版は自作しない

### 部品の決まり (`editor/widgets`)

- **ImGui のように 1 回の呼び出しで描いて、何をされたかを返す**: `w::Button` / `w::IconButton` / `w::Selectable` / `w::NavItem` / `w::CollapsingHeader` / `w::ComboBox` / `w::TextField` / `w::Checkbox` / `w::MenuPopup` / `w::BeginModal` / `w::Tooltip` / `w::BeginScroll` …
- **画面のコードは四角を自分で塗らない**。箱は `w::DrawSurface` (Panel / Raised / Hovered / Pressed / Sunken / Accent / Selected / Popup)、一覧の行は `w::DrawRow`、タブは `w::DrawTab`、窓の帯 (メニューバー・ステータスバー・サイドバー) は `w::DrawBar`、印 (× ・ ⋯ ・ ⋮ ・ ▾ ・ ▸ ・ ✓) は `w::DrawIcon`。見た目を変えるときはここを 1 か所直せば全部の画面が変わる (憲法 3)
- 印は文字ではなく線と点で描く (文字の「…」は下に寄る。線ならどの大きさでも箱の真ん中に来る)
- **色はテーマの色にグラデーションを掛ける**: 上が少し明るく下が少し暗い (光が上から当たる)。色合いはパレットのまま。`theme::Raised` (ボタン・見出し・タブ) / `theme::Gentle` (パネル・帯) / `theme::Sunken` (入力欄: 上が暗い) / `theme::AccentOf` (アクセント)。盛り上がった面の上の縁に 1 本の明るい線 (`theme::Highlight`)。押したときはグラデーションを上下逆にする
- 影は `Painter::Shadow` (少しずつ広く・薄くした角丸を 4 枚重ねる。ぼかしの代わり)。メニュー・ダイアログ・ツールチップ・ドラッグ中の札に付く
- グラデーションのブラシは色の組ごとに 1 つ作って使い回す (`Painter::Gradient`。毎回作らない)

### 実際に踏んだ罠 (このリポジトリで直したもの)

| 罠 | 直し方 |
|---|---|
| メニューを開いたクリックが、同じフレームで「メニューの外のクリック」と判定されて即閉じる | `Popup::fresh` — 開いたフレームは外クリック判定をしない |
| ダイアログを開いたクリックが、同じフレームで最初の入力欄のフォーカスを外す | `Context::FocusIsNew()` — フォーカスを付けたフレームは外クリック判定をしない |
| ウィンドウに**送られた** (`SendMessage`) WM_CLOSE で終了を頼んでも、次に何かメッセージが来るまで終わらない | 送られたメッセージは `GetMessage` の中で処理され、ループに戻らない。`App::Request*` が `PostThreadMessage(WM_NULL)` でループを起こす |
| Esc でダイアログを閉じても、次の入力まで古い画面が残る | クリック・キーのあったフレームの後は必ずもう 1 回描く |
| IME の変換中にボタンを押すと、変換中の文字が捨てられる | マウスを押した瞬間に `CPS_COMPLETE` で確定させ、入力欄は「打った文字の処理 → クリックの処理」の順にする |
| 別ウィンドウからタブをドラッグすると、エディター側に目印が出ない (落とす先は合っている) | ドラッグ中に毎回「全部描き直し」を頼むと、ドラッグ元のウィンドウが自分のフレームの中で自分を無効化し続け、その WM_PAINT がほかのウィンドウの描画を止めていた。**見た目が変わったときだけ**描き直しを頼む |

## 4-2. 見た目と言語 (オプション)

- **オプション** = `RM_STRUCT Options` (`editor/project/Options.h`: 色のテーマ・言語・自動保存の間隔・自動アップデート)。`hub.json` の `options` に保存 (知らないキーは保持)。Hub の「オプション」は**インスペクターでこの型を描く** (設定の画面を手で書かない。憲法 1・9)。変えるとすぐ効く (`App::ApplyOptions`)。プロジェクトのデータではないので Undo は無い
- **色のテーマ**: `editor/widgets/Theme.h` に組み込みの色の組 (`Palette`。黒・白) と、**テーマの一覧 `Themes()`** (id・名前・色の組・パックの名前・絵。色の組が無い = 「PC の設定に合わせる」)。**組み込みは黒・白・PC の設定に合わせるの 3 つだけ**で、ほかは**テーマパック** = テーマのファイルを持つプラグイン (`plugins/<作者>/<名前>/themes/*.json`。1 テーマ 1 ファイル。形は `editor/widgets/ThemeFile.h` の `RM_STRUCT` (読み込みはリフレクションから)。色は `#RRGGBB` / `#RRGGBBAA`、書いていない色は組み込みの黒 / 白のもの)。いまのパックは 基本カラーテーマパック (青・緑) / 季節テーマパック (スプリング・サマー・フォール・ウィンター) / 紙。`App` がプラグインを読むたび (起動・インストール・削除) に、使えるプラグインのインストール先の `themes/` を読み (`LoadThemes`)、`theme::SetPackThemes` で組み込みの後ろに並べる (パックごとに `group` を 1 つ。id が重なるものは読まない)。テーマを足す = パックにファイルを 1 つ足す (名前の英語はそのプラグインの `lang/en.json`。`check_lang.ps1` が見る)。オプションに残すのはテーマの id (`options.theme`。組み込みは前の 3 択の名前と同じ。知らない id = パックが入っていない ときは、`LoadThemes` が最初のテーマ (黒) にして `hub.json` に書く: パックを入れ直しても前のテーマには戻らない。前の id はファイルの `aliases` で読み替える: 「桜」の `Sakura` → スプリング)。Hub の「テーマを変更…」の専用の画面 (カードを 4 列。`w::ThemeCard`。`group` が変わる所で行を改め、パックの名前と横線) で選ぶ。**テーマの絵** (季節) はパックのコード: `w::OrnamentInfo` (名前・ウィンドウ全体の絵・パネルごとの物) を口 `w::kOrnamentPoint` に差し出し、テーマのファイルの `"ornament"` がその名前を指す (同じプラグインの物だけ)。**絵はいつも背景**: `w::DrawBackdrop` がウィンドウを消した直後に描き、`DrawPanelFrame` と `DrawBar` が自分の地を塗った直後に `w::DrawBackdropOn` で**同じ絵をその四角で切り取って**もう一度描く (+ パネルごとの物: 冬の積もる雪)。だから文字・行・ボタンはいつも絵の上。シーンビュー・ゲームビューは 3D の絵がパネルを覆うので飾りは見えない (前の `Context::KeepClear` / `Decorate` は無くした)。季節の絵の形は `plugins/rm_engine/theme_seasons/editor/Ornament.*` の純粋なコード(テストあり)。1 フレームに何度も描くので、ウィンドウの大きさごとに作った形を覚えておく (`Seasons.cpp` の `Cached`)。重なった図形は 1 つの影になるように、図形は全部時計回りに作り、`Painter::FillPath` は winding で塗る。乱数は決まった種から (毎フレーム同じ絵)。使う色 (`theme::Text` など) は `Apply` で入れ替わる変数。全部の画面が描くたびに読むので、切り替えると次の描画から変わる。タイトルバーも `Window::SetCaption` で合わせる。「PC の設定に合わせる」は Windows の `AppsUseLightTheme` (レジストリ) を読み、`WM_SETTINGCHANGE` ("ImmersiveColorSet") で切り替えに付いていく
- **言語**: 画面の文字はコードに日本語で書き、`Tr(L"…")` / `TrF(L"…{}", …)` / `TrU8(…)` を通す (`editor/lang/Lang.h`)。日本語の文がそのまま鍵。英語は `resources/lang/en.json` (核) と `plugins/<作者>/<名前>/lang/en.json` (プラグイン) にあり、ビルドで exe の横 (`Lang/`・`Plugins/…/lang/`) へ写る。英語が無い文は日本語のまま
  - 一度登録して後で描く名前 (パネル・ソフト・テンプレート・メニューの見出し) は `TrKey(L"…")` で印だけ付け、描くところで `Tr` を通す (言語を変えた後も正しい)
  - リフレクションの項目名 (`Label=` / `Tooltip=` / 列挙の `RM_ITEM(Label=)`) はインスペクターが描くときに訳す
  - **`tools/check_lang.ps1` (build.ps1 が走らせる)**: `Tr…(…)` の文と `Label=` / `Tooltip=` と `plugin.json` の `displayName` に英語があるか、`{}` の数が同じかを調べ、無ければビルドを失敗にする
  - ログ (コンソール・`editor.log`) と Undo の履歴の名前は日本語のまま
- **アップデート情報**: `resources/updates.json` (版・日付・項目ごとに日本語と英語)。exe に埋め込む (`IDR_UPDATES`)。目に見える変更をしたらここに足す

## 4-3. 自動保存と整合性の確認

- **自動保存**: エディターが 15 秒ごとに見て、未保存の最初の変更からオプションの間隔がたっていれば `Save()` (Ctrl+S と同じ)。ダイアログ・メニュー・文字の入力中・マウスのボタンを押している間 (ドラッグ中) は待つ。失敗したらエラーを出し、もう 1 間隔待つ
- **整合性の確認**: ビルドの最後に `tools/make_filelist.ps1` が `RM_Engine.files.json` (exe・`Lang/**`・`Plugins/**` の大きさと SHA-256) を書く。「確認する」でファイルの SHA-256 を計り直して比べる (`editor/app/Integrity`: 純粋でテストあり。ハッシュは `platform::Sha256File` = Windows の BCrypt)。入れたプラグインはエンジンの写しと比べ、違えば「入れ直して直す」(`Plugins::Install`)。**入れたプラグインはエンジンごと** (2026-11-11 に決めた): `<エンジン>` = `EngineKey(exe のフォルダ)` (フォルダの名前 + フルパスの FNV-1a 64 の 16 進。大文字小文字と最後の区切りは無視。純粋でテストあり)。版で分けるのではなく場所で分ける (同じ版の Debug と Release、worktree どうしも別にしたいため)。そのエンジンの最初の起動は、前の共有の場所 `%LOCALAPPDATA%\RM_Engine\Plugins` に入っていた顔ぶれ (`FirstStartInstalls`) を入れる。前の場所は読むだけ。`hub.json`・共通の配置・最近のプロジェクトはこれまでどおり全部のエンジンで共有。**入れ直しは前の写しを先に消さない** (`Plugins::CopyIn`): `<名前>.installing` に写す → 前の写しを `<名前>.old` へよける → 新しい写しを置く → よけた写しを消す。置けなければよけた写しを戻す。落ちて `.old` だけが残っていたら `Reload` のときに戻す (`PutBackInterrupted`)。**エンジンを新しくしたとき**: 起動ごとに `Plugins::PlanEngineRefresh` (作業スレッド。4-5) が一覧の SHA-256 を前の印 (`<入れた先>/engine_files.sha256`) と比べ (`integrity::EngineChanged`)、違えば入れたプラグイン (エンジンにもあるもの) のうちファイルが違うものを黙って写し直す (`PluginsToRefresh`: 一覧があれば全部のファイル、無ければ `plugin.json` だけ。純粋でテストあり)。削除したものは入れない。写すのは UI のスレッドで、エディターが開いていないとき (`App::ApplyEngineRefreshIfReady`: Hub が出ていればすぐ、エディターなら Hub に戻ったとき。エディターはプラグインの登録を指しているので、その間は読み直さない)。全部写せたときだけ印を書く (失敗したら次の起動でもう一度)。★ 改ざんを防ぐものではない (一覧に署名は無い)。壊れた・欠けた・古いを見つけるためのもの
- **自動アップデート**: ★ 設定だけ。配布の仕組み (取ってくる先) を決めてから作る

## 4-5. 遅いディスクの処理は作業スレッドで (`editor/app/Worker`)

- **描いている間にディスクを待たない** (届かないネットワークのパスは 1 つで数秒かかる)。`Worker::Run(work)` が `work` を自分のスレッド (`std::jthread`) で動かし、結果は `post(fn)` で UI のスレッドへ渡す。`fn` は App のメッセージループ (`RunPostedToUi`) がフレームの間に動かす (描画の途中ではない)
- 新しい `Run`・`Stop`・Worker が消えたときは、前の work に止まるよう頼み (`stop_token`)、その後に post されたものは捨てる (古い結果が新しい一覧や消えた画面に当たらない)。work は待たない (detach): 画面を閉じるのが遅いドライブで止まらないように。そのため work が使うのは渡されたコピーだけ (画面とアプリには `post` の中でだけ触る。翻訳・ログも UI のスレッドで)
- 使っている所: Hub の最近のプロジェクト (`Refresh`: 行はすぐ出して「読み込み中…」、1 行ずつ埋まる。最後に日付で並べ直す。テーマや言語の変更では読み直さない: 行の文字は描くときに作る)・プラグインを外すときの「N 個が使っています」(読んだ行から数える。読み込み中の行は数えない)・整合性の確認 (進み具合と「やめる」)・起動のときのプラグインの確かめ (上の「エンジンを新しくしたとき」)
- テスト: `tests/TestWorker.cpp` (本物のスレッドで、順番・止めた / 置き換えた / 消えた Worker の結果は捨てる)

## 4-4. GPU が失われたとき (`platform/Gfx` + `editor/app`)

```
描く前 (ScreenWindow::EnsureDevice)     Gfx::Lost()? ──はい──▶ App::RecoverGraphics ──▶ Gfx::Recreate (D3D / DXGI / D2D のデバイスを作り直し、Generation +1)
                                         │                       └ 失敗: 1 秒後にもう一度 (3 回で Windows のダイアログ「保存しますか?」)
                                         ▼
                                   自分のスワップチェーンの Generation が違う? ──▶ 作り直す + Painter のブラシ・効果を捨てる + OnDeviceChanged (Hub のロゴ)
描いた後                           EndDraw が D2DERR_RECREATE_TARGET / Present が失敗して Lost ──▶ Gfx::MarkLost → 次のフレームで上へ
GPU の物を持つ所                   覚えた Generation と違えば自分の物を全部捨てる (要るときに作り直す)
```

- **1 本の口**: `Gfx::Generation()` (デバイスを作った回数)。GPU に物を持つ所は、それを作った回を覚え、違っていたら捨てる。持つ所: ウィンドウのスワップチェーン (`SwapTarget::Generation`)・`ui::Painter` (ブラシ・グラデーション・色を塗る効果: `DeviceChanged`)・Hub のロゴ・3D のシーンビュー (2 つの `Renderer` = シェーダー・バッファ・影の地図・絵とそのビットマップ、モデル、テクスチャのキャッシュ `TextureCache::Clear`。モデルのファイルは読み直す)・2D のシーンビュー (`Renderer2D` のブラシと効果・画像のビットマップ)・サムネイル (ビットマップ。絵そのものはメモリーに持っているので作り直すだけ)・3D のサムネイルの `Renderer`
- Direct2D / DirectWrite / WIC の**ファクトリーは GPU に無いので作り直さない** (形 (ジオメトリ)・文字の書式はそのまま使える)
- 失われたことを知る道: `ID3D11Device::GetDeviceRemovedReason`・`EndDraw` の `D2DERR_RECREATE_TARGET`・`Present` の `DXGI_ERROR_DEVICE_REMOVED` / `RESET`。試すための口: Ctrl+Alt+Shift+F12 (`Gfx::MarkLost`)
- ウィンドウ 1 つにスワップチェーンは 1 つしか作れないので、古いものを先に捨てる。Direct3D は物をあとでまとめて消すので、捨てたら古いデバイスのコンテキストを `Flush` する (`SwapTarget::Reset`)
- 作り直しに失敗している間は描かない (前の絵のまま)。3 回続けて失敗したら、GPU を使わない Windows のダイアログ (`MessageBoxW`) で伝え、保存を勧める (`ScreenWindow::SaveWork`: エディターは `Save`、Hub は保存する物なし)
- ★ 画面は未確認 (2026-11-11。ビルドとテストだけ。試し方は `docs/HOW_TO_TRY.md` の 8-3 章)

## 5. パネルのドッキング (`editor/dock`)

```
Layout                         (DockLayout.h — 純粋。RMTests で検査)
  main       エディターのウィンドウの木 (空でも葉 1 枚は残る)
  floating[] 外へ出したウィンドウ 1 つにつき木 1 本 + 画面上の位置 (物理ピクセル)
Node = 分割 (横 / 縦・比率) | 葉 (パネル ID のタブの束)
```

- 1 つのパネルは配置全体で**多くて 1 回**。配置に無いパネルは「閉じている」
- 操作は `Close` / `Open` / `Dock(パネル, 目標, 中央|上下左右, タブ位置)` / `Float` / `DockFloating` だけ。**取り出す → 差し込む → 空の葉をたたむ**の順で、自分のいる組の端へ落としても壊れない
- 大きさは比率で持つ (ウィンドウを大きくすると全部が伸びる)。仕切りは両側を 80 DIP より小さくしない
- 読み込んだら `Sanitize`: 知らないパネル (消したプラグインのもの)・重複・壊れた比率を直す。新しい版の `Layout.json` は使うが**上書きしない**
- **タブの列が入りきらないとき** (`FitTabStrip` などの純粋な計算。テストあり): 列の右端に ‹ › ▾。ずらす量 (scroll) は葉ごとに `DockSpace` が覚える (保存しない)。表に出たタブ (クリック・▾・メニューで開いた・落とした) は、見える所まで列がずれる。ホイールでも流れる。見える所の外のタブは切り抜いて描かず、押せない。ドラッグ中は列の端でマウスを動かすと流れる (止まっているときは流さない: 自分を描き直し続けると別のウィンドウが描けなくなるため。下の「ドラッグ中」の行)。落とす位置は隠れたタブも数えた列の中の位置 (`TabInsertIndex`)
- **名前を付けた配置** (`NamedLayouts.*`。純粋でテストあり): ソフトごとの一覧を `Layout.json` のそのソフトの `"named"` に置く (`[{ "name", "layout" }]`)。項目は `RM_STRUCT NamedLayoutInfo` (リフレクションで保存・知らないキーは書き戻す)、`layout` は木の保存形式そのまま。名前の無い要素・同じ名前の 2 つ目も、見せずにそのまま書き戻す。使うときに `FromJson` + `Sanitize`。一覧が変わったらすぐ `Layout.json` を書く。**共通の配置** (別のプロジェクトへ持っていく形。2026-11-11 に決めた): 書き出し / 読み込みのファイルではなく、エンジン全体の 2 つ目の一覧を `%APPDATA%\RM_Engine\Layouts.json` (`paths::SharedLayoutsFile`。`{ kind: "rm_engine.shared_layouts", formatVersion: 1, softwares: [{ author, plugin, software, named: [...] }] }`、ソフトの見分け方は `Layout.json` と同じ) に置く。エディターを開くときに読み、変わったらすぐ書く (入っていないソフトの分と知らないキーは書き戻す。読めない・新しい版のファイルは上書きしない)。一覧の間は `NamedLayouts::Move` で移す (知らないキーも一緒。向こうに同じ名前があると移さない)。プロジェクトのデータではないので Undo も未保存の印も無い。画面は「ウィンドウ」メニュー (名前で並べて切り替え・「今の配置に名前を付けて保存…」・「配置の管理…」・「最初の配置に戻す」) と `editor/shell/EditorLayouts.cpp` のダイアログ

`DockSpace` が全部のウィンドウ (エディター = site 0、外のウィンドウ = その id) を 1 つで受け持つ:

| 操作 | 動き |
|---|---|
| タブを押す | 表に出す。6 DIP 動いたらドラッグ開始 |
| ドラッグ中 | カーソルの下のウィンドウ (`TopLevelWindowAt`) の、下にあるパネルに十字の目印 + ウィンドウの四辺に目印。目印の上 = 分割 / タブの列の上 = タブとして入れる。行き先は赤く塗って見せる |
| 目印の外で離す | 別ウィンドウになる (その場所に)。ひとりだけの別ウィンドウなら、そのウィンドウが動くだけ |
| 別ウィンドウのタイトルバーで動かす | `WM_MOVING` でエディター側に目印を出し、`WM_EXITSIZEMOVE` で目印の上なら中身ごと戻す |
| Esc | ドラッグをやめる |
| 別ウィンドウの ✕ | 中のパネルを閉じる (「ウィンドウ」メニューで開き直せる) |

- 木を変えるのは**フレームの最後** (描いている途中の節を消さない)。ウィンドウを作る / 壊すのは**メッセージループに戻ってから** (`RequestSyncFloating` → `Defer`)
- 新しく出すウィンドウは、そのモニターの作業領域 (タスクバーを除く) に収める。保存した位置のモニターが無ければ中央に出す

## 6. プラグインとソフト (`editor/plugin`)

```
起動 ─ Plugins::Load (exe の横の Plugins/<作者>/<名前>/plugin.json)
        ├ BuiltinPlugins() の 1 つずつ: コードの ID と plugin.json の ID を照らし合わせる
        ├ ResolvePlugins: 前提がそろっているか・輪になっていないか → 使える順 (前提が先)
        └ 使えるものだけ RegisterEditor(PluginRegistry&) → AddSoftware({id, 名前, create})
プロジェクトを開く ─ .rmpf の plugins に使えないものがあれば開かない (理由を Hub に出す)
エディター ─ 登録されたソフト 1 つにつき Workspace 1 つ
        { ソフト (create で作る) / DockSpace (核のパネル + ソフトのパネル) / UndoHistory }
```

- 核のパネル (階層 / インスペクター / コンソール / アセット) は**ソフトごとに 1 つずつ**。ソフトは自分のパネルと最初の配置を出す。パネルの ID はソフトの中で重ならないこと、`core.` で始めないこと (破ると登録しないでログに出す)
- **Undo はソフトごと**: Ctrl+Z / 編集メニューは表に出ているソフトの履歴だけを戻す。どの履歴に積んでも**未保存の印は 1 つ**
- ソフトのタブで切り替える。切り替えるとき、前のソフトの別ウィンドウは閉じて、次のソフトの別ウィンドウを開く (配置はそれぞれ覚えている)
- ソフトが 1 つも無いとき (プラグインが使えないときも) は、核のパネル + 「スタート」だけの Workspace 1 つで開く
- プラグインの状態は Hub の「プラグイン」とエディターの「プラグイン」メニューで見られる
- `.rmpf` の `plugins` (使っているプラグインの記録) は**自動で書く** (ソフトがデータを保存したとき。7 章「ソフトのデータ」)
- **差し出し (contribution)**: プラグインが別のプラグインへ物を渡す口。核はどちらも中身も知らない。読む側が「口の名前」と「物の型」を決め (`game_production::kComponentPoint` + `ComponentInfo`)、渡す側が `registry.Contribute(口, 物)` (物は static)、読む側のソフトが `host.Registry().Contributions<型>(口)` で受け取る。型が違う物は読まない (`typeid` で照らす)。使えるプラグインだけが登録するので、無いプラグインの物は出てこない

### つなぎプラグイン (RME_PLATFORM 4-f、案 C)

```
ゲーム制作 (needsConnector)          3D 空間 (Transform と計算と描画。エディター側はギズモとサムネイル)
        ▲                                   ▲
        ├──── ゲーム制作 × 3D (connectorFor = ゲーム制作 / requires = 両方) ────┘
        │       Transform を「部品」として差し出す (3D のゲームの新しいエンティティに付く)
        │
        └──── ゲーム制作 × 2D (connectorFor = ゲーム制作 / requires = ゲーム制作・2D 空間) ──▶ 2D 空間
                Transform 2D・スプライトを差し出す (2D のゲームの新しいエンティティに Transform 2D)
```

- **ゲーム制作は空間を知らない** (3D 空間のヘッダーを読まない。`check_layers.ps1` が見張る)。空間を知る部分は、両方を前提にした**つなぎ**に入れる。矢印はつなぎ → 両方の 1 方向だけなので、前提が輪にならない
- `plugin.json`: つなぎが要る側に `"needsConnector": true`、つなぎに `"connectorFor": {作者, 名前}` (相手は `requires` にも書く。書かないと読み込まない)
- **つなぎが 1 つも使えないと、つなぎが要るプラグインは使えない** (`NoConnector`。Hub では「⚠ 前提が無い」と「前提をインストール」)。そのプラグインを前提にしているものも一緒に止まる
- **つなぎは自分で選ばない**: インストールの計画 (`InstallPlan`) が、要るものがそろったつなぎを一緒に入れる。つなぎが要るプラグインだけを入れようとすると、このエンジンが持っている最初のつなぎとその前提も入る (ゲーム制作 → 3D 空間 + ゲーム制作 × 3D)
- 削除の警告: 3D 空間を消すと、つなぎ → (最後のつなぎなら) ゲーム制作 → ゲーム制作を前提にするもの、の順に「使えなくなる」に出る。別のつなぎ (2D) が残っていればゲーム制作は出ない
- **見せ方でもつなぎは選ばない** (2026-11-11): Hub の「プラグイン」は、つなぎ (`plugin.json` に `connectorFor` があるもの。`Plugins::Entry::connector`) を上の行に出さず、一番下の「つなぎのプラグイン」の見出しの下に小さな行で出す: 名前・つなぐもの (`requires`)・状態。インストールと削除のボタンは無い (つなぐものを入れる・消すと一緒に起きる)。壊れているときだけ「再インストール」。エディターの「プラグイン」メニューでも、入っていないつなぎは押せない行 (「つなぐ両方が入ると自動で入ります」)。一覧は流れる (`w::BeginScroll`。プラグインが増えて窓に入らなくなった)
- 登録するものの無いプラグイン (2D 空間・テーマのファイルだけのもの) も `BuiltinPlugins.cpp` に `RegisterEditor` 無しで載せる (入れる・前提にする・状態を出すのに要る)。3D 空間は前は無しだったが、3D モデルのサムネイルを差し出すようになった (2026-11-11)
- 設計書では「3D 空間」と「3D 描画」は別のプラグインだったが、**1 つにまとめた** (2026-11-05 ユーザー決定: 「合わせず使うことはない」)。だから、つなぎの前提は ゲーム制作 + 3D 空間
- 入れたプラグインの `plugin.json` はインストールしたときの写し。エンジンのものと違う (古い) 写しは「入っていない」扱いになり、次のインストールの計画 (開くときの「インストールして開く」・「前提をインストール」) で写し直される (`ReadyPlugins`。テストあり)

### インストール・削除 (Hub のプラグイン管理)

```
このエンジンが持っているもの   <exe>/Plugins/<作者>/<名前>/                        (ビルドで plugins/ から写す)
入れたもの                     %LOCALAPPDATA%\RM_Engine\Engines\<エンジン>\Plugins\<作者>\<名前>\   (エンジンごと)
```

- **インストール = フォルダを写す / 削除 = 消す / 再インストール = もう一度写す** (壊れたファイルを直す。「入っていない」状態を通らない)。写すときは横に `.installing` で写してから入れ替える (途中で失敗しても前のものが残る)
- コードは exe に入ったまま。入っていない・前提がそろっていないプラグインは**初期化を呼ばない**だけ (RME_PLATFORM 1-b-2 懸念 5)
- **最初の起動** (入れたものの置き場が無いとき) は、エンジンが持っているものを全部入れる
- **前提は一緒に入る**。入る前に一覧を出す (`InstallPlan`: 前提の木を下まで見て、入っていない・壊れているものを前提が先の順に。入っているものの先に足りないものがあっても見つける)
- **削除は前提になっていても消せる**。消す前に「以下のプラグインの前提として使われています」と、直接・間接 (「○○ を通して」) の一覧と、最近のプロジェクトのうち使っている数を出す。**Enter / Esc は「いいえ」**
- 前提が欠けたプラグインは使えないまま起動し、Hub の一覧に「⚠ 前提が無い」と「前提をインストール」を出し続ける
- プラグインを変えたら Hub がその場で読み直す (エディターが開いていないので、登録を作り直してよい)

### プロジェクトを開く前の確認

| 場面 | 出すもの |
|---|---|
| プロジェクトが使っているプラグインが使えない | **すぐ**「起動できません」+ 一覧 + [やめる] [インストールして開く]。このエンジンに無いプラグインなら「エンジンを新しい版にしてください」で [OK] だけ |
| 使っていないプラグインが使えない (入っているのに前提が無い・壊れている) | **開く前に 1 回だけ**「お知らせ」+ 一覧 + [インストール] [このまま開く] + 「**この状態が変わるまで表示しない**」(使えないプラグインの顔ぶれが変わったらまた出す。`hub.json` の `hiddenPluginNotice`) |
| エディターの「プラグイン」メニューでインストール | 「保存してから、このプロジェクトを開き直します。元に戻す (Undo) の履歴は消えます」→ 保存 (失敗したら何もしない) → 入れる → エディターを閉じて読み直し → 同じプロジェクトを開く |

- 確認はすべて Hub のダイアログで 1 つずつ (`--project` で起動したときも、まず Hub を出して訊く)
- RME_PLATFORM の「Play 中なら先に止める」: エディターを閉じて開き直すので、Play のコピーはそのとき捨てられる (保存されるのは Play の前のシーン)。★「見ていた場所に戻す」は今は無い (配置とカメラは `Layout.json` で戻る)

### テンプレートの木 (Hub の新規作成。RME_PLATFORM 1-b-2 / 5-a、2026-11-11)

```
plugins/rm_engine/game_production/templates/game/template.json     path ["game"]        ゲーム (3D と 2D の両方・空のシーン)
plugins/rm_engine/game_x_3d/templates/game_3d/template.json        path ["game", "3d"]  3D のゲーム (カメラ・光・床・箱)
plugins/rm_engine/game_x_2d/templates/game_2d/template.json        path ["game", "2d"]  2D のゲーム (カメラ・地面・プレイヤー)

- **テンプレートはコードではなくデータ** (`editor/project/Templates.h` に形)。`kind` / `format` / `id` / `path` (木の場所) / `name` / `description` / `order` / `plugins` (中身が使うもの。持ち主のプラグインは自動で足す) / `open` (最初に開くソフト) / `project` (新しい `.rmpf` に入れるキー: `softwareData` にゲームの設定とシーンの一覧) / 横の `Assets/` (新しいプロジェクトに写す: 最初のシーンのファイルと `.meta`) / `userSettings` (`Layout.json` の `softwares` に入れるもの: 最初の配置・ビュー)。知らないキーは読み飛ばす (新しい版のもの)
- **核がエンジンの持つプラグインのフォルダから読む** (`<exe>/Plugins/<作者>/<名前>/templates/*/template.json`。`Plugins::LoadTemplates`)。入っていないプラグインのテンプレートも木に出る (入れますかと訊くため。設計 09-29 懸念 2)。核は中身の意味を知らない: `project` と `userSettings` を写すだけ。`registry.Contribute` の口にしなかったのは、口は**使えるプラグインだけ**が登録するので、入っていないもののテンプレートが見えなくなるため
- 木は `path` から作る (`BuildTemplateTree`)。枝は見せ方だけ: テンプレートを持たない枝はその ID を出す (今は無い)。同じ場所に 2 つ・同じプラグインに同じ `id` が 2 つなら、先のものを使って後のものはログに出す。並びは `order` → 名前。ID の決まりは a-z 0-9 _ (書き方の揺れで枝が 2 本に割れないように。「3d」のように数字から始めてよい)
- **枝を選ぶと、その下のテンプレートの分も入る** (`TemplatePlugins`。設計 09-29 16:47 の決まりを途中の枝にも)。「ゲーム」なら 3D と 2D の両方。作るときの中身は、その枝自身のテンプレート (「ゲーム」は空のシーン)
- 足りないプラグインは**開くときの確認と同じ流れ**: `TemplateInstallPlan` = 1 つずつの `InstallPlan` (前提・つなぎ) を合わせたもの。つなぎが要るもの (ゲーム制作) は最後に計画するので、2D のゲームに 3D のつなぎ (エンジンの最初のつなぎ) が付いてこない。足りなければ作成の前に「必須プラグインがインストールされていません」+ 一覧 + [やめる] [インストールして作成]。このエンジンに無いものはダイアログの中に「エンジンを新しい版にしてください」。確認は描画の後に出す (作成を押した Enter で答えてしまわない)
- 作ったときの `.rmpf`: `template` = `{author, plugin, id}` (白紙は `{id: "blank"}`。プラグインの ID を 1 本の文字につながない)、`project` のキー (核のキー `kind` / `formatVersion` / `name` / `engineVersion` / `template` / `plugins` は上書きしない)、`softwareData` に入れたソフトのプラグインを `plugins` に記録 (保存のときの記録と同じ決まり。テンプレートに書いた `plugins` は**記録しない**: 「ゲーム」で作っても 3D と 2D に縛られない)。`UserSettings/Layout.json` は `.rmpf` より先に書く (`kLayoutKind` などは `Project.h` に 1 か所)
- **ソフトで絞る** (Hub の「プラグイン」。設計 1-b-2 懸念 A): ソフト = 木の一番上の枝。そのソフトのプラグイン = その下のテンプレートを入れると入るもの全部 (前提・つなぎ込み) + `plugin.json` の `"software": ["game"]` (どのテンプレートも使わないもの用)。どこにも入らないものは「共通」(テーマパック)。`GroupPluginsBySoftware`。人が一覧を書かない
- ★ 決めていないこと: 設計 09-29 懸念 4 (テンプレートの中身と `plugins` の書き漏れを CI で照らす) は、リポジトリのテンプレートを読んで最初のシーンが警告なしで読めることをテストで見るところまで (`Template_ThePlugins`)。部品の型名から使うプラグインを数える検査はまだ

## 7. リフレクション (`core/reflect` + `tools/rmgen`)

```
GameSettings.h                         rmgen (ビルドの最初に毎回)                 build/generated/<プロジェクト>/
  RM_STRUCT(Label="ゲームの設定")   ──▶  ヘッダーを読む (トークン単位)    ──▶   <ヘッダー>.reflect.cpp (型の表 + 検査)
  struct GameSettings {                  注釈・属性・型を調べる                    rm_all_types.cpp (全部の型の一覧)
    RM_PROPERTY(Edit, Min=1, Max=240)    間違いは file(行,列): error RM#### で止める
    int targetFps = 60;
  };
```

- **作るのは型の表 (`TypeDesc`: フィールドの名前・種類・属性・取り出し方) と検査だけ。** 保存・読み込み・比較・差分・インスペクター・Undo は、表を辿る**共通の関数 1 本ずつ** (設計書 R1 §4 は「型ごとに 8 つの関数を作る」形だったが、表を辿る 1 本にすると同じものが型の数だけ増えない: 憲法 2・3)
- **ユーザーのヘッダーは何も include しない** (生成物の方がヘッダーを include する。「必ず最後」の決まりが無い)。**自己登録はしない** (`rm_all_types.cpp` の一覧から引く。静的ライブラリで登録が黙って消える罠を踏まない)。型は `TypeOf<T>()` で引く (中身は `typeid` で一覧を探す)
- **作るファイルの名前** (`OutputName`): include のパスの '/' を '_' にした読める名前 + **パス全体のハッシュ** (FNV-1a 32 ビット、8 桁) + `.reflect.cpp` (`rm_engine/game_x_3d/A.h` → `rm_engine_game_x_3d_A.<8 桁>.reflect.cpp`)。前は '/' を '_' にするだけで、`rm_engine/game_x_3d/A.h` と `rm_engine/game_x/3d/A.h` が同じファイルになった。それでも `Validate` が全部の組を大文字小文字を区別せずに比べ (Windows のファイル名と同じ)、同じ include のパス (`src/core/…` と作者名 `core` のプラグインの `core/…`、大文字小文字だけ違う) か同じ出力になる組は **RM0012** で止める (2026-11-12。テストは `tests/TestRmgen.cpp`)
- **注釈の付け忘れは 2 段で止める**: ① rmgen が `RM_PROPERTY` も `RM_TRANSIENT` も無いフィールドを `RM0001` で止める ② 生成物の `static_assert` が「フィールドの数」(集成体のメンバーを数える)・名前・型を固定する → ヘッダーを変えて rmgen を通さないと**コンパイルが止まる**
- **数の入り方は 1 本** (`SanitizeNumber`: 有限でなければ今の値 → Min / Max → int は丸め)。**ファイルの読み込みもインスペクターの入力も同じ関数を通る** (前のエンジンの不具合 #12 の再発防止。テスト T3 が 2 つの道を並べて比べる)
- **列挙は名前で保存** (並べ替え・途中への追加で古いファイルの意味が変わらない)
- **知らないものは捨てない**: 知らないキー・知らない列挙の名前は `Unknowns` に入れて、保存のときにそのまま書き戻す。知らない列挙は既定値で動き、コンソールに警告、インスペクターには「名前 (不明)」と出す。ユーザーが選び直したときだけ上書きされる (Undo で元の名前に戻る)
- float はファイルに「同じ float に戻る一番短い 10 進」で書く (`0.02`。`0.019999999552965164` にしない)
- 使える型: `bool` `int` `float` `std::string` `Vec2` `Vec3` `Color` / **`AssetRef` `EntityRef`** (参照: `base/Ref.h`。7-3 章) / `RM_ENUM` の列挙 / `RM_STRUCT` の入れ子 / それらの `std::vector`
- 参照の属性 `AssetKind="model"` / `"image,model"`: その種類のファイルだけを入れられる。rmgen は形 (小文字の名前をコンマで区切る・`AssetRef` だけ) を `RM0003` で止め、名前が本当にある種類かは RMTests (`Asset_KindsOfReflectedFields`) が全部の型を見て確かめる (種類の一覧は `core/asset` の 1 か所。rmgen に写さない: 憲法 2)

### インスペクター (`editor/inspector`)

- Undo のまとめ (`ICommand::MergeWith` / `CanMergeWith`): `SetFieldCommand` は鍵・型・欄に加えて**同じ物** (`resolve` の先) のときだけまとまる。`CommandGroup` は、全部の子がまとめられると分かってから (`CanMergeWith`) まとめる (途中まで書き換えて失敗する、ということがない)。テストあり (`Reflect_SetFieldCommand_OnlyTheSameObjectJoins`)
- 型ごとのコードは無い。表から欄を作る: 真偽 = チェック / 数 = 数の欄 (クリックで全部選ぶ・ドラッグで選ぶ。**打つたびに Edit を返す** (数になっていない間は返さない)。1 つの欄に入っている間の Edit は同じ `merge` の鍵を持ち、`SetFieldCommand` が `UndoHistory` の中で 1 つにまとまる (`ICommand::MergeWith`。何も戻していないときだけ。結局変わらなかったら消える)。Esc は入る前の値を返す) / 文字 / ベクトル・色 (狭いときは次の行へ) / 列挙 = 一覧 (パネルに切られないよう、フレームの最後に描く) / 入れ子 = 字下げ / 配列 = 「N 個」と ＋、要素ごとに つまみ (上下にドラッグで並べ替え)・番号・値・× (どの変更も**配列全体を 1 つの `SetFieldCommand`** で。要素の中の欄の Edit は `Wrap` で配列全体の Edit に直す (入れ子の配列も重ねて直す))
- 1 つの値 (数・文字・ベクトル・チェック・一覧) を描くのは `DrawValue` 1 本: 欄でも配列の要素でも同じ (憲法 3)
- **数のドラッグ**: 数の名前 (ベクトルは X / Y / Z の文字、配列は番号) を左右にドラッグ。マウスを固定 (`LockMouse`) して動いた量だけ数える。速さはドラッグを始めたときに決める: `Step` があれば 1 ピクセルでその量、無ければ max(1, √|値|) × 0.03 (Unity と同じ考え)。Shift ×4・Alt ×1/4。1 回のドラッグが同じ `merge` の鍵で Undo 1 回分
- **オブジェクトを直接書き換えない。** 確定した変更は `SetFieldCommand` になってソフトの履歴に積まれる = Undo できる・未保存になる (憲法 7)
- ソフトは `SoftwareHost::Inspect` で見せたいものを渡すだけ (核が見せ方、ソフトが中身: RME_PLATFORM 4-c)

## 7-3. アセットと参照 (`core/asset` + `editor/assets`)

```
Assets/                                   core/asset (ゲームに入る)
  Models/            Models.meta            AssetIndex   純粋: 種類・.meta の文・Reconcile・木の順 (tests/TestAsset.cpp)
    robot.glb        robot.glb.meta         AssetFiles   読み書き: ScanFolder → Reconcile → ApplyPlan (= Update)・ReadIndex (ゲームが ID → ファイル)
  sky.png            sky.png.meta
                                          editor/assets
{"guid": "32 文字の 16 進"}                 AssetLibrary プロジェクトに 1 つ: ID の表・変化の見張り・名前の変更 / 移動 / 新しいフォルダ / ごみ箱
 (ほかのキーは書き戻す)                     AssetPanel   ソフトごとに 1 つ: 核の木 (tree::Source) で描くアセットのパネル
```

- **ID は横の `.meta` に** (Unity と同じ形)。ファイルを動かす・名前を変えるときは `.meta` も一緒に動かすので、参照 (`AssetRef` = ID) は外れない。フォルダにも `.meta` がある。`.meta` は自己記述型の JSON で、知らないキーは ID を書き直すときも残す (憲法 6)
- **エディターの外の変化に付いていく** (`asset::Reconcile`。純粋でテストあり): 見るたびに「見つけた物 (と、その `.meta` の ID)」「置き去りの `.meta` (ファイルが無い)」「前に見たときの表」を比べる
  0. `.meta` があるのに読めない物は、書き換えも新しい ID もしない (下の「`.meta` を壊さない」)
  1. 自分の `.meta` がある物はその ID。同じ ID が 2 つ (`.meta` ごとコピー) なら元の物が持ち (下の「コピーと元を見分ける」)、ほかは新しい ID
  2. `.meta` が無い物は、消えた物の ID をもらう — 同じ場所 (`.meta` だけ消された) / 同じ名前で 1 つだけ (動かした) / 同じフォルダで同じ拡張子、しかも新しい物もそこに 1 つだけ (名前を変えた)。消えた物 = 置き去りの `.meta` か、`.meta` も無ければ前の表の ID。置き去りの `.meta` は新しい場所へ動かす
  3. どれでもなければ新しい ID (乱数 128 ビット)。使われなかった置き去りの `.meta` は消さない (ファイルを戻すと ID も戻る)
- **いつ見るか**: 開いたとき・パネルの操作の後・Windows の変更通知 (`platform::FolderWatch` = `FindFirstChangeNotification`。名前の追加・削除・変更) が来た後の最初の描画。描くたびに待たずに聞くだけ (`WaitForSingleObject(…, 0)`)。見直しで自分が `.meta` を書いたときは、その分の通知をその場で捨てる (自分の書き込みで 2 回目の見直しをしない。★ 同じ瞬間に外で起きた変化も一緒に捨てることがあり、それは次の変化のときに拾う)
- **大きなフォルダでも重くしない** (2026-11-12): ① 見直しは `.meta` を読み直さない — 一覧 (`recursive_directory_iterator`) が持っている大きさと更新時刻が前と同じ `.meta` は、前に読んだ中身 (`asset::MetaCache`。消えた物は捨てる) を使う。`.meta` があるかどうかも一覧から分かるので、ファイルごとに Windows に聞かない ② 照合 (`Reconcile`) は道・名前・フォルダ + 拡張子・ID ごとの索引で引き、拡張子や小文字の名前は 1 回だけ作る (前は段 b・c が全部の組を数えてファイル数の 2 乗だった。テスト: 2 万ファイルで数秒以内) ③ 見直しは作業スレッドで (2026-11-12、下)
- **見直しを作業スレッドで** (`AssetLibrary::Refresh` → `editor/app/Worker`): フォルダの一覧・`.meta` の読み込み・照合 (`asset::Look` = `ScanFolder` + `Reconcile`。**何も書かない**) は Worker のスレッドで。決まったプラン (`asset::Plan`) を UI のスレッドへ渡し、そこで `.meta` を書いて (`ApplyPlan`) ID の表を 1 回で差し替える (`ApplyLook`)。作業スレッドが触るのは渡されたコピー (フォルダ・前の ID の表) と、`.meta` の読んだ中身の覚え (`MetaCache`。ロックで 1 つの見直しだけが使う) だけで、ID の表・テクスチャ・ログの画面の受け手には触らない (ログは Queued の受け手)
  - **古い結果を当てない**: 見直しを頼むたび・エディターの操作 (名前の変更・移動・新しいフォルダ・削除・保存した Prefab に ID を付ける) のたびに番号を進め (`asset::LookNumber`)、番号が最新でない結果は捨てる。新しく頼むと Worker が前の見直しに止まるよう頼み (`ScanFolder` が 256 件ごとに `stop_token` を見る)、その結果は Worker が捨てる。結果を当てる前にフォルダの通知が来ていれば、それも捨てて頼み直す (見直しの途中の変化を取りこぼさない)
  - **操作はすぐ見える**: エディターの操作は ID の表をその場で直し (`MovedInIndex` / `RemovedFromIndex`、新しいフォルダと書いたばかりのファイルは `AdoptFile` = `asset::GiveId` でその `.meta` だけ書く)、それから見直しを頼む。だから操作の前に始まった見直しの結果が操作を巻き戻すことはない
  - 見直しの間、パネル・インスペクター・シーンビューは前の結果のまま。パネルの下の行に「調べています…」(`AssetLibrary::Looking`)。結果を当てたら `onChanged` で全部のウィンドウを描き直す
  - **最初の 1 回だけは待つ** (`LookNow`、プロジェクトを開くとき): ソフトはデータを読むとすぐ Prefab・モデルを ID で探す (`RefreshPrefabsOnOpen`)。ID の表が空のままだと全部「見つからない」になるので、ソフトを作る前に 1 回だけその場で見る。前は `Open` の中 (ソフトがデータを読んだ後) で見ていたので、開いた直後の Prefab の読み直しが ID を引けていなかった
- **ファイルの操作はプロジェクトのデータではない**: ディスクにすぐ行い、Undo にも未保存にもならない (Unity と同じ)。削除はごみ箱へ、それが戻り道。**完全には消さない**: `IFileOperation` (`FOFX_RECYCLEONDELETE`) の進み具合の受け手 (`IFileOperationProgressSink::PreDeleteItem`) が、ごみ箱へ行かない物 (`TSF_DELETE_RECYCLE_IF_POSSIBLE` が付かない: ごみ箱の無いドライブ・ごみ箱より大きい) をその場で取り消し、「消していません」と出す。前の `SHFileOperation` + `FOF_NOCONFIRMATION` はその場合に確かめずに完全に消していた。`FOF_WANTNUKEWARNING` は「完全に消しますか」と訊くだけ (はいを押せば消える)、`SHQueryRecycleBin` はドライブにごみ箱があるかは分かっても 1 つの物の大きさで溢れるかは分からないので、シェル自身が物ごとに決める受け手を選んだ。1 つのアセット (ファイルと `.meta`) ずつ渡すので、入れられない物だけが残る
- **`.meta` を壊さない**: `.meta` が「無い」と「あるが読めない」を分ける (`asset::ReadMeta` / `MetaState`)。開けない (ほかのアプリ・同期中) か、JSON として読めず ID も見つからないものは Unreadable: **決して書き換えず、新しい ID も付けない** — 前に見たときの ID があればそれを使い、無ければ一覧から外してコンソールに理由 (同じ内容は 1 回だけ)。次に見たとき読めれば元どおり。JSON として壊れていても `"guid": "…"` が 1 つだけはっきり書いてあれば Damaged: その ID を使い、やはり書き換えない。`.meta` を書く所 (`ApplyPlan` / 取り込みの設定 / 名前の記録) はどこも、そこに読めない `.meta` があれば書かない (`SafeToWrite`)。書きかけの `X.meta.tmp` はアセットに数えない
- **コピーと元を見分ける**: `.meta` を書くときに、そのファイルの名前を `"name"` に書く (新しい ID・動かした後・エディターでの名前の変更と移動)。同じ ID の `.meta` が 2 つあれば、元は ① 前に見たときその ID があった場所 ② `.meta` の `"name"` と名前が合う方 (コピー「X - コピー.png」は元の名前を持ったまま) ③ `.meta` の作られた時刻 (Windows の作成日時: コピーで新しくなり、移動では変わらない) が一番早い方 ④ どれでも決まらなければ並びの最初 (コンソールに「どれが元か分からない」)。前は並びの最初だったので、閉じている間のコピー (' ' が '.' より前に並ぶ) が元の ID を取っていた
- 名前の変更・移動: 行き先にもう `.meta` があれば動かさない (黙って上書きしない・その ID を取らない)。`.meta` が付いてこられなければファイルを戻し、戻すのにも失敗したら、ファイルと `.meta` の場所をエラーで出す
- エディターを閉じるとき: `AssetLibrary` と `Thumbnails` は `EditorScreen` の中でワークスペースより**前に**宣言する (後に壊れる)。各ソフトのアセットのパネル・履歴の中の `ImportCommand`・`Workspace::AssetFile` がそれを指したまま壊されるため
- **アセットのパネル** (`core_panel::kAssets`) は**核の木の部品をそのまま使う** (憲法 3): 選ぶ・検索・F2 / ダブルクリックで名前の変更・ドラッグでフォルダへ移動・右クリックのメニュー。項目の ID は GUID の FNV-1a (`asset::NumberOf`)。フォルダが先、名前の順 (大文字小文字を区別しない)。印は種類ごと (`tree::Icon` に Folder / Image / Model / Audio / Font / Text / File を足し、`w::DrawIcon` が線で描く)
- **参照の型** (`base/Ref.h`): `AssetRef { guid }` は文字で、`EntityRef { id }` は数で保存。知らない文字 (この版で ID でない物) もそのまま持って書き戻す。インスペクター (`DrawRef`) は名前と印・マウスを乗せると場所・クリックで一覧 (`w::PickerPopup`: 検索の欄 + 流れる行。先頭が「(なし)」)・× で外す・ドロップで入れる。変更はほかの欄と同じ `SetFieldCommand` (憲法 7)。何があるかは `inspector::Refs` でエディターが渡す (インスペクターはアセットも階層も知らない)
- **エンティティの参照 = そのソフトの階層の項目**: 核は「エンティティ」を知らないので、`EntityRef` の ID は `tree::Item::id` (ゲームならエンティティの ID)。名前と一覧は `Software::Hierarchy()` から
- **パネルをまたぐドラッグ** (`w::DragThing`): 木のドラッグが続いている間、その物 (`Source::DragOut`: 既定は `"item"` + ID、アセットのパネルは `"asset"` + GUID) を 1 つの置き場に出す。受ける所 (`w::DropTarget`) はマウスが上にあれば枠を光らせ、ボタンが離されたフレームに受け取る。置き場はフレームの最後に片付ける (後で描くパネルも「離した」を見られる)。**別のウィンドウ**: ドラッグの続くウィンドウ (マウスを捕まえている) がフレームの最後に `EditorScreen::ForwardDrag` で、マウスが自分の外にあれば下のウィンドウ (`TopLevelWindowAt`) がエディターか外に出したパネルのウィンドウかを見て、そのウィンドウの DIP の座標を `w::SetDragElsewhere` で渡して描き直させる。そのウィンドウの `DropTarget` はその点で枠を光らせ、離したと渡されたら受け取る (使われなければそのフレームの最後 `w::EndDragFrame` で捨てる)
- **エンティティの参照の付け替え** (`reflect::MapEntityRefs`: 入れ子と配列の中まで全部の `EntityRef` を写し替える。純粋でテストあり): 複製・貼り付け (`Scene::Duplicate` / `PasteList`) はコピーした中を指す参照をコピーへ、外を指す参照はそのまま。Prefab のファイル (`MakePrefab`) では中はファイルの ID、外は 0。置く (`PlacePrefab`) とファイルの ID → 新しい ID、反映 (`ApplyPrefab`) は先に全部の ID を決めてからファイルの ID → その ID (上書きの値はシーンの ID のまま)。上書きを数えるとき (`Overrides`) は Prefab の値をシーンの ID に直してから比べる (中の参照は「違う所」にならない)。テストは `tests/TestEntityRefs.cpp`
- **取り込みの設定** (`core/asset/ImportSettings`): `.meta` の `"import"` に、種類ごとの `RM_STRUCT` (`ModelImport` = 大きさ・上の向き・中の絵の圧縮・中の絵の大きさの上限 / `ImageImport` = くっきり・大きさの上限・圧縮 (`TextureCompression`: 自動 / なし / BC1 / BC3 / BC4 / BC5 / BC7)。`ImportTypeOf(kind)`)。読む側 (3D 空間の `LoadMeshFile` → `ApplyModelImport` (純粋でテストあり)、`TextureCache`、2D のシーンビューの画像) が `ReadImport<T>(file)` で読み、`ChangedAt(file)` (ファイルと `.meta` の新しい方の時刻) が動いたら読み直す (サムネイルも)。くっきりは 3D では点のサンプラー (`MIN_MAG_POINT_MIP_LINEAR`) を材質ごとに選び、2D ではスプライトの「くっきり」とどちらか
  - エディター: アセットのパネルで 1 つ選んで (ボタンを離したとき。ドラッグしたときは出さない) `SoftwareHost::Inspect` に「種類・場所・ID」と設定のかたまり。かたまりの `onEdit` が `ImportCommand` (今の設定のその欄だけ変える。Undo は前の値に。打つたびの変更は `merge` で 1 つ) をソフトの履歴に積む = Undo でき、未保存の印が付く (憲法 7)。**`.meta` へは編集が終わってから書く**: 変えた設定は `AssetLibrary` に待たせ (`QueueImport`。インスペクターと次の変更はそれを見る)、どのウィンドウでも、マウスのボタンが離れていて文字の入力中でないフレームの終わりに `FlushImports` がその `.meta` だけに書く (保存と閉じるときも)。数のドラッグで毎フレーム書いてフォルダ全体を見直していたのをやめた。書いた分の通知は捨てる (フォルダは見直さない。使う側は `.meta` の時刻でそのアセットだけ読み直す)。知らないキーは `Unknowns` で書き戻す
- **エンティティの参照の欄**: 階層の一覧はインスペクターを描くたびに、欄が聞いたときに 1 回だけ作り、ID の索引で引く (前は欄ごと・毎フレーム一覧を作り直し、親を順に探して 2 乗だった)
- 参照の欄の一覧 (`w::PickerPopup`) も、アセットなら同じサムネイルを出す (`inspector::Refs::thumbnail` → `AssetThumbnail`。見えている行だけ聞く)
- **サムネイル** (`editor/assets/Thumbnails`。プロジェクトに 1 つ、全部のソフトのパネルで共有): 画像は WIC で縮めた絵 (`platform/Image`)、ほかの種類は**プラグインが差し出した描き方** (`kThumbnailPoint` + `ThumbnailMaker{kind, prepare, draw}`。核は 3D を知らない。3D モデルは 3D 空間プラグインの `space3d/editor/Thumbnail` が同じ `Renderer` で小さく描いて GPU から読み戻す)。GUID ごとに覚え、1 秒ごとにファイルの時刻を見て変わったら作り直す。32 / 64 / 128 / 256 ピクセルの段で作る (つまみを動かすたびに全部作り直さない)。**重い所は別のスレッドで** (2026-11-11): `Thumbnails` が作業スレッドを 1 本持ち (`std::jthread`。最初の仕事で始まる)、待ち行列は新しい順 (いま画面に出ている物が先)。画像はそこで全部 (`platform::ThreadImagingFactory`: スレッドごとの WIC)。プラグインの種類は `prepare` (ファイルを読み、絵を解く) までがそこで、`draw` (GPU) だけが UI のスレッドで 1 回の描画に 30 ms まで。Direct3D の即時コンテキストと Direct2D は UI のスレッドだけが触る。作っている間は `RequestAnimation` で次のフレームを頼み、できた物から出る。待っている間にファイルが変わった結果は捨てて作り直す。新しい順に作るので、先に頼んだ小さい物が大きい物の後に届いても置き換えない。**作業スレッドの中の例外 (壊れたファイルでメモリーが足りなくなる・プラグインが投げる) は受け止めて「作れない」(種類の印) にする** (スレッドから例外が出るとエディターごと落ちる)。UI のスレッドの `draw` の例外も同じ。1 分見えなければ捨てる。作れないものは種類の印のまま (コンソールに情報 1 回)
  - 木の部品に足したもの: `tree::Source::RowHeight()` (行の高さ。絵は行に合わせた正方形) と `DrawPicture()` (絵を自分で描くなら true。false なら核が `Icon` を描く)。描く部品は `w::DrawThumbnail` (薄い四角の上に形を保って収める) と `w::Slider` (つまみ)
  - 大きさはパネルの下の行のつまみ (左の端 = サムネイルなし = 前の 24 の行)。ソフトごとの見え方なので `UserSettings/Layout.json` の `"assets": {"thumbnail"}` (知らないキーは残す)
- プラグインがファイルを開くとき: `SoftwareHost::AssetFile(ref)` (今の場所のフルパス)。ID でない値 (参照ができる前のデータの `"Assets/Models/robot.glb"` のような相対パス) はそのパスとして読む (プロジェクトの外は読まない)
- **メッシュの部品** (`MeshRenderer::model`) は `RM_PROPERTY(Edit, Label="モデル", AssetKind="model") AssetRef model;`。シーンビューは `host.AssetFile(model)` でファイルを開き、読んだモデルを ID ごとに覚える (動かしても読み直さない)。参照ができる前のデータ (`"model": "Assets/…"`) はそのまま読める (上の「ID でない値」)。インスペクターで選び直すと ID になる

## 7-2. 階層 (`editor/tree`)

**木の表示は核、何を並べるかはソフト** (RME_PLATFORM 4-c)。13 のソフトで木の部品を 1 回だけ作る (憲法 3)。

| | 核 (`editor/tree`) | ソフト (`tree::Source`) |
|---|---|---|
| 並べるもの | 知らない | `Items()`: ID・親・名前・子を持てるか・薄く出すか を表示の順に並べる (毎回の描画で聞く) |
| 開く・閉じる | ▸ / ▾、← / → | — |
| 選ぶ | クリック / Ctrl (足す・外す) / Shift (範囲) / ↑↓ Home End (+Shift) / Ctrl+A / 何も無い所のクリックで外す | `SelectionChanged()` で知らされる (ゲームなら 1 つならインスペクターへ、複数なら「N 個選んでいます」) |
| 並べ替え | 行のドラッグ: 行の上の端 = 前、下の端 = 後 (開いている行なら最初の子)、真ん中 = 中 (最後の子)、最後の行より下 = 一番上の段の最後。自分の中には落とせない。Esc でやめる。端に近づけると流れる | `Move(items, parent, index)`: index は動かすものを**抜いた後の**兄弟の中の位置 |
| 名前の変更 | F2 / ダブルクリック / 右クリック → その場の入力欄 (Enter・ほかをクリック = 確定、Esc = やめる、空は無視) | `Rename()`。Undo に積むのはソフト |
| 検索 | 上の欄。名前に含む物とその親を、全部開いて出す (英字は大文字小文字を区別しない)。Esc で消す | — |
| 右クリック | メニューの枠 (+「名前を変更 F2」)。何も無い所の右クリックは選択を外してから | `Actions(selection)`: 行と、そのショートカット (木が最後にクリックされた所で、文字の入力中でないときに効く) |

- 純粋な部分 (`TreeModel`: 見える行・検索・選択・落とす場所) はテストあり (`tests/TestTree.cpp`)。描画と入力 (`TreeView`) はそれを使うだけ
- **重さ**: 毎フレームの仕事は「項目の数 + 選んだ数」に比例させ、「項目 × 選んだ物」にしない。id から位置は `ItemIndex` (フレームに 1 回作る)、選んだ物・動かす物は集合 (`Selection::Set()`) で引く。`Prune`・`Roots`・Shift の範囲・落とす場所 (`SiblingsBefore` / 自分の中に落とさない判定は親から 1 回たどるだけ) も同じ。2 万項目を全部選ぶテストあり (`Tree_ThousandsAllSelected_StayLight`)
- 選択・開いている物・検索の文字はソフトごと (`Workspace::treeState`)。**閉じた物と選択は覚える**: `tree::SaveState` / `LoadState` で `Layout.json` のソフトの行の `"tree"` に (配置と同じとき。プロジェクトのデータではない)。消えた物の ID は次の描画で忘れる
- 行の絵: `Item::icon` (`tree::Icon`: 無し / 物 (丸) / 立方体)。ソフトが選ぶ。ゲームは部品が決める (`ComponentInfo::icon` の名前 → `tree::IconNamed`。最後の部品の絵、無ければ丸)
- **コピー / 切り取り / 貼り付け**: ゲーム制作の `Scene::Copy` / `Paste` (純粋でテストあり)。クリップボードにはファイルと同じ形のエンティティを JSON の文字で (`SoftwareHost::SetClipboard` / `Clipboard`)。貼ると新しい ID、クリップの中の親子は前に出てきた親だけをたどる (輪にならない)。別のプロジェクトにも貼れる
- **まとめての編集**: 複数選ぶと、全部に付いている部品のブロックだけを、最後に選んだ物で出す。`InspectBlock::also` にほかの物を渡すと、インスペクターは全部で同じでない値を「—」で出し (ベクトルは成分ごと。チェックは横線の印 `w::Checkbox(mixed)`、押すとオンにそろう。選び肢と一覧も「—」)、変更は全部への `SetFieldCommand` を `CommandGroup` 1 つにして積む (ベクトルは打った成分だけ: `Edit::component`)。打つたびの変更は `CommandGroup` どうしが命令ごとにまとまる (目標がいつも同じ順で全部入っているので)
- ソフトが選ばせたいとき (作った直後など) は `SoftwareHost::SelectInTree(ids, rename)`。次の描画で選び、`rename` なら名前の入力を始める
- インスペクターに型の無いもの (`Inspectable{nullptr, {}, 文}`) を渡すと、その文だけを出す

### ゲーム制作のシーン (`plugins/rm_engine/game_production/runtime/Scene`)

- エンティティは `RM_STRUCT Entity { id, parent, name, active }` (`id` / `parent` は保存するが出さない)。シーンはその並び。**並びの順 = 兄弟の順**
- 作る (選んでいる物の次・子として・一番上の最後) / 複製 (下の物ごと、元のすぐ後ろ) / 削除 (下の物ごと) / 移動 (自分の中は拒否・何も変わらなければ false) は純粋でテストあり (`tests/TestScene.cpp`)
- ID は使い回さない (`nextId` を保存)。読み込みで直すもの: 0 以下や重なった ID → 新しい ID / 無い親・自分が親・親の輪 → 一番上へ (どれも警告)。知らないキー (シーンにも各エンティティにも) は書き戻す
- Undo: 名前・有効の変更は `SetFieldCommand` (階層での名前の変更もインスペクターと**同じフィールド・同じコマンド**)。形の変更 (作る・複製・削除・移動・親から外す・貼り付け・部品を足す / 外す / 並べ替える・Prefab の操作) は**触った物だけの前と後** (`SceneRecord` → `RecordCommand`。下)。何も変わらない操作は積まない
- **触った物だけを覚える Undo** (`game_production/runtime/SceneRecord.h`。Unity の `Undo.RecordObject` と同じ考え。2026-11-12):
  - 形の変更は必ず `GameSoftware::EditTouching(触る物, 名前, 変更)` を通る (1 か所)。`SceneRecord::Begin` が触る物とその下全部の状態 (あるか・並びの中の場所・`SaveEntity` の JSON = RM_PROPERTY の欄・親・部品・Prefab のつながり) を取り、変更のあと `End` が同じ物と、その間に作られた物 (ID は使い回さないので、Begin のときの次の ID から End のときの次の ID まで) の状態を取る。Undo / Redo はその物たちだけを取り出して、覚えた場所に入れ直す (`Scene::RestoreStates`。ほかの物は並びの中の順が変わらないので、場所はそのまま合う)
  - 決まりは 1 つ: **作る物以外で変える物は全部「触る」と言う**。各操作が言う物: 作る・貼り付け・複製・Prefab を置く = なし (作る物だけ) / 削除・切り取り・移動・親から外す = 選んだ物 / 部品を足す・外す・並べ替える = その物 (まとめてなら全部) / Prefab にする・切り離す = その物 / Prefab に反映・読み直す = その Prefab を置いた物全部 (入れ子の中の物も、その下全部で入る)
  - **守り**: Debug ビルドでは、毎回シーン全体の前と後も取り、記録の Undo / Redo をシーンのコピーに当てて全体と比べる。違えばコンソールに「触ると言っていない物が変わりました」と出して assert (Release には何も足さない)。テスト `TestSceneRecord.cpp`: 乱数で作った 4000 回の操作 (足す・消す・親を変える・並べ替え・貼り付け・複製・部品・Prefab にする / 置く / 反映 / 切り離し) の 1 回ごとに、Undo の後のシーン全体 (次の ID を除く) が操作の前と、Redo の後が操作の後と同じか。300 回をまとめて新しい順に Undo、古い順に Redo しても同じか。わざと「触る」を 1 つ抜くと失敗することも確かめた
  - 大きさ: 1 万個のシーンで 1 つ消したとき、前 (シーン丸ごと 2 つ) は 1 段 約 3.6 MB・約 93 ms、いま (触った物 1 つ) は 465 バイト・約 4 ms (Release、手元の PC)
  - 「シーン丸ごと」の `SceneCommand` (`Edit`) は残してあるが、いまは使う操作が無い
- エンティティは毎回 ID で探す (`ResolveEntity`)。Undo で並びが作り直されても、消えた後に戻っても、インスペクターは同じエンティティを指す
- **重さ** (2026-11-11 の点検で直した): `Scene::Find` は ID → 並びの中の場所の索引 (`unordered_map`) を引く (並びを順に見ない)。索引は足す・消す・並べ替え・読み込み (= Undo) のあと、次に要るときに作り直す (`Touch`)。引いた先の ID が違えば作り直してもう一度引く (作り直し忘れがあってもずれない)。「この物とその下全部」は `Subtree` (親 → 子の一覧を 1 回作って辿る) で、物ごとに `IsUnder` を回さない (削除・コピー・複製・Prefab の仲間・つなぐ・外す・作り直す)。`Roots` (選んだ物のうち親が選ばれていない物。2D / 3D のギズモが毎フレーム使う) も木の順に 1 回。システムの `ForEachComponent` は物ごとに索引を引く。1 万個のシーンで読み込み・検索・システム 1 回・複製・削除がゆるい時間 (数秒) で終わることをテストで見る (`Scene_TenThousand_InReasonableTime`)。索引が変更・Undo・コピーのあともずれないこともテスト (`Scene_IndexStaysRightAfterEveryChange`)
- インスペクターの「Prefab と違う所: N 個」と保存のときの上書き (`UpdateOverrides`) は、置いた物ごとに 1 回作って覚え、**履歴の変更番号** (`UndoHistory::Changes`: 積む・まとめる・戻す・やり直す・消すで 1 つ上がる) か、Prefab のファイル・読み込んだデータが変わったときだけ作り直す (描くたびに作らない)

### インスペクターの「値のかたまり」(RME_PLATFORM 4-c)

- インスペクターに出すもの (`Inspectable`) = 上の題 + **かたまり (`InspectBlock`) の並び** + 下の「足す」ボタンとそのメニュー。かたまり = 型・今どこにあるか (`resolve`)・見出し・注意書き・見出しの ⋮ メニュー
- **核は「コンポーネント」という言葉を知らない** (ゲームの言葉)。ゲームなら 1 つ目のかたまり = エンティティ、2 つ目から = 部品、⋮ = 外す、足すボタン = 部品を足す、を**ゲーム制作が**組み立てる
- かたまりの並びは**描くたびに聞く** (`blocks()`)。Undo で部品が戻ったり消えたりしても、今あるものが出る。物が消えたかたまり (`resolve` が空) は出さない。全部消えたら「何も選ばれていません」
- 見出しを押すと畳む (題で覚える)。⋮ と足すボタンのメニューは、フレームの最後に描く (パネルで切れない。`w::ActionMenu` = 階層の右クリックと同じ 1 本)
- 欄の ID は見出しの題で分ける (部品が増えたり減ったりしても、入力中の欄が別の部品に移らない)

### ゲーム制作のコンポーネント (ECS の C。`plugins/rm_engine/game_production/runtime/Components.h`)

- 部品の型は**リフレクションの型ならどれでも**。ほかのプラグインが `kComponentPoint` に `ComponentInfo{型, 新しいエンティティに付けるか, …, multiple, placement}` を差し出す。ゲーム制作は型を知らない (3D 空間を読まない)
- エンティティは部品を**型ごとに 1 つまで**持つ。`ComponentInfo::multiple` (「複数可」) の型だけは何個でも (いまは「回り続ける」)。部品は「エンティティ ID + 型の名前 + その型の中の何番目 (0 から)」で探す (`SceneEntity::FindComponent(type, nth)`)。Undo の命令は探し方を覚え、戻すときに探し直す (並べ替えも Undo の順に戻るので、指す物がずれない)。インスペクターは 2 つ以上のとき「名前 (1)」「名前 (2)」(かたまりの題 = 欄の ID の区切りなので、番号で分ける)。複数選んだときは各型の最初の 1 つだけをまとめて編集
- 保存の形は変えていない (`components` の並びに同じ `type` が何度出てもよい)。前のファイル (1 つずつ) はそのまま読める。複数可でない型の 2 つ目は前と同じく「使えない部品」として持って書き戻す
- 値は `reflect::Object` (型を消した値。型の表の construct / copy / destruct で作る・写す・壊す。テストあり)
- 保存: エンティティの `components` = `[{"type": "rm::space3d::Transform", "data": {...}}]`。**型は C++ の名前で書く** (★ 名前空間や型の名前を変えると読めなくなる。そのときは「使えない部品」として残る)
- **使えない部品** (プラグインが無い・2 つ目・形が違う) は**読んだまま持ち、そのまま書き戻す**。インスペクターには「(使えない部品)」と説明と「外す」だけを出す。読み込みでコンソールに警告
- 足す・外す・並べ替えはシーンの形の変更と同じ `SceneCommand` (前後のシーン)。部品の欄の変更は `SetFieldCommand` (エンティティ ID と型の名前と番号で部品を探す)

### C++ スクリプト (2026-11-12。設計: TestEngine `NewEngineBluePrint.md` §5・§6・§6-b・§20-c、`RME_PLATFORM.md` §4-b)

```
ユーザー   <プロジェクト>/Assets/Scripts/*.h / *.cpp      (RM_SCRIPT + RM_PROPERTY。#include "RM.h")
エディター  Library/Scripts/Scripts.vcxproj + Scripts.sln    (開くたびに書く。IntelliSense 用のインクルードパス入り)
            作業スレッドで MSBuild ── 前に rmgen --scripts (Generated/rm_scripts.cpp: 表と RmModuleInit)
                                   └→ Library/Scripts/Scripts_0007.dll (毎回別の名前)
ランタイム  ScriptModule::Load(dll, api) ─ LoadLibrary → RmModuleInit(&api, RM_ABI_VERSION) → スクリプトを reflect::TypeDesc に
            スクリプト = エンティティの部品 (型の名前で保存。インスペクター・保存・Undo・コピーは部品と同じ道)
            ScriptRunner::Frame(scene, world, module, 実行順, dt) / Stop (EndPlay)

- **境目** (`game_production/runtime/sdk/RmAbi.h`。C だけ): DLL が export するのは `RmModuleInit(const RmApi*, uint32_t abi)` の 1 本。両方が `RM_ABI_VERSION` を確かめ、違えば弾く (`CheckModule`。整列 16 より大きい型・知らない欄の種類・同じ名前も)。境目で `std::string` を渡さず仮想関数も使わない (`const char*` と関数ポインタ)。スクリプトの欄の `std::string` はエンジンが直接読み書きする (同じツールセット v143・同じ CRT: Release は /MD、Debug のエンジンは /MDd でビルドする)
- **API の表**: `RmApi{abi, ctx, core, part}`。`core` (`RmCoreApi`) はゲーム制作のもの (ログ・時間・名前で探す・有効・名前・親・キー・カメラ・GetScript)。**空間を知る物はプラグインの部分**: 各プラグインのランタイムが `RuntimeRegistry` の口 `kScriptApiPoint` に `ScriptApiPart{名前, 版, 表}` を差し出し、スクリプトは `api->part(ctx, 名前, 版)` で引く (つなぎ「ゲーム制作 × 3D」= `RM3DAbi.h` の Transform、「× 2D」= `RM2DAbi.h`)。ゲーム制作は 3D / 2D を知らない。`ctx` はゲーム制作の `ScriptWorld` (動いているシーン・dt・時間・カメラ・キー)
- **配るヘッダー**: `plugins/**/runtime/sdk/*.h` (RM.h・RmAbi.h・RM3D.h・RM3DAbi.h・RM2D.h・RM2DAbi.h) をビルドで `<exe>/Sdk/` に写す。ヘルプは RM.h のコメント (Visual Studio のツールチップ)。ユーザーのヘッダーは生成物を読まない (`rm::Api()` は生成した登録が定義する)
- **rmgen `--scripts`**: スクリプトのフォルダのヘッダーを読み、`rm_scripts.cpp` を書く (各スクリプトの欄の表・作り方・フック (`requires` で有るものだけ)・コンパイル時の検査 (集成体・欄の数・欄の型)・`RmModuleInit`)。スクリプトでまだ使えない物 (RM_STRUCT / RM_ENUM・一覧・入れ子・AssetRef) は `RM0013`。エンジンのビルドは `--skip-dir templates` (テンプレートの中のスクリプトはゲームのもの。vcxproj・check_layers・check_lang も templates/ のコードを見ない)
- **実行順** (§5 の決定): 型ごとにまとめて回す。型どうしはゲームの設定の「スクリプトの実行順」(`ScriptOrderEntry{型, 順番}`) の小さい順、無い型は 0、同じ数は型名の辞書順 (`SortScriptTypes`)。同じ型の中はエンティティの ID の順 → 付けた順 (★ 設計の「アタッチごとの安定 ID」は保存形式に足していない。ID と付けた順で代える)。1 フレーム = まだ始まっていない物の BeginPlay を全部 → 全部の Tick (そのフレームに作られた物は次のフレームの最初に BeginPlay)。有効でない (親を含む) 物は回さない。インスペクターのかたまりに「スクリプト ・ 実行順 N」
- **落ちたとき**: 全部のフックと `RmModuleInit` を `__try` / `__except` で呼ぶ (`ScriptGuard.cpp`: デストラクタを持つ物を置けない関数なので分けた)。落ちたスクリプト (その 1 つ) は止めて、コンソールに 1 回だけ出す

- **ビルド** (`editor/ScriptBuild.*`): vswhere で MSBuild を探し (`-requires Microsoft.Component.MSBuild`)、`Scripts.vcxproj` を `-p:TargetName=Scripts_<次の番号> -p:OutDir=Library/Scripts/` でビルド。出力はファイルのログ (UTF-8) から読み、`error` の行をコンソールへ。2 つ前より古い DLL は消す (使っている物は消えない)。作業スレッド (`editor/app/Worker`) で走り、結果は UI のスレッドに戻ってから使う (`GameScripts`)

### Prefab (`plugins/rm_engine/game_production/runtime/Prefab.h`)

```
Prefab のファイル (.rmprefab)   { "kind": "rm_engine.game_production.prefab", "format": 1, "entities": [一番上, その下 …] }
置いた物 (シーンの中)           各エンティティに "prefab": {"source": ファイルの中の id}
                                一番上だけ  + "path": "Assets/箱.rmprefab", "overrides": {fields, addedComponents, removedComponents, removedEntities}
```

- **作る** (階層の右クリック「Prefab にする」): `MakePrefab` (木の順 = 親が先。置いた Prefab なら `source` をファイルの id のまま使う: ほかの置いた物と合い続ける) → `Assets/<名前>.rmprefab` に書く → `LinkPrefab` で元の物が置いた物になる (この切り替えは Undo できる。ファイルは残る)
- **置く** (右クリック「Prefab を置く: …」。Assets の中を 2 秒に 1 回まで探す): 貼り付けと同じ道 (`PasteList`) で新しい ID、`source` を付ける
- **上書き** = 置いた物と Prefab の差分 (`Overrides`): エンティティ・部品の一番上の欄ごとの違う値、足した部品、消した部品、消した子。一番上の物の自分の欄 (名前・有効) と「置き場所」の部品 (`ComponentInfo::placement` = Transform) の欄はいつも上書き (Prefab を直しても置いた場所が動かない)。プラグインが無くて使えない部品は Prefab に従う
- **伝える** (`ApplyPrefab`): 元の Prefab と比べて上書きを取る → 新しい Prefab から作り直す → 上書きを掛ける。ID は `source` で合わせて保つ (Undo の命令・ローカル / ワールドの覚え・選択が切れない)。Prefab に増えた物は新しい ID。置いた物に足したふつうの子は残る (親が消えたら一番上の物の下へ)
  - 「Prefab に反映」: 置いた物の今の形でファイルを書き、ほかの置いた物全部に伝える。**ファイルの書き込みも Undo に入る**: シーンの変更 (`SceneCommand`) と、ファイルの前と後の中身を持つ `FileCommand` を 1 つの `CommandGroup` にして積む。Undo でファイルが前の中身 (バイトそのまま) に戻り、置いた物も戻る。Redo でまた書く (ファイルはそのときの場所を AssetRef から引く)。新しい版の Prefab・読めないファイルには反映しない (上書きして壊さない)。★「Prefab にする」で作ったファイルは Undo しても残る (アセットとして作ったもの)。「読み直す」: ファイルの今の中身を全部に伝える。「切り離す」: ふつうのエンティティに
  - 開くとき: 保存してある上書き + Prefab のファイルの今の中身で作り直す (ほかの所で Prefab が変わっていても合う。編集ではないので未保存にならない)。ファイルが読めなければ保存したまま
  - 保存するとき: 上書きをその時の Prefab と比べて作り直して書く (シーンのコピーに。`SaveData` は const)
- 純粋でテストあり (`tests/TestPrefab.cpp`)。ファイルの読み書きはエディター (`GameSoftware`)
- **Prefab のファイルはアセットの参照** (`PrefabLink::asset` = `AssetRef`。`.rmprefab` の横の `.meta` の ID): アセットのパネルやエクスプローラーで動かしても名前を変えても外れない。シーンには `"asset": "<ID>"`。参照ができる前のデータの `"path": "Assets/箱.rmprefab"` も `asset` に読み (`SoftwareHost::AssetFile` はどちらも引ける)、開いたときにそのファイルの ID に直す (次の保存で `"asset"` で書く)。作った Prefab は `SoftwareHost::AssetOf` (核に足した: Assets の中のファイル → ID。書いたばかりのファイルはここで `.meta` が付く) で ID にする
- **入れ子の Prefab** (Prefab の中に置いた Prefab):
  - ファイルには入れ子の**一番上の物だけ**を、自分の Prefab へのつながりと、そこで変えた所 (その Prefab に対する上書き) ごと書く (`"prefab": {"source", "asset", "overrides"}`)。中身はいつもその Prefab のファイルから作る (`NestedAssets` で中に入っている Prefab の一覧)
  - シーンでは入れ子の一番上の物は 2 つの顔を持つ: 自分の Prefab を置いた物 (`Root()`) で、外の Prefab の 1 つのエンティティ (`PrefabLink::outer` = 外のファイルの中の ID)。`PrefabMembers(外)` は入れ子の一番上の物までを含み、その中身は含まない。`NestedPrefabs(外)` = 入れ子の一番上の物
  - 上書きの持ち方: 外の上書きは外の物 (入れ子の一番上の物の置き場所なども) だけ。入れ子の中身で変えた所は、入れ子の一番上の物の上書き (自分の Prefab に対する)
  - **中の Prefab を直したとき**: その Prefab を置いた物は入れ子の物も含めて全部作り直される (それぞれの上書きは残る)。**外の Prefab を直したとき**: 外の物を作り直し、前からあった入れ子の物は自分の上書きを保つ (ここで変えていない = 前の外のファイルと同じ上書きなら、新しい外のファイルのものに替える)。消えた入れ子の物は中身ごと消える。そのあと入れ子の中身をそれぞれのファイルから作る (`GameSoftware::FillNested`。外から内へ)
  - 自分の中に自分が入る Prefab は作らない: 「反映」で入ることになるなら反映しない (`ContainsPrefab`)。読み込んだファイルが輪になっていたら、その中は作らない (コンソールに一言)
  - コピー: 置いた物の一部だけを貼り付け・複製すると、ふつうのエンティティになる。入れ子の一番上の物だけなら、手で置いた Prefab になる (`Scene::DetachCopies`)
  - **移動**: 置いた物の一部を別の親へ移すと (同じ Prefab の中の別の親へも)、その物と下の部分は Prefab から外れてふつうのエンティティになる (Prefab の中の親子は Prefab が決める)。入れ子の一番上の物を外へ移すと、手で置いた Prefab になる (`Scene::Move` → `DetachFromPrefab`)。同じ親の中の並べ替えだけなら外れない。これが無いと、移した物が前の Prefab の ID のまま別の Prefab の仲間になり、ID が重なって作り直すときに消えた (2026-11-11 の点検で見つけた)
  - `ApplyPrefab` は仲間のファイルの中の ID が重なっていたら (前の版のデータ・手で書いたファイル)、2 つ目からを Prefab から外して残し、コンソールに理由を出す。消さない
  - Prefab のファイルの知らないキー (一番上・入れ子のつながりの中) は書き戻す (`MakePrefab(…, previous)`)。`format` が新しいファイルは読まない (`NewerPrefab`)
- ★ Prefab を外で書き換えても、開き直す・「読み直す」までは置いた物は変わらない。★ 入れ子の中身の下に足したふつうのエンティティは、外の Prefab のファイルには入らない (シーンには残る)。エンティティの参照 (`EntityRef`) は `SceneEntity::MapEntityRefs` で付け替える: ファイルに書くとき (シーンの ID → ファイルの ID。Prefab の外を指すものは 0)、作り直すとき (ファイルの ID → シーンの ID)、上書きを比べるとき。入れ子の一番上の物は外のファイルの ID (`outer`) で対応を取るので、外の物から入れ子の一番上の物への参照は残る。★ 外の物から入れ子の**中身**への参照は、外のファイルに中身が無いので 0 になる (置いた物での上書きとしては残る)

### 3D 空間 (`plugins/rm_engine/space3d`)

- `Transform` = 位置・回転 (度。X → Y → Z の順のオイラー角)・大きさ。行列 `Mat4` (列ベクトル)、`LocalMatrix` (拡大 → 回転 → 移動)、`WorldMatrix` (親の行列 × 自分)。純粋でテストあり
- 見ること (`runtime/View`): ベクトルの計算・逆行列・透視投影 (右手系・Y が上・奥行き 0〜1)・LookAt・画面の点からのレイ・箱との当たり (スラブ法)・置いた立方体との当たり・編集用のカメラ `OrbitView` (見回す / 回る / 平行移動 / 近づく / 飛ぶ / 寄る)。純粋でテストあり
- 回転の計算: `RotationMatrix` (オイラー角 → 行列。`LocalMatrix` もこれを使う)・`AxisAngle` (軸のまわりに回す)・`EulerFromRotation` (行列 → オイラー角。同じ回り方を表す角度は 2 組 (+360 の倍数) あるので、**いま見えている角度に一番近い組**を選ぶ: ドラッグ中に数字が飛ばない)・`Decompose` (ワールド行列 → 位置・回転・大きさ)。純粋でテストあり
- **ローカル / ワールド**: 子のエンティティだけ、インスペクターの Transform のブロックの上にスイッチ (`w::Switch`: 横長の丸いつまみが左右にすべる) があり、同じ欄にローカル (Transform そのまま) かワールド (親を含めた値 `WorldPlacement`) を出す。親の無いエンティティは同じ数字なのでスイッチを出さない。子は最初ローカル。切り替えはエンティティごとに `UserSettings` の `"inspectorModes"` に覚える。ワールドで打った値は `FromWorld` (打った所だけを、親の逆行列などでローカルの値に直す。純粋でテストあり) で Transform の編集になる
  - ゲーム制作は意味を知らない: `ComponentInfo` の `derivedType` / `derive` / `underive` / 2 つの名前を、つなぎが Transform に付けて差し出す。核のインスペクターに足したのは、ブロックの「見せ方の切り替え」(`InspectBlock::modes` / `setMode`。2 つならスイッチ、3 つ以上なら横に並べた選択肢) と「編集を自分で受け取る」(`InspectBlock::onEdit`。見せている値が編集するデータそのものではないとき) だけ
- **ギズモ** (`space3d/editor/Gizmo`。3D 空間の**エディター側の部品**: ほかのプラグインのエディターが使う。ほかに登録するのは 3D モデルのサムネイルだけ: `space3d/editor/Thumbnail`): 形 (矢印・面の四角・こちらを向いた半分の輪) と、マウスの下の印・ドラッグで何が変わるか・Transform への当て方を計算するだけ。描くのは使う側 (シーンビュー) が**同じ形の関数から** (描くものとつかめるものが食い違わない)。純粋でテストあり (`tests/TestSpace3d.cpp`)
  - 移動: 矢印 = マウスの線と軸の一番近い点 / 面 = マウスの線と面の交わる点。回転: つかんだ点で輪が進む向き (画面の上) にマウスを動かした長さ ÷ 輪の半径 (ピクセル) = 回る角度 (輪を真横から見ていても回せる)。拡大縮小: 軸 = 掴んだ所からの距離の比 / 真ん中 = マウスの右と上への動き
  - 回転にはほかに 2 つ: **外の輪** (`Handle::View`。目に向いた円 `FacingCircle` の半径 `kViewRing` = 1.18 倍。目への向きを軸に、ほかの輪と同じ計算) と、**球の中** (`Handle::Free`。半径 1 の目に向いた円の中で、輪の上でない所。トラックボール: 画面の右と上を世界の向きに直しておき、マウスの動き m に対し 軸 = 目への向き × (右·m.x − 上·m.y)、角度 = |m| ÷ 半径のピクセル)。どちらも世界の軸 (`Change::worldAxis`) で回す
  - **それぞれ / 中心** (`Pivot`): 中心のときギズモは `Scene::Roots(選択)` の位置の平均 (軸は最後に選んだ物)。`Apply(…, pivot)` は回転なら位置も pivot のまわりに回し (軸はギズモの軸)、拡大縮小なら pivot からの距離をのばす (軸ごとならギズモのその軸の向きだけ)。pivot なしは今までどおり (それぞれ自分の場所で、ローカルなら自分の軸)
  - 刻む幅 (`Snap`) はシーンビューの見え方 (`SceneViewState`: `snapMove` / `snapDegrees` / `snapScale` / `snapAlways`。範囲は `RM_PROPERTY` の Min / Max)。いつも刻むときは Ctrl でなめらか
  - 当て方: 移動はワールドで動いた分を親の逆行列で親の中の量に。回転は軸を親の中に写し、`AxisAngle × いまの回転`。ローカル / ワールドは軸の取り方だけの違い
  - シーンビュー: ドラッグ中は Transform を直接書き換え (インスペクターが付いてくる)、ボタンを離したら**選んでいた物全部の `SetFieldCommand` を `CommandGroup` 1 つにまとめて**履歴に積む (Undo 1 回で全部戻る)。Esc でドラッグ前に戻す。親も選ばれている物は動かさない (`Scene::Roots`)
  - **ドラッグ中の元に戻す / やり直し** (2D も同じ): ボタンを押したまま Ctrl+Z などで履歴が動くと (Undo / Redo の数がドラッグを始めたときと違う)、ドラッグをやめる。ドラッグで変えた欄のうち、その後ほかから変わっていない欄だけを始めの値に戻し、何も積まない (消えた物は探し直して触らない)。押した物も毎フレーム ID で探し直す (2026-11-11: 押した物が Undo で消えると落ちていた)
  - `CommandGroup` (`core/UndoHistory.h`): いくつかの編集を 1 回の Undo にまとめる。戻すときは逆順
  - **Undo の履歴の大きさ**: 履歴は数 (1000) に加えて**合計のバイト数** (`UndoHistory::kMaxBytes` = 256 MB、ソフトごと) で切る。各エントリーは自分の大きさを `ICommand::Bytes` で言う (シーンの形の変更 `RecordCommand` は触った物の前後の JSON の長さ (丸ごとの `SceneCommand` は前後のシーンの長さ)、Prefab のファイルの `FileCommand` は前後の中身の長さ。欄の変更は小さいので 0)。超えたら古いものから捨てる (一番新しい 1 つはいつも残る)。2026-11-12 から形の変更は触った物だけを持つ (上の `SceneRecord`) ので、大きなシーンでも 1 段は小さい

### 3D の描画 (`plugins/rm_engine/space3d/runtime/Renderer3D`) とシーンビュー

```
ゲーム制作 「シーン」パネル ── 差し出しの口 kSceneViewPoint ──▶ ゲーム制作 × 3D の SceneView3D
                                                                  ├ 3D 空間: 親子をたどってワールド行列・カメラ・クリックのレイ
                                                                  ├ 3D 空間の Mesh / MeshFile: モデルのファイル → 頂点と三角形 (1 回だけ)
                                                                  └ 3D 空間の Renderer: 自分のテクスチャに線・箱・モデルと影を描く
                                                                        ▼ (同じ GPU)
                                                Direct2D のビットマップにしてパネルに貼る (painter.Image)
```

- **色** (2026-11-11 から PBR): 表面の色 = 描くときの色 (`MeshDraw::color`。モデルは白、有効でない物は透けた白) × 材質の色 × テクスチャ (UV で貼る。くり返し・異方性フィルター・ミップマップ)。シェーダーでは `Paint()` が表面の色を出し、`Shade()` が光の量を計算する: 光ごとに拡散 (Lambert。金属には無い) + つや (GGX の D・Smith の G・Schlick の F) と、空 (下より上が明るい、拡散 + 映り込みを少し)。金属・ざらざらは材質の数 × 金属 / ざらざらの絵 (青・緑)、法線は法線マップで曲げ (接線は画面の上での位置と UV の変わり方から作る「cotangent frame」: 頂点に接線を持たない)、光る色を足す。光の値 (`Lights`。`Lighting.h`) の作り方は変えず、`LightAt()` で 1 つずつ読む。モデルは**部分 (`MeshPart`) ごとに**材質を替えて描く (`DrawMaterial`: 色・`GpuTexture`・アルファの扱い)。OPAQUE は絵のアルファを無視、MASK は切り抜き (`clip`)、BLEND は透ける。**透ける物は最後に、目から遠い順に**描く (`BackToFront`。純粋・テストあり): 部分 (`MeshPart`) ごとの境界の真ん中 (`GpuMesh::partCenters`、`Upload` で作る) の遠さで並べ、深度は書かない (透ける物の奥の透ける物も見える)。不透明な物 → 床の影 → 線 → 透ける物 の順。有効でない物 (描くときの色のアルファ < 1) も透ける物の組。1 つの部分の中の三角形どうしの順は並べ替えない (同じ部分の中で重なると、前後が逆に見える所がある)。影の地図には形だけを描く (切り抜きの穴は影に出ない)
  - **選んだ物**: 箱は前と同じく色を変える。モデルは色を変えず、**目から見て横を向いた所 (縁) をアクセントの色で光らせる** (`MeshDraw::highlight`。`pow(1 - n·v, 2.5)`) + 境界の箱の枠
  - **リニアで計算して最後に sRGB に**: 材質の色・光る色はリニア (glTF はそのまま、.mtl の画面の色は `ScreenToLinear`)。色と光る色の絵は `R8G8B8A8_UNORM_SRGB` (GPU が読むときにリニアに。ミップマップもリニアで平均する)、金属 / ざらざらと法線の絵は `UNORM`。描くときの色 (UI の色) は画面の色で受け取りシェーダーでリニアに。ピクセルの最後に `ToScreen` で sRGB に直して書く (絵は `B8G8R8A8_UNORM` のまま: Direct2D に貼るため)。だから半透明の重ね合わせと MSAA の混ぜ方は sRGB の上で行う。床の影・線・縁の光は画面の色のまま
  - 明るさの合わせ方: 強さ 1 の光が白い面に正面から当たると 0.85、空は 0.08〜0.16 (前の見た目に近いように)。光の部品の色 × 強さはそのまま光の量 (リニア) として使う
- **描き手の分け方** (2026-11-12): 描き手 (`Renderer`) はシーンビュー・カメラのプレビュー・サムネイルにそれぞれあるが、**シェーダー・状態・箱と床の形・定数バッファ・影の地図 (と何を持っているか) はデバイスごとに 1 つ** (`Renderer::Shared`。デバイスのポインターで引き、最後の描き手が無くなると消える。GPU のリセットで作り直したデバイスは別のデバイスなので、別の `Shared` になる)。シェーダーのコンパイルはデバイスごとに 1 回、影の地図 (平行光 3 × 2048² + 点光源・スポット 8 × 1024² ≒ 80 MB) もデバイスごとに 1 組で、影を使う描き手が最初に要るときに作る (サムネイルは影を使わないので作らない)。絵 (描き先・深度) は描き手ごと
- **1 フレームの数の送り方** (2026-11-12): 物ごとの数 (ワールド行列・法線の行列・色・縁の光) と材質ごとの数 (色・絵の有無・金属・ざらざら・光る色) を、フレームの最初に**1 つのバッファ (`Buffer<float4>`、t6) に全部書いて 1 回で送る** (`Map` 1 回)。描く命令はどれも「どの物の・どの材質の数か」(2 つの番号) だけを、もう 1 本の頂点の流れ (インスタンスごとの `DRAW`) から読む: `DrawIndexedInstanced(…, 1, …, 番号の場所)` の始めのインスタンスで選ぶ (機能レベル 10.0 で使える)。前は描く命令ごと・影の地図ごとに定数を `UpdateSubresource` していた。シェーダーの中では前と同じ名前 (`world` / `color` / `material` …) の `static` の変数に読み込むので、色と光の計算は変わっていない。1000 個・光 8 個で 1 フレームの CPU の時間がおよそ半分 (下の「検証」)
- **インスタンシングと描く順** (2026-11-12、`space3d/runtime/DrawOrder` は純粋・テストあり): 同じメッシュ・同じ部分・同じ絵 (材質のテクスチャ 4 枚とサンプラー。材質の数はインスタンスごとに違ってよい) の描く命令が続くと、**1 回の `DrawIndexedInstanced` にまとめる** (`Renderer::Emit`: 前の命令の次の番号なら、その命令のインスタンスを 1 つ増やす)。そのために、絵のある物は**シェーダー → 絵 → メッシュ → 部分の順に並べてから**命令を作る (`SortDraws`: 同じ鍵は来た順のまま。もう並んでいれば並べ替えない)。影の地図に描く物は、フレームの最初に 1 回メッシュで並べ (`casterOrder_`)、地図ごとにその順で入る物を選ぶ。透ける物は奥から順のまま (隣どうしが同じならまとまる)。絵をつなぎ直すのも変わったときだけ。箱 1000 個・光 8 個で、1 フレームの描く命令が 4000 ほど → 5 (カスケード 3・物・床)。機能レベル 10.0 のまま (始めのインスタンスで番号の組を選ぶ前の仕組みに、インスタンスの数を足しただけ)
- **多くの箱を 1 つの見え方で調べる** (`View.h` の `Frustum` / `BoxInFrustum`。純粋・テストあり): 影の地図ごと (光ごと・カスケードごと) と絵のカメラで、見える範囲の 6 面を 1 回だけ平面にしておき、箱は面ごとに「一番内側の角」だけで調べる (`BoxInView` の 8 つの角を行列に通すのと同じ答え。テストで 8000 個の箱で一致を確かめた)。その範囲に入らない物は、その地図には描かない
- **描画** (3D 空間プラグインの中。ランタイム): Direct3D 11。シェーダーは HLSL をコードに書き、起動して最初に使うときに `D3DCompile` でコンパイル (Windows に入っている)。線 (グリッド・枠) と、光の当たった箱 (単位立方体 × ワールド行列) とモデル (`MeshDraw` = GPU のメッシュ × ワールド行列)。**箱も同じメッシュの描き方** (単位立方体を `Upload` したもの。描くコードは 1 本)。4x MSAA (使えれば) → 解決して 1 枚の絵に。絵の大きさはパネルのピクセル数 (高 DPI でもくっきり)
  - 三角形の表は**反時計回り** (glTF・OBJ と同じ)。裏も描き (`CULL_NONE`: 閉じていないモデルの内側も見える)、**見えている側は目の位置から決める**: 法線が目と反対を向いていたら裏返して明るさを決める (定数 `eye`)。前は画面の上での三角形の回り (`SV_IsFrontFace`) で決めていたが、向きが逆に判定されて表の面が暗く、床の影も捨てられていた (2026-11-11 に画面で見つけて直した)。床は目が床より下にあるときだけ描かない
  - 法線はワールド行列の**逆行列の転置**で回す (大きさが軸ごとに違っても面に直角のまま)
- **材質** (`Mesh` の `MeshMaterial` / `MeshImage` / `MeshPart`。純粋・テストあり): glTF は `materials[].pbrMetallicRoughness` の `baseColorFactor` / `baseColorTexture` / `metallicFactor` / `roughnessFactor` / `metallicRoughnessTexture`、`normalTexture` (+ `scale`)、`emissiveFactor` / `emissiveTexture` (+ `KHR_materials_emissive_strength`) (絵は → `textures[].source` → `images[]`: 横のファイルの `uri` / `.glb` の `bufferView` / `data:` URI。同じ画像は 1 つ)・`alphaMode` / `alphaCutoff`。書いていない金属 / ざらざらは glTF の既定 (1 / 1)。OBJ は `mtllib` (名前に空白があればまず全体を 1 つの名前として、だめなら空白で分けて) の `.mtl` の `newmtl` / `Kd` / `d` / `Tr` / `Ns` (Blender の読み方で ざらざら = 1 − √(Ns/1000)) / `Pr` / `Pm` / `Ke` / `map_Kd` / `map_Ke` / `norm`・`map_Bump`・`bump` (法線マップとして。`-bm` が強さ) (オプションを飛ばす。`\` は `/` に。絵の場所は `.mtl` のフォルダから)、面ごとの `usemtl`。三角形は**材質ごとに並べ替えて** (`SortByMaterial`。最初に出てきた順・中の順は保つ) `parts` にする (描くのが材質ごとに 1 回で済む)。材質の無いモデルは `material = -1` の部分 1 つ (白)。`.mtl` が無い・無い名前は `warnings` に (形は読む)。絵はここでは**解かない** (WIC が要る。`Texture`)
  - 横のファイルの場所は `MeshFile::RelatedFile` (純粋・テストあり): モデルのフォルダから辿って `root` の中だけ。バッファーと `.mtl` はモデルのフォルダの下だけ、テクスチャはプロジェクトの `Assets` の中なら `../Textures/` も
- **テクスチャ** (`space3d/runtime/Texture`): **絵を解くのとミップマップ作りは別のスレッド** (`PictureDecoder`: 作業スレッド 1 本、頼まれた順。スレッドごとの WIC で解いて `MakeTexturePixels` (`TexturePixels.*`。純粋・テストあり: 2 × 2 の平均、色の絵は光として表で平均) まで)。UI のスレッドは `Renderer::UploadTexture(TexturePixels)` で GPU に写すだけ (4096 × 4096 で約 26 ms、解くのは約 0.2 秒が別のスレッドで — エディターの外で測った)。頼んだ側が `Job` (共有の結果) を持ち、`Done()` になったら写す。頼んだ物が捨てられた仕事は解かない。スレッドの中の例外は受け止めて「読めない」にする。`TextureCache` = 絵のファイルをフルパスごとに 1 回だけ GPU へ (4096 より大きければ WIC で縮める)。1 秒ごとにファイルの時刻を見て変わったら読み直す (できるまで前の絵のまま)。読めなければその絵なし + コンソールに理由 1 回 (ファイルが変わったらまた試す)。10 秒使われなければ捨てる。`ModelPaint` = 1 つのモデルの材質を `DrawMaterial` に: 中の絵 (`.glb` / `data:`) もキャッシュの `PictureDecoder` で解き、横のファイルの絵はキャッシュから。できるまでその絵なしで描き、シーンビューは `TextureCache::Waiting()` の間フレームを頼み続ける
  - **1 フレームに GPU へ写す時間の上限** (2026-11-12。`kUploadSecondsPerFrame` = 2 ms、Unity の asyncUploadTimeSlice と同じ考え。`Texture.h` の 1 か所): 写すたびに QueryPerformanceCounter (`platform::NowSeconds`) で測り、そのフレームで 2 ms を使ったら残りは次のフレームへ。ただし**フレームの 1 枚目はいつも写す** (大きな 1 枚で止まらない)。数え方は `UploadSlice` (純粋・テストあり)。前は 32 MB まで
  - **GPU の圧縮形式 (BC) で持つ** (2026-11-12。`BlockCompress.*`・`TextureFile.*`: 純粋・テストあり): 作業スレッドで「解く → ミップマップ → 圧縮」し、GPU にはそのまま写す (4〜8 分の 1 のメモリーと、写す時間)。形式は使い方と絵で決める (`ChooseFormat`): 不透明な色 BC1・透明のある色 BC7 (機能レベル 11.0 未満の GPU では BC3)・ノーマルマップ BC5 (シェーダーが z を x と y から作る)・灰色の数 (金属 / ざらざら) BC4 (シェーダーが .r を両方に)・それ以外の数 BC1。上の段の大きさが 4 の倍数でない絵は圧縮しない (Direct3D 11 の決まり)。`.meta` の取り込みの設定で変えられる (画像の「圧縮」・「大きさの上限」、モデルの「中の絵の圧縮」・「中の絵の大きさの上限」。`RM_STRUCT`)。使い方に合わない形式 (色に BC4 など) は自動に戻す
  - **圧縮したものはディスクに** (`<プロジェクト>/Cache/Textures/<アセットの ID>_<16 桁>.dds`。`Project::CacheDir()`): 名前は「アセットの ID (中の絵は `#番号` 付き) + 元のバイト列のハッシュ (FNV-1a 64) + 取り込みの設定 (JSON) + 使い方 + BC7 が使えるか + `kCacheVersion`」から。次からは作業スレッドがその DDS を直接読む (解く・圧縮をしない)。どれかが変われば別の名前なので、古いものを間違って読むことはない。フォルダを消しても作り直す。書くときは `.tmp` に書いてから置き換える
  - **BC7 は自分で書いた** (モード 6 だけ: RGBA を 1 本の線と 16 段で。透明も色と同じ細かさ)。bc7enc (MIT / パブリックドメイン) を入れようとしたが、取ってきたコードをビルドに入れることが権限で止められたので、自作にした。細かい色が混ざるブロックはモード 1〜3 (線を 2〜3 本) の方がきれい。あとで入れるなら `BlockCompress.cpp` の `EncodeBC7` だけを差し替える
  - 測った数 (エディターの外で、同じコードに 4096 × 4096 の絵 (ノイズ・透明あり) を 4 枚持つ .glb を読ませた): 前 (RGBA・32 MB ずつ) は 1 フレームが長くて 20〜24 ms・GPU に 356 MB。後は 1 回目 (作業スレッドで BC7 に圧縮: 15 秒) で長くて 6.3 ms、2 回目 (キャッシュから) で 4.8 ms・全部で 0.27 秒・GPU に 85 MB。2 ms を越えるのは BC7 の 4K を 1 枚写すのにそれだけかかるため (1 枚目はいつも写す)
  - **絵は共有で持つ** (`TextureRef` = `shared_ptr<const GpuTexture>`): `DrawMaterial` が絵を持ち続けるので、キャッシュが読み直して古い絵を手放しても、描いている途中の物は消えない
  - **GPU の作り直し** (`platform::Gfx::Generation`): シーンビューは世代が変わるとモデルとキャッシュを捨てる (`DropGpuIfNew`)。それに頼らないように、`GpuTexture::madeBy` (作った `Renderer::Id`。`Init` ごとに違う) が今の描き手と違う絵はキャッシュも `ModelPaint` も使わずに読み直す (中の絵のバイト列は持っておく)。1 つのキャッシュは 1 つの描き手で使う (シーンビューは `main_` の描き手で作り、プレビューは同じデバイスなのでそのまま使える)
- 画像を解く (`platform/Image`。ゲームにも入る): WIC (`IWICImagingFactory` → デコーダー → 必要なら `IWICBitmapScaler` (Fant) → `IWICFormatConverter`) で RGBA (テクスチャ) か事前乗算の BGRA (Direct2D) に。Hub のロゴを読む `LoadBitmapFromMemory` もこれを通す
- **メッシュの読み込み** (`space3d/runtime/Mesh` = 純粋・テストあり、`MeshFile` = ファイルを読むだけ): glTF 2.0 (`.gltf` + 別ファイル / 埋め込みの `data:` のバッファー、`.glb`) と OBJ と FBX (下)。外部ライブラリは使わない (glTF は JSON + バイナリーの表で、今ある `base/Json` で読める。必要なのは形だけ)。glTF は既定のシーンのノードをたどり、ノードの行列 (matrix か T・R (四元数)・S) を**頂点に焼き込んで 1 つのメッシュ**にする (鏡に映す行列なら三角形を裏返して表を保つ)。三角形・ストリップ・ファン。法線が無ければ面から作る (面積で重み付けしたなめらかな法線)。UV の (0, 0) は左上 (OBJ の V は上向きなので裏返す)。壊れたファイル (アクセサーがバッファーからはみ出す・インデックスが頂点の数を超える・GLB のチャンクがはみ出す) は日本語で理由を返す (はみ出しは全部確かめてから読む)。読まないもの: 材質の色と絵のほか (金属・ざらざら・法線マップ・光る色・サンプラー)・スキン・モーフ・アニメーション・疎なアクセサー・Draco
- **FBX** (`space3d/runtime/Fbx` と `Inflate`。純粋・テストあり): FBX SDK は使わない (エンジンに入れて配れる許諾ではない。要るのは形と色だけ)。バイナリー (7.x。7500 から長さが 64 ビット) とテキストを同じノードの木 (`FbxNode`: 名前・プロパティ・子) に読み、その木から形を作る。大きな配列は zlib で圧縮されているので、deflate を解く小さなコード (`Inflate`。RFC 1950 / 1951。固定・動的ハフマン・圧縮なしの 3 種、Adler-32 も確かめる) を自分で持つ。`Objects` の `Geometry` (Vertices・PolygonVertexIndex (負の数が多角形の終わり)・LayerElementNormal / UV / Material) を、`Connections` でつながった `Model` の行列 (FBX SDK と同じ T・Roff・Rp・Rpre・R (回す順)・Rpost⁻¹・Rp⁻¹・Soff・Sp・S・Sp⁻¹ と親、形だけの Geometric の行列) と `GlobalSettings` の軸 (UpAxis / FrontAxis / CoordAxis と符号 → Y が上の右手系) と単位 (UnitScaleFactor はセンチメートル、÷100 でメートル) で頂点に焼き込む。glTF と同じ `AppendPlaced` (鏡に映す行列なら三角形を裏返す) と `SortByMaterial`。材質は模型につながった順 (LayerElementMaterial の番号がそれを指す)。絵は Texture の RelativeFilename (絶対パスしかなければファイル名だけ) か Video の Content (中に埋め込まれた絵)。色 (DiffuseColor・EmissiveColor) はリニアの光の値として読む (Blender が書くのと同じ。glTF と同じ扱い)。金属・ざらざらは FBX の材質の書き方がツールごとに違うので、まだ読まない (既定の値)
- **読み込みの上限** (`Mesh.h` の `ReadBudget`。全部の読み込み (glTF・OBJ・FBX・`LoadMeshFile`) が、場所を作る前に聞く。純粋・テストあり): 壊れた・細工したファイルは、中身より何桁も大きなものを頼める (データの無いアクセサーが 0 バイトで 5000 万頂点、1 つのメッシュを 100 万のノードで置く、子を 2 回ずつ書いて 2^256 回たどらせる、FBX の配列が長さだけ大きい、同じつながりを何度も書く)。1 つのモデルにつき:
  | 上限 | 値 | 定数 |
  |---|---|---|
  | 頂点の数 (できあがったモデル全部) | 2000 万 | `kMaxModelVertices` |
  | 読むのに使うメモリー (ファイル・バッファー・JSON の木 (文字の 4 倍で数える)・頂点・インデックス・FBX の配列 (いつも double の 8 バイトで数える。圧縮なら解く前の分も)) | 2 GB | `kMaxModelBytes` |
  | たどるノード・つながりの数 (glTF のノード、FBX のノードとつながり) | 100 万 | `kMaxModelSteps` |
  | FBX の配列 1 つ (double にして) | 1 GB | `Fbx.cpp` の `kMaxArrayBytes` |
  | ファイル 1 つ | 1 GB | `MeshFile.cpp` の `kMaxFileBytes` |
  - 超えたら「読めない」(日本語の理由。シーンビューは箱 + コンソール)。`ReadBudget` は取り消しの印 (`std::atomic<bool>`) も持ち、聞かれるたびに見る: `MeshLoader::Cancel` とエディターを閉じるときは、読んでいる途中でも次に聞いた所で止まる (閉じるのが固まらない)
  - 読む作業スレッドの本体と `LoadMeshFile` は例外を受け止める (メモリー不足など → 「読めない」)。スレッドから例外が出るとプログラムごと終わるため
  - FBX の数 (double) は、整数や添字にする前に範囲を確かめる (NaN・とても大きな数を変換するのは C++ では未定義)。同じ「C: OO」のつながりは 1 回と数える。模型の親はつながりの表から 1 回だけ作る
  - FBX のシーンの組み立ては、つながりを最初に 1 回だけ索引にする (子 → 親の模型 `parentOf_`、親 → そのつながり `childrenOf_`: 模型の材質・材質の絵・絵の中身はここから引く)。ジオメトリごとに全部のつながりを見ない (10 万のつながりでもすぐ。テスト `Fbx_ManyLinksStayQuick`)
  - `Renderer::Upload` も、プラグインが直接作ったメッシュのために、インデックスが頂点の数の中か確かめる (`IndicesInRange`。読み込みは読むときに確かめている)
- **小さな物** (`View.cpp` の `Inverse`): 逆にできるかは、行列式を「列の長さの積」(行列式がなり得る一番大きな値) と比べて決める (1e-7 未満なら平ら = 逆にできない)。計算は double。だから一様に 1e-6 の大きさの物でも、選ぶ・法線の行列・ワールドの値の打ち込み (`FromWorld`) が働く (前は行列式の絶対値 1e-12 未満で「逆にできない」にしていて、大きさ 1e-4 以下で壊れた)。ギズモの大きさのドラッグは、一様も軸ごとも、始めの大きさの `kMinScaleFactor` (0.01) 倍より小さくしない (0 や裏返しにならない)
- **メッシュの部品** `MeshRenderer` (`game_x_3d/runtime/MeshRenderer.h`、`RM_STRUCT`): `model` (**アセットの参照** `AssetRef`、3D モデルだけ。7-3 章) と `castShadows`。新しいエンティティには付けない (足すと箱がモデルに変わる)
  - 参照ができる前の `.rmpf` の `"model": "Assets/…"` (相対パスの文字) は、`AssetRef` がその文字のまま持ち、`SoftwareHost::AssetFile` がパスとして開く (読み替えの手間なしで今までどおり出る。選び直すと ID に変わる)
- **シーンビューのモデルの覚え方** (`SceneView3D` の `models_`): 部品に書かれたパスごとに 1 つ。初めて要るときに読んで `Renderer::Upload` で **GPU に 1 回だけ**上げ (`GpuMesh`: 頂点・インデックスのバッファーと境界の箱と部分)、材質は `ModelPaint`、横のファイルの絵はシーンビューの `textures_` (`TextureCache`) で共有。同じパスの物はみんなそれを使う。1 秒ごとにファイルの更新時刻を見て、変わっていたら読み直す。10 秒使われなければ捨てる。**ファイルを読む (解く) のは別のスレッド** (`space3d/runtime/MeshLoader`: 作業スレッド 1 本 (`std::jthread`) と待ち行列。最初に頼まれたときに始まり、壊すときは読んでいる 1 つを待って残りを捨てる)。描くスレッドは毎フレーム `Take` で受け取り、`Renderer::Upload` と `ModelPaint::Load` (GPU と WIC) は**描くスレッドで**する (Direct3D と WIC を 2 つのスレッドから触らない)。読んでいる間は前の形 (初めてなら箱 + 「読み込み中…」)、待っている物がある間は `RequestAnimation` で描き続ける (読み終わったらマウスを動かさなくても差し替わる)。要らなくなった物 (外した・変えた・10 秒使われない) は `Cancel`。読めないファイルは**箱のまま**、コンソールに日本語で理由を 1 回 (無いパスは、インスペクターで打っている途中のパスで騒がないよう、次に見たときにまだ無ければ)。絶対パスは読まない
- **クリックで選ぶ・F で寄る・選んだ枠**は、箱なら単位立方体、モデルなら**境界の箱** (`IntersectPlacedBox` / 境界の真ん中と対角線の長さ)
- **影** (2026-11-11 に光の部品・カスケード・点光源とスポットの影を足した: 「カメラと光」の節。ここは一番初めの形の説明。平行光のシャドウマップは、光の部品があれば「影を落とす平行光の 1 つ目」の向き、無ければ決まった向き): 影を落とす物全部の境界の箱 (ワールド) を、光から見た正射影にぴったり収める (`DirectionalShadowMatrix`。純粋・テストあり。物が動かなければ影の行列も変わらないので、カメラを動かしても影がちらつかない)。2048 × 2048 の深度テクスチャ (`R32_TYPELESS` を D32 で書いて R32 で読む) に光から描き、絵を描くときに各ピクセルが光の行列で自分の深さと比べる。比べるのは**比較サンプラー** (`SampleCmpLevelZero`。2 × 2 の線形補間込み) を 3 × 3 か所で (PCF: 縁がぼける)。自分に影が落ちないように、傾きに比例した深度のずれ (`SlopeScaledDepthBias`)・テクセル 1 つ分の深さのずれ・法線の向きに 1.5 テクセルずらして見る (normal offset)。光の届く範囲の外とマップより奥は「光が当たる / 一番奥」(境界色 1 + 深さを 1 に切り詰め): 影は落とす物の真下 (光の向き) にしか落ちないので、それで足りる
  - **床**: Y = 0 の大きな見えない板 (裏からは出さない)。影の所だけ `theme::SceneShadow()` の色を半透明で重ねる。深度は書かない (グリッドの線が上に乗る)
  - オン / オフはシーンビューの左上の帯の「影」(`SceneViewState::shadows`。見え方なので `UserSettings`。プロジェクトのデータではない)。有効を外した物・`castShadows` を外したモデルは落とさない (受けはする)
- 2D の UI と 3D を混ぜる: Direct2D の描画を `Flush` してから、3D は**別のテクスチャ**に描き、そのテクスチャの DXGI サーフェスから Direct2D のビットマップを作って貼る (テクスチャが変わったとき・ウィンドウが変わったときだけ作り直す)。Direct3D の設定は描いた後に外す
- **シーンビューの口**: ゲーム制作は `kSceneViewPoint` に差し出された `SceneViewInfo` (空間ごとに 1 つ。どれを使うかは下の「3D と 2D の両方があるとき」) で、ゲームごと・空間ごとに `SceneView` を作り、パネルを描くたびに `Draw(c, rect, {host, scene, selection, select})` を呼ぶ。無ければ「プラグインが入ると…」の説明。**ゲーム制作は 3D を知らない**
- カメラの操作は Unity と同じ (右ドラッグ見回し + WASD/QE 飛行・中ドラッグ平行移動・ホイール・Alt+左ドラッグで回る・F で寄る・クリックで選ぶ)
- 入力の土台に足したもの: **マウスの動いた量** (`Input::mouseDX / mouseDY`) と**マウスの固定** (`Context::LockMouse`: 頼まれている間はカーソルを隠し、動くたびにドラッグを始めた点へ戻して、動いた量だけを数える。画面の端で止まらない)、**押し続けているキー** (`Input::keyDown` / `Context::KeyDown`。窓がフォーカスを失うと全部離す) と、**描き続ける** (`Context::RequestAnimation`: 頼まれている間は次のフレームをすぐ描く。普段は入力があったときだけ描く)。キー W / E / Q / F を足した
- **見え方を覚える**: `Software::LoadView` / `SaveView` (ソフトの「見え方」。プロジェクトのデータではないので未保存にも Undo にもならない) を、エディターが `UserSettings/Layout.json` のソフトの行の `"view"` に読み書きする (配置と同じとき: 保存と閉じるとき)。ゲーム制作はそれをシーンビューに渡す (`SceneView::LoadState` / `SaveState`)。中身は `SceneViewState` (カメラ `OrbitView`・道具・ローカル / ワールド・それぞれ / 中心・刻む幅・影。`RM_STRUCT` なので保存・読み込みと範囲の切り詰めはリフレクションから。知らないキーは書き戻す)
- 左上の帯 (移動 / 回転 / 拡大縮小・ローカル / ワールド・それぞれ / 中心・刻み・影) は幅が足りないと折り返す。「刻み」の箱 (`w::DrawSurface` の Popup の面に `TextField` 3 つと `Checkbox`) が開いている間は、その上のクリックをシーンに渡さず、外のクリックは閉じるだけ
- ★ **モデルの色とテクスチャ・アセットのパネルのサムネイル** (2026-11-11) は画面では未確認 (読み込みはテスト、シェーダーは fxc。エディターの外で同じ `Renderer` と `MakeModelThumbnail` にサンプルを描かせて、絵・色・くり返し・影・縁の光・透けたサムネイルが出ることを見た)
- ★ ギズモの外の輪・自由な回転・中心・刻みの箱、**メッシュと影** (2026-11-11) は画面では未確認 (シェーダーは fxc で全部コンパイルできることだけ確かめた。読み込みと影の行列はテスト。試し方は `docs/HOW_TO_TRY.md` の 7-2 章、サンプルのモデルは `docs/samples/models/`)

### カメラと光 (`game_x_3d/runtime/Camera` / `Light`、`space3d/runtime/Lighting`)

```
カメラの部品 Camera (RM_STRUCT)  ── ProjectionOf(カメラ, 縦横比) ─┐
エンティティのワールド行列       ── ViewFromWorld (大きさは捨てる) ─┴▶ RenderFrame の view / projection
光の部品 Light (RM_STRUCT)       ── ToRenderLight(光, ワールド行列) ──▶ space3d::Light ──▶ MakeLights ──▶ 定数バッファ Lights (b1)
                                                                                         └ 影の光 (1 つ) ──▶ シャドウマップ
```

- どちらも**つなぎ** (ゲーム制作 × 3D) の部品で、**エンティティの -Z** を向く (編集用のカメラ・`LookAt` と同じ。Transform の回転で回る)、+Y が上。大きさは見る向きに効かない
- **カメラ**: 投影 (透視 / 平行投影。列挙は名前で保存)・画角・見える大きさ (平行投影の縦の半分)・近い面・遠い面・背景。遠い面が近い面より手前でも描ける値にする (打っている途中で絵が壊れない)。純粋でテストあり
- **背景の色の関係**: カメラの「自分の背景の色を使う」が外れている (最初) と、**ゲームの設定の「背景の色」**で塗る。入れるとカメラの「背景の色」(`BackgroundOf`)。ゲーム全体の色を 1 か所で変えられ、カメラごとに変えたいときだけカメラに持つ
- **ゲームが見るカメラ** = ゲームの設定の「最初のカメラ」(`EntityRef`)。ゲーム制作は 3D を知らないので、渡すのはエンティティの ID と画面の縦横比と「設定を開く」だけ (`SceneViewHost::camera` / `aspect` / `openSettings`)。何がカメラかはつなぎが決める。選んでいない・エンティティが無い・カメラの部品か Transform が無い・有効でない のとき、ゲームビューは理由の文と「ゲームの設定を開く」を出す (勝手にほかのカメラを探さない: 何が映っているか迷わない)
- **シーンビューの印**: カメラ・光の付いたエンティティはその場所に印 (`w::Icon::Camera` / `Light`、色は `theme::SceneCamera()` / `SceneLight()`、選ぶとアクセント)。モデルの無いもの (`marker`) は箱を描かず、印のクリックで選ぶ (印から 11 ピクセル以内。印は物より先)。F は印のまわり 1 の大きさで寄る。カメラは視錐台の線 (遠い面は最大 10 まで: `ShownNear`。`FrustumCorners` で view-projection の逆行列から 8 つの角)、光は 平行光 = 小さな輪と向きの 5 本 / スポット = 届く距離までの円すい / 点光源 = 選んでいる間だけ届く距離の 3 つの輪
- **プレビュー**: カメラの付いた物を選んでいると、シーンビューの右下にそのカメラの絵 (ゲームの画面の形。幅はパネルの 3 割、140〜360)。Direct3D で描くのは**別の `Renderer`** (1 枚目の絵は Direct2D がまだ貼っていないので、同じ絵に描き直せない)。シェーダーと影の地図はシーンビューの描き手と共有する (デバイスごとに 1 つ: 下の「3D の描画」)。プレビューの上のクリックはシーンに渡さない
- **光** (`space3d::Light` → `MakeLights`。純粋でテストあり): 平行光 / 点光源 / スポット・色 × 強さ・届く距離・円すいの角度・影を落とすか。**光の部品が 1 つも無いときは、今までの「決まった向きの白い平行光 1 つ (影あり)」**(`RenderFrame::lightDirection`)。有効でない光は照らさない
  - **上限は 8 個** (`kMaxLights`。平行光も含む)。定数バッファの配列の大きさで、ピクセルシェーダーは光の数だけ回る。多いときは**平行光を先に** (全体を照らすので。階層の順)、**次に点光源・スポットをカメラにとって大事な順** (`LightWeight` = 明るさ (色の輝度 × 強さ) ÷ (1 + 目が届く距離の外にいる長さ²)。同じなら階層の順) に 8 個まで選び、残りは捨てる (シーンビューがコンソールに 1 回言う)。カメラが動くと選ばれる光が変わる (2026-11-12。前は階層の順の最初の 8 個)
  - **影** (`Lighting.h`。地図の作り方は純粋でテストあり。「影」ボタンで全部オン / オフ):
    - **平行光**: 影を落とす平行光の 1 つ目。影を落とす物全部が半径 `kSingleMapRadius` (25) の球に収まるなら、それにぴったりの正射影 1 枚 (`DirectionalShadowMatrix`。カメラが動いても変わらない)。広いときは**カスケード** (`PlanSunShadows`): カメラの近い面から `kShadowDistance` (150) までを 3 つに分け (`CascadeSplits`: 等比と等間隔を 0.75 : 0.25 で混ぜる)、それぞれの部分の 8 つの角を囲む球に合わせた正射影 (球なので向きを変えても大きさが同じ・中心をテクセル単位に切り捨てるので、カメラを動かしても影がちらつかない)。奥行きは光の側へ影を落とす物全部まで伸ばす。シェーダーは「目の前にどれだけ先か」(`viewForward`) で地図を選ぶ。最後の地図より先は影なし
    - **点光源**: 立方体の 6 面の透視の地図 (`PointShadowMatrices`。画角は 95 度: PCF の縁が隣の面と重なる)。シェーダーは光からの向きの |x| |y| |z| の一番大きい軸で面を選ぶ (+X −X +Y −Y +Z −Z の順)。**スポット**: 円すいを囲む透視の地図 1 枚 (`SpotShadowMatrix`。画角は円すいの 1.1 倍 + 4 度、170 度まで)
    - 点光源とスポットは地図 **`kLocalShadowSlices` (8) 枚**を光の順に分け合う (点光源 6・スポット 1)。足りない光は影なし (`shadowsLeftOut`。シーンビューがコンソールに 1 回)。近い面は届く距離の 1% (0.02〜0.5)
    - 透視の地図は奥行きが均一でないので、深度のずれは「テクセル 1.5 個分の世界の長さ」を深さの変わり方 f n / ((f − n) d²) で地図の深さに直し、シェーダーで距離 d で割る。法線の向きのずれ (normal offset) も距離に比例
    - 地図は種類ごとに**1 枚のテクスチャに並べたタイル** (アトラス。平行光は 2048 のタイルを 1 か 3 枚 = 最大 6144 × 2048、点光源とスポットは 1024 のタイル 8 枚 = 4096 × 2048)。テクスチャの配列 (`Texture2DArray`) を比較サンプラーで読むには ps_4_1 が要り、このエンジンは機能レベル 10.0 の GPU でも動かすため。最初に要るときに作る (使わなければメモリーを取らない)。PCF の 3 × 3 は自分のタイルの中に切り詰める
    - 影の絵には、**その地図の範囲に入る物だけ**を描く (`BoxInView` を光の行列で。カリングと同じ判定)
    - **描き直さない**: 地図ごとに「何を持っているか」の指紋 (光の行列 + 中に描く物それぞれの形の番号 `GpuMesh::serial` と置き場所の行列。64 ビット。物ごとの指紋はフレームに 1 回だけ作り、地図ごとにはそれを 8 バイトずつ混ぜる。4 バイトずつ掛けてたたむ `HashWords`: 前の FNV-1a は 1 バイトずつで、地図の数 × 物の数 × 72 バイト回っていた) を覚え、同じなら描かない (光と影を落とす物が動かなければ、点光源・スポットの地図も、物が狭い所に収まるときの平行光の地図も、毎フレームは描かない。カスケードはカメラに付いて動くので、カメラが動くと描き直す)。地図は種類ごとに 1 枚のテクスチャのタイルなので、タイルだけを消す (`ClearVS`: 深度 1 の三角形を深度のテストなしで)
    - **動く物と止まっている物** (2026-11-12): `Box` / `MeshDraw` の `moving` (シーンビューは、置き場所がこの 1 秒の間に変わった物: ギズモで動かしている・Play で動いている物に付ける)。動く物の入った地図は、**止まっている物だけの「層」**を別のテクスチャの同じタイルに取っておき (層の指紋が同じなら描き直さない)、地図のタイルには層を写してから (`CopyDepthPS`: 層の深さをそのまま `SV_Depth` に書く三角形。タイルの一部だけはテクスチャごとの写し (`CopySubresourceRegion`) ができないため) 動く物だけを描く。層のテクスチャは、初めて動く物が入ったときに作る。`moving` は手がかりだけで、付け忘れても絵は正しい (地図を丸ごと描き直すだけ)。影の深さは描く順に関係なく一番近いものが残るので、層 + 動く物と丸ごとの絵は画素まで同じ (`Bench3D.exe image … moving` で確かめた)
    - 地図の割り当ては選んだ順 (上の「上限は 8 個」): **影を落とす点光源は実際には 1 つまで** (6 枚使うので、残り 2 枚はスポット 2 つ分)。スポットだけなら 8 つ
  - **環境光** (`AmbientLight` の部品。最初の有効な物。無ければ `space3d::Ambient` の既定 = 前の見た目: 上 0.16・下 0.08。光の色と同じくリニアの値): 上からの色 (上を向いた面) と下からの色 (下を向いた面) を面の向き (0.5 + 0.5 × 法線の Y) で混ぜ、強さを掛ける。つやのある面の空の映り込みも同じ 2 色を映った向きで混ぜる (前は上 0.20 だったのが 0.16 になり、上を映す映り込みが少しだけ暗い)。値は `Lights` (b1) の `ambientSky` / `ambientGround`
  - シェーダーの色: PBR (`Shade`。material-texture のセッション、2026-11-11) の「環境光 + Σ 光ごとの拡散と GGX のハイライト × 影」。光 1 つ分は `LightAt` = 色 × 強さ × 弱まり (`FadeAt`: 平行光 1 / 点光源 (1 − 距離 / 届く距離)² / スポットはさらに縁から半角の 3/4 までなめらかに)。影は光ごとに `ShadowOf` (平行光の地図か、点光源・スポットの地図。無ければ 1)。光の値は定数バッファ `Lights` (b1)、影の地図の行列と大きさは `Shadows` (b2)。物ごとの `PerDraw` (b0) からは影の値を外した (`lightViewProj` は影の地図を描くときだけ)。床は、届いている光 (cos × 弱まり) の中で一番濃い影を出す。影の地図は t0 (平行光) と t5 (点光源・スポット)。t1〜t4 は材質の絵
- **カリング (いつもオン)**: `Renderer::Render` が、箱とモデルの境界の箱 (`WorldBounds`) を view-projection で調べ (`BoxInView`: クリップ空間で 8 つの角が全部「同じ面の外」なら外。純粋でテストあり)、外の物は絵に描かない。**影の絵 (シャドウマップ) には全部描く** (外の物の影が画面に落ちる)。シーンビュー (編集用のカメラ)・ゲームビュー・プレビュー・サムネイルのどれも同じ `Render` を通るので、全部に効く。数は `Renderer::LastStats()` (シーンビューの左上の帯の下に「描いた物 a / b」)。判定は物ごとに 8 点だけで、正確 (面に近い物を「見える」と言うことはあるが、見える物を外すことはない)
- **止まっているときのゲームビュー**: Play していなくても、`SceneViewHost::game` でシーン (`scene_`) を最初のカメラから描く。上に帯 (`DrawStoppedStrip`)
- **Play 中のカメラの切り替え**: ゲームが見ているカメラは `SystemContext::camera` (エンティティの ID。ゲーム制作は 3D を知らないので ID だけ)。`SystemRunner` が持ち (▶ で `SetCamera(最初のカメラ)`、`Reset` で 0)、システムが書き換えると次のシステム・次のフレームへ続く。ゲーム制作は Play 中は `runner_.Camera()` を `SceneViewHost::camera` に渡し、変わったらコンソールに 1 行。組み込みの部品「カメラを順に切り替える」(`game_x_3d/runtime/CameraCycle`。間隔ごとに階層の順で次の動いているカメラへ。純粋でテストあり) は画面で試すためのもの (スクリプトができたら同じ口を使う)
- 階層の絵: `ComponentInfo::icon` に "camera" / "light" (核の `tree::IconNamed`)。「最後に付いた部品の絵」なので、Transform の後に付けたカメラ・光の絵が出る。参照の欄の一覧の絵も同じ関数 (`tree::PictureOf`)
- ★ 画面は未確認 (2026-11-11。テストは投影・視錐台・光の値・保存。シェーダーは fxc でコンパイルできることを確かめた。試し方は `docs/HOW_TO_TRY.md` の 7-6 章)

### 2D 空間 (`plugins/rm_engine/space2d`)

- `Transform2D` = 位置 (Vec2)・回転 (度。**反時計回りが +**)・大きさ (Vec2)・**並び順** (int。奥行きの代わり: 大きいほど手前。**子は親の並び順に足す** (3D の子の Z が親に足されるのと同じ。グループごと手前に出せる))。平面は X が右・**Y が上** (Unity の 2D・数学と同じ)。画面の Y は下向きなので、ひっくり返すのはカメラだけ
- 行列 `Mat3` (2D のアフィン: 列ベクトル、`a b c d tx ty`)。`LocalMatrix` = 移動 × 回転 × 拡大 (3D と同じ順)、`WorldMatrix` = 親 × 自分、逆行列・行列式 (負 = 鏡)。`Decompose` (ワールド行列 → 位置・回転 (いまの角度に一番近い +360 の組)・大きさ (鏡なら Y が負))・`FromWorld` (打ったワールドの値だけを、親の逆行列でローカルに直す。3D と同じ考え)
- **何を手前に描くか** (`DrawOrder`): (ワールドの並び順, スプライトの並び順, 階層の順) の小さい順に描く (後ろ → 手前)。最後は階層で後ろの物が手前 (Unity と同じ)。安定ソート
- カメラ `Camera2D` = 真ん中の点・`zoom` (1 単位が何 DIP か。既定 100 = 100 ピクセル / 単位のスプライトが 1:1)・`rotation` (カメラが回ると絵は逆に回る。編集のカメラは回さない、ゲームのカメラはエンティティに付いて回る)。`ToScreen` / `ToWorld` / `ScreenMatrix`・`Pan` (絵がマウスに付いてくる)・`ZoomAt` (マウスの下の点を動かさない: 前後の差だけ真ん中を動かす)・`Frame`。格子の刻み `GridFor` (線の間が 12 DIP 以上になる 1・2・5 × 10^n の一番小さいもの。5 本 / 10 本ごとに濃い線)
- 当たり: `InsidePlacedBox` (点を物の逆行列で物の中へ戻し、箱と比べる。回っても鏡でも同じ 1 本)
- **ギズモ** (`space2d/editor/Gizmo2D`。3D の `gizmo` と同じ分け方: 形と当たりと変え方の計算だけ。描くのはシーンビューが同じ形 (`ShapeOf`) から): 矢印 X / Y と真ん中の四角 (自由に)・輪 (回転)・軸の箱と真ん中 (拡大縮小)。画面の上での大きさは決まった DIP (近づいても同じ大きさ)。回転はマウスの角度の差を毎回 ±180 に直して足す (何周でも数える)。刻み: 移動は今の格子の刻み、回転 15 度、拡大縮小 0.1 倍。当て方: 移動はワールドで動いた分を親の逆行列で、回転は親が鏡なら逆向き、大きさは物の軸でかける
  - **それぞれ / 中心** (`Pivot`、3D と同じ考え): 中心のときギズモは `Scene::Roots(選択)` の場所の平均 (`CenterFrame`、軸は最後に選んだ物)。`Apply(…, &frame)` は回転なら場所も中心のまわりに回し、拡大縮小ならギズモの軸ごとに中心からの距離をのばす
  - **刻み**: Ctrl で刻む (「いつも刻む」なら Ctrl でなめらか)。移動は「格子の目に合わせる」(今の格子の刻み) か決めた幅、回転・大きさは決めた幅。幅は見え方 (`SceneViewState2D`、範囲は `RM_PROPERTY` の Min / Max)。箱は `w::DrawSurface` の Popup に `w::Checkbox` と **`w::NumberField`** (数の欄: 入力中は打った文字、それ以外は値。数でない文字では変えない。核の部品に足した。★ 3D の刻みの箱も同じ部品にできる)
  - **四角で囲んで選ぶ**: 何も無い所から左ドラッグ。画面の上で、物の四角 (スプライトの角を画面に写した外接の四角・輪の四角) に少しでも触れた物を選ぶ。Ctrl で足す。四角は **`w::DrawSelectionBand`** (核の部品に足した: 画面のコードで四角を塗らない)
- 純粋でテストあり (`tests/TestSpace2d.cpp`)

### 2D の描画 (`space2d/runtime/Renderer2D`) とシーンビュー (2D)

```
ゲーム制作 「シーン」パネル ── kSceneViewPoint (space = "2d") ──▶ ゲーム制作 × 2D の SceneView2D
                                                                  ├ 2D 空間: 親子をたどってワールド行列・並び順・カメラ・当たり・ギズモ
                                                                  ├ 画像: SoftwareHost::AssetFile → WIC → Direct2D のビットマップ (ID ごとに 1 回)
                                                                  └ 2D 空間の Renderer2D: パネルの四角に直接 Direct2D で描く
```

- **描画は Direct2D で足りる**ので Direct3D を使わない (3D と違い、自分のテクスチャも持たない)。理由: UI と同じデバイスコンテキストに、回転・拡大・鏡・半透明の画像を GPU で描ける (`SetTransform` + `DrawBitmap`)。色を掛けるのは効果 `CLSID_D2D1ColorMatrix` (対角に色を置く。白なら効果を使わず `DrawBitmap` の不透明度だけ)。ドット絵は `NEAREST_NEIGHBOR`、ほかは `HIGH_QUALITY_CUBIC`。1 フレームのスプライトが何千にもなったら、そのときに Direct3D のまとめ描き (インスタンシング) を考える
  - 描く物の行列 = 画面の行列 (`ScreenMatrix`) × ワールド × 「画像の DIP → 物の中の単位 (真ん中が原点・Y を上に・反転)」。Direct2D は行ベクトルなので `Matrix3x2F(a, b, c, d, tx, ty)` にそのまま並ぶ
  - 背景の塗り・格子 (平面の線)・スプライト・枠 (上に重ねる線) の順。線の太さは画面の DIP (近づいても同じ太さ)
- **画像の読み込み**: **核の 1 本の道 `platform/Image`** (WIC。モデルのテクスチャ・アセットのサムネイルと同じ) で乗算済みの BGRA にして `BitmapFromImage`。Direct2D の 1 枚の限界 (16384) より大きい画像は縮めて読み、スプライトの大きさはファイルのピクセルで決める (縮めても大きさは変わらない)。2D の自前の読み込みは消した (2026-11-11)。ファイルを読んで解くのは画像ごとの `editor::Worker` で (2026-11-12)、届いたら UI のスレッドでビットマップにする (できるまで前の絵のまま、読んでいる間はフレームを頼む)。ビットマップは Direct2D の**デバイス**の物で、窓は全部同じデバイスなので、パネルを別ウィンドウに出しても作り直さない
- **シーンビューの画像の覚え方** (`SceneView2D` の `images_`): 3D のモデルと同じ形。アセットの ID ごとに 1 つ、1 秒ごとにファイルの更新時刻を見て変わっていれば読み直す、10 秒使われなければ捨てる、読めない・無いときは白 (色) の四角で、コンソールに日本語で 1 回
- **スプライトの部品** `Sprite` (`game_x_2d/runtime/Sprite.h`): 画像 (`AssetRef`、画像だけ)・色・左右 / 上下反転・並び順・1 単位のピクセル数 (大きさ = コマのピクセル ÷ これ)・横 / 縦のコマ数とコマ・くっきり。画像が無ければ 1 × 1 の色の四角
- **アトラス** (`space2d/runtime/Atlas`。純粋でテストあり): 画像を同じ大きさの格子に切る (`CellOf`: 番号は左上から、範囲の外は一回り、割り切れない分は最後の列・行が小さく、はみ出さない)。描くのは `SpriteDraw::part` の四角だけ: 色を掛けないときは `DrawBitmap` の元の四角、掛けるときは効果の出力を `DrawImage(…, 元の四角)`。★ 不ぞろいなコマ (詰めて並べたアトラス) はまだ
- **スプライトのアニメーション** (`SpriteAnimation`、部品とシステム「毎フレーム」): 遊んだ時間 (`RM_TRANSIENT`: 保存しない。Play のコピーの中だけで進む) から `AnimationCell` (コマの並び・1 秒のコマ数・繰り返す。純粋でテストあり) でスプライトの「コマ」を決める。■ で止めるとコピーごと捨てるので、コマは Play の前に戻る
- **シーンビュー** (`game_x_2d/editor/SceneView2D`): 格子と軸・スプライトを並び順で・スプライトの無い物は小さな輪 (画面で同じ大きさ。ゲームビューには出ない)・選んだ物の枠。操作は 2D のツールに合わせた: 右 / 中ドラッグで平行移動 (カーソルを隠さない: 絵がマウスに付いてくる方が 2D では分かりやすい)・ホイールでマウスの下に近づく・クリックで一番手前を選ぶ (Ctrl で足す / 外す)・**物をドラッグで動かす** (選んでいる物をつかめば全部、そうでなければその物だけ)・F・W / E / R / X。ドラッグ中は Transform 2D を直接書き換え、離したら `SetFieldCommand` (位置・回転・大きさ) を `CommandGroup` 1 つで積む (3D と同じ)。Esc で戻す
- 見え方 (`SceneViewState2D`: カメラ・道具・ローカル / ワールド・格子) は `UserSettings` に (3D と同じ `Software::LoadView` の道)
- **カメラ (2D)** (`game_x_2d/runtime/Camera2D`。純粋でテストあり): 見える大きさ (画面の縦の半分の単位)・自分の背景の色。ゲームビュー・Play は 3D と同じく**ゲームの設定の「最初のカメラ」**から、ゲームの画面の形 (`SceneViewHost::aspect`) で見る (`ViewOf`: 真ん中 = エンティティの場所、zoom = 絵の高さの半分 ÷ 見える大きさ)。無い・指していない・部品が無い・有効でないときは理由と「ゲームの設定を開く」(3D と同じ文の形)。シーンビューには映る範囲の四角。カメラはエンティティの場所と**回転**に付いていく (`ViewOf`: ワールド行列を `Decompose`。大きさは見える範囲を変えない: Unity と同じ)
- ゲームビュー: 3D と同じ (`SceneViewHost::game` で絵だけ・有効でない物は出さない・背景はゲームの設定の色かカメラの色)。部品「回り続ける (2D)」(`Spin2D`、複数可) とそのシステム
- **3D の上に 2D を重ねる** (ゲームビュー): ゲーム制作はまずゲームの空間のビューで描き、ほかの空間のビューに `SceneView::DrawLayer` (既定は何もしない) を順に頼む。2D は、カメラ (2D) の「3D の上に重ねる」が入った有効なカメラ (「最初のカメラ」がそれならそれ、違えば階層で一番上) があれば、同じゲームの画面の四角に**背景を塗らずに** (`RenderFrame2D::clear` の透明度 0) 描く。ゲーム制作は 3D も 2D も知らないまま (「重ねる」口があるだけ)。★ 2D のゲームの下に 3D (3D のビューの `DrawLayer`) はまだ
- ★ 未確認 (画面)。書き出したゲームでの 2D の描画は `game_x_2d/runtime/GameDraw2D` (2026-11-12。7-9 章)

### 3D と 2D の両方があるとき (シーンの空間)

```
SceneViewInfo { create, space = "3d" / "2d", label = 3D / 2D, order = 0 / 10 }   (つなぎが差し出す)
ComponentInfo { ..., space = "3d" / "2d" }                                       (Transform / Transform 2D)
GameSettings::space = "2d"   (プロジェクトのデータ。空 = order が一番小さいもの = 3D)
```

- **ゲームごとに 1 つ選ぶ** (ゲームの設定の `space`)。決めた理由: その選択で、**ゲームビュー** (と、後で書き出したゲーム) が何を映すか、**新しいエンティティにどちらの Transform が付くか**が変わる = プロジェクトの中身に効く。人ごとの見え方 (`UserSettings`) にすると、同じプロジェクトを開いた別の人で新しいエンティティの形が変わってしまう (Unity でも「2D / 3D」はプロジェクトの設定)
- **選び方**: 空間が 2 つ以上あるとき、「シーン」パネルの一番上に帯 (`w::Segmented`: 3D | 2D)。押すと `GameSettings::space` への `SetFieldCommand` = **Undo できる・未保存になる** (憲法 7)。Play 中は押せない。ゲームの設定のインスペクターには出さない (選べるものはプラグインが決めるので、列挙にできない)。値が知らない空間 (そのプラグインが無い) なら、文字はそのまま持って書き戻し、表示は既定 (一番小さい order) にする
- **ゲーム制作は空間の名前を知らない**: `"3d"` / `"2d"` は、つなぎどうしが合わせる文字にすぎない。ゲーム制作は `SceneViewInfo::space` と `ComponentInfo::space` と `GameSettings::space` が同じかどうかを見るだけ
- 新しいエンティティ: `onNewEntities` の部品のうち `space` が無い物と、今の空間の物だけを付ける (2D のゲームには Transform 2D、3D には Transform)
- 見え方は空間ごと (`Layout.json` のソフトの `"view"` の `"sceneViews": {"3d": …, "2d": …}`)。前の版の `"sceneView"` (1 つだけ) は既定の空間 (3D) のものとして読み、次の保存で `"sceneViews"` に移す
- シーンの中には両方の部品が混ざっていてよい (3D のビューは Transform の物だけ、2D のビューは Transform 2D の物だけを映す)。★ 両方を重ねて映す (3D の上に 2D の UI など) のは、カメラの部品ができてから考える

### ソフトのデータ

- `.rmpf` の `softwareData` (配列: `author` / `plugin` / `software` / `data`) に、ソフトごとの中身を持つ。`Software::LoadData` / `SaveData`
- データを保存したソフトのプラグインは、`.rmpf` の `plugins` に**自動で記録**される → そのプラグインが無いと開かない (RME_PLATFORM 5-a の「使用の記録は自動」)。既定のままなら書かない (開いただけでプラグインに縛られない)
- いま入っているもの: ゲーム制作の「ゲームの設定」(名前・目標 FPS・物理の刻み・重力・背景の色・画面 (幅 / 高さ / 表示のしかた / 垂直同期)・タグ)。「ゲーム」ビューの「ゲームの設定を開く」でインスペクターに出る。それと**シーンの一覧** (`data.sceneList`: シーンのアセット ID の並びと開いているもの)。設定が既定のままでシーンも空なら何も書かない
- **シーンは 1 つずつ別のファイル** (2026-11-12。`plugins/rm_engine/game_production/runtime/SceneFile.h`): `Assets/Scenes/<名前>.rmscene` (`{"kind": "rm_engine.scene", "format": 1, "nextId", "entities"}` = `Scene::Save` に kind / format)。アセットなので `.meta` と ID を持ち、`.rmpf` の一覧は ID で指す (動かしても名前を変えても外れない)。理由: `.rmpf` の上限 (`platform::kMaxFileBytes` = 256 MB) に近づかないため・保存を軽くするため
  - **保存**: ソフトは `SaveData(data, files)` で `.rmpf` に入れないファイルを渡す (`ProjectFileWrite`。プロジェクトのフォルダからのパス)。核 (`EditorScreen::Save`) はそれを 1 つずつ `WriteFileAtomic` で書いてから `.rmpf` を書く (`.rmpf` がまだ無いファイルを指すことが無い)。1 つでも失敗したら `.rmpf` を書かずにエラー。全部書けたら `Software::Saved()`。ロック (`.rmpf.lock`) はエディターが開いている間ずっと持っている
  - **変わったシーンだけ書く**: 書く中身の印 (`TextSign` = FNV-1a 64 ビット) を、読んだとき / 書いたときのファイルの印と比べる (`PlanSceneSave`)。Undo で戻して同じ中身なら書かない。新しいシーンは `.meta` (新しい ID) をシーンより先に書く (間に見直しが走っても別の ID が付かない)。書いたら `AssetOf` でその場で ID を取り込む
  - **読み込み**: 一覧の `open` (無ければ最初) のシーンだけを、ID → ファイル (`AssetFile`) で読む。開くときのアセットの見直し (`LookNow`) はソフトがデータを読む前に終わっている。読めない (無い・壊れている・新しい版の形式) ときは空のシーンで開き、**元のファイルは上書きしない**: 編集して保存すると新しいファイル (`Main 2.rmscene`、新しい ID) に書く。無くなったファイルの ID は、一覧の同じ場所を新しい ID に置き換える
  - **前の版のプロジェクト** (`data.scene` が `.rmpf` の中): そのまま読み (`TakeOldScene`)、次の保存で `Assets/Scenes/Main.rmscene` に分けて `scene` を消し `sceneList` を書く。その前に、分ける前の `.rmpf` を `<名前>.rmpf.before-scenes.bak` に 1 回だけ残す (もうあれば書かない)
  - 知らないキー: シーンのファイルの中 (`Scene` の extra と各エンティティの unknowns)・一覧 (`SceneList` は RM_STRUCT、`reflect::Unknowns`)・ゲームのデータ (読んだデータに上書きして保存) で全部残る
  - テンプレート: ゲームのテンプレートは `templates/<id>/Assets/Scenes/Main.rmscene` + `.meta` を持ち、新規作成でプロジェクトの `Assets/` に写す (`ProjectTemplate::folder`)。`template.json` の `project` には `sceneList` (その ID) だけ
  - ★ まだ: シーンを足す・切り替える画面 (今は一覧の 1 つ目を開く。ほかのシーンのファイルと ID は触らずに残る)

## 7-9. ゲームの書き出し (`src/game` + `editor/export` + `tools/make_gamekit.ps1`。2026-11-12)

設計: TestEngine NewEngineBluePrint 11-b / 11-b-2 (書き出したゲームはそれだけで完全に遊べる)、RME_PLATFORM 5-a「書き出しの条件」「書き出しを作り直す」流れ 1〜7、「書き出したゲームのアセットとコードを読めないようにする」(.rmpak)。

```
ビルド (RMGameKit.vcxproj)   ゲームに入る層 (base core platform ui game) と各プラグインの runtime/ をコンパイル
  └ make_gamekit.ps1      → <exe の横>/GameKit/  kit.json・lib/core.lib・lib/<作者>/<名前>/runtime.lib・反映する型の名前 (reflect/)
書き出し (ゲーム制作の「書き出し」パネル / --export-template)
  1 使うプラグイン = .rmpf の記録 + シーンと Prefab の部品の持ち主 + ゲームの空間の描き手 → 前提とつなぎを足す (ExportPlugins)
  2 main.cpp を生成 (使うプラグインの登録の C の名前と、反映する型の一覧だけ: GameMainSource)
  3 cl で main.cpp、rc で名前とアイコンのリソース → link: main.obj + game.res + core.lib + 使うプラグインの .lib だけ → <exe の名前>.exe
  4 Game.rmpak (game.json・シーン・使うアセットだけ)・Scripts.dll・VS の C++ ランタイムの DLL を横に
  5 exe にこの PC のパスが無いか確かめる
<exe の名前>.exe          src/game: ウィンドウ・Game.rmpak・登録 → ゲーム制作の「ゲーム」(GamePlayer) → 空間の描き手 (GameDraw)
```

- **使ったプラグインだけを入れる** (条件 1〜3): 保存のたびに、シーンと Prefab の部品を差し出したプラグインを `.rmpf` の `plugins` に記録 (`Software::UsedPlugins` → `PluginsOffering`)。書き出しはそれに今の中身の分を足して、インストールの計画と同じ数え方で前提とつなぎを足す。2D だけのゲームに 3D は入らない (テンプレートで確かめた: 2D 679 KB / 3D 766 KB)
- **リンクして名前を付けて作る** (コピーして名前を変えない): コンパイルするのは生成した `main.cpp` (数十行) だけ。**静的ライブラリの罠** (名前を呼ばれない .obj はリンカが捨てる = 登録が消える) は、生成した main が使うプラグインの登録関数 (`RM_RUNTIME_ENTRY` が作る C の名前 `rm_runtime__<作者>__<名前>`) と、反映する型 (`rmgen_generated::T_…`) を名前で並べることで避ける (`reflect::AllTypes` もそこで作る。エディターの `rm_all_types.cpp` はゲームの部品には入れない)。ゲームだけの登録 (ゲーム制作の「ゲーム」・3D / 2D の描き手) は `RegisterForGame` (C の名前の入口) で、エディターとテストはそれをリンクしない (`RuntimePlugins.cpp` は共通の `RegisterRuntime` だけ)
- **アイコンとゲームの名前はリソースで埋め込む**: `rc /c65001` (UTF-8) の `VERSIONINFO` (説明・製品名・元のファイル名) と `ICON` (ゲームの設定の「アイコン」の PNG をそのまま入れた .ico。今は PNG だけ)
- **リンカは VS**: `vswhere` で C++ のツールの入った VS を探し、`vcvars64.bat` の環境 (`cmd /c "vcvars64.bat && set"` で読む) で `cl` / `rc` / `link` を直に起動 (`platform/Process`)。メッセージは英語 (`VSLANG=1033`) で受ける (コードページで文字化けしない)。入口は `/ENTRY:wWinMainCRTStartup` (`wWinMain` が .lib の中にあるため)。PDB は作らない (`/DEBUG` なし・ゲームの部品の .obj もデバッグ情報なし)
- **C++ ランタイム**: エンジンは今 `/MT` (`RM.Common.props` の `RmCrt` の 1 か所。`kit.json` の `crt` で生成した main も同じに)。スクリプトの DLL は `/MD` なので、VS の Redist (`VC\Redist\MSVC\<版>\x64\Microsoft.VC*.CRT\*.dll`) を exe の横に置く (アプリごとの配置)
- **パスは書き出したフォルダからの相対だけ**: ゲームが読むのは exe のフォルダの `Game.rmpak` と `Scripts.dll` だけ。`.rmpak` の中のパスは `Assets/…` (`PortablePath`)。`game.json` に絶対パスがあれば書き出さない (`AbsolutePathsIn`)。できた exe をこの PC のパス (プロジェクト・エンジン・ユーザーのフォルダ) で探して、見つかれば知らせる (`tools/check_export.ps1` は失敗にする)
- **.rmpak** (`core/pak`): まとめる + 簡単な暗号化 (固定の鍵・書き出しの番号・ファイルの順番からの XOR の流れ。目次も)。中身の印 (FNV-1a) で壊れたら読まない。exe と同じ書き出しの番号 (入れる中身から作る: 同じ中身なら同じ番号) でなければ読まない。「使っているアセットだけ」: シーンと Prefab の中のアセットの ID (たどった Prefab の中も) とアイコン
- **ゲームの本体** (`src/game`、L5): 核とプラグインを知らない。プラグインを登録し、口 `rm.game.maker` (`GameInfo`) の 1 つ目にゲームを作らせる。フレームは ゲームの Update (スクリプト → システムと固定の刻み) → 描画 (D2D の上に。3D は Renderer3D の絵を貼る)。ウィンドウの大きさはゲームの設定の「画面」。`--smoke` で 5 フレーム描いて 0 で閉じる。失敗は `game.log` (exe の横) とメッセージボックス (`--smoke` では出さない)
- **書き出しの画面**: ゲーム制作のパネル「書き出し」(ウィンドウ メニュー。最初の配置ではコンソールとアセットの隣のタブ): インスペクターで ゲームの名前 (= ゲームの設定の「ゲームの名前」)・exe の名前 (空なら `ExeNameFrom` で作った名前を欄に出す。黙って変えない)・出力先 (この PC の設定: `Layout.json` のゲームの view。既定は `<プロジェクト>/Build/<exe の名前>`)。アイコンはゲームの設定のもの (表示と「ゲームの設定を開く」)。「書き出す」で作業スレッド (`std::jthread`)、進み具合の帯とログ。失敗は日本語の理由 + ツールの言葉 (最後の 30 行)
- **確かめ**: `RM_Engine.exe --export-template <作者> <プラグイン> <id> <作業フォルダ>` (ウィンドウを出さない: テンプレートからプロジェクトを作って書き出す) と `tools/check_export.ps1` (「ゲーム」「2D のゲーム」「3D のゲーム」を書き出して `--smoke` で起動、PDB と PC のパスが無いことも)。別の PC (Windows サンドボックス) は `HOW_TO_TRY.md` の手順でユーザーが確かめる
- ★ まだ (最初の版で残したこと):
  - **3D モデルを書き出したゲームで描く** (今はモデルの付いた物も箱で描く。`MeshFile` がファイルを読む作りで、モデルの横のファイル (テクスチャ・.bin) は中に名前があるため。`.rmpak` から読む口が要る)。2D の画像は `.rmpak` から読む (取り込みの設定の「くっきり」「大きさの上限」はまだ効かない)
  - **ゲーム用の形に変える (焼く)**: テクスチャの BC 圧縮 (別のセッション) のキャッシュの DDS を入れる・シーンをバイナリ (キー付き) にする

  - 2D を 3D の上に重ねる (カメラ (2D) の「3D の上に重ねる」)・シーンの切り替え・フォント・ライセンスの文章のフォルダ・開発者向けの「詰めない書き出し」・中身の一覧を出す道具
  - 出力先の「参照…」(OS のダイアログ)・書き出し画面の「ゲームに足される大きさ」(5 段階の色)
