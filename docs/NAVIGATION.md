# ナビゲーション (ナビメッシュと経路探し)

敵や村人が、壁をよけて目的の場所まで歩くようにする。シーンの形から「歩ける所」の地図
(**ナビメッシュ** = 歩ける床を多角形で表した網) を作り (**焼く** = 前もって計算してファイルにする)、
その上で道を探し (**経路探し**)、道に沿って動かす (**動く者** = エージェント)。3D と 2D の両方で使う。

段階 1 (焼く・経路を試す) を作った (2026-11-26、版 0.0.35。12 章)。地形 ([TERRAIN.md](TERRAIN.md))・タイルマップ
([TILEMAP.md](TILEMAP.md)) の設計図は同じ時期に別に書いている。名前や口の形は、3 つがそろったときに
合わせ直す (11 章)。

## 2. 作り方の大きな選択: 自作か、Recast / Detour か

**Recast / Detour** (リキャスト / デトゥール) は、多くのゲームエンジンが使っているナビメッシュのライブラリ
(zlib ライセンス: 名前を偽らなければ、売るゲームにも入れられる)。4 つに分かれている。

| 部分 | すること |
|---|---|
| Recast | 焼く: 三角形 → ナビメッシュ |
| Detour | 道を探す: A*・道をなめらかにする (ファネル)・一番近い点・光線 |
| DetourCrowd | 群れ: たくさんの動く者がお互いをよける |
| DetourTileCache | 動く障害物: ゲームの中で、変わった所の区画 (タイル) だけを作り直す |

### Recast 型の焼き方 (どちらを選んでも、この順番)

1. **細かい箱に分ける** (ボクセル = 小さな立方体。高さの柱の集まり)。三角形を箱に塗る
2. **歩ける箱を選ぶ**: 坂が急すぎない・上に頭がつかえない (背の高さ)・段差が登れる高さ
3. **壁から半径の分だけ削る** (体の太さの分、壁に近づけない)
4. **領域に分ける** (つながった床をいくつかのかたまりに)
5. **縁をたどって線にし、なめらかにする** (輪郭)
6. **凸の多角形にする** (へこみの無い多角形。これがナビメッシュ)
7. **細かい高さの三角形を足す** (坂や階段の上で、足が床に合うように)

大きな世界は**タイル** (区画。たとえば 48 × 48 マス) ごとに焼く。区画は別々に焼けるので、
作業スレッドに並べられ、変わった所の区画だけを焼き直せる。

### 比べる

| | 自作 (Recast 型) | Recast / Detour を `src/third_party` に |
|---|---|---|
| 手間 | 大きい。焼くの 7 段・A*・ファネル・群れ・動く障害物を全部書く | 包むコードだけ (Jolt の `PhysicsWorld` と同じ形) |
| 質 | 細い壁・重なった床 (橋の下)・階段で詰まりやすい。直すのに時間がかかる | 長く使われていて、こうした罠をもう踏んで直してある |
| 群れと動く障害物 | さらに大きい仕事 | DetourCrowd と DetourTileCache がある |
| 大きさ | 必要な分だけ | おおよそ 2〜3 万行 (取り込むときに数えて確かめる)。Jolt (約 11.4 万行) よりずっと小さい |
| ビルド | 今のまま | Jolt と同じ: `src/RMRecast.vcxproj` (静的ライブラリ・警告を切る・デバッグ情報なし)・`RM.Common.props` に読む場所・`RM_Engine` と `RMGameKit` の `ProjectReference`・`make_gamekit.ps1 -ExtraCoreLibs`・`layers.txt` の `third_party` の説明に足す |
| 結果が PC で変わらないか | 自分で気をつける | 小数 (float) の計算。同じ exe・同じ入力なら同じ。Jolt のような決まった印は無い |
| テスト | 全部自分で | 包んだ所と、つなぎの決まりをテストする |
| 学び・プレゼン | 中身を全部説明できる | 「使ったライブラリと、包み方・エディターの見せ方」を説明する。焼く途中の段 (箱・領域・輪郭) を見せる画面を作れば、中身も説明できる |

### おすすめ: **Recast / Detour を入れる。マス目の A* は自作**

1. 物理で Jolt を選んだのと同じ理由: 難しくて罠の多い計算は、確かな物を使う。時間はエディターの使いやすさ・2D・つなぎに使う
2. 群れと動く障害物まで最初から道がある
3. zlib ライセンスで、公開のリポジトリにも書き出したゲームにも入れられる (`licenses/` に文章を置く)
4. Recast の型は `navigation/runtime/*.cpp` の中だけ (pimpl)。外へは自分の型だけを見せる (憲法 4・10 の柵と同じ考え)
5. **自作するもの**: 2D のマス目の A* と、マス目の道をなめらかにすること (5-4)。小さく、純粋で、テストしやすい。
   3D の A* とファネルは Detour のものだけを使う (同じ計算を 2 本にしない: 憲法 2)
6. 取り込む物: Recast・Detour・DetourCrowd・DetourTileCache の 4 つ (見本のアプリ・テスト・`DebugUtils` は入れない。
   線を出す部分は自分で書く: 7 章)。版は取り込むときに決め、`src/third_party/RecastNavigation/README` などに版と元の場所を書く

## 3. プラグインの分け方

核はプラグインを知らない (憲法 10)。ナビの計算は 3D も 2D もゲーム制作も知らない形にして (アニメーションの
`animation` と同じ)、つなぎで空間とゲームにつなぐ。

| プラグイン | 中身 | 前提 |
|---|---|---|
| **ナビゲーション** `navigation` (新しい) | 焼く入力の型 (三角形・エリアの番号・つなぎの線)・焼く (Recast を包む)・焼いたデータの読み書き・道を探す (Detour)・群れ (DetourCrowd)・動く障害物 (DetourTileCache)・マス目の A* とならし。**純粋** (描画もファイルもシーンも無い) | なし |
| **ゲーム制作 × ナビゲーション** `game_x_navigation` (つなぎ) | 部品「ナビメッシュ」「ナビの動く者」「つなぎの線」「ナビのエリア」「ナビの障害物」「ナビの形」と 2D の部品・シーンの設定「ナビ」・システム「ナビ」・スクリプトの `RMNav.h`・「ナビ」タブ・シーンビューの線・`.rmnav` の書き出し。**ほかのプラグインに開く口**: 形を差し出す `rm_engine.game_x_navigation.source`・動かし方を差し出す `rm_engine.game_x_navigation.mover` | ゲーム制作・ナビゲーション・3D 空間・2D 空間 (物理・気候と同じく、1 つで 3D と 2D の部品を持つ) |
| **ナビ × 3D** `navigation_x_3d` (つなぎ) | 「メッシュ (3D モデル)」の形を焼く入力に (口 `source`)・3D のシーンビューでナビメッシュの面を塗る (段階 4) | ゲーム制作 × ナビゲーション・ゲーム制作 × 3D・3D 空間 |
| **ナビ × 物理** `navigation_x_physics` (つなぎ) | 動かないコライダー (3D と 2D) を焼く入力に・キャラクターで歩かせる (口 `mover`: `PhysicsWorld::Move`)・動く剛体を「よける相手」に | ゲーム制作 × ナビゲーション・物理 |
| **ナビ × アニメーション** `navigation_x_animation` (つなぎ) | 歩く速さと向きをアニメーターのパラメーターへ・(後で) ルートモーション | ゲーム制作 × ナビゲーション・ゲーム制作 × アニメーション |
| 地形 × ナビ `terrain_x_navigation` (つなぎ。TERRAIN.md 3 章) | 地形の高さを焼く入力に・地形の塗り (草・砂・沼) をエリアに | 地形のゲーム側・ゲーム制作 × ナビゲーション |
| タイルマップ × ナビ `tilemap_x_navigation` (つなぎ。TILEMAP.md 11-1) | タイルの「通れる / 費用」をマス目に・通れないタイルを 2D のナビメッシュの壁に | タイルマップのゲーム側・ゲーム制作 × ナビゲーション |

- `game_x_navigation` は**ゲーム制作 × 3D も ゲーム制作 × 2D も前提にしない**。2D だけのゲームに 3D を入れないため (ARCHITECTURE.md 7-9: 「2D だけのゲームに 3D は入らない」)。
  3D のモデルの形は `navigation_x_3d` が差し出す
- 物理は「メッシュ (3D モデル)」を名前で読んでいる (`physics/runtime/Shapes.h` の `MeshOf`)。ナビでは同じ読み方をもう 1 つ書かない (憲法 2): 型を知っている `navigation_x_3d` が読む
- 動く者を動かす人は 1 人だけ。キャラクターがあれば `navigation_x_physics`、無ければ `game_x_navigation` が Transform を直に動かす (4-3)

## 4. データ

どれも `RM_STRUCT` + `RM_PROPERTY` で書く (保存・読み込み・インスペクター・Undo が付いてくる。憲法 1・9)。
シーンのファイルは自己記述の JSON で、知らないキーは書き戻す (憲法 6)。

### 4-1. シーンの設定「ナビ」 (`NavSettings`)

| 項目 | 意味 |
|---|---|
| エージェントの型 (`agentTypes`) | 体の形ごとに 1 つ。型ごとに 1 枚のナビメッシュを焼く。番号 (`id`) で見分ける (並べ替えても消しても、ほかは変わらない。気候の種類と同じ) |
| エリアの種類 (`areas`) | 名前・色 (エディターで見せる色。ゲームには出ない)・通る費用 (1 = ふつう。2 = 2 倍遠く感じる)・通れない (`blocked`)。番号 0 は「ふつう」、番号 63 までは Detour の決まり |

エージェントの型:

| 項目 | 既定 | 意味 |
|---|---|---|
| 名前 | 人 | |
| 半径 | 0.3 m | 壁からこれだけ離れる (キャラクターの既定と同じ) |
| 高さ | 1.8 m | 天井がこれより低い所は通らない |
| 登れる坂 | 45 度 | |
| 登れる段差 | 0.3 m | |
| 飛び降りられる高さ | 0 m | つなぎの線を自動で作るときに使う (段階 4) |
| 細かさ (箱の大きさ) | 半径 ÷ 3 | 小さいほど細かく、焼くのが遅い。タブで「荒い / ふつう / 細かい」も選べる |

- シーンごとに持つ (今ある口 `kSceneSettingPoint` で足りる)。ゲーム全体で持つかは 11 章
- 2D のシーンでは「高さ」「坂」「段差」を出さない (`SceneSettingInfo::space` と同じ考えで、欄ごとに隠す道は実装のときに決める)

### 4-2. 部品

| 部品 | 中身 |
|---|---|
| **ナビメッシュ** (`NavMeshVolume`。3D) | どこを焼くかの箱 (大きさ・ずらし。Transform が掛かる)・エージェントの型 (番号。複数)・焼く物 (メッシュ / 動かないコライダー / 地形 のどれを入れるか)・**焼いた物** `AssetRef baked` (`.rmnav`)。範囲が重なっても別々に焼く |
| **ナビメッシュ 2D** (`NavMeshVolume2D`) | 長方形の範囲・型・焼く物 (コライダー (2D) / タイルマップ / 手で描いた「歩ける形」)・焼いた物 |
| **ナビの動く者** (`NavAgent`。3D と 2D 共通。Transform か Transform 2D の物に付く) | エージェントの型・速さ (3.5 m/s)・加速 (8 m/s²)・回る速さ (360 度/秒。0: 向きを変えない)・止まる距離 (0.1 m)・着く前にゆるめる (切ると全速で着く)・よける (しない / ふつう / ていねい)・よける優先度 (0〜99。小さいほうが道をゆずられる)・通れるエリア (エリアの番号の集まり)・つなぎの線を自分で渡る (切るとイベントだけ)・道を探し直す間 (秒)。スクリプトが頼んだこと (行き先・止まる) は `RM_TRANSIENT` で持つ (`ParticleSystem.h` と同じ) |
| **つなぎの線** (`NavLink`) | 始め (自分の位置)・終わり (ずれ、または別のエンティティ)・両方向・幅・エリア・渡り方 (歩く / 跳ぶ (放物線) / スクリプトにまかせる)・使える (扉のように、スクリプトで切れる) |
| **ナビのエリア** (`NavArea`) | 形 (箱 / 円柱。2D: 長方形 / 円)・エリアの番号。焼くときに、その中の床をそのエリアにする (沼・道路・入ってはいけない所)。「閉じている」を切り替えると、焼き直さずに通れなくなる (扉。Detour の多角形の印) |
| **ナビの障害物** (`NavObstacle`) | 形 (円柱 / 箱)・大きさ・**止まったら穴をあける** (止まって 0.5 秒たつと、まわりの区画を作り直して道から外す。動いている間は、よける相手になるだけ) |
| **ナビの形** (`NavGeometry`。付いていなくてもよい) | 焼く物を変える: 入れない / 歩けない (壁だけ) / エリアを決める。付いていない物は、ナビメッシュの決まりどおり |

- **動く者の体の値を 2 か所に書かない** (憲法 2)。半径・高さ・坂・段差は「エージェントの型」だけが持つ。
  同じ物に物理の「キャラクター」があって値が違うときは、インスペクターに印と「キャラクターに合わせる」(型の値をキャラクターの値にする。Undo の 1 件) を出す
- 焼く物の「動かない」: ナビメッシュの範囲の中で、動く剛体・キャラクター・ナビの動く者・ナビの障害物を持たない物 (自分も親も)。
  動く物はよける相手か障害物にする

### 4-4. 焼いたデータ `.rmnav`

- **アセット**。既定は `Assets/Navigation/<シーンの名前>_<範囲の名前>.rmnav` と `.meta`。部品「ナビメッシュ」が `AssetRef` で指す

- 形は `.rmmesh` と同じ**キー付きのチャンク** (知らないチャンクは飛ばす)。頭は JSON (`.rmimage` と同じ考え: 中身が自分を説明する)

| チャンク | 中身 |
|---|---|

- 焼いたときの型の値と、今の値・形の指紋を比べて「**古い**」を出す (タブとインスペクター)。古くてもゲームは動く (焼いた物を使う)
- 同じ入力なら同じバイトになるように焼く (区画の順を決める・時刻を入れない)。テストで確かめる

## 5. ランタイム (純粋な計算を離してテストする: 憲法 5)

### 5-1. 焼く (`navigation/runtime/Bake.*`)

```
NavInput (三角形・エリア・つなぎの線) + 型 + 範囲  →  Bake(…, stop_token, 進み具合)  →  NavData (区画の並び)
```

- 区画ごとに Recast の 7 段 (2 章)。区画は互いに関係しないので、作業スレッドに並べる (5-6)
- 「ナビのエリア」は 4 段の前に箱 / 円柱の中の床へ番号を塗る (Recast の `rcMarkBoxArea` など)
- **途中の段を見せる**: 頼まれたとき (タブの「焼く途中を見る」) だけ、箱・領域・輪郭を線で残す。エディターだけで、`.rmnav` には入れない
- 2D: 2D の形は**平らな 3D** にして同じ道で焼く (平面の X, Y → ナビの X, Z。壁は厚さのある箱にする)。焼く道を 2 本にしない (憲法 3)。
  向きを写す関数は `game_x_navigation` の 1 か所

### 5-2. 道を探す (`navigation/runtime/Query.*`。Detour を包む)

| 関数 | すること |
|---|---|
| `FindPath(始め, 終わり, 通れるエリア, 費用)` | 一番近い多角形を探し → **A*** (多角形から隣の多角形へ、費用の小さい順に広げる探し方) → 通る多角形の並び (通路) |
| `Straighten(通路)` | **ファネル** (漏斗。通路の中で、角だけを曲がるようにひもを張る) → 角の点の並び |
| `Raycast(a, b)` | a から b へまっすぐ歩けるか |
| `ClosestPoint(p, 半径)` | ナビメッシュの上の一番近い点 (クリックした所へ行く・落ちた物を戻す) |
| `RandomPoint(中心, 半径)` | 歩ける所のでたらめな点 (うろうろする敵) |

- 長い道は**分けて探す** (Detour の sliced: 1 刻みに調べる多角形の数の上限。既定 1 刻みに全体で 2000)。終わるまで `PathPending()` が真
- 行き先がナビメッシュの外なら、一番近い点まで行く (`PathPartial()` が真)

### 5-3. 動く者と群れ (`navigation/runtime/Crowd.*`。DetourCrowd を包む)

1 刻みごとに:

1. 行き先が変わった・道を探し直す間が過ぎた・通路がふさがれた → 道を探す (5-2)
2. 通路の先の角へ向かう「望む速さ」を作る (着く前にゆるめる・止まる距離)
3. **よける**: まわりの動く者と障害物を見て、望む速さの近くの速さをいくつも試し、ぶつかりにくい物を選ぶ
   (DetourCrowd の速さの候補を試すやり方。RVO = お互いが半分ずつよける考えに近い)
4. 速さと位置を出す。位置はナビメッシュの面の上を進める (壁を抜けない)

- 群れは `Scene::PlayState("rm_engine.game_x_navigation.world")` に置く (物理の世界と同じ: Play のコピーと一緒に捨てる)
- 動く者の数の上限: 既定 128 (シーンの設定。超えたら警告。黙って止めない)
- テスト: 正面から来る 2 人がすれ違う・狭い通路で順番に通る・止まる距離・着いたら止まる

### 5-4. 2D のマス目 (`navigation/runtime/GridPath.*`。自作)

マスごとに動くゲーム (RPG・将棋のような戦略・倉庫番) 用。ナビメッシュは使わない。

- **A***: マス目の上で。4 方向か 8 方向。斜めは角を削らない (壁の角をすり抜けない)。費用はマスごと (タイルマップが答える)。
  見積もり (残りの距離の当て推量) は 4 方向でマンハッタン距離 (縦 + 横)、8 方向でオクタイル距離 (斜めを √2 で数える)
- **ならし** (自由に動くとき): 見通せるマスを飛ばして点を減らす (線の上のマスが全部通れるか調べる)
- **予約**: 次に入るマスを予約し、ほかの動く者は待つか別の道 (マス目ではよけるの代わり)
- 純粋。テスト: まっすぐ・壁を回る・行けない・斜めの角・費用の高いマスを避ける・同じ費用なら毎回同じ道

2D で**自由に動く**ゲーム (上から見るアクション) は、コライダー (2D) とタイルマップから平らなナビメッシュを焼き (5-1)、3D と同じ 5-2・5-3 を使う。

### 5-5. つなぎの線・扉・動く障害物

- **つなぎの線**: 焼いたナビメッシュに「ここからここへ跳べる」線を足す (Detour のオフメッシュリンク)。
  動く者は線の始めに来ると、渡り方に従う: 歩く (まっすぐ)・跳ぶ (放物線。高さは距離から)・スクリプトにまかせる (イベント `NavLink` を送って待つ。
  スクリプトが `CompleteLink()` を呼ぶと続ける)。線の「使える」を切ると、その線を通る道を探さない
- **扉**: 「ナビのエリア」の「閉じている」→ その中の多角形に印を付ける。焼き直さないのですぐ効く
- **動く障害物**: 「ナビの障害物」が止まったら、まわりの区画だけを作り直す (DetourTileCache。1 刻みに作り直す区画の数に上限)。
  動いている間は、よける相手になるだけ (毎刻み作り直すと重い)
- 自動のつなぎの線 (段差から飛び降りる・すき間を跳ぶ) は焼くときに見つける (段階 6)

### 5-6. 重さ

| 何 | どこで |
|---|---|
| エディターで焼く | 作業スレッド (`editor::Worker`)。中で区画を `std::jthread` 数本 (CPU の数 − 1、多くて 8) に分ける。止める合図で途中でやめる (古い結果を当てない)。UI スレッドで写したシーンだけを読む |
| 焼き直し (変えた所だけ) | 形の指紋が変わった区画だけ |
| ゲームの中の道探し | 分けて探す (5-2)。1 刻みに上限 |
| ゲームの中の動く障害物 | 1 刻みに作り直す区画の上限 (既定 4) |
| 群れ | まずゲームのスレッドで。数百人で重くなったら作業スレッドへ (段階 7) |
| 書き出したゲーム | 焼かない (読むだけ)。ゲームの中で作った地形を焼くのは段階 7 |

- デバッグのパネル (`rm_engine.game_production.debug_info`) に: 動く者の数・待っている道探し・1 刻みの時間・作り直した区画

## 9. 1 フレームの順番

今のコード (`GamePlayer.cpp` の `Update`) の順番に入れる:

1. **スクリプトの Tick**: `SetDestination` などをためる
2. **Fixed の刻み** (0〜8 回):
   1. システム「ナビの世界」(Fixed・order -20): 焼いた物を読む (最初だけ)・扉とエリアの費用・止まった障害物の区画を作り直す (上限まで)
   2. システム「ナビの動く者」(Fixed・order -10): Transform から今の位置を読む (物理やスクリプトが動かした分) → 道を探す (上限まで) → 群れ (よける) →
      望む速さを動かし方へ: キャラクターがあれば `navigation_x_physics` が `PhysicsWorld::Move`、無ければ Transform (2D は Transform 2D) を直に、面の上に置く
   3. 物理 (Fixed・order 0): キャラクターが坂・段差・ぶつかりを見て歩く
3. **Frame のシステム**:
   1. 「ナビ × アニメーション」(Frame・order 90): 動く者の今の速さ → アニメーターのパラメーター (`speed`。向きは体から見た `moveX` / `moveY`)
   2. アニメーション (order 100)・骨に付ける (110)
4. **イベント**: 「着いた」「つなぎの線に来た」→ `OnEvent`
5. 描く

- Fixed に置く理由: 物理のキャラクターと同じ刻みで動く (速いフレームでも遅いフレームでも同じ道)。物理の前なので、その刻みで渡した速さがすぐ効く
- 止まっているエディターでは動かさない。タブの「経路を試す」だけが道を探す

### ほかの設計図と関わる点

- **地形 (TERRAIN.md)**: 地形は焼く入力の 1 つ (口 `source`)。決めること: 高さの地図をどの細かさの三角形にして渡すか (ナビの箱の大きさに合わせて間引く)・穴・塗りの層をエリアの番号にするか (沼・水は通りにくい)・地形を変えたときに「変わった範囲」を知らせる道 (区画だけ焼き直す)・広い地形の区画の大きさ・木や岩を障害物に入れるか
- **タイルマップ (TILEMAP.md)**: タイルに「通れる」「費用」を持たせる (その欄の名前と、どこに書くか: タイルの種類か、マスごとか)。マス目の口 `grid` (マスの大きさ・原点・「このマスは」) と、自由に動くゲーム用に通れないタイルを壁として `source` に渡すこと。斜めのマス・六角形のマスがあるなら A* も合わせる
- **アニメーション (ANIMATION.md)**: 速さのパラメーターはアニメーションのシステム (Frame・order 100) より前 (90) に入れる。2D で混ぜる状態 (段階 4) は向きの `moveX` / `moveY` で使える。ルートモーション (3-5・段階 5) ができたら「動いた分」をナビへ戻す道 (ナビは道を決め、動くのはクリップ) を 2 つの設計図で合わせる。ルートモーションも物理のキャラクターを動かすので、**キャラクターの `Move` を呼ぶのは 1 人だけ**の決まりを両方に書く。3-10 の「Fixed → Tick」はコードの順番 (Tick → Fixed → Frame) に直したほうがよい

### 設計から変えたこと (実装で決めた)

- 三角形の表の向き: エンジンの表 (3D 空間の `FaceOut`: (b - a) x (c - a) が外) と Recast の床の向きは同じなので、裏返さずに渡す
- 口 `source` の形: `collect(NavSourceContext&, std::vector<NavShape>&)` (シーン・ワールド行列・範囲・アセット・やめる合図を 1 つにまとめた) と、
  `fingerprint(scene, worlds, assets, hasher)`・省略できる `moves(entity)` (動く物を知っているのは物理なので、物理のつなぎが答える)。エリアの番号と
  ナビの形の決まりは ゲーム制作 × ナビゲーション が 1 か所で当てる (口は三角形とエンティティだけを返す)
- エリアの番号: 種類の id 0 (ふつう) は Detour の 63、1 .. 62 はそのまま。焼いた多角形の番号 0 は「歩けない」(Recast の決まり)
- 部品の欄の型とエリアは、ドロップダウン (`ComponentLook::choices` は文字の欄) のため、id を文字で持つ ("1")
- `.rmnav` の HEAD に「焼くのにかかった時間」は入れない (同じ入力で同じバイトにするため)。時間はタブに出す
- 指紋は区画ごとではなく範囲ごとに 1 つ (区画ごとは「変わった所だけ焼き直す」(段階 4) のときに)。範囲の外の物を動かしても「古い」になることがある
- 既定のファイルの名前は `Assets/Navigation/<範囲の名前>.rmnav` (重なれば `_2` …)。シーンの名前はタブから分からないので入れていない
- 範囲は Transform の位置と大きさを掛けた箱を囲むワールドの軸の箱 (回転は囲む箱になる)
