## 0. 準備

**ビルド**

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build.ps1
```

- 本体は `build\bin\x64\Debug\RM_Engine.exe` にできる
- Visual Studio で `RM_Engine.sln` を開いても動かせる (スタートアップは RM_Engine)
- `RM_Engine.exe --project <ファイル>.rmpf` で、そのプロジェクトを開く (確認のために Hub は一度出る: 5 章)
- 「デバッグ」メニューは Debug ビルドにだけ出る

**ファイルの置き場所**

| 場所 | 中身 |
|---|---|
| `%APPDATA%\RM_Engine\hub.json` | 最近のプロジェクト・「この状態が変わるまで表示しない」の記録・オプション (`options`) |
| `build\bin\x64\Debug\Lang\en.json` / `Plugins\…\lang\en.json` | 英語の表 (ビルドで写る) |
| `build\bin\x64\Debug\RM_Engine.files.json` | エンジンのファイルの一覧と SHA-256 (整合性の確認に使う。ビルドのたびに作る) |
| `RM_Engine\Project\` (リポジトリのフォルダ) | 新しいプロジェクトの既定の保存先。中身は git に入らない |
| `%LOCALAPPDATA%\RM_Engine\Logs\editor.log` | ログ (起動ごとに上書き)。エディターのコンソールと同じ中身 |
| `%LOCALAPPDATA%\RM_Engine\Engines\<エンジン>\Plugins\<作者>\<名前>\` | インストールしたプラグイン |
| `build\bin\x64\Debug\Plugins\` | エンジンが持っているプラグイン (ビルドで写される) |
| `<プロジェクト>\<名前>.rmpf` | プロジェクトファイル (JSON) |
| `<プロジェクト>\Assets\` | 素材 |
| `<プロジェクト>\UserSettings\Layout.json` | パネルの配置 (個人の設定) |

## 0-2. 見た目 (全部の画面)

> パネルの縁 (2 本の線・くっついた角だけ四角) は画面では**未確認** (ビルドとテストは通っている)

単色の四角をやめて、テーマの色にグラデーションを掛けた。色合いは前と同じ (黒でも白でも)。見てほしい所:

- **ボタン**: 上が少し明るく下が少し暗い。上の縁に細い明るい線。マウスを乗せると明るくなり、押すと上下が逆 (へこむ) になって文字が 1 ドット下がる。「新規作成」などの赤いボタンも同じ形
- **入力欄・チェックボックス**: へこんだ形 (上が暗い)。入力中は赤い枠と、その外に薄い赤の輪
- **Hub の左のページ (プロジェクト / プラグイン / アップデート情報 / オプション) とプロジェクトの一覧**: 角丸の箱ではなく、端から端までの行を線で区切っただけ。行のどこを押してもよい (行全体がボタン。カーソルが手の形になる)。乗せると薄いグラデーション、選ぶと赤みのグラデーション + 左端に赤い線。プロジェクトの行は少し高く、文字も少し大きい
- **ほかの一覧の行** (階層・メニュー): 角丸の行。乗せると薄いグラデーション、選ぶと赤みのグラデーション + 左に赤い線
- **オプションの「設定」**: 4 つの欄がそのまま並び、欄の横にスクロールバーは出ない
- **タブ** (パネル・ソフト): 選んだタブが盛り上がり、下に赤い線
- **メニュー・ダイアログ・ツールチップ・ドラッグ中の札**: ぼけた影が付いて浮いて見える。ダイアログは題の帯が付いた
- **印**: Hub の行の「⋯」、タブの「×」、インスペクターの「⋮」、階層とインスペクターの「▾ / ▸」、並べ替えの矢印、メニューのチェックが、線で描いた印になった (箱の真ん中に来る)
- **インスペクターの部品の見出し**: ボタンと同じ盛り上がった帯。左の ▾ / ▸ が開閉
- **メニューバー・ソフトのタブの列・ステータスバー・Hub の左の欄**: ゆるいグラデーションの帯
- **パネルの縁** (エディターのパネル・Hub の箱・別ウィンドウに出したパネル): 2 本の線で縁取る
  - **外側に暗い線** (背景より暗い)。並んだパネルのあいだは、この暗い線 **1 本だけ** で四角く区切られる (前の 4 ドットのすき間は無くなった)
  - **内側に細い明るい線**。上がいちばん明るく、下に行くほど薄くなるが、下の辺も背景よりは明るいので縁が見える
  - **角**: 何ともくっついていない角だけ丸い。例: 左右に 2 つ並んだら、左のパネルは左上と左下、右のパネルは右上と右下だけが丸く、くっついている側は四角。上下・3 つ以上に分けても同じ (くっついている角はすべて四角)。パネルが 1 つだけのウィンドウは 4 つの角が全部丸い
  - **区切りの線をつかむ**: 線は 1 ドットだが、線の両側 3 ドットまでつかめる (カーソルが ↔ / ↕ に変わる)。乗せると線が明るく、ドラッグ中は赤くなる
  - 確かめ方: エディターを開き、パネルを左右・上下に分ける (タブをパネルの端へドラッグ) → 角の丸さ・区切りの線・下の辺の縁を見る。オプションで「白」にしても縁が見えるか
- オプションで「白」にすると、同じ形が明るい色で出る

## 1. Hub

**ウィンドウ**

- 起動すると「RM Engine Hub」が出る (1280×760、最小 980×600)
- 左のサイドバーにロゴ、「プロジェクト」「プラグイン」「アップデート情報」「オプション」、版 (0.0.1)

**プロジェクトのページ**

- **新規作成** (Ctrl+N) でダイアログが開く (左にテンプレートの木、右に選んだテンプレートの説明と名前・保存先。下の「テンプレートの木」)。名前の欄には最初からカーソルが入っている
  - 保存先は欄に直接書くか「参照…」で選ぶ。下に、作られるパスが出る
  - 既定の保存先は**毎回** エンジンのフォルダの `Project` (ソースからビルドした exe なら `RM_Engine.sln` のあるフォルダ = `C:\Users\…\RM_Engine\Project`、配った exe なら exe の横)。「参照…」でほかの場所にしても、次の新規作成ではまた `Project` に戻る
  - Enter で作成、Esc で閉じる
  - 作ると `<保存先>\<名前>\<名前>.rmpf` と `Assets\` ができ、エディターが開く
- **名前のエラー表示** (試してみる):
  - 空
  - 65 文字以上
  - `\ / : * ? " < > |` を含む
  - `CON` `NUL` `COM1` などの予約名
  - 先頭が空白
  - 末尾が `.` か空白
- **開く…** (Ctrl+O): `.rmpf` を選ぶダイアログ
- **一覧**
  - 検索欄で名前・場所を絞り込む
  - 見出し (名前 / 更新日時 / 場所) を押すと並べ替え、もう一度押すと逆順
  - ダブルクリックか、選んで Enter で開く。F5 で読み直す
  - 読み直しは作業スレッドで (2026-11-11。画面では**未確認**): 一覧はすぐ出て、まだ読んでいない行は更新日時の所が「読み込み中…」(薄い字)。読めた行から名前と日付が入り、全部読めたら日付で並ぶ。届かないネットワークのパス (例 `\\存在しないPC\共有\a.rmpf`) が一覧にあっても Hub は固まらない (その行だけ「読み込み中…」のまま、やがて「見つかりません」)。テーマや言語を変えても読み直さない
- 一覧は画面の背景色のまま (灰色の板は無い)。見出し (名前 / 更新日時 / 場所) の下に線が 1 本。マウスを乗せた行・選んだ行だけ色が付く
- **行の右端の「…」ボタン (点 3 つが上下の真ん中) か右クリック**のメニュー
  - 開く
  - 名前を変更… (F2。ファイルが見つからない行では押せない)
  - エクスプローラーで表示
  - 一覧から外す (ファイルは消さない)
- **ファイルが消えたプロジェクト**は「見つかりません」と出る。開こうとするとエラーになり、そこからも一覧から外せる

**テンプレートの木** (画面では**未確認**。ビルドとテストは通っている)

- 新規作成のダイアログの左に、テンプレートが木で並ぶ:
  ```
  白紙
  ゲーム                ← 3D と 2D の両方。空のシーン
    3D のゲーム         ← カメラ・光・床・箱
    2D のゲーム         ← カメラ・地面 (緑の四角)・プレイヤー (黄色の四角)
  ```
  最初は「白紙」が選ばれている。行を押すと右に名前・説明・**使うプラグイン**と、それぞれが「インストール済み」か「インストールされていません」かが出る。前提やつなぎで一緒に入るものは「(一緒に入る)」と出る
- **枝を選ぶと、その下のテンプレートの分も入る**: 「ゲーム」を選ぶと、使うプラグインにゲーム制作・3D 空間・2D 空間・両方のつなぎが出る (「使うプラグイン (この下のテンプレートの分も入ります)」)。「2D のゲーム」なら 3D のものは出ない
- **作ってみる** (Hub の「プラグイン」で全部入っている状態で):
  1. 「3D のゲーム」を選んで作成 → エディターが「ゲーム」のタブで開き、階層に「カメラ」「光」「床」「箱」。シーンビューに大きな平たい床と箱、箱の影。ゲームビューはカメラから見た床と箱 (ゲームの設定の「最初のカメラ」が「カメラ」になっている)
  2. 「2D のゲーム」 → シーンビューが 2D で、緑の横長の地面と黄色の四角。ゲームの空間が「2D」になっている
  3. 「ゲーム」 → 空のシーンの「ゲーム」タブ。シーンの上の帯で 3D / 2D を切り替えられる
  4. 「白紙」 → 今までどおり核のパネルと「ゲーム」(入っていれば) だけ
  - 作ったプロジェクトの `.rmpf` に `"template": { "author": "rm_engine", "plugin": "game_x_3d", "id": "game_3d" }`、`plugins` にゲーム制作、`softwareData` にゲームの設定とシーンの一覧 (`sceneList`)。シーンそのものは `Assets\Scenes\Main.rmscene` (と `.meta`。テンプレートから写したもの)。`UserSettings\Layout.json` に `active` (最初に開くソフト)
- **プラグインが足りないとき**:
  1. Hub の「プラグイン」で「2D 空間」を削除する (ゲーム制作 × 2D も休む)
  2. 新規作成 → 木の「2D のゲーム」と「ゲーム」の右に「要インストール」(黄色)。右の一覧で「2D 空間」「ゲーム制作 × 2D」が「インストールされていません」、下に「作成の前に 2 個のプラグインをインストールします。」
  3. 作成 (Enter でも) → 「**必須プラグインがインストールされていません**」と、入るものの一覧。**このとき Enter を押した続きで勝手に進まない**こと
  4. 「やめる」(Esc) → 新規作成のダイアログに戻る (名前・保存先はそのまま)
  5. 「インストールして作成」(Enter) → 入れてから作り、エディターが開く。Hub の「プラグイン」に戻ると 2D 空間が「使用中」
- 名前のエラーは、プラグインを入れる前に出る (名前が空なら「必須プラグイン…」の確認は出ない)
- テンプレートは `plugins/<作者>/<名前>/templates/<id>/template.json` (ビルドで exe の横の `Plugins\` に写る)。エンジンが持っているプラグインのものは、**入っていなくても木に出る**。壊れた `template.json` は木に出ず、ログ (`editor.log`) に「テンプレートを読めませんでした: … (理由)」

**プロジェクトの名前を変える**

- 行を選んで F2、または右クリック /「…」→「名前を変更…」
- ダイアログに今の名前が全選択で入っている。下に、何が変わるかが出る (フォルダ: 古い → 新しい / ファイル: 古い.rmpf → 新しい.rmpf / 場所)
- 「変更」か Enter で、**一度に**新しい名前にする: `.rmpf` のファイル名・`.rmpf` の中の `name`、それに**フォルダの名前がプロジェクトの名前と同じときだけ**プロジェクトのフォルダ (このエンジンが作った形 `<名前>\<名前>.rmpf`)。中身 (Assets・`UserSettings`・ソフトのデータ・知らないキー) はそのまま
- **フォルダの名前がプロジェクトの名前と違うとき** (「開く…」で `D:\Work\game.rmpf` を開いたときなど) は、フォルダは**変えない** (2026-11-11 に直した。前は `D:\Work` ごと名前が変わっていた)。ダイアログには「フォルダ: Work (変えません。プロジェクトの名前のフォルダではないため)」と出る。画面では**未確認** (テストはある)
  - 試し方: エクスプローラーで `D:\Work` のような自分のフォルダに、作ったプロジェクトの `.rmpf` と `Assets` などを写す → Hub の「開く…」で開いて閉じる → Hub でその行を「Foo」に変える → `D:\Work\Foo.rmpf` になり、`D:\Work` はそのまま
- キャンセルか Esc で何も変えずに閉じる
- 名前の決まりは新規作成と同じ (空・65 文字以上・`\ / : * ? " < > |`・`CON` など・先頭の空白・末尾の `.` や空白はエラー)
- 大文字小文字だけを変えることもできる (`game` → `Game`)
- 名前を変えても一覧の順番と更新日時の並びは変わらず、その行が選ばれたまま新しい場所を指す
- 試してほしい失敗:
  - 同じ場所に同じ名前のフォルダがある → 「同じ名前のフォルダが既にあります」で何も変わらない
  - ほかのアプリがそのフォルダを使っている (確実に起こせる例: コマンドプロンプトでそのフォルダに `cd` したままにする) → 「フォルダの名前を変えられませんでした…」で何も変わらない
- 途中で失敗したときは、それまでに変えたもの (フォルダ・ファイル名) を元に戻す。コンソールとログ (`editor.log`) にも出る
- エディターで開いている間は Hub が出ないので、開いているプロジェクトの名前は変えられない (閉じて Hub に戻ってから)。**別に起動した RM Engine で開いているときも止める** (下の「同じプロジェクトを 2 つで開かない」)

**同じプロジェクトを 2 つで開かない** (2026-11-11。画面では**未確認**。ロックのテストは本物のファイルで通っている)

- エディターが開いている間、プロジェクトの横に隠しファイル `<名前>.rmpf.lock` を持つ。閉じると消える。RM Engine が落ちても (タスクマネージャーで止めても) Windows が消す
- 試し方:
  1. RM Engine を 2 つ起動する (exe を 2 回)
  2. 1 つ目でプロジェクトを開く
  3. 2 つ目の Hub から同じプロジェクトを開く → 「このプロジェクトは別の RM Engine で開いています。そちらを閉じてから開いてください。」で開かない (Hub のまま)
  4. 2 つ目の Hub でそのプロジェクトの名前を変える → ダイアログに「…別の RM Engine で開いているので、名前を変えられません…」と出て何も変わらない
  5. 1 つ目で「Hub に戻る」→ 2 つ目で開ける / 名前を変えられる
  6. 1 つ目をタスクマネージャーで終わらせる → 2 つ目で開ける (`.rmpf.lock` が残らない)
- 書けないフォルダ (読み取り専用など) では印を作れないので、コンソールに警告を出してそのまま開く (守られない)
- Hub の「プラグイン」でインストール・再インストール・削除を押したときは、その描画が終わってから行う (2026-11-11 に直した: 一覧を描いている途中で一覧を作り直していた。見た目は変わらない)
- Hub にプロジェクトのファイルを消す操作は無い (「一覧から外す」はファイルを消さない) ので、止める必要があるのは名前の変更だけ

**プラグインのページ** → 5 章

**アップデート情報のページ**

- 左の欄の「アップデート情報」(「オプション」の上)。版と日付ごとに、変わったことの一覧が新しい順に出る
- 言語を English にすると英語で出る (中身は `resources/updates.json`。exe に埋め込まれている)
- 長いときは下に流れる (ホイール / 右のつまみ)

**オプションのページ**

いちばん上の「設定」は、変えるとすぐ効いて `hub.json` の `options` に保存される (Undo は無い。プロジェクトのデータではないため)。欄の動きはインスペクターと同じ (一覧を押して選ぶ / チェック)。

| 設定 | 選べるもの | どうなるか |
|---|---|---|
| 色のテーマ | 「テーマを変更…」を押して、専用の画面で選ぶ (下の「テーマの画面」) | 画面の色が全部変わる。タイトルバーの色も変わる。「PC の設定に合わせる」は Windows の「設定 > 個人用設定 > 色 > アプリ モード」に合わせ、そちらを切り替えると開いている画面もすぐ変わる |
| 言語 | 日本語 (最初) / English | Hub・エディターの文字、メニュー、ダイアログ、インスペクターの項目名 (「目標 FPS」→ Target FPS など)、プラグインの名前、パネルの名前が英語になる。**コンソールとログは日本語のまま**。新しく作るエンティティの名前も English なら "Entity" |
| 自動保存の間隔 | 1 / 2 / 3 / 4 / **5 (最初)** / 10 / 30 / 60 分 | エディターで未保存の変更があると、最初の変更からこの時間がたったときに保存する (Ctrl+S と同じ)。文字を入力中・ダイアログやメニューが開いている・マウスのボタンを押している間は待つ。コンソールに「自動保存します (N 分ごと)」 |
| エディターの自動アップデート | チェック (最初はオン) | **今は設定を覚えるだけ** (配布の仕組みができたら効く)。下にそう書いてある |

- **テーマの画面** (画面では**未確認**。ビルドとテストは通っている)
  - 「設定」のいちばん上の行に、「色のテーマ」と今のテーマの名前 (黒 など)。右の「テーマを変更…」を押すと、「色のテーマ」のダイアログが開く
  - テーマが**カードで 4 つずつ横に並ぶ**。最初の 3 つ (黒 / 白 / PC の設定に合わせる) だけで 1 行目になり、その下に**テーマパックごとに**、左に**パックの名前** (「基本カラーテーマパック」など、小さめの薄い字) と、その右に続く**横線**、線の下にそのパックのテーマが 4 つずつ並ぶ。カードには、そのテーマの色で描いた小さなエディターの絵 (上の帯・左の欄と選んだ行・パネルと文字の線・赤いボタン) と名前
  - 今のテーマのカードは赤い枠と右下のチェック。乗せるとカードが明るくなり、カーソルが手の形になる
  - カードを押すと**すぐにテーマが変わる** (ダイアログ自体も新しい色になる)。`hub.json` にも保存される。「閉じる」/ Esc / Enter で閉じる

## 3. パネルのドッキング

**タブ**

- クリックすると、そのパネルが表に出る
- 「×」はアクティブなタブか、マウスを乗せたタブに出る。中クリックでも閉じる
- 右クリックのメニュー
  - 閉じる
  - 別ウィンドウに出す
  - エディターのウィンドウに戻す (別ウィンドウの中のタブだけ)

**タブが列に入りきらないとき** (2026-11-11。画面では**未確認**。ビルドとテストは通っている)

試し方: パネルを細くする (仕切りをドラッグ) か、1 つの列にタブを 4 つ以上集める (ほかのパネルのタブをドラッグして入れる)。

- タブの列の右端に **‹ › ▾** の 3 つのボタンが出る (入りきるときは出ない)
- **ホイール**: タブの列の上でホイールを回すと、列が左右に流れる
- **‹ ›**: 押すたびに、その側で切れている (隠れている) 次のタブが全部見える所まで流れる。端まで来たボタンは薄くなって押せない
- **▾**: その列のタブの一覧が出る (表のタブにチェック)。選ぶと表に出て、**見える所まで列がずれる**
- タブを表に出したとき (クリック・▾・「ウィンドウ」メニューで開いた・ドラッグで入れた) は、いつもそのタブが見える所まで列がずれる
- 隠れているタブには触れない (列の外の端に半分見えているタブは、見えている所だけ押せる)
- ドラッグ:
  - 今までどおり、列の中で並べ替え・別の列へ・外に出して別ウィンドウ、が動くこと
  - 入りきらない列の**左端・右端 (‹ › ▾ の上も)** でタブを持ったまま**マウスを少しずつ動かす**と、列がその向きに流れる (止めていると流れない)。流してから離すと、隠れていた所にも入れられる
  - ‹ › ▾ の上で離すと、見えている最後のタブの後ろに入る
- 確かめること: ウィンドウを広げて全部入るようになるとボタンが消え、列が左端に戻る / 別ウィンドウの中の列でも同じに動く

**タブをドラッグする** (6 DIP 動かすと始まる。タブ名の札がマウスについてくる)

- **下にあるパネルの真ん中**に、十字の目印が 5 つ出る (中央と上下左右)。パネルが小さいと中央だけ
- **ウィンドウの四辺の中ほど**にも目印が出る (パネルが 2 つ以上あるとき)
- 目印に乗ると、行き先が赤く塗られる。離した先によって次のようになる

| 離した場所 | どうなるか |
|---|---|
| 端の目印 | そこで分割される |
| 中央の目印、または別のパネルのタブ列 | タブとして入る (タブ列なら離した位置に。同じ列の中で並べ替えもできる) |
| どの目印でもない所 (メニューバーの上なども) | そのパネルが**別ウィンドウ**になる |

- Esc でドラッグをやめる

**仕切り**

- パネルの間をドラッグすると大きさが変わる。カーソルが ↔ / ↕ になる
- 片側が 80 DIP より小さくはならない
- 大きさは比率で覚えるので、ウィンドウを大きくすると全部が伸びる

**別ウィンドウ**

- エディターの上に乗り続けるウィンドウで、タスクバーには出ない。タイトルは中のパネル名
- 中でも、タブ・仕切り・目印・分割が同じように使える。ほかのパネルを入れることもできる
- 別ウィンドウのタブをエディターへ (逆も) ドラッグできる
- **タイトルバーを持ってエディターの上へ動かす**と目印が出る。目印の上で離すと、中のパネルごと戻る
- 別ウィンドウの「×」を押すと、中のパネルは閉じる (「ウィンドウ」メニューから開き直せる)
- 別ウィンドウにフォーカスがあっても、Ctrl+S / Ctrl+Z は効く

**保存**

- 配置は、保存したときとエディターを閉じたときに `UserSettings\Layout.json` へ書かれる
- 次に開くと、別ウィンドウの位置も含めて元に戻る
- 保存した位置がもう無いモニターの上なら、画面の中に移して出す
- 配置を変えても、未保存 (「*」) にはならない

**「ウィンドウ」メニュー**

- 閉じたパネルを選ぶと、一番大きいパネルにタブとして戻る
- 「最初の配置に戻す」で、ソフトの最初の配置に戻る (前の「パネルの配置を元に戻す」)

**名前を付けた配置** (2026-11-11。画面では**未確認**。ビルドとテストは通っている)

- 「ウィンドウ」→「**今の配置に名前を付けて保存…**」: 名前を入れて「保存」(Enter)。別ウィンドウの位置も一緒に覚える
  - 名前は前後の空白 (全角も) を除く。空なら「保存」は押せない
  - 同じ名前があると「同じ名前の配置があります。今の配置で上書きします。」と黄色で出て、ボタンが「上書き」になる
  - 最後に切り替えた (保存した) 配置があれば、その名前が最初から入っている (変えた所を上書きしやすい)。無ければ「配置」「配置 2」… の空いている名前
- 保存した配置は「ウィンドウ」メニューのパネルの下に**名前で並ぶ** (右に「配置」)。選ぶと切り替わる。最後に切り替えた / 保存したものにチェック
- 「ウィンドウ」→「**配置の管理…**」: このソフトの名前付きの配置の一覧
  - 「切り替え」: その配置にする (ダイアログは開いたまま。後ろのパネルが変わる)
  - 「名前の変更」: その行が入力欄になる。「決定」(Enter) / 「やめる」(Esc)。ほかと同じ名前・空の名前は「決定」できない

  - 配置を 2 つ (例: 「絵を描く」「全部」) 作り、メニューから行き来する。別ウィンドウも出たり消えたりする
  - 名前の変更・削除・保存のあと、エディターを閉じて開き直しても一覧が残っている (`UserSettings\Layout.json` の、そのソフトの `"named"`。共通の配置は `%APPDATA%\RM_Engine\Layouts.json`)

  - 配置に入っていたパネルのプラグインを外して切り替える → そのパネルだけ無い形で開く (エラーにならない)
  - 配置を切り替えても未保存 (「*」) にならない・Ctrl+Z で戻らない (プロジェクトのデータではない)
  - ソフトが 2 つ以上あるとき: 一覧はソフトごとに別 (今はソフトが 1 つなので未確認)

**共通の配置 (別のプロジェクトへ持っていく)** (2026-11-11。画面では**未確認**。ビルドとテストは通っている)

  - プロジェクト A で配置を共通にする → Hub に戻ってプロジェクト B を開く → 「ウィンドウ」メニューにその配置があり、切り替えられる

## 6. 階層 (ゲームのエンティティ)

- **項目がとても多いとき** (2026-11-11 に軽くした。画面では**未確認**。2 万項目を全部選ぶテストは通っている): エンティティを数千作って (Ctrl+D をくり返す) Ctrl+A で全部選んでも、階層・Shift+クリック・ドラッグが重くならないこと

左の「階層」パネル。木の表示は核が持ち、中身 (ここではシーンのエンティティ) はゲーム制作プラグインが出す。

**最初**

- 新しいプロジェクトでは空で、「エンティティはまだありません。ここを右クリックして…」と出る
- パネルの一番上に検索の欄がある
- **行の名前の前に小さな絵** (画面では**未確認**): Transform の付いたエンティティは**立方体** (六角形の輪郭と、手前の角から出る 3 本の線)、付いていないエンティティは**丸**。「有効」を外したエンティティは絵も薄い

**作る** (右クリックのメニュー)

| 項目 | ショートカット | どこにできるか |
|---|---|---|
| エンティティを作る | Ctrl+Shift+N | 何も選んでいなければ一番上の段の最後。選んでいれば、その (最後に選んだ) エンティティのすぐ後ろ (同じ親の中) |
| 子エンティティを作る | — | 1 つだけ選んでいるときだけ押せる。その子の最後 |

- 作ると、そのエンティティが選ばれ、**名前の入力欄が開いた状態**になる (「エンティティ」が全選択)。そのまま打って Enter で名前が決まる。Esc なら「エンティティ」のまま
- ショートカットは、**階層の中を最後にクリックしたときだけ**効く (ほかのパネルをクリックした後や、文字を入力中は効かない)。右クリックのメニューにも出ている

**選ぶ**

- クリック = それだけ / Ctrl+クリック = 足す・外す / Shift+クリック = 前に選んだ所からの範囲 / Ctrl+Shift+クリック = 範囲を足す
- ↑ ↓ で上下、Home / End で最初 / 最後。Shift を押しながらだと範囲が広がる
- Ctrl+A で見えている物を全部
- 何も無い所 (行の下) をクリックすると選択が外れる
- 選んだ行は赤っぽい色 + 左に赤い線。ほかのパネルをクリックすると灰色になる (キーが階層に効かない印)

**インスペクターとのつながり**

- 1 つ選ぶと、インスペクターに「エンティティ」として **名前** と **有効**、その下に部品 (7 章) が出る
- **2 つ以上選ぶと、まとめて編集できる** (画面では**未確認**)
  - 上に「N 個のエンティティ」。名前・有効と、**選んだ全部に付いている部品だけ**が出る (1 つにしか付いていない部品は出ない)。数字は最後に選んだ物のもの
  - **全部で同じでない値は「—」**と出る。ベクトル (位置など) は X / Y / Z ごと (例: 位置の Y だけ違えば Y だけ「—」)
  - 欄に打つと**選んだ全部がその値になる**。位置の X を打つと、全部の X だけがそろう (Y・Z はそれぞれのまま)。打った分は Ctrl+Z 1 回で全部戻る
  - 部品の ⋮ →「外す」で全部から外す。「＋ 部品を足す」で、付いていない物に足す (全部に付いている部品は一覧に出ない)
  - 「—」の欄に打ってから Esc を押したときは、打った値のまま (元がばらばらで 1 つの値に戻せないため)。Ctrl+Z で戻せる
  - 子を選んでいても、まとめて編集のときはローカル / ワールドのスイッチは出ない (ローカルの値)
  - チェック (有効など) がばらばらのときは、**横線の印** (赤い四角に「−」) で出る (2026-11-11。画面では**未確認**)。押すと全部がオン (チェック) にそろう。もう一度押すと全部オフ。Ctrl+Z 1 回で、ばらばらだった元に戻る
  - 選び肢 (列挙。投影のしかたなど) がばらばらのときは「—」。一覧 (配列) の中身がばらばらのときは数の所が「—」で、「選んだ物で中身が違うので、まとめては変えられません。」
- 何も選んでいない状態にすると、インスペクターは空になる (「ゲームの設定」を見ていたときはそのまま)
- 「ゲームの設定を開く」を押すと、階層の選択は外れる
- インスペクターで名前を変えると階層の名前も変わる。**有効** を外すと、そのエンティティと中の物が階層で薄い字になる

**開く・閉じる**

- 子がいる行の左に ▾ (開いている) / ▸ (閉じている)。押すと切り替わる
- キーボード: ← で閉じる (閉じている行なら親へ移る)、→ で開く (開いている行なら最初の子へ移る)
- **閉じた行と選んでいた物を覚える** (画面では**未確認**): 開き直しても、閉じた行は閉じたまま、選んでいた物は選ばれたまま (インスペクターにも出る)。保存したとき (Ctrl+S) とエディターを閉じたときに `UserSettings/Layout.json` の `"tree"` に書く。プロジェクトのデータではないので、開け閉めしても未保存にならない

**名前の変更**

- F2、ダブルクリック、右クリック →「名前を変更」のどれでも、行がその場で入力欄になる
- Enter か、ほかの所をクリックで確定。Esc でやめる。空にして確定すると変わらない
- 名前の変更も Undo 1 回分 (インスペクターで変えたときと同じ扱い)

**ドラッグで並べ替え・親子付け** (行を 6 DIP 動かすと始まる。名前の札がマウスについてくる)

| 離す場所 | どうなるか | 目印 |
|---|---|---|
| 行の上の 1/4 | その行の前 (同じ親の中) | 行の上に赤い線 |
| 行の下の 1/4 | その行の後ろ。**開いていて子がいる行なら、その最初の子**になる | 行の下に赤い線 (子になるときは一段右から) |
| 行の真ん中 | その行の子 (最後) | 行を赤い枠で囲む |
| 最後の行より下 | 一番上の段の最後 | 最後の行の下に線 |

- 自分の中 (自分や自分の子孫) には落とせない。そのときは目印が出ず、札の枠が灰色になる。離しても何も起きない
- 複数を選んでドラッグすると全部動く (選んだ物の子は親についていく)。選んだ行の 1 つをつかんで動かす
- Esc でドラッグをやめる。パネルの上下の端に近づけると、少しずつ流れる
- 落とした先の親は開く
- 何も変わらない所に落とすと、Undo には積まれない

**右クリックのメニュー** (行の上で右クリックすると、その行が選ばれていなければそれだけを選んでから出る)

| 項目 | ショートカット | 押せるとき |
|---|---|---|
| 名前を変更 | F2 | 1 つだけ選んでいる |
| エンティティを作る | Ctrl+Shift+N | いつでも |
| 子エンティティを作る | — | 1 つだけ選んでいる |
| コピー | Ctrl+C | 選んでいる。子ごと、部品の値ごとクリップボードへ (コンソールに「N 個のエンティティをコピーしました」) |
| 切り取り | Ctrl+X | 選んでいる。コピーして消す (Undo 1 回で戻る) |
| 貼り付け | Ctrl+V | いつでも。最後に選んだ物のすぐ後ろ (同じ親の中)。何も選んでいなければ一番上の段の最後。貼った物が選ばれる |
| 子として貼り付け | — | 1 つだけ選んでいる。その子の最後 |
| 複製 | Ctrl+D | 選んでいる。子ごとコピーして元のすぐ後ろに置き、コピーが選ばれる (名前は同じ) |
| 親から外す (一番上に出す) | — | 選んだ中に親のいる物がある。一番上の段の最後へ |

- 何も無い所で右クリックすると、選択を外してから「エンティティを作る」「子エンティティを作る」「コピー」(押せない)「切り取り」(押せない)「貼り付け」「子として貼り付け」(押せない) のメニューが出る

**コピーと貼り付け** (画面では**未確認**)

- クリップボードには **JSON の文字**で入る (`"kind": "rm_engine.game_production.entities"`、エンティティはファイルと同じ形)。メモ帳に貼ると中身が見える
- **別のプロジェクトや、もう 1 つ開いた RM Engine にも貼れる**。貼った物には新しい ID が付く (同じ物を何回貼ってもよい)
- 入っていないプラグインの部品が付いていても、そのまま残して貼る
- クリップボードにエンティティが無いとき (普通の文字など) に貼ると、何も起きずにコンソールに「クリップボードにエンティティがありません」
- 試し方: 子のいるエンティティを選んで Ctrl+C → 別のエンティティを選んで Ctrl+V → すぐ後ろに子ごと出る。Ctrl+Z で消える。Ctrl+X で消えて、Ctrl+V で戻る

**Undo と保存**

- 作る・複製・切り取り・貼り付け・削除・移動・親から外す・名前・有効、どれも 1 回で Undo 1 回分。「*」が付く
- Ctrl+Z で消したエンティティが戻る (戻っても選ばれはしない)。インスペクターに出していたエンティティを消して戻すと、また同じものを指す
- 保存すると `.rmpf` の `softwareData[…].data.scene` に `nextId` と `entities` (`id` / `parent` / `name` / `active`) が書かれる。開き直すと同じ木に戻る
- 並びの順がそのまま兄弟の順
- エンティティを 1 つでも作って保存すると、ゲーム制作プラグインがこのプロジェクトの「使うプラグイン」として記録される

**検索**

- 上の欄に打つと、名前にその文字を含む物と、その親だけが出る (全部開いた状態)。英字は大文字と小文字を区別しない
- 当てはまる物が無いと「見つかりません。」
- 欄で Esc を押すと消える

**ファイルをいじって試す**

- `entities` の 1 つに知らないキー (例: `"components": []`) を足して開き、何か変えて保存 → そのキーは残る
- 同じ `id` を 2 つにする / `parent` を無い番号にする / 2 つのエンティティを互いの親にする → 開くとコンソールに警告が出て、新しい ID が付く / 一番上に置かれる

## 7. 部品 (コンポーネント) と 3D 空間

エンティティに「部品」を付ける仕組み (ECS の C)。部品の種類はプラグインが増やす。いまは「ゲーム制作 × 3D」が **Transform (位置・回転・大きさ)** を出している。

**新しいエンティティ**

- 階層で「エンティティを作る」/「子エンティティを作る」と、**最初から Transform が付いている**
- 前からあるエンティティ (前の版で作ったもの) には付いていない → 下の「部品を足す」で付けられる

**インスペクターの形** (エンティティを 1 つ選んだとき)

```
エンティティ                         ← 題
  名前 [エンティティ        ]         ← エンティティそのもの (見出しなし)
  有効 [✓]
 ▾ Transform (位置・回転・大きさ)   ⋮  ← 部品の見出し (押すと畳む)。⋮ = メニュー
  位置       [0] [0] [0]
  回転 (度)  [0] [0] [0]             ← 名前にマウスを乗せると「X 軸 → Y 軸 → Z 軸 の順に回します」
  大きさ     [1] [1] [1]
        [ ＋ 部品を足す ]
```

- 数の欄の動きは 8 章と同じ (クリックで全部選ぶ・ドラッグで選ぶ・打つたびに反映・Esc で入る前に戻す・1 つの欄に打った分が Undo 1 回分)
- 見出しを押すと、その部品が畳まれる (▸)。もう一度押すと開く。別のものを選ぶと、全部開いた状態に戻る (保存もしない)

**足す・外す**

- 「＋ 部品を足す」→ まだ付いていない部品の一覧。押すと付く (Undo 1 回分、「*」が付く)
  - 全部付いていれば「足せる部品は全部付いています」(押せない)
  - 部品を出すプラグインが無ければ「足せる部品がありません (3D 空間 などのプラグインで増えます)」
- 部品の見出しの「⋮」→「外す」で外れる (Undo 1 回分)
- **部品の順番** (画面では**未確認**): 「⋮」→「上へ移動」/「下へ移動」で、インスペクターでの並びが 1 つずつ変わる (一番上の部品は「上へ移動」が押せない、一番下は「下へ移動」が押せない)。保存すると `.rmpf` の `components` の順もそうなる。Undo 1 回分
- **同じ部品は 1 つまで** (一覧に出なくなる)。ただし「複数可」の部品 (いまは「回り続ける」) は何個でも付く (7-4 章)
- Ctrl+Z で外した部品が値ごと戻る。Ctrl+Y でまた外れる
- 複製 (Ctrl+D) すると部品も値ごとコピーされる。コピーの値を変えても元は変わらない

**保存**

- `.rmpf` の `softwareData[…].data.scene.entities[…].components` に `[{"type": "rm::space3d::Transform", "data": {"position": [...], "rotation": [...], "scale": [...]}}]` と書かれる
- 開き直すと値が戻る

**使えない部品** (プラグインが無いとき・ファイルをいじったとき)

- 試し方 1: `.rmpf` の部品の `"type"` を `"someone::Physics"` などに書き換えて開く → コンソールに「部品「someone::Physics」は、いま入っているプラグインでは使えないので、そのまま残します」→ インスペクターに「someone::Physics (使えない部品)」と説明だけが出る (欄は無い)、⋮ →「外す」はできる
- ほかを変えて保存しても、その部品は書いたまま残る (ファイルを見て確かめられる)
- 試し方 2: 部品の `"data"` の中に知らないキー (例: `"pivot": "center"`) を足して開く → 普通に使え、保存しても `pivot` は残る
- 試し方 3: 同じエンティティに同じ `"type"` の部品を 2 つ書く → Transform なら 2 つ目は「使えない部品」になる (「回り続ける」なら 2 つとも使える)

## 7-2. シーンビュー (3D)

「シーン」パネル (ゲームビューと同じ列のタブ) に、3D でシーンが映る。描くのは 3D 空間プラグイン、つなぎ「ゲーム制作 × 3D」が出している。

**映るもの**

- 床のグリッド (1 ごとに線、10 ごとに少し濃い線)。赤い線 = X 軸、青い線 = Z 軸、原点から上に緑の短い線 = Y 軸 (上)
- **Transform の付いたエンティティ**が、その位置・回転・大きさで**箱** (1 × 1 × 1 の立方体) として出る。上から光が当たったように面ごとに明るさが違う。**メッシュ (3D モデル) の部品**が付いていれば、箱の代わりにそのモデル (下の「メッシュ」)。床と物に**影**が落ちる (下の「影」)
  - 親子: 子は親の Transform に付いていく (親を動かす・回すと子も一緒)
  - 「有効」を外したエンティティ (と、その子) は薄い色
  - 選んでいるエンティティは赤みの色 + 赤い枠線
  - Transform の付いていないエンティティは出ない (エンティティが 1 つも出ないときは左上に「Transform の付いたエンティティが、ここに箱で出ます。メッシュ (3D モデル) の部品を付けると、そのモデルで描きます。」)
- 下に操作の説明

**カメラ (Unity と同じ)**

| 操作 | 動き |
|---|---|
| 右ドラッグ | その場で見回す |
| 右ボタンを押したまま W / A / S / D | 前 / 左 / 後ろ / 右へ飛ぶ (マウスを止めていても動き続ける) |
| 右ボタンを押したまま E / Q | 上 / 下へ |
| 上の飛行中に Shift | 4 倍速 |
| 中ドラッグ | 平行移動 (絵がマウスに付いてくる) |
| ホイール | 近づく / 離れる |
| Alt + 左ドラッグ | 見ている点のまわりを回る |
| F (シーンビューの上にマウスがあるとき) | 選んでいるエンティティへ寄る |
| 左クリック | クリックした箱のエンティティを選ぶ (階層とインスペクターも切り替わる)。何も無い所をクリックすると選択が外れる |

- **右ドラッグ・中ドラッグ・Alt+左ドラッグの間はカーソルが消え**、マウスを動かした分だけいくらでも回る・動く (画面の端で止まらない)。ボタンを離すと、カーソルはドラッグを始めた所に戻って出てくる

**試し方**

1. 階層でエンティティを 2〜3 個作る (最初から Transform が付いている)。原点に箱が重なって出る
2. インスペクターで位置を (2, 0, 0) などに変える → 箱が動く。Ctrl+Z で戻る
3. 回転 (0, 45, 0)、大きさ (1, 2, 1) なども試す
4. 階層でドラッグして親子にし、親の位置を変える → 子も付いてくる
5. 箱をクリック → 階層とインスペクターでも選ばれる。何も無い所をクリック → 外れる
6. 上のカメラ操作を一通り
7. パネルを別ウィンドウに出しても映る。ウィンドウの大きさを変えても絵が引き伸ばされない
8. オプションで「白」にすると、背景・グリッドも明るい色になる

**ギズモ (箱をつかんで動かす・回す・大きさを変える)** (画面では**未確認**)

選んだエンティティの真ん中に、つかむための印 (ギズモ) が出る。シーンビューの左上の帯か、キーで道具を選ぶ。

| 道具 | キー | 見た目 | つかむと |
|---|---|---|---|
| 移動 | W | 赤・緑・青の矢印 3 本と、矢印の間の小さな四角 3 つ | 矢印: その向きだけに動く。四角: その面 (例: 赤と緑の間の四角 = X と Y) の中で動く |
| 回転 | E | 赤・緑・青の輪 3 つ。こちらを向いた半分は濃く太く、奥の半分は薄く細く (どの輪も丸ごと 1 周見える)。その外に**こちらを向いた白っぽい輪** (文字の色。少し大きい)。輪の内側に**球の輪郭** (薄い丸) | 色の輪: 輪に沿ってマウスを動かした分だけ、その軸のまわりに回る。奥の半分もつかめるが、手前の輪が近くにあれば手前が先。**外の輪**: 画面の奥へ向かう線のまわりに回る (画面の上で時計の針のように回る)。**球の中 (輪の上でない所)**: マウスを乗せると球の中が薄い黄色になり、ドラッグすると**ボールを転がすように自由に回る** (右へ動かすと手前の面が右へ、上へ動かすと上へ。動かした長さで角度が決まる) |
| 拡大縮小 | R | 先に小さな四角の付いた線 3 本と、真ん中の白っぽい四角 | 線: その軸の大きさだけ変わる (外へ引くと大きく)。真ん中の四角: 3 つとも同じ割合で (右か上へ動かすと大きく) |

- マウスを乗せた印は**黄色**になる。つかんでいる間も黄色
- 左上の帯の右側「ローカル / ワールド」(キー X で切り替え): ローカル = 選んだ物自身の向きに矢印と輪が向く (箱を回してあると斜めになる)。ワールド = いつも世界の X / Y / Z の向き。**拡大縮小はいつも物の向き** (Transform の大きさがそういう値なので)
- **Ctrl を押しながら**ドラッグすると刻んで動く: 最初は移動 0.25 ずつ・回転 15 度ずつ・大きさ 0.1 倍ずつ
- **刻み** (左上の帯のいちばん右のボタン): 押すと下に小さな箱が開く。「移動」「回転 (度)」「大きさ」の刻む幅を打てる (クリックで全部選ばれる。打つたびに変わる。0 や文字は受け付けず、移動 0.001〜1000・回転 0.1〜180 度・大きさ 0.001〜10 に収める)。「**いつも刻む (Ctrl を押すとなめらか)**」にチェックすると、Ctrl なしで刻み、Ctrl を押している間だけなめらかに動く。そのときは「刻み」ボタンがアクセントの色になる。箱の外をクリックするか Esc で閉じる (そのクリックで物は選ばれない)。もう一度「刻み」を押しても閉じる。箱の上をクリックしてもシーンの物は選ばれない
- 「**それぞれ / 中心**」(左上の帯の 3 つ目。キー **Z**。Ctrl+Z は Undo のまま): **それぞれ** = ギズモは最後に選んだ物に出て、回転・拡大縮小はそれぞれの物が自分の場所で回る・大きくなる (今までどおり)。**中心** = ギズモは**選んだ物全部の真ん中**に出て (親と子を両方選んでいるときは子は数えない)、**全部がその真ん中を中心に回る・離れていく** (回すと位置も円を描いて動く。2 倍にすると真ん中からの距離も 2 倍)。矢印と輪の向き (ローカルのとき) は最後に選んだ物の向き
- 確かめ方 (中心): 箱を 2 つ、(-2, 0, 0) と (2, 0, 0) に置いて両方選ぶ → 「中心」にすると、ギズモが (0, 0, 0) に出る → 回転の緑の輪で 90 度回すと、箱が (0, 0, 2) と (0, 0, -2) あたりへ回り込む → 拡大縮小の真ん中の四角で 2 倍にすると、箱が (-4, 0, 0) と (4, 0, 0) へ離れる → Ctrl+Z 1 回で全部戻る。「それぞれ」に戻すと、同じ操作でも箱はその場で回るだけ
- ドラッグ中に **Esc**: 全部ドラッグ前に戻る (そのままボタンを離しても何も変わらない)
- ドラッグ中はインスペクターの数字も一緒に変わる。**ボタンを離したところで Undo に 1 つ積まれ**、未保存の印が付く。Ctrl+Z で 1 回で戻る (何個選んでいても 1 回)
- 階層で**複数選ぶと全部一緒に**動く・回る (「それぞれ」のときは自分の位置で、「中心」のときは真ん中を中心に)。親と子を両方選んでいるときは、子は親に付いていくだけ (2 回動かない)
- 印が奥を向いて点のように見えるとき (矢印がまっすぐこちらを向いている、四角を真横から見ている) は、その矢印・四角は出ない (つかめない)
- ギズモは箱やグリッドより常に手前に描かれる。画面の端からはみ出した分は切れる
- Alt+左ドラッグ (回る) が先。印の上でも Alt を押していればカメラが回る
- 左上の帯は、シーンビューの幅が足りないと 2 段・3 段に折り返す。幅が 210 くらいより狭いと出ない (キーは使える)
- 下のヒントの文は、幅が足りないと下から折り返して複数行になる

**カメラと道具を覚える** (画面では**未確認**)

- カメラの位置・向き・近さ、選んでいた道具 (移動 / 回転 / 拡大縮小)、ローカル / ワールド、それぞれ / 中心、刻む幅といつも刻むか、影のオン / オフを、プロジェクトの `UserSettings/Layout.json` に覚える (パネルの配置と同じ所。ソフトごとの `"view"`)。**プロジェクトのデータではない**ので、カメラを動かしても未保存にならず、Undo にも積まれない

- 読むもの:

**金属・ざらざら・法線マップ・光る色 (PBR)** (画面では**未確認**。ビルドとテストは通っている。エディターの外で同じ描画のコードに `pbr_ball.glb` ほかを描かせて、金属の映り込み・ざらざらの違い・くぼみ・光る輪が出ることは見た)

- 読むもの:
  - glTF: `metallicFactor` (金属か: 0〜1)・`roughnessFactor` (ざらざら: 0 = 鏡、1 = つや消し)・`metallicRoughnessTexture` (青 = 金属、緑 = ざらざら)・`normalTexture` (+ `scale`)・`emissiveFactor` と `emissiveTexture` (自分で光る色。`KHR_materials_emissive_strength` で 1 より明るく)。何も書いていない材質は glTF の決まりどおり「ざらざらの金属」(metallic 1・roughness 1)
  - OBJ の .mtl: `Ns` (つや: Blender と同じく ざらざら = 1 − √(Ns ÷ 1000))・`Pr` / `Pm` (ざらざら / 金属)・`Ke` / `map_Ke` (光る色と絵)・`norm` / `map_Bump` / `bump` (法線マップとして読む。`-bm` が強さ。Blender が法線マップをこの形で書く)

  1. `pbr_ball.glb` を置く → 金色の帯はつやがあって光が小さく鋭く映り、青い帯はつや消しで柔らかい。帯のあちこちに小さなくぼみ (法線マップ: 形は丸いまま、光り方だけがへこむ)。真ん中の橙の輪は影の側でも明るい (自分で光る)
  2. 光の部品を回したり、カメラで周りを回ると、金属の帯の映り込みが動く
  3. ほかのサンプル (家・箱・ドーナツ) は前とほぼ同じ見た目 (少しだけ明暗がはっきりした)
- 色の決まり: 材質の色は「光の量」(リニア) で持つ (glTF はそのまま、.mtl の `Kd` / `Ke` は画面の色なので直す)。色の絵と光る絵は sRGB として GPU が読み (`_SRGB` の形式)、金属 / ざらざらと法線の絵は数として読む。最後に画面の色 (sRGB) に直して出す。UI の色 (箱の灰色・選んだ縁の光・床の影・線) は今までどおり画面の色
- 光の部品の色 × 強さは、そのまま光の量として使う (色を画面の色から直さない)
- ★ 周りの景色の映り込み (環境マップ) はまだ無いので、磨いた金属は空の明るさが少し映るだけで暗めに見える

**透ける物 (BLEND) の重なり** (画面では**未確認**。ビルドとテストは通っている。エディターの外で同じ描画のコードに `glass.gltf` ほかを描かせて、3 枚とも透けて正しい前後で重なることは見た)

- 透ける物 (glTF の `alphaMode: BLEND`、.mtl の `d` が 1 より小さい物、「有効」を外したモデル) は、ほかの物を全部描いた後に**目から遠い順に**描く。透ける物の後ろの透ける物も見える

  1. `glass.gltf` (赤・緑・青の 3 枚の色ガラスが前後に並んだもの) を置く → 3 枚とも透けて、重なった所は混ざった色。後ろの物 (グリッドや他のモデル) も透けて見える
  2. カメラで裏側へ回る → 重なる順が逆になる (青が手前、赤が奥) ように見える
  3. 「有効」を外したモデルをガラスの後ろに置く → 薄く透けたまま、ガラス越しに見える

## 7-3. Play とシステム (画面では**未確認**。ビルドとテストは通っている)

ゲームを動かして見る。Play の間は**シーンのコピー**が動き、■ で止めると **Play の前に戻る** (Undo の履歴は増えない・「*」も付かない)。

**準備**

1. エンティティを作る (Transform が付いている)
2. インスペクターの「＋ 部品を足す」→「回り続ける」(1 秒に回る角度 (度) が (0, 90, 0))

**ボタン** (エディターの上、ソフトのタブ「ゲーム」の右の帯)

```
 [ゲーム]   [▶] [⏸] [⏭] [■]   Play 中 — 編集はできません。■ で止めると Play の前に戻ります
```

- 止まっているときは ▶ だけが押せる (⏸ ⏭ ■ は薄い)。マウスを乗せると説明 (「Play (Ctrl+P)」など)
- **▶ (Ctrl+P)**: Play。▶ がアクセントの色になり、**タブの帯全体がアクセントの色に染まる**。右に「Play 中 — …」。コンソールに「▶ Play (システム 1 個)…」
  - シーンビューの箱が Y 軸のまわりに回り続ける (1 秒に 90 度)
  - 「ゲーム」タブ (シーンと同じ列) に切り替えると、**ゲームの設定の「最初のカメラ」のカメラ**から見たゲームが映る (7-6 章。選んでいなければその案内): 床の線・軸・選択の色は無く、背景は「ゲームの設定」の「背景の色」(カメラが自分の色を使うときはその色)。有効を外したエンティティは映らない
- **⏸ (Ctrl+Shift+P)**: 一時停止 (⏸ がアクセントの色、文字は「一時停止中 — …」)。もう一度 ⏸ か ▶ で続ける
- **⏭**: 1 コマ (1 / 目標 FPS 秒) 進めて一時停止
- **■ (Play 中にもう一度 Ctrl+P)**: 止める → 箱の向きが Play の前に戻る。帯の色も戻る。コンソールに「■ 停止 (…秒・…コマ)。シーンは Play の前に戻りました」

**Play 中は編集できない** (止めると全部戻るので、変えた物が消えて驚かないように)

- インスペクターの一番上に「Play 中です。ここに出ているのは動いているコピーで、変えられません。…」。欄は動いている値を出し続ける (回転の Y が増えていく) が、クリックしても入れない
- 部品の ⋮ のメニューは全部薄い。「＋ 部品を足す」は「Play 中は部品を足せません」だけ
- 階層の右クリック: 一番上に「Play 中は編集できません (■ で止めてから)」、ほかの行は全部薄い。Ctrl+D・Delete などのショートカットも効かない。F2 で名前の変更も始まらない。行のドラッグもできない
- シーンビューのギズモが出ない (カメラは動かせる・クリックで選べる)
- Ctrl+Z / Ctrl+Y・「編集」メニューの元に戻す: 何もせず、コンソールに「Play 中は元に戻す / やり直しはできません (止めてから)」
- 「ゲームの設定」も Play 中は変えられない
- Ctrl+S は効く (保存されるのは Play の前のシーン)

**固定の刻み** (物理の刻み)

- システムには「毎フレーム」と「固定の刻み」の 2 種類がある。「固定の刻み」は「ゲームの設定」の「物理の刻み (秒)」ごとに動く (PC が速くても遅くても同じ回数)。いま組み込みのシステムは「回り続ける」(毎フレーム) だけなので、画面では見えない (テスト `Systems_FixedStepCatchesUpAndCarries` で確かめた)

## 7-4. 同じ部品を複数 (画面では**未確認**)

「回り続ける」は 1 つのエンティティに何個でも付く (部品の種類ごとに「複数可」をプラグインが決める。Transform は 1 つだけ)。

- 「＋ 部品を足す」→「回り続ける」を 2 回。2 回目からは一覧に「回り続ける (もう 1 つ)」と出る
- インスペクターに「回り続ける (1)」「回り続ける (2)」の 2 つのかたまりが出る (1 つだけのときは番号なし)
- 2 つ目の「1 秒に回る角度」を (30, 0, 0) にして Play → Y と X の両方に回る (足し算)
- ⋮ →「上へ移動」/「下へ移動」で並べ替え (番号が付け替わる)、「外す」でその 1 つだけが外れる。どれも Undo 1 回分
- 片方の値を変えてから並べ替え、Ctrl+Z を順に押す → 並びが戻ってから値が戻る (別の方の値は変わらない)
- 保存すると `components` に同じ `"type"` が 2 つ並ぶ。前の版のファイル (1 つずつ) もそのまま読める
- 複数選んだときは、それぞれの最初の 1 つだけがまとめて編集できる

## 7-5. Prefab (画面では**未確認**。ビルドとテストは通っている)

エンティティ (子ごと) をファイルにして、何度でも置ける。Prefab を直すと置いた物に伝わる (置いた物で変えた所はそのまま)。

**作る**

1. 「箱」というエンティティに子「ふた」を作り、箱に「回り続ける」を付ける
2. 階層で「箱」を右クリック →「Prefab にする (Assets に保存)」
3. `<プロジェクト>/Assets/箱.rmprefab` ができる (JSON。同じ名前があれば `箱 (2).rmprefab`)。コンソールに「Prefab を作りました: Assets/箱.rmprefab」。アセットのパネルにも出る
4. 「箱」をインスペクターで見ると、見出しの下に「Prefab「箱」を置いた物です (Assets/箱.rmprefab)。Prefab と違う所: N 個 (名前と置き場所を含む)」。「ふた」には「Prefab「箱」の一部です」
5. Ctrl+Z で「Prefab にする」は戻る (ふつうのエンティティに戻る) が、**ファイルは残る**

**置く**

- 階層の右クリックの下の方に「Prefab を置く: Assets/箱.rmprefab」(Assets の中の `.rmprefab` が全部。20 個まで)。押すと、選んでいる物の次 (何も選んでいなければ一番上の最後) に、子ごと置かれて選ばれる。Undo 1 回分
- Assets に Prefab が無いと「Prefab を置く (Assets に Prefab がありません)」(押せない)

**置いた物で変える (上書き)**

- 置いた「箱」を動かす・名前を変える・「ふた」の位置を変える・部品を足す / 外す・子を足す / 消す → 置いた物だけが変わる。「Prefab と違う所」の数が増える

**Prefab を直して伝える**

1. 元の「箱」(または置いたどれか) の「ふた」を上に動かし、「回り続ける」の速さを変える
2. 「箱」を右クリック →「Prefab「箱」に反映 (置いたほかの物も変わる)」
3. 置いたほかの「箱」の「ふた」も上に動き、速さも変わる。**ただし、置いた物で変えていた所 (名前・置き場所 (一番上の Transform)・変えた値・足した部品・消した子) はそのまま**。Undo 1 回で置いた物も**ファイルも**反映の前に戻る (Ctrl+Y でまた反映)。新しい版のエンジンで作られた Prefab には反映しない (コンソールに理由)
- 「Prefab「箱」を読み直す」: ファイルを手で書き換えたとき、置いた物を全部ファイルに合わせる (上書きはそのまま)
- 「Prefab「箱」から切り離す」: ふつうのエンティティに戻る (ファイルは消えない)

**置いた物の一部を動かす** (画面では**未確認**)

- 置いた「箱」の「ふた」を、階層のドラッグで別の置いた箱の下へ移す → ふたは Prefab の印の無いふつうのエンティティになる (見出しの下の「Prefab「箱」の一部です」が消える)。保存して開き直しても、どの箱からも何も消えない
- 同じ箱の中で並びだけを変える (同じ親の中で上下に) → ふたは Prefab の一部のまま
- 部屋の中の箱を部屋の外へ移す → 「Prefab「部屋」の中に入っています」が消え、手で置いた箱になる

**形の変更の Undo** (画面では**未確認**。見た目は前と同じ)

- 作る・消す・移す・貼り付け・複製・部品を足す / 外す・Prefab の操作をして、Ctrl+Z / Ctrl+Y → 前と同じように戻る / やり直せる。違いは中身だけ (シーン全体ではなく、触った物だけを覚える)
- Debug ビルドで動かしているときは、どの操作でもコンソールに「SceneRecord:「…」で、触ると言っていない物が変わりました」が出ないこと (出たら止まる。その操作を教えてほしい)

**Undo のまとめ** (どの画面でも)

- インスペクターで数を打っている途中に、別のエンティティを選んで同じ欄に打っても、Undo は物ごとに別になる (前は同じ鍵だと 1 つにまとまることがあった)

**開き直す**

- 保存すると、置いた物の一番上に `"prefab": {"source": 1, "asset": "<箱.rmprefab の ID>", "overrides": {…}}`、子に `"prefab": {"source": 2}` が書かれる。ID は `箱.rmprefab.meta` の `guid`。`overrides` = Prefab と違う所
- **ファイルを動かしても外れない**: アセットのパネル (またはエクスプローラーで `.meta` ごと) で `箱.rmprefab` を別のフォルダへ動かす・名前を変える → 置いた物の見出しの下の場所と、右クリックの「Prefab「…」に反映」の名前が新しいものになる。開き直しても Prefab のまま
- **前の版のファイル**: 前の版で保存した `.rmpf` (`"path": "Assets/箱.rmprefab"`) もそのまま開ける。開くとそのファイルの ID に直り、次に保存すると `"asset"` で書かれる
- `箱.rmprefab` をテキストエディターで直して (例: 「ふた」の `"position"`) から開き直す → 置いた物が全部ファイルに合わせて作り直される (上書きは残る)
- ファイルを消して開くと、コンソールに「Prefab「…」を読めませんでした」と出て、置いた物は保存したまま (見出しの下に「ファイル … が読めません」)

**決まり**

- Prefab のファイルは**アセットの参照** (`.meta` の ID) で指す
- Play 中は Prefab の操作もできない

**入れ子の Prefab** (Prefab の中に置いた Prefab。画面では**未確認**)

1. 上の「箱」の Prefab を作っておく。「部屋」というエンティティを作り、その子に「床」を作る
2. 「部屋」を選んで右クリック →「Prefab を置く: Assets/箱.rmprefab」→ 箱が部屋の子として置かれる。その箱の「ふた」の名前を「部屋のふた」に変える
3. 「部屋」を右クリック →「Prefab にする」→ `Assets/部屋.rmprefab` ができる。テキストエディターで見ると、中の箱は**一番上の物だけ**が `"prefab": {"asset": "<箱の ID>", "overrides": {…}}` 付きで入っていて、「ふた」は入っていない
4. 部屋の中の箱を選ぶと、見出しの下に「Prefab「箱」を置いた物です (…)。Prefab「部屋」の中に入っています。…」
5. 「Prefab を置く: Assets/部屋.rmprefab」でもう 1 つ部屋を置く → 中に箱があり、そのふたは「部屋のふた」(中身は箱の Prefab から作られる)
6. **中の Prefab を直す**: どこかの箱の「ふた」を上に動かして「Prefab「箱」に反映」→ 部屋の中の箱 (2 つとも) のふたも上に動く。名前は「部屋のふた」のまま
7. **外の Prefab を直す**: 部屋の「床」の名前を変えて「Prefab「部屋」に反映」→ もう 1 つの部屋の床の名前も変わる。中の箱はそのまま (ふたの位置・名前も)
8. 部屋から箱を消して「Prefab「部屋」に反映」→ もう 1 つの部屋からも箱が中身ごと消える。どれも Undo 1 回で戻る (ファイルも戻る)
9. 開き直す → 同じ形に作り直される
- 自分の中に自分が入ることになる「反映」(例: 箱の中に部屋を置いて、部屋の Prefab に反映すると、部屋の中に部屋が入る) は、コンソールに「Prefab「…」の中に「…」自身が入ることになるので、反映しません」と出て何も変わらない
- 箱の「ふた」だけをコピーして貼り付けると、ふつうのエンティティになる (Prefab の印は付かない)。部屋の中の箱だけを複製すると、手で置いた箱になる (部屋の Prefab には入らない)

## 7-6. カメラと光 (画面では**未確認**。ビルド・テスト・シェーダーのコンパイルは通っている)

ゲームが**どこから見るか** (カメラの部品) と、**何で照らすか** (光の部品)。どちらもつなぎ「ゲーム制作 × 3D」の部品で、エンティティの -Z の向き (Transform の回転で回る) を向く。

**カメラを置いて、ゲームビューで見る**

1. 階層でエンティティを作り、名前を「カメラ」にする → インスペクターの「＋ 部品を足す」→「**カメラ**」
   - 階層の行の絵が**カメラの形** (箱と、右にレンズ) に変わる
   - シーンビューでは**箱が消え**、カメラの場所に**カメラの印** (灰色) と、**見える範囲の線** (視錐台: 手前の小さな四角・奥の四角・その間の 4 本。上の辺に小さな三角 = 上の向き) が出る。線は奥へ最大 10 まで (遠い面が 1000 でも床いっぱいに広がらない)
2. カメラを選ぶと、印と線がアクセントの色になり、**シーンビューの右下にプレビュー** (「カメラのプレビュー: カメラ」の見出し付きの小さな絵) が出る。ゲームの画面の形 (ゲームの設定の「画面」の幅 / 高さ。最初は 1280 × 720 = 16:9) で、床の線・軸・印は無く、背景は「ゲームの設定」の「背景の色」
   - ギズモで動かす・回すと、線もプレビューも付いていく
   - プレビューの上のクリックは、後ろの物を選ばない。左下の操作の説明はプレビューにかからないところで折り返す
   - 最初は (0, 0, 0) にいて -Z (奥) を見ている。位置を (0, 2, 8) くらいにすると、真ん中の物が見える
3. インスペクターのカメラの欄:
   - **投影**: 透視 / 平行投影。平行投影にすると、遠くの物も同じ大きさ。線は箱の形になる
   - **画角 (度)** (透視のとき。1〜179)・**見える大きさ** (平行投影のとき。画面の縦の半分)・**近い面**・**遠い面**。打つと線とプレビューがすぐ変わる。遠い面を近い面より手前にしても落ちない (少し奥として描く)
   - **自分の背景の色を使う** + **背景の色**: チェックを入れると、ゲームの設定の「背景の色」ではなく、カメラの色で塗る
   - どの変更も Undo 1 回分・未保存の印
4. 「ゲーム」タブ →「ゲームの設定を開く」→ 一番下の「**最初のカメラ**」に、階層から「カメラ」の行をドラッグ (またはクリックして一覧から選ぶ)
5. ▶ で Play →「ゲーム」タブに**そのカメラから見た絵**。パネルの形がゲームの画面の形と違うと、左右か上下に帯 (パネルの地) が出る。Play 中にカメラが「回り続ける」で回ると、絵も回る

**カメラが無い・指していないとき** (Play 中のゲームビューに、文と「ゲームの設定を開く」ボタン。ボタンでインスペクターにゲームの設定が出る)

| 場面 | 出る文 |
|---|---|
| 「最初のカメラ」が (なし) | 「ゲームの設定の「最初のカメラ」が選ばれていません。…」 |
| 指したエンティティを消した | 「「最初のカメラ」のエンティティがシーンにありません …」 |
| 指したエンティティにカメラの部品が無い (部品を外した・別の物を選んだ) | 「「名前」にカメラの部品がありません (Transform も要ります)。…」 |
| カメラのエンティティ (か親) の「有効」を外した | 「カメラの「名前」が有効ではありません。…」 |

**光を置く**

1. エンティティを作る →「＋ 部品を足す」→「**光**」。階層の絵が**太陽** (丸と 8 本の光) に、シーンビューは箱が消えて**黄色い太陽の印**
2. **光の部品が 1 つも無いとき**は、今までどおり上から斜めの白い光が 1 つ (影あり)。**1 つでも置くと、その光だけで照らす** (今までの光は消える)。どの面にも当たる**環境光** (少し上向きの面が明るい) はいつもある (下の「環境光」で変えられる)
3. 種類:
   - **平行光** (最初): 太陽のように、どこでも同じ向き (位置は関係ない)。シーンビューでは印のまわりの小さな輪と、光の向きへ伸びる 5 本の線。最初は -Z (奥) へ向いているので、回転を (-50, 30, 0) くらいにすると上から斜めに当たる。**影を落とす**にチェックがあれば影が出る
   - **点光源**: 電球のように周りへ。**届く距離**で 0 になる (近いほど明るい)。選んでいる間だけ、届く距離の 3 つの輪が出る。**影を落とす** (下の 5)
   - **スポット**: 懐中電灯のように円すいの中だけ。**円すいの角度 (度)** の円すいが、届く距離まで線で出る。縁はなめらかにぼける。**影を落とす** (下の 5)
4. **色**・**強さ** (0〜100) で明るさと色が変わる。強さ 0 は消えたのと同じ。強い光を当てると白く飛ぶ
5. **影**: 「影を落とす」にチェックのある光が影を出す。シーンビューの左上の「影」ボタンは今までどおり全部の影のオン / オフ (マウスを乗せた説明が変わった)。ゲームビューとプレビューはいつも影あり (光の部品で決まる)
   - **平行光**: チェックのある平行光の **1 つ目** (階層の上の方) だけ
   - **点光源・スポット**: 影の地図 **8 枚**を階層の順に使う (点光源は 6 枚 = 立方体の 6 面、スポットは 1 枚)。足りない光は影なしで、コンソールに「シーンビュー: 影の地図が足りないので、点光源・スポットの … 個は影を落としません …」が 1 回。だから**影を落とす点光源は 1 つ + スポット 2 つ**、または**スポット 8 つ**まで
   - 確かめ方: 床の上 (0, 0.5, 0) に箱、その横 (2, 1, 0) に点光源 (届く距離 10) → 箱の反対側の床に、光から離れるほど広がる影。点光源を上下に動かすと影の長さが変わる。スポットを箱の真上 (0, 4, 0) から下へ (回転 (-90, 0, 0)) → 箱の真下に影 (円すいの中だけ)
   - 床の影は、届いている光の中で一番濃い影 (光が届かない所には出ない)
6. 「有効」を外した光は照らさない (印と線は薄く残る)
7. **光は 8 個まで** (平行光も含めて)。多いときは**平行光を先に、次にカメラに近くて明るい点光源・スポット**から 8 個を使い、残りは照らさない。コンソールに「シーンビュー: 光が … 個あります。描くのは最初の 8 個だけです」が 1 回。確かめ方: 点光源を 10 個、X 方向に 5 ずつ離して並べる (届く距離 3) → カメラの近くの 8 個が照らし、遠い 2 個は照らさない。カメラを反対の端へ動かすと、照らす光が入れ替わる (影を落とす点光源は、近いものから 1 つだけ)
8. **環境光**: 「＋ 部品を足す」→「**環境光**」(階層の絵は太陽、シーンビューは箱が消えて太陽の印)。**上からの色** (上を向いた面。最初は 0.16 の暗い灰色)・**下からの色** (下を向いた面。最初は 0.08)。どちらも光の色と同じ「リニア」の値なので、欄の色は画面に出る明るさより暗く見える・**強さ** (0〜10)。付けない・外すと今までの明るさ。上を青っぽく、下を茶色っぽくすると、空と地面に照らされたような色になる。強さ 0 で光の当たらない所は真っ黒。2 つ以上あるときは、階層で上の有効な物が使われる。場所は関係ない
9. 確かめ方の例: 床の上に箱を 3 つ並べ、光を 2 つ置く (赤い点光源を左の箱の横、青いスポットを右の箱の上から下へ (回転 (-90, 0, 0)))。左の箱の片側が赤く、右の箱の上面が青く照らされる。平行光を足すと全体が明るくなり、影が出る

**印のクリック**

- シーンビューでカメラ・光の印をクリックすると、その物が選ばれる (物の後ろにあっても、印が先)。F で寄ると、印のまわりに寄る
- モデルの付いた物にカメラや光を付けると、モデルはそのまま描かれ、印も出る (階層の絵は後から足した部品の絵)

**カメラの外の物は描かない (カリング。いつもオン)** (画面では**未確認**)

- シーンビュー・ゲームビュー・プレビューのどれも、**カメラに見える範囲 (視錐台) の完全に外にある物は描かない** (切り替えは無い。描かなくても見た目は同じで、物が多いときに速くなる)
- シーンビューの左上の帯の下に、薄い字で「**描いた物 a / b (カメラの外は描かない)**」(b = 箱とモデルの数、a = 描いた数)。確かめ方:
  1. 箱を 5 つ、横に 2 ずつ離して並べる → 全部見えていれば「描いた物 5 / 5」
  2. 右ドラッグで見回して、箱が 2 つ画面の外へ出る → 「3 / 5」。見える所に戻すと「5 / 5」(物が消えたり欠けたりしないこと: 半分だけ画面に入っている箱も描く)
  3. 箱の後ろに回る (箱が目の後ろ) → 数が減る
- **影は残る**: 箱を画面の外 (左の外など) に置いても、その影が画面の中の床に落ちるなら影は出る (影の絵には全部描く)。確かめ方: 高い所 (Y = 5) に箱を置き、カメラを下に向けて箱だけ画面の上の外に出す → 箱は数から減るが、床の影は残る

**遠くまで広いシーンの影 (カスケード)** (画面では**未確認**)

- 影を落とす物を広く置く (たとえば箱を (-40, 0.5, 0) と (40, 0.5, 0) に。全部を囲む球の半径が 25 を超える) と、影の地図がカメラの前を 3 つに分けたもの (カスケード) に切り替わる
- 確かめ方: 箱を X 方向に 5 ずつ 20 個並べる (-50〜45) → 近くの箱の影はくっきり、遠くの箱の影は粗め。カメラを動かしても影の縁がちらちらしない (地図はテクセル単位で動く)。カメラから 150 より遠くの物には影が落ちない
- 物が狭い所に戻る (半径 25 以下) と、前のぴったりの 1 枚に戻る

**止まっているときのゲームビュー**

- Play していなくても、「ゲーム」タブに**最初のカメラから見たシーン**が映る (前は「▶ で Play すると…」の案内だけだった)。上に帯: 「止まっています (▶ / Ctrl+P で Play)。最初のカメラから見たシーン」と右に「ゲームの設定を開く」ボタン
- シーンビューでカメラや物を動かすと、ゲームビューもすぐ付いていく。Play を押すと帯が消え、動いているコピーが映る。■ で止めると帯が戻る
- 最初のカメラが無い・指していないときは、止まっていても上の表の文と「ゲームの設定を開く」が出る

**Play 中にカメラを切り替える (システムから)**

- システムは `SystemContext::camera` (ゲームが見ているカメラのエンティティ ID) を書き換えると、ゲームのカメラを切り替えられる (▶ のときは最初のカメラ)。切り替わるとコンソールに「ゲームのカメラを「名前」に切り替えました」
- 画面で試すための組み込みの部品「**カメラを順に切り替える**」(間隔 (秒)。最初は 3):
  1. カメラの部品を付けたエンティティを 2 つ作る (「カメラ A」を (0, 2, 8)、「カメラ B」を (8, 2, 0) で回転 (0, 90, 0) など)。最初のカメラは A
  2. 別のエンティティ (どれでもよい) に「＋ 部品を足す」→「**カメラを順に切り替える**」
  3. ▶ → ゲームビューが 3 秒ごとに A → B → A … と切り替わり、そのたびにコンソールに出る。順番は階層の順 (有効でないカメラは飛ばす)。■ で止めると最初のカメラに戻る
  4. 「カメラを順に切り替える」を付けた物が 2 つあると、階層で上の物の間隔を使う

**保存**: `.rmpf` の部品に `{"type": "rm::game_x_3d::Camera", "data": {"projection": "Perspective", "fieldOfView": 60, …}}`・`{"type": "rm::game_x_3d::Light", "data": {"kind": "Spot", …}}` (種類は名前で)

## 7-7. 2D 空間とシーンビュー (2D) (画面では**未確認**。ビルドとテストは通っている)

2D のゲームを作る道。描くのは 2D 空間プラグイン (Direct2D)、つなぎ「ゲーム制作 × 2D」が部品とシーンビューを出している。

**準備: プラグインを入れる**

- 前の版から使っている PC では、「2D 空間」と「ゲーム制作 × 2D」はまだ入っていない (最初の起動のときだけ全部入るため)
- Hub の「プラグイン」→「2D 空間」の**インストール** → 確認の一覧に「ゲーム制作 × 2D」も出る (つなぎは自分で選ばない) → 入れる

- `%LOCALAPPDATA%\RM_Engine\Engines\<エンジン>\Plugins` を消して起動し直しても、全部入る

**3D と 2D を切り替える (シーンの上の帯)**

1. プロジェクトを開いて「シーン」パネルを見る。3D と 2D の両方が入っていると、パネルの一番上に細い帯があり `[3D] [2D]` が並ぶ (片方だけなら帯は出ない)
2. 最初は **3D** (前に作ったプロジェクトも 3D のまま)。**2D** を押すと、2D のシーンビューに変わる。コンソールに「シーンの空間を「2d」にしました…」
3. これは**ゲームの設定の変更**なので、タイトルに「*」が付き、Ctrl+Z で 3D に戻る。保存すると `.rmpf` の `settings` に `"space": "2d"` が書かれる (ゲームの設定のインスペクターには出ない)
4. 2D のときに階層で作ったエンティティには **Transform 2D** が付く (3D のときは今までどおり Transform)。階層の絵は 2D の物 = 少し回った四角、スプライト付き = 絵の印
5. 「ゲーム」タブ (ゲームビュー) も、選んでいる空間で映る
6. Play 中は帯を押しても切り替わらない (説明に「Play 中は切り替えられません」)
7. 見え方 (カメラなど) は空間ごとに別に覚える (`UserSettings/Layout.json` の `"sceneViews": {"3d": …, "2d": …}`。前の `"sceneView"` は 3D のものとして読み、保存のときに移す)

## 8. リフレクションとインスペクター

**開き方**

- 「ゲーム」パネルの「ゲームの設定を開く」を押す
- プロジェクトを開いたときにも、最初からインスペクターに出ている

**項目** (すべて `plugins\rm_engine\game_production\runtime\GameSettings.h` の書き込みから自動で作られる)

| 欄 | 種類 | 決まり |
|---|---|---|
| ゲームの名前 | 文字 | 名前にマウスを乗せると説明が出る |
| 目標 FPS | 整数 | 1〜240 |
| 物理の刻み (秒) | 数 | 0.001〜0.1 |
| 重力 | 3 つの数 | 狭いときは次の行に出る |
| 背景の色 | 色見本 + 4 つの数 | 0〜1 |
| 画面 > 幅 | 整数 | 320〜7680 |
| 画面 > 高さ | 整数 | 240〜4320 |
| 画面 > 表示のしかた | 一覧 | ウィンドウ / フルスクリーン / 枠なしの全画面 |
| 画面 > 垂直同期 | チェック | 説明あり |
| タグ | 配列 | 「0 個」と右に「＋」。下の「配列の欄」を参照 |

**数をドラッグで変える** (画面では**未確認**)

- 数の欄の**名前** (例: 「目標 FPS」) にマウスを乗せると、カーソルが左右の矢印になる。押したまま左右に動かすと数が変わる (右で増える)
  - ベクトル (位置・回転・大きさ・色) は、欄の前の小さな **X / Y / Z** (赤・緑・青の文字。色は R / G / B / A) をドラッグすると、その成分だけが変わる
  - 配列の数の要素は、左の番号 (0, 1, 2 …) をドラッグ
- ドラッグ中は**カーソルが消え**、画面の端で止まらずにいくらでも動かせる。離すと元の位置にカーソルが戻る
- 速さ: 普通は値が大きいほど速い (0 なら 1 ピクセルで 0.03、100 なら 0.3)。`Step=` を決めてある欄は 1 ピクセルでその量。**Shift** で 4 倍、**Alt** で 1/4
- 整数の欄は整数ずつ。範囲 (Min / Max) の外には出ない
- **1 回のドラッグが Undo 1 回分**。打っている途中の欄があれば、ドラッグを始めたところでその入力は終わる
- 複数選んでいるとき (6 章) は全部が同じ値になる (ベクトルはその成分だけ)

**配列の欄** (画面では**未確認**。試すなら「ゲームの設定」の「タグ」)

- 名前の行に「N 個」と、右端に **＋**。＋ を押すと 1 つ増える (最後の要素のコピー。空なら既定の値。タグなら空の文字)
- その下に要素が 1 行ずつ: 左から **つまみ (≡)**・番号・値の欄・**×**
  - 値の欄は普通の欄と同じ (クリックで全部選ぶ・打つたびに反映・Esc で戻す)。要素が入れ子の型なら、その欄が字下げで並ぶ
  - × で、その要素を消す
  - **つまみを上下にドラッグ**すると、入る場所に赤い線が出て、離すとそこへ動く。同じ場所なら何も起きない
- どの操作も Undo 1 回分 (打った分はまとまる)。保存すると `.rmpf` にその順で書かれる
- 複数選んで、配列の中身が物によって違うときは「—」と「選んだ物で中身が違うので、まとめては変えられません。」と出て、変えられない

**数・文字の欄の動き** (画面では**未確認**)

- **欄をクリックすると中身が全部選ばれる**。そのまま打てば置き換わる
- **欄の上でドラッグすると、なぞった所だけ選ばれる** (欄の外へ出ても、ボタンを離すまで選び続ける)。入力中の欄でクリックすると、その位置にカーソルが来る。ダブルクリックで全部選ぶ
  - ドラッグで選べるのは、ほかの文字の欄 (Hub の名前・検索など) も同じ。「クリックで全部選ぶ」はインスペクターの欄だけ
- **打つたびにすぐ反映される** (Enter を押さなくてよい)。シーンビューの箱も打つたびに動く
  - 「-」や「1e」のように、まだ数になっていない間は変わらない (数になったところで変わる)
  - Enter・ほかの所をクリックで入力を終える。**Esc なら、その欄に入る前の値に戻る**
  - **1 つの欄に打った分は Undo 1 回分**にまとまる (「1」「12」「123」と打っても Ctrl+Z 1 回で入る前に戻る)。打ってから Esc で戻したときは Undo に何も残らない
- 範囲の外の数は収まる (999 → 240)
- 整数は丸める (2.6 → 3)
- 数でない文字や `nan` / `inf` では変わらない
- 変えると「*」が付く。Ctrl+Z / Ctrl+Y で戻せる

**保存**

- 保存すると、`.rmpf` に `softwareData` と、`plugins` へのゲーム制作の記録が書かれる
- 既定値のままなら何も書かない。開いただけではプラグインに縛られない
- 試し方: 開き直して、値が戻ることを見る

**知らないデータを残す動き**

- `.rmpf` の `softwareData[0].data.settings` に、知らないキー (例: `"abc": 1`) を足す
- `display.mode` を `"Ultra"` にする
- 開くと「表示のしかた」が「Ultra (不明)」と出て、コンソールに警告が出る
- ほかの欄を変えて保存しても、`abc` と `"Ultra"` は残る。一覧で選び直したときだけ上書きされる (Ctrl+Z で `Ultra` に戻る)

**開発側の動き**

- `GameSettings.h` に、`RM_PROPERTY` を付けずにフィールドを書いてビルドしてみる
- `GameSettings.h(行,列): error RM0001: フィールド … に注釈がありません` と出て止まる
- そのほかのエラー:
  - `RM0002`: 属性名の打ち間違い (`Mim=0` など)
  - `RM0003`: 属性の値の形 (`Label=名前`、`Min=定数名`、`Min` が `Max` より大きい など)
  - `RM0004`: 使えない型 (`double`、ポインターなど)
  - `RM0006`: 印の付いていない型
  - ほかに `RM0005` `RM0007`〜`RM0011`
- 正しく足せば、インスペクターと保存に自動で出る

## 8-2. アセットと参照の欄 (画面では**未確認**。ビルドとテストは通っている)

**準備**

- プロジェクトのフォルダの `Assets\` に、エクスプローラーでファイルを入れておく (例: `sky.png`、`Models\robot.glb`、`song.ogg`、`readme.txt`)
- エディターでプロジェクトを開く。「アセット」パネルは、最初の配置ではコンソールの隣のタブ

**ID (.meta) ができること**

- 開くと、`Assets\` の中の全部のファイルとフォルダの横に `<名前>.meta` ができる (中身は `{"guid": "32 文字の英数字"}`)。コンソールには何も出ない (初めての ID は普通のこと)
- `.meta` はパネルには出ない (`desktop.ini`・`Thumbs.db`・`.` で始まる名前も出ない)
- `.meta` に自分でキーを足しても (例: `"memo": 1`)、ID が書き直されるときに消えない

**アセットのパネル**

| やること | 起きること |
|---|---|
| 見直し | エクスプローラーでファイルを足す・動かすと、エディターに戻ったとき裏で調べ直す。その間も前の一覧のまま動かせて、パネルの下の行に「調べています…」。終わると一覧が変わる (ファイルが何万あっても描画は止まらない。★ プロジェクトを開くときの最初の 1 回だけは、調べ終わるまで待つ) |
| 見る | フォルダが先、その後にファイル (名前の順・大文字小文字を区別しない)。種類ごとの印: フォルダ (黄色) / 画像 (額と山) / 3D モデル (立方体) / 音 (音符) / フォント (A) / 文書 (行のある紙) / そのほか (角の折れた紙) |
| ▸ / ▾、← / → | フォルダを開く・閉じる |
| クリック / Ctrl / Shift / ↑↓ | 選ぶ (階層と同じ)。パネルの下の行に「種類 · Assets/場所」(2 つ以上なら「N 個選んでいます」、何も選ばないと「N 個のファイルとフォルダ」) |
| 上の「検索」 | 名前に含む物と、その上のフォルダが出る |
| F2 / ダブルクリック / 右クリック →「名前を変更」 | その場で名前を変える。拡張子も名前の一部 (`.png` を消すと種類が変わる)。`.meta` も一緒に名前が変わる (ID はそのまま) |
| 行をフォルダの上へドラッグ | そのフォルダへ動かす (`.meta` も一緒)。行の上下の端に落としたときは、その行のいるフォルダへ。一番下の空いた所は `Assets\` の一番上 |
| 右クリック →「新しいフォルダ」(Ctrl+Shift+N) | 選んでいるフォルダの中 (ファイルなら同じフォルダ、何も選んでいなければ一番上) に「新しいフォルダ」(あれば「新しいフォルダ 2」…) ができ、すぐ名前を打てる |
| 右クリック →「エクスプローラーで表示」 | エクスプローラーが開き、そのファイルが選ばれている |
| 何も無い所を右クリック →「エクスプローラーで開く」 | `Assets\` が開く |
| 右クリック →「削除 (ごみ箱へ)」/ Delete | 確認なしで**ごみ箱へ** (`.meta` も)。ごみ箱から戻すと、同じ ID で戻る。**ごみ箱に入れられない所** (USB メモリ・ネットワークのフォルダ・ごみ箱の大きさより大きいファイル) では**消さずに**「…ごみ箱に入れられない場所にあるので、消していません」と出る (★ 画面と USB メモリでは未確認) |

- ファイルの操作は**ディスクにすぐ**行われ、Ctrl+Z では戻らない。プロジェクトの「*」(未保存) も付かない (Unity と同じ考え。戻すのはごみ箱)
- 名前に使えない文字・同じ名前がある・動かせない、などはエラーのダイアログとコンソールに出る

**エディターの外で変えたとき** (ID が付いていくこと)

1. エディターを開いたまま、エクスプローラーで `sky.png` **だけ** (`.meta` を置いたまま) 別のフォルダへ動かす → エディターに戻ってマウスを動かすと、パネルが新しい場所を出す。コンソールに「アセット: sky.png → … (移動。ID はそのまま)」。`.meta` も新しい場所へ動いている
2. エクスプローラーで `.meta` を置いたまま名前を変える (`sky.png` → `sky2.png`) → 「(名前の変更。ID はそのまま)」。同じフォルダに同じ拡張子の新しいファイルが 1 つだけのときに限る (2 つ同時ならどちらか分からないので新しい ID)
3. フォルダの名前をエクスプローラーで変える → 中の物はそのまま、フォルダの ID も付いていく
4. `.meta` ごとファイルをコピーする (同じ ID が 2 つ) → コピーの方が新しい ID になり、コンソールに「ほかのファイルと同じ ID だったので、新しい ID にしました」。**エディターを閉じている間にコピーしても、元のファイルが元の ID のまま** (`.meta` に書いてある元の名前 `"name"` が合う方が元。`"name"` の無い古い `.meta` なら、`.meta` が先に作られた方)
5. エディターを閉じている間に 1 〜 3 をしても、次に開いたときに同じように付いていく
6. **読めない `.meta` は書き換えない**: エディターを閉じて、どれかの `.meta` をメモ帳で開き、最後の `}` の前にカンマを足して保存 (JSON としては壊れる) → 開く → そのファイルは同じ ID のまま出て、`.meta` はカンマ付きのまま (エディターは直さない)。中身を全部「あああ」にすると → そのファイルは一覧から消え、コンソールに「…meta を読めないので、ID が分からないまま一覧から外しています … .meta は書き換えません」が 1 回。直して保存すると、元の ID で戻る
   - ほかのアプリが `.meta` を開いたまま (読めない) のときも同じ: 開いている間に見直しても、前の ID のままで書き換えない
7. 名前の変更・移動で、行き先に同じ名前の `.meta` だけが残っているとき (例: `b.png.meta` だけがある所へ `b.png` を動かす) は、**動かさずに**「行き先にもう「b.png.meta」があるので、…動かしていません」と出る

**参照の欄 (インスペクター)**

- 試す場所: 「ゲーム」パネルの「ゲームの設定を開く」の一番下の 2 つ
  - 「アイコン」= アセットの参照 (`AssetRef`、画像だけ)。書き出したゲームの exe のアイコンになる (PNG だけ。7-9 章)
  - 「最初のカメラ」= エンティティの参照 (`EntityRef`)。ゲームビューと Play はこのエンティティのカメラの部品から見る (7-6 章)
  - エンティティの部品「メッシュ (3D モデル)」の「**モデル**」(3D モデルだけ)。入れるとシーンビューの箱がそのモデルになる (7-2 章の「メッシュ」)
- 欄には名前と種類の印。何も入っていなければ「(なし)」。マウスを乗せると場所 (`Assets/…` / 親の名前) が出る

| やること | 起きること |
|---|---|
| アセットのパネルから画像の行を「アイコン」の欄へドラッグ | 欄が青い枠で光り、ドラッグ中の札も青い枠になる。離すと入る。**画像でないファイル** (音など) は光らず、離しても入らない |
| 階層からエンティティの行を「最初のカメラ」へドラッグ | 同じように入る |
| 欄をクリック | 一覧が開く: 先頭が「(なし)」、その後に入れられる物 (アイコンなら画像だけ、カメラなら階層の全部) と右に場所。上の検索に打つと絞られる。クリックか Enter (一番上) で入る。Esc・外のクリックで閉じる |
| 欄の右の × | 外す (「(なし)」に) |
| Ctrl+Z / Ctrl+Y | どれも 1 回ずつ戻る・やり直す。変えると「*」 |
| 入れたファイルをパネルで名前を変える・動かす | 欄の名前もすぐ変わる (ID で持っているので外れない) |
| 入れたファイルを消す / エンティティを消す | 欄は「(見つかりません)」。値 (ID) は残り、保存しても消えない。ごみ箱から戻す / Ctrl+Z で戻すと、また名前が出る |

- 保存すると `.rmpf` の `settings` に `"icon": "<32 文字の ID>"`、`"startCamera": <エンティティの番号>`
- **別ウィンドウをまたぐドラッグ** (画面では**未確認**): アセットのパネル (か階層) をタブのドラッグで外に出し、そこから行をエディターのインスペクターの参照の欄へドラッグ → 欄が青い枠で光り、離すと入る。逆 (エディターのアセットのパネル → 外に出したインスペクター) も同じ。★ ドラッグ中の札 (名前) は運んでいる側のウィンドウの中にしか出ない。札の青い枠も、ほかのウィンドウの欄の上では付かない (欄の枠は光る)
- **エンティティの参照の付け替え** (画面では**未確認**。テストあり): 「最初のカメラ」などの欄を持つ部品 (例: カメラを指す欄を持つ自作の部品) を付けたエンティティ A と、その子 B があって、A の欄が B を指しているとき
  1. A を複製 (Ctrl+D) / コピーして貼る → 新しい A の欄は**新しい B** を指す。コピーした中に無い物 (ほかのエンティティ) を指していた欄は、そのまま同じ物を指す
  2. A を Prefab にする → ファイルの中では Prefab の中の物を指す。Prefab の外を指していた欄は、ファイルでは「(なし)」(元の A ではそのまま。置いた物の「Prefab と違う所」に数えられる)
  3. Prefab を置く → 置いた A は**置いた B** を指す。Prefab に反映・読み直しても、それぞれ自分の B を指したまま
  - ★ いまの部品で EntityRef を持つのはゲームの設定の「最初のカメラ」だけ (部品ではない)。部品で試すには、自作の部品に `RM_PROPERTY(Edit) rm::EntityRef target;` を足す

**サムネイル** (画面では**未確認**。ビルドとテストは通っている。3D モデルの絵を作るコードはエディターの外で動かして、サンプルの 4 つの絵が出ることを見た)

- アセットのパネルで、**画像はその絵を小さくしたもの**、**3D モデルは小さく描いた絵** (前から少し右上から、全体が入るように。まわりは透けている) が、種類の印の代わりに出る。ほかの種類 (音・文書など) とフォルダは今までどおり印
- **大きさを変える**: パネルの一番下の行の右にある**横のつまみ** (スライダー) をドラッグ。右へ行くほど大きく (行も高くなる)、**左の端はサムネイルなし** (前と同じ小さな印の行)。マウスを乗せると「サムネイルの大きさ (左の端: サムネイルなし)」。大きさはソフトごとに `UserSettings/Layout.json` の `"assets": {"thumbnail": 40}` に覚える (閉じて開き直しても同じ。プロジェクトのデータではないので「*」は付かない)。最初は 40
- 確かめ方:
  1. `docs/samples/models/` の中身を `Assets/Models/` にコピーして開く → `house.gltf`・`house.glb`・`crate.gltf`・`torus.obj` が小さな家・箱・ドーナツの絵、`.png` 3 つはその絵。`.mtl` は文書の印

  4. ファイルがたくさんあるフォルダを開く・大きな画像やモデルがある → 作っている間も**パネルのスクロールや他の操作が止まらない** (読むのは別のスレッド)。サムネイルはできた物から 1 つずつ出てくる。スクロールした先の物から先に作る
  5. 読めない絵 (`.psd` など) は種類の印のまま。コンソールに「サムネイル: 「…」を作れないので種類の印で出します: …」が 1 回 (情報)
- 「インスペクター」の参照の欄をクリックして開く一覧にも、画像と 3D モデルは**サムネイル**が出る (行が高くなる。作っている途中は種類の印で、できると絵に変わる)。アセットのパネルと同じ絵を使う

**取り込みの設定** (画面では**未確認**。ビルドとテストは通っている)

- 2D のシーンビューのスプライトの画像も、ファイルを読んで解くのは別のスレッドで行う (大きな画像を置いてもカメラの操作が止まらない。読めるまでは四角か前の絵のまま)

- アセットのパネルで**ファイルを 1 つクリック** (ボタンを離したとき) → インスペクターに、上に名前、その下に「種類 · Assets/場所」と ID。画像と 3D モデルは、その下に設定のかたまりが出る
  - ドラッグした (参照の欄へ運んだ) ときは、インスペクターは変わらない。2 つ以上を選んだときも変わらない
  - 階層でエンティティを選ぶと、インスペクターはそちらに戻る
- **3D モデルの取り込み**
  - 「**大きさ**」: 形に掛ける倍率 (0.0001〜10000)。`house.gltf` で 0.5 にする → シーンビューの家がすぐ半分になる (コンソールに「モデル「house.gltf」をもう一度読みました」)。クリックで選ぶ枠・F で寄る距離も小さくなる
  - 「**上の向き**」: Y が上 / Z が上。Z にすると、モデルが X 軸のまわりに起き上がる (Z が上で作られた OBJ が寝てしまうときに使う)。サムネイルもそのうち (1 秒ほどで) 起き上がる
- **画像の取り込み**
  - 「**くっきり (ドット絵)**」: オンにすると、その画像を使う 3D のテクスチャと 2D のスプライトが、拡大してもぼけずにピクセルのまま大きくなる (スプライトの部品の「くっきり」がオフでも)
  - 「**大きさの上限 (ピクセル)**」: 16〜8192。これより大きい画像は縮めて読む (たとえば 64 にすると、テクスチャが粗くなるのが分かる)。ファイルそのものは変わらない
  - 「**圧縮**」: 自動 / なし / BC1 / BC3 / BC4 / BC5 / BC7。3D のテクスチャとして GPU でどの形で持つか (下の「テクスチャの圧縮」)
- **3D モデルの取り込み** には「**中の絵の圧縮**」と「**中の絵の大きさの上限**」もある (`.glb` などの中に入っている絵に効く)
- 変えると、その `.meta` (`Assets/…/<名前>.meta`) の `"import"` に書かれる。**数をドラッグしている間は書かず、ボタンを離したとき** (打っているときは、打ち終えて欄を出たとき) に 1 回書き、そこでモデルや絵が読み直される (例: `{"guid": "…", "import": {"scale": 0.5, "up": "Y"}}`)。**Ctrl+Z で戻すと `.meta` も元に戻り**、モデルも元の大きさで読み直される。履歴に積むので「*」(未保存) が付く (保存してもプロジェクトのファイルが書かれるだけ。`.meta` はもう書いてある)
- 数をドラッグで変えている間も、打っている間も、Undo は 1 回分にまとまる
- `.meta` に自分で `"import"` の中に知らないキーを足しても、設定を変えたときに消えない

**開発側の動き**

- 型に参照を書く: `RM_PROPERTY(Edit, Label="モデル", AssetKind="model") rm::AssetRef model;` / `RM_PROPERTY(Edit) rm::EntityRef target;`。配列 (`std::vector<rm::AssetRef>`) も使える
- `AssetKind` に書ける種類: `image` `model` `audio` `font` `text` `other` `folder` (コンマで区切って複数)。無ければどのファイルでも
- `AssetKind` を `AssetRef` 以外に付ける・大文字や空の名前を書くと `RM0003` で止まる。知らない種類の名前は RMTests (`Asset_KindsOfReflectedFields`) が見つける

## 8-3. GPU が失われたとき (画面では**未確認**。ビルドとテストは通っている)

ドライバーの更新・ドライバーの落ち直し・GPU が固まって Windows がリセットしたとき (TDR) などで、GPU のデバイスが失われる。前は画面が真っ黒か止まったままになり、保存の確認も見えなかった。今は**デバイスを作り直して、そのまま続けられる**。

**試し方 1: 作り直しの道だけを試す (いつでもできる)**

1. Hub かエディターを開き、3D のシーンビュー (箱やモデル・影・光)・2D のシーンビュー (スプライト)・アセットのパネル (サムネイル) が見えるようにしておく
2. **Ctrl+Alt+Shift+F12** を押す (どのウィンドウでもよい)。コンソール / ログに
   - 「GPU のデバイスが失われたことにします (Ctrl+Alt+Shift+F12: 作り直しの試し)」
   - 「GPU が使えなくなりました (0x887A0005)。デバイスを作り直します」
   - 「GPU のデバイスを作り直しました (作り直し 1 回目)」
   - 「シーンビュー: GPU が作り直されたので、3D の描画とモデルを作り直します」(3D のシーンビューがあるとき)
3. 画面は一瞬で元どおりに描き直される。確かめること: 文字・ボタン・グラデーション・Hub のロゴ、3D の箱・モデル (色とテクスチャ)・影・光、カメラのプレビュー、2D のスプライト、アセットのパネルとインスペクターの参照の欄のサムネイル、別ウィンドウに出したパネル。どれも前と同じに出る (モデルとテクスチャは読み直すので、大きなモデルは「読み込み中…」が少し出る)
4. 何度押してもよい (押すたびに「作り直し n 回目」が増える)。未保存の印・Undo の履歴・Play 中のゲームはそのまま

**試し方 2: 本当に GPU をリセットする (Windows の開発者向けの道具が要る)**

- Windows の「グラフィックス ツール」(設定 → システム → オプション機能 →「グラフィックス ツール」を追加) を入れると、`dxcap.exe` が使える。管理者のコマンドプロンプトで `dxcap -forcetdr` を実行すると、GPU が数秒止まってリセットされる (画面が一度ちらつく)。そのあと試し方 1 の 3 と同じになること
- ほかに、デバイス マネージャーでディスプレイ アダプターを「無効」→「有効」にしても失われる (無効の間は Windows の基本のディスプレイ (WARP) になることがある。そのときコンソールに「ハードウェアの Direct3D 11 を作れませんでした …。WARP (ソフトウェア) で続けます」)
- ★ どちらも画面全体がちらつく。作業を保存してから試す

**作り直せないとき**

- 1 秒ごとにもう一度試す (コンソールに「GPU のデバイスを作り直せませんでした (n 回目)。少ししてからもう一度試します」)
- 3 回続けて失敗すると、Windows のダイアログ (GPU を使わずに出る) で「GPU (グラフィックス) が使えなくなり、作り直せませんでした。… 今の作業を保存しますか?」。**はい** でプロジェクトを保存して「保存しました。エディターを閉じて開き直してください。」(Hub では「保存するものはありません …」)、**いいえ** で何もしない。ダイアログは 1 回だけ (作り直せたらまた出るようになる)
- この道は画面では試しにくい (ずっと失敗させる口は無い)
