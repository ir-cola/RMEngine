# 地形 (3D)

3D のゲームの地面を作る。高さの地図を筆で盛り上げ・削り、何枚かの絵を塗り分け、木や草をばらまく。
遠くは粗く描いて軽くし、物理 (Jolt) で歩けて、天気 (雨・雪・濡れ) と気候にもつながるようにする。

作り始める前の設計で、まだコードは無い (2026-11-26)。書き方は [ANIMATION.md](ANIMATION.md) と
[CLIMATE.md](CLIMATE.md) にそろえた。姉妹の設計図 [NAVIGATION.md](NAVIGATION.md) (ナビメッシュ) は
別の人が同時に書いている。地形の側から渡すものは 5-7 に書いた。[TILEMAP.md](TILEMAP.md) (タイルマップ) も同じ時期に書かれている。

| ほかの物が形を足す口 | (無い) | 物理の部品 (コライダー) の付いたエンティティしか物理の世界に入らない。地形を入れるには**新しい口**が要る (3 章) |

## 3. プラグインの分け方

核 (`src/`) は地形を知らない (憲法 10)。新しいフォルダは `plugins/` の下だけなので、`layers.txt` は
変えない (憲法 8)。

| プラグイン | 中身 | 前提 |
|---|---|---|
| **地形** `terrain` (新しい) | 地形のデータの型・高さの計算 (高さ・法線・光線との当たり)・筆の計算・区画のメッシュ作り・細かさ (LOD) の選び方・草木のばらまき方・焼いた形の読み書き。**ゲーム制作を知らない** (純粋。後で 3D モデル制作のソフトも使える)。`"needsConnector": true` | 3D 空間 |
| **ゲーム制作 × 地形** `game_x_terrain` (つなぎ) | 部品「地形」・アセット `.rmterrain` の作成・「地形」タブ・シーンビューの筆・地形を描く (下の口)・書き出しの焼き手・スクリプトの `RMTerrain.h`・「追加 ▸ 3D オブジェクト ▸ 地形」 | ゲーム制作・ゲーム制作 × 3D・3D 空間・地形 |

## 4. データ

### 4-1. どこに持つか: 部品 + アセット

- エンティティの部品 **「地形」** (`RM_STRUCT TerrainRenderer`。名前は仮) が、アセット **`.rmterrain`** を指す
  (`AssetRef`、`AssetKind=".rmterrain"`)。シーンの設定にはしない (11 章の 1)
- 部品の欄 (インスペクターに出る。保存・インスペクター・Undo はリフレクションから: 憲法 1・9)

| 欄 | 意味 | 既定 |
|---|---|---|
| 地形 | `.rmterrain` のアセット | 空 (インスペクターに「新しい地形を作る」) |
| 影を落とす | メッシュと同じ | オン |
| 細かさ | 遠くを粗くするときの、許すずれ (画面のピクセル。5-2) | 2 px |
| 木を描く距離 / 草を描く距離 | その先は描かない (m) | 400 / 80 |
| 草の濃さ | 草の数の倍率 (遅い PC 向け) | 1 |

- 置き場所は Transform の**位置だけ**が効く (回転と大きさは使わない。インスペクターに注意書き)。
  高さの格子は軸にそろっているほうが、物理・天候・ナビ・「地面の高さ」がみんな簡単になる (11 章の 10)
- 2D のゲームでは使わない (`ComponentInfo::space = "3d"`)

### 4-2. `.rmterrain` の中身

自己記述の JSON (憲法 6)。全体を 1 つの `RM_STRUCT TerrainFile` で書く (憲法 9)。
`{"kind": "rm_engine.terrain", "format": 1, …}`。知らないキーは `reflect::Unknowns` で書き戻す。

| 項目 | 意味 | 既定 |
|---|---|---|
| マスの大きさ (`cell`) | 点と点の間 (m) | 1 |
| 区画の数 (`chunksX` / `chunksZ`) | 横と奥の区画の数。区画 1 つ = 64 × 64 マス (決まった数) | 8 × 8 (512 m 四方) |
| 高さの範囲 (`low` / `high`) | 16 ビットの高さが表す範囲 (m)。0 が low、65535 が high | −100 / 400 (約 0.8 cm 刻み) |
| 層 (`layers`) | 番号 (`id`)・名前・マテリアル (`.rmmat`)・繰り返しの大きさ (m)・エリアの名前 (5-7) | 1 つ (「土」、マテリアル無し = 灰色) |
| 木の種類 (`trees`) | 番号・名前・モデル・当たり (カプセル) の有無と幹の半径・大きさの幅・向きをばらす | 無し |
| 草の種類 (`grasses`) | 番号・名前・モデル (または画像の板)・大きさの幅・色のゆらぎ・1 m² の本数 | 無し |
| 区画 (`chunks`) | 下の表。**インスペクターに出さない** | — |

区画 1 つ (`TerrainChunk`):

| 項目 | 中身 |
|---|---|
| `x` / `z` | 区画の番号 |
| `heights` | 高さ。16 ビット (小さい桁が先) を行ごと (z の小さい行から) に並べたバイト列の **base64** |
| `layers` + `weights` | この区画に塗られた層の番号の並びと、点ごと・層ごとの重み (8 ビット) の base64。塗られていない層は持たない |
| `holes` | 穴の点。気候の地図と同じ**ランレングス** (同じ値の続きを「値*数」と書く) の文字 (`"0*120,1*4,0*3972"`) |
| `grass` + `density` | この区画にある草の番号と、点ごとの濃さ (8 ビット) の base64 |
| `trees` | 木 1 本ずつ: 種類・x・z (ワールドの場所)・向き・大きさ |

- **同じ点を 2 つの区画に持たない** (憲法 2)。点の数は 1 辺 `区画の数 × 64 + 1`。区画 (i, j) は
  点 i × 64 〜 i × 64 + 63 を持ち、一番東 (+X) と北 (+Z) の端の 1 列は、端の区画が 1 列多く持つ
- 番号 (`id`) で層・草・木の種類を見分ける (気候の種類と同じ: 並べ替えても消しても、ほかが変わらない)
- base64 を作る関数は今は無い。解く関数 (`space3d/runtime/Mesh.h` の `DecodeBase64`) と一緒に
  `base/` へ移して 1 か所にする (憲法 2。`base` は標準ライブラリだけなので置ける)
- ランレングスの関数 (`EncodeRuns` / `DecodeRuns`) は今、気候のプラグインの中 (`climate/runtime/Climate.h`)。
  地形は気候を前提にしないので、そのまま呼べない。[TILEMAP.md](TILEMAP.md) が塗る計算 (ランレングス・
  筆の補い方) を核 (`src/core` の中。例 `core/paint`) へ移す計画 (その 11 章の 20) なので、地形もそれを使う
- 大きさの目安 (層 4 つを全部に塗ったとき): 512 m 四方 (513² 点) で 高さ 0.5 MB + 重み 1 MB →
  base64 で約 2 MB。2 km 四方 (2049² 点) で約 34 MB (8 層全部なら約 56 MB)。**上限は 1 辺 2048 マス**
  にする (11 章の 2 と 4。ファイルの上限 256 MB に余裕を残す)

### 4-3. エディターでの持ち方 (大きいデータを毎回全部写さない)

- 地形の中身は、アセットのバイト列のままでは扱わない。ゲーム制作 × 地形のランタイムに**地形の置き場**
  (`TerrainStore`。アセットの ID → 解いた地形) を 1 つ持ち、区画ごとに **版の番号**を付ける
- 区画は「版ごとの、変えない写し」(`shared_ptr<const 区画>`) で持つ。エディターの筆は新しい区画を作って
  差し替え、版を上げる。描く側は版の上がった区画だけメッシュを作り直す。作業スレッド (ナビを焼く: 5-7・
  書き出し) は、その時の区画の写しを持てば、筆と同時でも安全に読める
- ファイルへ書くのは今の道 (`SetAssetContent`。筆を離したとき)。そのとき、変わっていない区画は前に作った
  base64 の文字を使い回す (全部を作り直さない)
- ファイルが外で変わった・ほかの道で中身が戻った: 中身の印 (FNV-1a) が置き場と違えば読み直す
- Undo は `ContentCommand` (中身全体の前と後) を使わず、触った区画だけを持つ命令にする (6-4)

## 5. ランタイム (純粋な計算は I/O と描画から離してテストする: 憲法 5)

地形のプラグイン (`terrain/runtime/`) の中身。どれも GPU もファイルも使わない。

| ファイル (案) | 中身 | テスト |
|---|---|---|
| `TerrainData` | 解いた地形 (区画ごとの float の高さ・重み・穴・草・木)。`.rmterrain` との往復 | 往復でバイト一致・知らないキー・壊れた base64・数の合わない区画・新しい版は読まない |
| `Heights` | `HeightAt(x, z)`・`NormalAt`・`Raycast` (光線とマス目: 通るマスを順に見て 2 つの三角形と当たり) | 描く三角形と同じ分け方 (対角線の向き) で答える・穴・地形の外・端の区画 |
| `Brush` | 筆の重み (中心からの距離となめらかな縁)・なぞった線の上の判子の場所・各操作 (5-1) | 操作ごとの式・判子の間隔・1 回の筆で触った区画の一覧 |
| `ChunkMesh` | 区画 1 つ・細かさ 1 段の `MeshData` (と、その段で粗くしたときに一番ずれる高さ) | 点と三角形の数・段ごとのずれ・スカート・穴の三角形が無い |
| `Lod` | 区画ごとの細かさの段を、カメラから選ぶ | 近い区画ほど細かい・画面のずれが上限より小さい |
| `Scatter` | 草の濃さ → 置き場所 (決まった種の乱数)・遠いときに描く数 | 同じ入力で同じ置き場所・濃さ 0 で 0 本 |
| `Splat` | 層の重みの足し算と、合計を 255 にそろえる・GPU に送る形 (RGBA 8 ビット 2 枚 = 8 層) | 合計・層を消したとき |
| `TerrainBake` | 焼いた形 (7 章) の読み書き | 往復・知らないチャンクを飛ばす |

### 5-1. 筆の操作

筆 = 半径 (m)・強さ (0〜1)・縁のやわらかさ (%)。重み w は真ん中で 1、縁で 0 (なめらかな段)。
押したまま動かすと、半径の 3 割ごとに判子を押す (気候の筆と同じ。フレームの速さで結果が変わらない。
補い方の計算は、上の核へ移したものを使う)。

| 操作 | 式 (点ごと) | キー (案) |
|---|---|---|
| **上げる** | h += 強さ × w × 1 回の量 | Shift で下げる |
| **下げる** | h −= 強さ × w × 1 回の量 | Shift で上げる |
| **ならす** | h を まわり 3 × 3 の平均へ 強さ × w だけ寄せる | — |
| **平らにする** | h を 決めた高さへ 強さ × w だけ寄せる。決めた高さ = 押し始めた所の高さ (Ctrl + クリックで拾う・欄に打つ) | Ctrl + クリック |
| **穴** | w > 0.5 の点を穴にする | Shift で穴を消す |
| **塗る** | 選んだ層の重みを 強さ × w だけ増やし、ほかの層を減らして合計をそろえる | — |
| **草** | 選んだ草の濃さを増やす | Shift で減らす |
| **木** | 筆の中に、決めた間隔より近くならないように木を置く (決まった種の乱数) | Shift で消す |

- 高さは高さの範囲 (`low` / `high`) に切り詰める
- 計算は区画をまたいでよい (端の点は持ち主の区画に書く)

### 5-2. 遠くを粗くする (LOD)

LOD (Level of Detail) は、遠い所ほど少ない三角形で描くこと。段階を分けて作る:

- **段の格子 + スカート** (最初): 区画ごとに、点を 1・2・4・8・16 マスおきに間引いた 5 段のメッシュを
  CPU で作る (要る段だけ。10 秒使わなければ捨てる: モデルと同じ)。となりの区画と段が違うと継ぎ目に
  すき間ができるので、区画の縁から下へ垂らした帯 (**スカート**) で隠す
- 段の選び方: 「その段で粗くしたときにずれる高さ」が、画面で何ピクセルになるか (距離と画角から) を
  出し、部品の「細かさ」(既定 2 px) より小さい一番粗い段にする
- メッシュはふつうの `GpuMesh` なので、見える物だけ・影の地図・向きの地図・光線の当たり (エディター)
  が今のまま効く
- **CDLOD** (後で。11 章の 6): 区画を四分木 (4 つずつに分けた木) で分け、カメラからの距離で細かさを選び、
  段の境目では頂点を少しずつ動かして (モーフ) 継ぎ目と「ぱっと変わる」のを消すやり方。同じ小さな格子を
  ずらして何度も描き、高さは頂点シェーダーが絵から読む。ずっと広い地形に向く。ただし影の地図・向きの地図の
  頂点シェーダーも高さを読むものに替える必要がある
- **クリップマップ** (選ばない案): カメラを中心に入れ子の輪のような格子を置き、外の輪ほど粗くする。
  カメラが動くと高さの絵をずらして書き足す。とても広い (数十 km) 地形向けで、今のエンジンには大きすぎる

### 5-3. 草木をばらまく

- **木**: 1 本ずつの列 (区画の `trees`)。描くのは今の `MeshDraw` (同じモデル・同じ部分は 1 回の
  インスタンス描画にまとまる: `DrawOrder`)。区画ごとに「木を描く距離」で切る。遠い木を板の絵に
  替える (インポスター) のは後で
- **草**: 点ごとの濃さ + 決まった種の乱数で、区画ごとに置き場所を作る (データは小さい。同じ地形は
  いつも同じ草)。数が多い (数万〜数十万) ので `MeshDraw` を 1 本ずつ作らない: 区画ごとに置き場所を
  **GPU に 1 回だけ置き** (草の束)、描くときは数だけ言う
- **遠い物は減らす**: 区画の中の置き場所を、乱数の順に並べておく。遠い区画は**先頭から一部だけ**描く
  (数 = 全部 × 距離で小さくなる割合)。毎フレームの計算が要らず、減らしても残る物が飛ばない
- 草は影を落とさない (既定)。風で揺らすのは段階 9 (天候の風を読む)

### 5-4. 描画 (3D の描画への載せ方)

```
ゲーム制作 × 地形 (口 world_meshes に答える)
  ├ シーンの「地形」の部品ごとに: 区画を見える範囲で選ぶ → 段を選ぶ (Lod) → メッシュ (無ければ作る)
  ├ MeshDraw (区画のメッシュ + 塗り分けの見た目 TerrainLook)
  ├ 木の MeshDraw (区画ごと、描く距離まで)
  └ 草の束 (区画ごと、描く距離まで、先頭から何本)
ゲーム制作 × 3D ── RenderFrame::meshes に足す / WorldDrawFrame にも渡す ──▶ 天候 (向きの地図の形に入れる)
3D 空間の Renderer ── 影の地図 → 空 → 不透明な物 (地形もここ) → 積もった雪 (solids) → 透ける物 → extras
```

**塗り分けのシェーダー** (3D 空間に足す):

- 区画のメッシュはふつうの頂点 (位置・法線・UV)。UV は地形全体の中の場所 (0〜1)
- `TerrainLook` = 混ぜ方の絵 2 枚 (RGBA 8 ビット。地形全体で 1 組。点ごとに 8 層の重み) + 層ごとの
  `DrawMaterial` (マテリアルの絵と数) + 繰り返しの大きさ
- ピクセルシェーダーは、重みが 0 でない層だけ、その層の絵をワールドの x, z ÷ 繰り返しの大きさで読み、
  色・金属・ラフネス・法線を重みで混ぜてから、今と同じ `Shade()` で光を当てる。`RendererShaderText` から
  作るので、天候の `Surface()` (濡れ) もそのまま掛かる
- 層の絵は 1 枚ずつ結ぶ (テクスチャの配列にしない: 層ごとに大きさや圧縮が違ってよい)。8 層 × 絵 4 枚
  (色・金属 / ラフネス・法線・発光) で t の番号を 32 まで使う (Direct3D 11 は 128 まで)
- 混ぜ方の絵は、筆で変わった区画の四角だけ GPU に書き直す (`UpdateSubresource` の箱)
- 崖で絵が縦に伸びる問題 (3 方向から貼る **triplanar** = x・y・z の 3 つの向きから絵を投げて、面の向きで
  混ぜるやり方) は後で (11 章の 13)

**草の束** (3D 空間に足す):

- `RenderFrame` に「メッシュ・材質・GPU に置いた置き場所のバッファ・描く数」の並び
- 頂点シェーダーは置き場所 (位置・Y の回り・大きさ・色のゆらぎ) をバッファから読む (今の `things` と同じ
  `Buffer<float4>` の作り)。光の当て方は `Shade()`
- 地形だけのものではない (後で、パーティクル以外の「たくさんの同じ物」にも使える)

### 5-5. 当たり判定 (物理)

- 地形 × 物理が、物理の新しい口 `static_shapes` に、区画ごとの高さの格子を答える
  - 区画 1 つ = Jolt の `HeightFieldShape` 1 つ (64 マス = 65 点。切り上げの扱いは 2 章のとおり確かめる)。
    `mOffset` = 区画の角の場所、`mScale` = (マスの大きさ, 1, マスの大きさ)
  - 穴は `cNoCollisionValue`。マスの材質 = そのマスで一番濃い層 (当たった所の層が分かる)
  - 縮めたときのずれは `CalculateBitsPerSampleForError` で 1 cm 以下に
- **描く三角形と当たる三角形を同じにする**: 対角線の向きと穴で消える三角形を、Jolt の決まりに合わせる。
  テストで「同じ (x, z) で `Heights::HeightAt` と Jolt の光線の高さが同じ」を確かめる (ギズモの「描くものと
  つかめるものが食い違わない」と同じ考え)
- 作るのは Play の始めに 1 回 (物理の世界は Play のコピーのもの)。版が変われば作り直す
- 木: 種類の「当たり」がオンなら、幹のカプセル (半径・高さはモデルの大きさから)
- キャラクター (`CharacterVirtual`) と光線 (`rm::Physics::Raycast`) は、形の種類によらず当たる (実装のとき
  にテストで確かめる)
- シーンビューの「形: 全部」には、地形の線は出さない (多すぎる)。選んだときだけ外の枠

### 5-6. 天気・気候とのつなぎ

| つなぎ | どうなるか | 天候・気候の変わり方 |
|---|---|---|
| 濡れ | 地形のシェーダーが `Surface()` を通るので、雨で地形も暗く・つやが出る | 変えない |
| 積雪 | 地形の区画が向きの地図の形に入るので、雪が地形の上に積もり、足跡も付く | `WeatherBlocksOf` が `WorldDrawFrame` の新しい「エンティティでない形」も入れる (数行) |
| 雨が当たる所 | 同じ (崖の下の張り出しには降らない) | 同じ |
| 山の上だけ雪 | 濡れと積雪の地図のマスの気温を、**そのマスの地面の高さ**で聞く (CLIMATE.md の「決めていないこと」の 1 つ) | 天候 × 気候の `RunPlace` が口 `ground` を読む。答える者が無ければ今のまま (カメラの高さ) |
| 気候の地図 | 気候のタブの真上の絵に、地形がそのまま映る (3D のシーンビューが描くので) | 変えない |
| 気候エリアを地形の形に | 後で (11 章の 12) | — |

- 地形は天候も気候も知らない。天候・気候も地形を知らない (口だけを見る)

### 5-7. ナビメッシュに渡すもの (NAVIGATION.md と合わせる)

ナビメッシュ (キャラクターが歩ける所を三角形でつないだ地図) の入力として、地形の側から出せるもの。
NAVIGATION.md (4-3) の口は `rm_engine.game_x_navigation.source` (`NavSourceInfo`: 範囲の中の三角形と
エリアの番号を足す `collect`、範囲の形の指紋 `fingerprint`)。つなぎ「地形 × ナビ」がそれに答える
(タブの「焼く物」に「地形」として出る)。

| 渡すもの | 中身 | どこから |
|---|---|---|
| 高さ | 区画ごとの格子 (マスの大きさ・点の数・高さの列)。または一番細かい段の三角形 | `TerrainData` / `ChunkMesh` (段 0。スカートは除く) |
| 歩けない所: 穴 | 穴の点 (落ちる所) | 区画の `holes` |
| 歩けない所: 層 | 層ごとの「エリアの名前」(`area`。例「水」「溶岩」)。その名前を歩けない・歩きにくい (コスト) にするかはナビの設定で決める | 層の `area` と、マスの一番濃い層 |
| 坂 | 法線 (ナビが三角形から出してもよい。登れる坂はキャラクターの部品が持つ) | `Heights::NormalAt` |
| 障害物 | 当たりのある木の幹 (場所・半径・高さ) | 区画の `trees` と木の種類 |
| 変わった所 | 区画ごとの版の番号を混ぜたものを `fingerprint` に。ナビは変わった区画の分だけ焼き直せる (ナビの区画を地形の区画と同じ 64 m か、その約数にすると合わせやすい) | 地形の置き場 |
| 地面に沿わせる | エージェントの足を地面に合わせる高さ | 口 `ground` |

- 三角形の細かさ: ナビの箱の大きさ (ボクセル) より細かくしても意味が無いので、`ChunkMesh` の段を
  ナビの細かさに合わせて選ぶ (段 0 = 1 マス。マス 1 m なら段 0 で足りる)
- **作業スレッドで読める形にする**: ナビの `collect` は作業スレッドで呼ばれ、UI スレッドで写したシーン
  (`SceneSnapshot`) だけを読む決まり。でも地形の高さはシーンではなくアセット (置き場) にある。だから置き場の
  区画は「版ごとに作り直す、変えない写し」(`shared_ptr<const 区画>`) にし、写しを作るときに区画の写しを
  一緒に持たせる (コピーしない。筆は新しい区画を作って差し替える)
- エリア: ナビのエリアの種類 (NAVIGATION.md ではシーンの設定。名前と番号) に、層の `area` の名前で合わせる

## 6. エディターの画面

画面のコードは `w::` の部品で描き (四角を自分で塗らない)、色は `theme::` だけ、文字は日本語で `Tr(L"…")`
を通し、英語を `plugins/rm_engine/game_x_terrain/lang/en.json` に足す。

### 6-1. 作る

- 階層の「追加 ▸ 3D オブジェクト ▸ 地形」(`rm_engine.game_production.create_item`): 部品「地形」の
  付いたエンティティを作る (Undo の 1 件)
- インスペクターの部品「地形」の欄が空なら「新しい地形を作る」: `Assets/Terrains/<名前>.rmterrain` を
  書いて欄に入れる。欄の変更は Undo できる。**作ったファイルは Undo しても残る** (「Prefab にする」と同じ)
- アセットのパネルの「作成 ▸ 地形」(`core.asset_file_type`) でも作れる。アセットのインスペクターは
  大きさ・層の数などを見せるだけにして、編集は「地形」タブでする (中身全体を Undo に持たないため。2 章)

### 6-2. 「地形」タブ (`rm_engine.game_production.view_panel`)

```
┌ 地形: Field.rmterrain ─────────────────────────────────────────────────────┐
│ [上げる][下げる][ならす][平ら][穴][塗る][木][草]  ← 正方形のアイコンのボタン      │
│ 筆   半径 [ 8.0 ] m   強さ [====|---] 0.4   縁 [=======|-] 70 %            │
│      平らにする高さ [ 12.5 ] m  (Ctrl + クリックで拾う)                      │
│ ┌ 層 ─────────────────────────┐ ┌ 木と草 ─────────────────────────────────┐ │
│ │ ● [絵] 土     4 m   ×        │ │ ● 木  杉   モデル ▾  当たり ✓       ×  │ │
│ │   [絵] 草地   6 m   ×        │ │   草  草   モデル ▾  1 m² に 12 本  ×  │ │
│ │   [絵] 岩     3 m   ×        │ │ ＋ 木   ＋ 草                          │ │
│ │ ＋ 層                        │ └────────────────────────────────────────┘ │
│ └─────────────────────────────┘                                             │
│ 大きさ: 8 × 8 区画 (512 m)  [区画を足す ▾]   高さの範囲 −100 〜 400 m        │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 道具のボタンは気候のタブと同じ形 (シーンビューの左上と同じ正方形のアイコン)
- タブは選んだエンティティの地形を見る (地形の無いエンティティなら、シーンの最初の地形)。無ければ説明と
  「地形を作る」
- 層・草木の行の値はインスペクターと同じ描き方 (`editor::inspector::Draw`。気候のタブと同じ)
- 道具の絵は新しく要る。今の絵の表は核の `editor/widgets/IconAtlas.cpp` の 1 か所なので、そこへの
  足し方 (またはプラグインから絵を足す口) は実装のときに確かめる
- 筆の設定・選んだ道具・層は**見え方** (`UserSettings` のパネルの配置と一緒。プロジェクトに入れない。
  気候の `ClimateTabState` と同じ)

### 6-3. シーンビューで塗る

- タブで道具を選んでいる間、3D のシーンビューは筆の道具になる (口 `scene_tool`。3 章)。マウスの下の
  地形に**筆の輪** (半径の円と、強さの分だけ内側の円。色は新しい `theme::SceneBrush`)
- 左ドラッグで筆。右ドラッグ・中ドラッグ・ホイール・WASD はいつもどおりカメラ。Esc でその筆をやめる
  (始めに戻す・何も積まない)
- 当たりは CPU の `Heights::Raycast` (物理は Play の間だけなので使わない)
- 筆の間、触った区画のメッシュを作り直す。1 フレームに使う時間を区切る (テクスチャの `UploadSlice` と
  同じ考え。2 ms)。区切って残った区画は次のフレーム
- Play 中は塗れない (道具のボタンも薄く)

### 6-4. Undo (憲法 7)

- **筆 1 回 (押してから離すまで) = Undo の 1 件**。触った区画だけの前と後 (エンコードしたバイト列) を
  持つ (`TerrainStrokeCommand`。シーンの `SceneRecord` と同じ「触った物だけ」)。`ICommand::Bytes` で
  大きさを言う (64 × 64 の区画 1 つで、高さ 8 KB + 4 層の重み 17 KB ほど)
- 層・草木の種類の足す / 消す / 値の変更・区画を足す・高さの範囲を変える (全部の高さを読み替える) も、
  それぞれ Undo の 1 件
- Undo / Redo も置き場の区画を差し替えて版を上げる (描く側は同じ道で作り直す)
- 筆の途中で Ctrl+Z などで履歴が動いたら、その筆をやめる (ギズモのドラッグと同じ決まり)

## 7. 書き出し (`.rmpak`)

- 焼き手 (口 `export_bake`) は ゲーム制作 × 地形のエディター。`.rmterrain` → `Baked/<id>.rmterrain`
  (キー付きのチャンクのバイナリ。`.rmmesh` と同じ作りで、知らないチャンクは飛ばす)

| チャンク | 中身 |
|---|---|
| `TERR` | 見出し: マス・区画の数・高さの範囲・層 / 草 / 木の種類 (名前・番号・アセットの ID) |
| `HGHT` | 区画ごとの 16 ビットの高さ |
| `SPLT` | 区画ごとの層の重み |
| `HOLE` | 区画ごとの穴 |
| `GRAS` | 区画ごとの草の濃さ |
| `TREE` | 区画ごとの木 |

- base64 をやめるので約 4 分の 3 の大きさ。区画のメッシュと混ぜ方の絵は**ゲームが読むときに作る**
  (速い。`.rmpak` を小さく)
- 層のマテリアル・木と草のモデルは、今の `CollectAssets` が `.rm…` の JSON の中の ID をたどるので
  自動で入る。それぞれ今の焼き方 (マテリアルの `BakeMaterial`・モデルの `.rmmesh`) で焼かれる
- 区画のメッシュ・段の選び方・Jolt の形の作り方は、エディターの Play と同じコードを通る
- 使うプラグイン: 部品「地形」があるとゲーム制作 × 地形と地形が入る。物理もあれば 地形 × 物理 も
  (つなぎの決まり)
- `tools/check_export.ps1` に地形のテンプレート (10 章の段階 1) を足し、書き出して `--smoke` で起動する

## 8. スクリプト API (`#include "RMTerrain.h"`)

形はほかと同じ: `runtime/sdk/RMTerrainAbi.h` (C の関数の表)・口 `rm_engine.game_production.script_api`
(部分 `rm_engine.game_x_terrain.terrain` 版 1)。

```cpp
float h;  rm::Vec3 n;
if (rm::Terrain::GroundAt(pos, &h, &n)) { ... }        // 地面の高さと向き (地形の外・穴: false)
float y = rm::Terrain::HeightAt(pos);                    // 地面の高さ (地面が無い所は 0。確かめるときは GroundAt)
std::string layer = rm::Terrain::LayerAt(pos);          // 一番濃い層の名前 (足音・砂ぼこり)
float snow = rm::Terrain::LayerWeight(pos, "雪");        // その層の濃さ 0..1
```

- 使い道: 物を地面に置く・足音を層で変える・車輪の砂ぼこり・NPC を地面に沿わせる
- 境目は C だけ (`const char*` と関数ポインタ。`RmAbi.h` の決まり)。文字は呼ぶ側の入れ物に写す
- 光線は物理の `rm::Physics::Raycast` がそのまま地形に当たる (新しく作らない: 憲法 3)
- ゲームの中で地形を変える (掘る・盛る) は後で (11 章の 11)

## 9. 1 フレームの順番

Play の間 (ARCHITECTURE.md の物理の節の順番に足す):

1. 入力 → スクリプトの `Tick` (`RMTerrain.h` は読むだけ)
2. 固定の刻み: システム「物理」(地形の高さの格子は Play の始めに作ってある。版が変われば作り直す)
3. 毎フレームのシステム: 天候 × 気候 (濡れの地図のマスの気温を口 `ground` の地面の高さで) → 天候 →
   アニメーション …
4. 描く (画面ごと): 地形の区画と段を選ぶ → 木と草の区画を選ぶ → `world_meshes` から `MeshDraw` と草の束 →
   世界に描く物の `PrepareFrame` (天候が地形の形も向きの地図に) → `Render` (影の地図 → 空 → 不透明な物 →
   積もった雪 → 透ける物 → extras)

止まっているエディター: 2 と 3 は無い。筆で変わった区画は 4 の始めに作り直す (1 フレーム 2 ms まで)。

## 11. 決めていないこと (聞くこと)

| # | 聞くこと | おすすめ |
|---|---|---|
| 1 | 地形を部品にするか、シーンの設定にするか | **部品「地形」+ アセット `.rmterrain`**。いくつも並べられる・Transform で動かせる・Prefab にできる・有効 / 無効が効く。シーンの設定 (気候の地図の形) はシーンに 1 つだけになる |
| 2 | マスの大きさ・区画の大きさ・広さの上限 | **マス 1 m (0.25〜8 m で選べる)・区画 64 × 64 マス (決まった数)・最初は 8 × 8 区画 (512 m)・上限は 1 辺 2048 マス** (段階 10 まで) |
| 3 | 高さの持ち方 | **16 ビット + 高さの範囲** (既定 −100〜400 m = 約 0.8 cm 刻み)。32 ビットの float は 2 倍の大きさ。Jolt も中で縮めて持つので、細かさは足りる |
| 4 | 大きいデータの置き方 | **1 つの `.rmterrain` (JSON) の中に、区画ごとの base64**。自己記述のまま、git の差分も区画ごとになる。2 km より大きい地形は、段階 10 で区画ごとのファイルに分ける |
| 5 | 筆をどこで使うか | **シーンビューで塗る** (ほかの物を見ながら。Unity と同じ) + **「地形」タブに道具と一覧**。タブの中に別の 3D の絵は作らない (シーンビューと 2 つになる: 憲法 3) |
| 6 | 遠くを粗くするやり方 | **段の格子 + スカート** を先に (今の影・向きの地図・当たりがそのまま効く)。広い地形が要るときに **CDLOD** (段階 10)。クリップマップは選ばない |
| 7 | 層の数と中身 | **8 層まで。層 = マテリアル (`.rmmat`) + 繰り返しの大きさ**。新しい「地形の層」のファイルは作らない (マテリアルの見た目と編集をそのまま使う: 憲法 2) |
| 8 | 草と木の持ち方 | **木は 1 本ずつの列** (1 本ずつ消せる・動かせる)、**草は濃さの地図 + 決まった種の乱数** (数十万本でもデータが小さい) |
| 9 | 木に当たりを付けるか | **木の種類ごとに「当たり」のチェック** (既定オン。幹のカプセル)。草には付けない |
| 10 | 地形の回転と大きさ | **位置だけ効く** (回転・大きさは使わない)。高さの格子が軸にそろっていると、物理・天候・ナビが簡単 |
| 11 | ゲームの中で地形を変える (掘る・盛る) | **後で** (段階 10)。まずは読むだけの API。変えるときは Jolt の `SetHeights` (ブロックの境目からの四角だけ) と区画のメッシュの作り直し |
| 12 | 層と気候をつなぐか (砂の層 = 砂漠など) | **つながない**。気候は気候のタブで塗る (地形は気候を知らない)。地形タブに気候の地図を薄く重ねて見せるのは後で |
| 13 | 崖で絵が伸びる (triplanar) | **層ごとのチェック** (重いので、崖の層だけ)。段階 9 |
| 14 | ナビの「歩けない」をどう書くか | **層に「エリアの名前」**を持たせ、ナビのエリアの種類 (シーンの設定) に名前で合わせる。歩けない / 歩きにくさ (費用) はナビの側が持つ (地形はナビを知らない)。NAVIGATION.md と合わせて決める |
| 15 | 高さの絵の取り込み | **段階 9** で 16 ビットの PNG と RAW (外の地形ツールがよく書く形)。今の `platform/Image` (WIC) が 16 ビットのまま読めるかは確かめる |
