## 1. プラグインの分け方

前の設計 (TestEngine `RME_PLATFORM.md`) の分け方に合わせる。

| プラグイン | 中身 | 前提 |
|---|---|---|
| **アニメーション** (`animation`) | クリップのデータ `.rmanim` (時間ごとの値の並び。3D か 2D かを知らない)・状態と遷移 `.rmanimstate`・それを進める計算 (純粋)・**アニメーターのタブ** | なし |
| **3D アニメーション** (`animation3d`) | 骨 (スケルトン)・スキン・FBX / glTF からクリップを読む・ポーズの計算・骨に物を付ける・(後で) IK・ブレンドシェイプ | アニメーション + 3D 空間 |
| **ゲーム制作 × アニメーション** (つなぎ) | 部品「アニメーター」・Play の間に進める (play_service)・スクリプトの `RMAnim.h`・書き出しで焼く | ゲーム制作 + アニメーション (+ 3D アニメーション) |
| **パーティクル** (`particles`) | エフェクト `.rmparticle` (エミッターとモジュールの並び)・モジュール `.rmfx` (HLSL)・GPU の計算と描画・**パーティクルのタブ** | なし (GPU は核の `platform/Gfx`) |
| **ゲーム制作 × パーティクル** (つなぎ) | 部品「パーティクル」・Play の間に進める・スクリプトの `RMParticles.h`・当たり判定の形をコライダーから受け取る・書き出し | ゲーム制作 + パーティクル |
| 3D / 2D への描き込み | 3D の描画 (space3d) と 2D の描画 (space2d) が「透ける物の後に描く口」を出し、パーティクルのつなぎが差し出す | — |

GPU のスキニング (頂点を骨で動かす) は 3D の描画 (space3d の Renderer3D) に入れる (描くのは 3D の描画の仕事)。
骨の行列を計算して渡すのは 3D アニメーション。

## 2. 3D のボーンアニメーション

### 2-1. 作る順番

1. **動かす**: FBX と glTF から骨・ウェイト・クリップを読む → GPU でスキニング → 部品「アニメーター」でクリップを 1 つ流す (ループ・速さ) → スクリプトの `Play("Run")` → 2 つのクリップをクロスフェード → 骨に物を付ける (部品「骨に付ける」) → クリップの途中の知らせ (イベント)
2. **アニメーターのタブ** (状態と遷移の図): 状態・遷移・パラメーター (数・整数・真偽・トリガー)・どこからでも (Any State)・遷移の条件と時間 (インスペクター)・タブのプレビュー (モデルを置いて動かす)・シーンビューでの再生
3. **組み立て**: ブレンドツリー (速さで歩きと走りを混ぜる)・レイヤーとマスク (上半身だけ)・ルートモーション
4. **仕上げ**: IK (足を坂に・顔を向ける)・ブレンドシェイプ (表情)・物理で揺らす (髪・服・ラグドール)

### 2-2. データ

- **モデル** (`.meta` の取り込みの設定): 骨の木・バインドポーズ・頂点ごとの骨 4 本とウェイト。取り込みの設定に「クリップ」の一覧 (名前・始め / 終わりのコマ・ループ)。Unity のモデルの取り込みの「Animation」と同じ
- **クリップ** `.rmanim`: 「どの値 (骨の名前 + 位置 / 回転 / 大きさ) を・いつ・いくつにするか」の並び。モデルの中のクリップはモデルのサブアセットとして見える (アセットのパネルでモデルを開くと中にクリップ)。書き出しではキー付きのチャンクのバイナリに焼く (`.rmmesh` と同じ考え)
- **状態と遷移** `.rmanimstate` (RM_STRUCT で書く。憲法 9): パラメーター・レイヤー・状態 (クリップ / ブレンドツリー・速さ・ループ・図の上の場所)・遷移 (元 → 先・条件の一覧・遷移の時間・終わりを待つ・割り込み)
- **部品「アニメーター」**: 状態と遷移の参照・モデルのエンティティ・パラメーターの初めの値 (状態と遷移を変えると欄が変わる)
- 骨は**エンティティにしない** (100 本の骨で階層が埋まらない・速い)。物を付けたいときだけ部品「骨に付ける」(骨の名前を一覧から選ぶ)

### 2-3. 動かし方

- ポーズの計算は CPU (クリップを読む → 混ぜる → 親から順に掛ける → スキンの行列)。純粋な計算にしてテストを書く (憲法 5)
- スキニングは GPU の頂点シェーダー。骨の行列は構造化バッファ (骨の数の上限は 1 つのメッシュで 256 から始める。定数バッファの上限に縛られない)
- インスタンシングはそのまま (骨の行列を 1 つの大きなバッファに並べ、インスタンスごとに先頭の位置)
- 影の絵にもスキニングした形で描く
- 多くのキャラクター (数百) で重くなったら、ポーズの計算を別のスレッドへ、スキニングを Compute Shader へ (後で)

## 3. パーティクル

### 3-1. 作り方の形

```
エフェクト「炎」 (.rmparticle)
 └ エミッター「火」
     ├ 出し方        1 秒に 200 個・円から          ← 用意したモジュール
     ├ はじめの値    寿命 1〜1.5 秒・上へ 2
     ├ 力            重力 -0.2・ゆらぎ 0.5
     ├ 色の変わり方  黄 → 橙 → 赤 → 透明
     ├ 風で曲げる    (Assets/Particles/Wind.rmfx)   ← HLSL で書いたモジュール
     ├ 当たり        地面で止まる
     └ 描き方        絵・足して光らせる・トレイル
```

- 1 つのエフェクトにエミッターがいくつか (火・煙・火の粉)。エミッターはモジュールの並び
- **用意したモジュールも `.rmfx` (HLSL) で書く**。自分で書いたモジュールと同じ仕組み (仕組みは 1 本。憲法 3)
- 並びの順に関数を呼ぶ 1 本の Compute Shader を、エンジンが組み立てる (並びを変えたら作り直す)

### 3-2. モジュール `.rmfx` (HLSL)

```hlsl
// Wind.rmfx
param float  strength = 1.0;        // 欄になる (名前・型・初めの値。範囲や説明も書ける)
param float3 direction = {1, 0, 0};

void Update(inout Particle p, float dt) {
    p.velocity += direction * strength * sin(p.age * 3.0) * dt;
}
```

- 段階: `Spawn` (生まれたとき 1 回)・`Update` (毎フレーム)・`Render` (描くときの値)。モジュールは使う段階の関数だけ書く
- 粒の値: 決まったもの (位置・速さ・年齢・寿命・大きさ・色・回転・種) + モジュールが足す値 (`attr float heat;`)
- `param` はエンジンが読んで、モジュールの欄にする (インスペクター・Undo・保存は欄の定義から。憲法 1)。数の代わりに「寿命で変わる曲線」や「色の帯」も選べる型にする
- 保存すると作り直してプレビューに出す。書き間違いは何行目かをコンソールとモジュールの欄に出す
- 書き出し: 組み立てたシェーダーをコンパイル済みのバイト列で入れる (ゲームは HLSL を読まない)

### 3-3. GPU の動かし方

- 粒は GPU のバッファ (構造化バッファ) に置き、空きの番号の一覧 (dead list) で生まれる・消えるを管理する。CPU は「このフレームに何個生まれるか」だけ決める
- 1 フレーム: 生まれる (Spawn) → 動かす (Update。当たり判定もここ) → 描く数を数える → 描く (DrawInstancedIndirect)
- 描き方: カメラを向く四角 (ビルボード)・速さの向きに伸びる四角・**トレイル** (粒ごとに過去の位置をいくつか覚えて帯でつなぐ)・(後で) メッシュ
- 透ける粒の重なり: 足して光らせる (加算) なら並べ替えは要らない。普通の透明は GPU で奥から並べる (後で)
- シーンビューの時間のつまみ: 種を決めて、0 秒から固定の刻みで計算し直す (同じ形がいつも出る)

### 3-4. 当たり判定

- **簡単な形**: 平面・球・箱・カプセル。部品「コライダー」(3D / 2D) から形を集めて GPU に渡す (つなぎが差し出す)。物理 (Jolt) は CPU なので直接ぶつけない
- **画面の深度** (3D だけ): 見えている物の表面で跳ねる・止まる・消える。速くて手軽。画面の外の物には当たらない
- 当たったときに「消える / 跳ねる / 止まる」と、(後で) 当たったところから別のエミッターを出す (サブエミッター)

### 3-5. 2D

- 2D の描画は Direct2D。粒は Direct3D で描くので、2D のビューでは Direct2D を区切って (Flush) Direct3D で描き、また Direct2D を続ける (エンジンはもう両方を混ぜている)
- スプライトとの前後: 粒の部品の「並び順」で、そのスプライトたちの間に描く (区切りが増えるので、粒の部品が多いと遅くなる。その時は層ごとにまとめる)
- 当たり判定は 2D のコライダーの形だけ (2D に深度は無い)

### 3-6. 作る順番
**2026-11-16 に作ったもの** (画面は未確認): 1 の大部分 = GPU の土台・用意したモジュール 9 つ (形: 円すい / 球 / 箱・はじめの値・力・ゆらぎ・色と大きさの変わり方・床で跳ねる)・`.rmparticle`・部品「パーティクル」(3D)・シーンビュー / ゲームビュー / 書き出したゲーム・「パーティクル」タブ (並び・値・プレビュー・エミッターの設定はインスペクター)。シーンビューの「再生・一時停止・時間のつまみ」はまだ (今は選ぶと始めから動く)。粒の置き場所は輪で使い回す形 (dead list は後で)。描く色はシーンの色と同じく画面の色 (sRGB) のまま。2 の HLSL のファイルのモジュールも 2026-11-16 に作った (保存で作り直し・間違いは行で・書き出しに入る)。3 の当たり判定 (コライダーの形・画面の深度) とトレイル・伸びる粒も 2026-11-16 に作った (サブエミッターはまだ)。4 の 2D・5・プリセット・画像の粒はこれから


1. **GPU の土台と最初のモジュール**: Compute Shader の仕組み・粒のバッファ・出し方 / はじめの値 / 力 / 色と大きさの変わり方 / 描き方 (ビルボード)・`.rmparticle` とタブ (モジュールの並び・プレビュー)・部品「パーティクル」(3D)・シーンビューで再生・Play と書き出し
2. **HLSL で書くモジュール**: `.rmfx` の `param` / `attr`・保存で作り直し・エラーの行
3. **当たり判定とトレイル**: 簡単な形・画面の深度・伸びる四角・トレイル・サブエミッター
4. **2D**: 2D のビューへの描き込みと並び順・2D のコライダー
5. **仕上げ**: 並べ替え・柔らかい粒 (地面との境目をぼかす)・光を受ける粒・見えない物を計算しない

## 前のエンジンから (TestEngine の docs と引き継ぎメモ)

**パーティクル** (`docs/PARTICLES.md`: CPU で計算・エミッターごとに 1 回描く)
- ユーザーの要望: 「○を放つだけで炎が作れない」(08-19) → 外の素材なしで炎・煙・火花が作れる**内蔵の絵とプリセット** (炎・煙・火花・爆発・キラキラ・電撃・レーザー)。電撃とレーザー (持続ビームと光弾、当たったら止める / 止めない) も欲しい (09-15)。→ 新しいエンジンでも**プリセットと内蔵の絵を最初から入れる**。描き方に**伸びる粒・稲妻・ビーム**を入れる
- 見送ったもの: トレイルとソフトパーティクル (「深度を読めない作りだった」「頂点の形を作り直す大工事」)。→ 新しいエンジンでは**最初から深度を読める形** (深度バッファを SRV にする) と、粒ごとの過去の位置を持つ形にしておく
- 困ったこと: 速く動くエミッターで粒が団子になる (フレームの間を埋めない) → 生まれる位置をフレームの間で補う。透ける粒が他の透ける物とエミッターの 1 点でしか並ばない。描き方を足したのに画面で確かめないまま終わった
- 良かったこと: 純粋な計算を分けた (描き方を足しても前の見た目が変わらない)・**部品は値だけ、動いている状態は別に持つ** (Play の巻き戻しが正しい)・値の範囲を 1 か所で直す

**アニメーター** (`docs/ANIM_STATE.md`)
- パラメーター (真偽・数・トリガー)・条件は AND だけ (OR は遷移を 2 本)・遷移はクロスフェードの秒数・Any State・**条件の無い遷移は通さない** (毎フレーム遷移する事故)・遷移の途中の割り込みは「元を差し替えるだけ」
- 失敗: 図の画面は見た目だけで終わった・編集が Undo とつながっていなかった (明示の保存)・**再生の道が MMD と FBX の 2 本に分かれた** (引き継ぎメモ「2 系統あるのが失敗」)・Play 中に再生する道が配線されていなかった
- → 新しいエンジンでは: 図の編集も Undo に積む (憲法 7)・再生の道は 1 本 (どの形式も `.rmanim` にしてから流す)・exit time とイベントは最初の版から

**骨とスキニング** (`docs/FBX_FULL.md`・`MMD.md`・引き継ぎメモ 4-9)
- 骨の行列の上限 512 で、超えた分が黙って 1 本に潰れた → 上限を超えたら知らせる
- 踏んだ罠: バインドポーズとファイルの上のポーズは別物 (逆バインド行列から作り直すと T ポーズになる)・アニメーションが無くてもスキニングは通す・メッシュのノードの行列を畳み込まないと大きさが二重に掛かる (37463 倍)・骨の親は「骨として登録された一番近い祖先」・骨の並びは親 → 子へ並べ替える・日本語の骨の名前の文字化け・同じ名前のノードがある (名前 + 何番目で引く)・袖の幽霊ウェイト (実物のモデルで試すまで分からない)
- → 骨の読み込みは**実物のモデル** (Blender・Mixamo・VRoid の書き出し) でテストする
